Binary Search on Answer

No sorted array? Search the range of possible answers with a feasibility check.

A. Pattern Overview

In binary search on the answer the sorted thing is not the input but the space of candidate answers. You guess a value x, ask "is x feasible?" with a greedy or counting check in O(n), and use the fact that feasibility is monotone (if speed 5 works, speed 6 works; if capacity 10 fails, capacity 9 fails) to discard half of the candidates. Total cost: O(n · log(range)).

KEY IDEA

The recipe: (1) define feasible(x); (2) prove it is monotone; (3) bound the answer: lo = smallest conceivable, hi = a value that is surely feasible; (4) binary search for the first feasible (minimise) or the last feasible (maximise).

B. When to Recognize This Pattern

Pattern Recognition Signals

"Minimise the maximum" or "maximise the minimum" appears in the statement: the unmistakable fingerprint.
The answer is a number in a bounded range (speed, capacity, days, distance, limit), and

given a candidate you can verify it greedily in O(n).

A brute force tries every answer 1, 2, 3, …; the feasibility pattern suggests answers are ordered by difficulty.
Constraints: values up to 10⁹ or 10¹⁵ (a linear sweep of the answer range is impossible)

but the array has n ≤ 10⁵.

Splitting, partitioning or scheduling into at most k groups / days / workers.
TWO-QUESTION TEST

Ask: "If I told you the answer was x, could I check it quickly, and would a bigger (or smaller) x be at least as easy?" Two yeses mean binary search on the answer.

CHECK MONOTONICITY

If feasibility is not monotone (for example, "is there a subarray of length exactly L with sum S" with negatives), binary search is invalid. Check monotonicity before coding.

C. Core Intuition with Illustrations

Koko eats bananas from piles [3, 6, 7, 11] and has h = 8 hours. Speed k takes Σ ⌈pile /

k⌉ hours. Speeds 1…11 form a clean F … F T … T row:

Figure 27. Index shown is speed − 1. The first T sits at speed 4: that is the minimum feasible answer. The blue row lists hours needed.

Binary search never evaluates all eleven speeds; it probes about log₂ 11 ≈ 4 of them.

INTUITION

Most mistakes here come from the bounds. lo must be the smallest value that could be correct (heaviest package, largest element, speed 1). hi must be a value that is certainly feasible (total weight, largest pile). A bad lo can skip the answer; a bad hi can make the search return an infeasible value.

D. Brute Force to Optimal Solution

Example: Capacity to Ship Packages Within D Days (LeetCode 1011)

Brute force: try capacities max(w), max(w)+1, … and simulate each: O(n · Σw). With Σw

up to 5·10⁷ this is too slow.

Observation 1: the answer lies in [max(w), Σw]. Below max(w) the heaviest package never fits; at Σw everything ships in one day.
Observation 2: if capacity c works, any c' > c works too, so feasibility is monotone.
Optimal: binary search c over that range, checking each with a greedy packing: O(n ·log Σw), O(1) space.

E. Java Implementation

Koko Eating Bananas: minimise the speed

KokoEatingBananas.java — LeetCode 875

Java 17+

/**
 * LeetCode 875 - Koko Eating Bananas. Binary search on the answer (minimise a feasible
 * speed).
 */
public class KokoEatingBananas {

    public static int minEatingSpeed(int[] piles, int h) {
        int lo = 1;                                  // slowest legal speed
        int hi = 0;
        // speed = max pile always works (h >= n)
        for (int pile : piles) hi = Math.max(hi, pile);

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (canFinish(piles, h, mid)) {
                hi = mid;                            // feasible: try slower
            } else {
                lo = mid + 1;                        // infeasible: must be faster
            }
        }
        return lo;
    }

    private static boolean canFinish(int[] piles, int h, int speed) {
        long hours = 0;
        for (int pile : piles) {
            hours += (pile - 1) / speed + 1;         // ceil(pile / speed) without overflow
            if (hours > h) return false;             // early exit
        }
        return true;
    }
}

TIME O(n · log max)

SPACE O(1)

(pile - 1) / speed + 1 is integer ceil division; the early exit once hours > h saves work.

Capacity to Ship Packages: minimise the maximum load

ShipPackages.java — LeetCode 1011

Java 17+

/**
 * LeetCode 1011 - Capacity To Ship Packages Within D Days. Minimise the maximum load per day.
 */
public class ShipPackages {

    public static int shipWithinDays(int[] weights, int days) {
        long lo = 0;                    // capacity must fit the heaviest single package
        long hi = 0;                    // capacity = total weight ships everything in one day
        for (int w : weights) {
            lo = Math.max(lo, w);
            hi += w;
        }
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;
            if (daysNeeded(weights, mid) <= days) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return (int) lo;
    }

    /** Greedy: load packages in order until the next one would overflow the capacity. */
    private static int daysNeeded(int[] weights, long capacity) {
        int days = 1;
        long load = 0;
        for (int w : weights) {
            if (load + w > capacity) {
                days++;
                load = 0;
            }
            load += w;
        }
        return days;
    }
}

TIME O(n · log Σw)

SPACE O(1)

The greedy check is optimal because delaying a cut never hurts: pack the current day as full as possible.

G. Variations of the Pattern

Split Array Largest Sum: the same engine, a different check

Split into k contiguous parts to minimise the largest part sum. Identical to shipping: parts

are days, sums are loads. Range [max(nums), Σnums].

SplitArrayLargestSum.java — LeetCode 410

Java 17+

/** LeetCode 410 - Split Array Largest Sum. Minimise the maximum subarray sum over k parts. */
public class SplitArrayLargestSum {

    public static int splitArray(int[] nums, int k) {
        long lo = 0;                    // the largest part is at least the largest element
        long hi = 0;                    // and at most the whole array
        for (int x : nums) {
            lo = Math.max(lo, x);
            hi += x;
        }
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;
            if (partsNeeded(nums, mid) <= k) {
                hi = mid;               // k parts (or fewer) suffice: try a smaller cap
            } else {
                lo = mid + 1;
            }
        }
        return (int) lo;
    }

    private static int partsNeeded(int[] nums, long maxSum) {
        int parts = 1;
        long current = 0;
        for (int x : nums) {
            if (current + x > maxSum) {
                parts++;
                current = 0;
            }
            current += x;
        }
        return parts;
    }
}

TIME O(n · log Σ)

SPACE O(1)

The DP alternative is O(k · n²): binary search is dramatically faster and shorter.

Maximise the minimum: Magnetic Force Between Two Balls

Now feasibility flips: a small gap is easy, a large gap is hard (T … T F … F). We want the last true, so lo = mid on success and the mid must be rounded up to avoid an infinite loop.

MagneticForce.java — LeetCode 1552
import java.util.Arrays;

/** LeetCode 1552 - Magnetic Force Between Two Balls. Maximise the minimum distance. */
public class MagneticForce {

    public static int maxDistance(int[] position, int m) {
        int[] pos = position.clone();
        Arrays.sort(pos);
        // any two distinct baskets are >= 1 apart
        int lo = 1;
        // m balls cannot be farther apart than this
        int hi = (pos[pos.length - 1] - pos[0]) / (m - 1);
        while (lo < hi) {
            // UPPER mid: avoids an infinite loop
            int mid = lo + (hi - lo + 1) / 2;
            if (canPlace(pos, m, mid)) {
                // feasible: try a larger minimum gap
                lo = mid;
            } else {
                hi = mid - 1;
            }
        }
        return lo;
    }

    private static boolean canPlace(int[] sorted, int m, int minGap) {
        int placed = 1;
        int last = sorted[0];
        for (int i = 1; i < sorted.length && placed < m; i++) {
            if (sorted[i] - last >= minGap) {
                placed++;
                last = sorted[i];
            }
        }
        return placed >= m;
    }
}

Java 17+

TIME O(n log n + n log D)

SPACE O(n)

Sorting dominates when the range D is small.

INFINITE-LOOP TRAP

Upper mid. With lo = mid the standard mid (lo + (hi - lo)/2) can equal lo and never advance. Use lo + (hi - lo + 1)/2 for any "last true" search.

Time as the answer: Minimum Days to Make m Bouquets

The candidate is a day; feasibility counts how many runs of k adjacent bloomed flowers exist by that day. Note the early -1 if m · k > n.

MinDaysBouquets.java — LeetCode 1482

Java 17+

/**
 * LeetCode 1482 - Minimum Number of Days to Make m Bouquets. Feasibility check is monotone in
 * the day.
 */
public class MinDaysBouquets {

    public static int minDays(int[] bloomDay, int m, int k) {
        if ((long) m * k > bloomDay.length) return -1;      // not enough flowers at all
        int lo = Integer.MAX_VALUE;
        int hi = 0;
        for (int day : bloomDay) {
            lo = Math.min(lo, day);
            hi = Math.max(hi, day);
        }
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (bouquets(bloomDay, k, mid) >= m) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    /** How many bouquets of k ADJACENT bloomed flowers can be made by the given day. */
    private static int bouquets(int[] bloomDay, int k, int day) {
        int made = 0;
        int run = 0;
        for (int d : bloomDay) {
            if (d <= day) {
                if (++run == k) {
                    made++;
                    run = 0;
                }
            } else {
                run = 0;                 // a flower that has not bloomed breaks adjacency
            }
        }
        return made;
    }
}

TIME O(n · log(max − min))

SPACE O(1)

(long) m * k prevents overflow in the impossibility check.

Kth smallest via value-range search

Instead of searching indices, search the values between the smallest and largest entry.

count(≤ x) ≥ k is monotone in x, and the count for a row-and-column-sorted matrix is a

single staircase walk. The answer is always an element of the matrix because lo converges

to the smallest x with count ≥ k.

KthSmallestMatrix.java — LeetCode 378

Java 17+

/**
 * LeetCode 378 - Kth Smallest Element in a Sorted Matrix. Binary search on the VALUE range.
 */
public class KthSmallestMatrix {

    public static int kthSmallest(int[][] matrix, int k) {
        int n = matrix.length;
        int lo = matrix[0][0];
        int hi = matrix[n - 1][n - 1];
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (countAtMost(matrix, mid) >= k) {
                hi = mid;               // at least k values are <= mid: the answer is <= mid
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    /** Number of entries <= x using the staircase from the bottom-left corner. O(n). */
    private static int countAtMost(int[][] matrix, int x) {
        int n = matrix.length;
        int row = n - 1;
        int col = 0;
        int count = 0;
        while (row >= 0 && col < n) {
            if (matrix[row][col] <= x) {
                count += row + 1;       // whole column segment above (and including) this cell
                col++;
            } else {
                row--;
            }
        }
        return count;
    }
}

TIME O(n · log(max − min))

SPACE O(1)

J. Interview Tips

INTERVIEW

Name the pattern early: "This is minimise the maximum, so I'll binary search the answer and write a greedy feasible(x)." It signals senior-level recognition.

Write feasible first, test it by hand on one value, then wrap the binary search around it. The search itself is boilerplate.

Justify the bounds and monotonicity in one sentence each; that is where interviewers probe.

Follow-ups: minimise the answer with additional constraints, return the actual partition (re-run the greedy with the final answer), parallel machines scheduling, double answers (fixed iteration count).number of days).

CHAPTER SUMMARY

Binary search the answer range when feasible(x) is monotone and checkable in O(n).

Minimise the maximum → first true (hi = mid); maximise the minimum → last true (lo = mid, upper mid).

Bounds: lo = smallest conceivable answer, hi = a certainly feasible answer. Use long for sums.

Complexity O(n · log(range)); prove monotonicity and greediness of the check in the interview.
