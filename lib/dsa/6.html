Sliding Window

Maintain a moving contiguous range and update its summary in O(1) per step.

A. Pattern Overview

A sliding window is a contiguous subarray (or substring) [left, right] whose summary (sum, character counts, distinct count, number of zeros) is updated incrementally as the window moves, instead of being recomputed from scratch. Each element enters the window once and leaves at most once, so a search over O(n²) subarrays costs O(n).

KEY IDEA

The pattern is valid when the window's validity is monotone: if [l, r] is valid then every sub-window is also valid (for a longest search over a constraint), or if it is invalid then every larger window is invalid. This is why sums with negative numbers break it, while counts, distinct values and non-negative sums work.

Versus two pointers: both indices move forward and never backward here, and the pair (left, right) is a range whose interior you summarise. Versus prefix sums: prefix sums answer any range query in O(1) after preprocessing and tolerate negatives; a sliding window needs no extra array and handles conditions that are not subtractable (distinct count, "at most k replacements").

B. When to Recognize This Pattern

Pattern Recognition Signals

The words substring, subarray, contiguous, consecutive appear together with longest, shortest, maximum, minimum, at most, exactly.
The condition is about the contents of the range: distinct characters, frequency match,

number of zeros, sum ≥ target with positive numbers.

A fixed k is given, or the question is "for every window of size k".
The brute force enumerates all (i, j) and recomputes a summary of a[i..j]; you

realise the summary of [i, j+1] follows from [i, j] in O(1).

Input is a string or array with n up to 10⁵–10⁶ and the target complexity is O(n).
THE MOST COMMON TRAP

Negative numbers and a sum constraint = not a sliding window. For sum == k or

sum ≥ k with negatives, use prefix sums + HashMap (Chapter 3) or a monotonic

deque (Chapter 8).

INTUITION

Why O(n) even with a while inside a for? left only ever increases and never exceeds n. Across the whole run, the inner loop body executes at most n times in total (amortised analysis). Cost = n right-moves + n left-moves = O(n).

Three templates to memorise

Templates (fragments: add / remove / valid depend on the problem)

// 1) FIXED SIZE k
long window = 0, best = Long.MIN_VALUE;
for (int right = 0; right < n; right++) {
    window += nums[right];                    // element enters
    if (right >= k) window -= nums[right - k]; // element leaves
    if (right >= k - 1) best = Math.max(best, window);
}

// 2) LONGEST VALID  (shrink only when invalid)
int left = 0, best = 0;
for (int right = 0; right < n; right++) {
    add(nums[right]);
    while (!valid()) { remove(nums[left]); left++; }
    best = Math.max(best, right - left + 1);
}

D. Brute Force to Optimal Solution

Example: Minimum Window Substring (LeetCode 76)

Smallest substring of s containing every character of t (with multiplicity).

Brute force: for every (i, j) build the character counts of s[i..j] and test coverage. O(n² · (n + m)), roughly O(n³).
First improvement: for a fixed i, grow j once instead of rebuilding: O(n²). The wasted work is re-scanning from i for every start.
Key observation: if s[i..j] already covers t, then s[i..j'] with j' > j also covers it but is longer, so for the next start i+1 we need not look below j. So j never moves backward: that is a window.
Optimal: keep need[c] (how many copies of each character are still required) and a single integer missing. Expanding fills requirements; while missing == 0, record and shrink. O(n + m).

E. Java Implementation

Fixed window: Maximum Sum Subarray of Size K

MaxSumSubarrayK.java
/** Maximum Sum Subarray of Size K (classic). Fixed-size sliding window. */
public class MaxSumSubarrayK {

    /** Returns the max sum of any k consecutive elements; throws if k is invalid. */
    public static long maxSum(int[] nums, int k) {
        if (nums == null || k <= 0 || k > nums.length) {
            throw new IllegalArgumentException("k must be in [1, nums.length]");
        }
        long windowSum = 0;
        for (int i = 0; i < k; i++) windowSum += nums[i];     // build the first window
        long best = windowSum;
        for (int right = k; right < nums.length; right++) {
            windowSum += nums[right];                          // element entering
            windowSum -= nums[right - k];                      // element leaving
            best = Math.max(best, windowSum);

        }
        return best;
    }
}

Variable window (longest): Longest Substring Without Repeating Characters

LongestSubstringNoRepeat.java — LeetCode 3

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 3 - Longest Substring Without Repeating Characters. Variable window, last-seen
 * jump.
 */
public class LongestSubstringNoRepeat {

    public static int lengthOfLongestSubstring(String s) {
        Map<Character, Integer> lastSeen = new HashMap<>();
        int left = 0;
        int best = 0;
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            Integer prev = lastSeen.get(c);
            if (prev != null && prev >= left) {
                // jump past the previous copy inside the window
                left = prev + 1;
            }
            lastSeen.put(c, right);
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}

TIME O(n)

SPACE O(min(n, Σ))

Σ = alphabet size. The prev >= left test matters: a stale index left of the window must be ignored.

Variable window (shortest) with a frequency array: Minimum Window Substring

MinimumWindowSubstring.java — LeetCode 76

Java 17+

/** LeetCode 76 - Minimum Window Substring. Variable window with a "missing" counter. */
public class MinimumWindowSubstring {

    /** Assumes ASCII input (the LeetCode constraint is English letters). */
    public static String minWindow(String s, String t) {
        if (s == null || t == null || t.isEmpty() || s.length() < t.length()) return "";

        int[] need = new int[128];               // need[c] > 0 means c is still required
        for (char c : t.toCharArray()) need[c]++;
        int missing = t.length();                // how many required chars are not yet covered

        int bestStart = 0;
        int bestLen = Integer.MAX_VALUE;
        int left = 0;

        for (int right = 0; right < s.length(); right++) {
            char in = s.charAt(right);
            if (need[in] > 0) missing--;         // this char fills a real requirement
            need[in]--;                          // may go negative = surplus copies

            // window is valid: shrink while it stays valid
            while (missing == 0) {
                if (right - left + 1 < bestLen) {
                    bestLen = right - left + 1;
                    bestStart = left;
                }
                char out = s.charAt(left++);
                need[out]++;
                if (need[out] > 0) missing++;    // we just removed a required char
            }
        }
        return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
    }
}

TIME O(n + m)

SPACE O(Σ)

need[c] may go negative (surplus). missing changes only when a needed copy enters or leaves.

G. Variations of the Pattern

Fixed window + frequency array: Permutation in String

A permutation of s1 is any window of length |s1| with identical letter counts. Keep a 26-slot count, compare with Arrays.equals (26 comparisons = O(1)).

PermutationInString.java — LeetCode 567

Java 17+

import java.util.Arrays;

/** LeetCode 567 - Permutation in String. Fixed window + frequency array comparison. */
public class PermutationInString {

    /** True if some substring of s2 is a permutation of s1 (lowercase letters only). */
    public static boolean checkInclusion(String s1, String s2) {
        int k = s1.length();
        if (k > s2.length()) return false;
        int[] target = new int[26];
        int[] window = new int[26];
        for (int i = 0; i < k; i++) {
            target[s1.charAt(i) - 'a']++;
            window[s2.charAt(i) - 'a']++;
        }
        if (Arrays.equals(target, window)) return true;

        for (int right = k; right < s2.length(); right++) {
            window[s2.charAt(right) - 'a']++;          // enter
            window[s2.charAt(right - k) - 'a']--;      // leave
            if (Arrays.equals(target, window)) return true;   // 26 comparisons = O(1)
        }
        return false;
    }
}

TIME O(n · 26) = O(n)

SPACE O(1)
Validity defined by a formula: Longest Repeating Character Replacement

A window can be turned into a single repeated letter with k replacements iff windowSize - maxFreq ≤ k. Trick: maxFreq is never decreased when the window slides, because the answer

can only improve when a new higher frequency appears. The window therefore never shrinks, it only slides.

LongestRepeatingCharReplacement.java — LeetCode 424

Java 17+

/**
 * LeetCode 424 - Longest Repeating Character Replacement. Window validity: size - maxFreq <=
 * k.
 */
public class LongestRepeatingCharReplacement {

    public static int characterReplacement(String s, int k) {
        int[] freq = new int[26];
        int left = 0;
        int maxFreq = 0;        // highest count of one letter seen in ANY window so far
        int best = 0;
        for (int right = 0; right < s.length(); right++) {
            maxFreq = Math.max(maxFreq, ++freq[s.charAt(right) - 'A']);
            // Replacements needed = windowSize - count of the most frequent letter.
            if ((right - left + 1) - maxFreq > k) {
                freq[s.charAt(left) - 'A']--;
                left++;                              // slide: window size never shrinks
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}

TIME O(n)

SPACE O(26)
Shortest valid window: Minimum Size Subarray Sum
MinSubArrayLen.java — LeetCode 209

/** LeetCode 209 - Minimum Size Subarray Sum (positive numbers). Shortest valid window. */
public class MinSubArrayLen {

    public static int minSubArrayLen(int target, int[] nums) {
        int left = 0;
        long sum = 0;
        int best = Integer.MAX_VALUE;
        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while (sum >= target) {                  // valid: record, then try to shrink
                best = Math.min(best, right - left + 1);
                sum -= nums[left++];
            }
        }
        return best == Integer.MAX_VALUE ? 0 : best;
    }
}

TIME O(n)

SPACE O(1)

Positive numbers only. With negatives the window is not monotone: see Chapter 8 (LeetCode 862).

Budgeted flips: Max Consecutive Ones III

/** LeetCode 1004 - Max Consecutive Ones III. Window may contain at most k zeros. */
public class MaxConsecutiveOnesIII {

    public static int longestOnes(int[] nums, int k) {
        int left = 0;
        int zeros = 0;
        int best = 0;
        for (int right = 0; right < nums.length; right++) {
            if (nums[right] == 0) zeros++;
            while (zeros > k) {
                if (nums[left++] == 0) zeros--;
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}

Counting windows: Subarrays with K Different Integers

"Exactly K" is not monotone (adding an element can raise or keep the count), but "at most K" is. Hence exactly(K) = atMost(K) − atMost(K−1). In atMost, every position right contributes right - left + 1 valid subarrays ending there.

SubarraysKDistinct.java — LeetCode 992

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 992 - Subarrays with K Different Integers. exactly(K) = atMost(K) - atMost(K-1).
 */
public class SubarraysKDistinct {

    public static int subarraysWithKDistinct(int[] nums, int k) {
        return atMost(nums, k) - atMost(nums, k - 1);
    }

    /** Counts subarrays with at most k distinct values. */
    private static int atMost(int[] nums, int k) {
        if (k < 0) return 0;
        Map<Integer, Integer> freq = new HashMap<>();
        int left = 0;
        int count = 0;
        for (int right = 0; right < nums.length; right++) {
            freq.merge(nums[right], 1, Integer::sum);
            while (freq.size() > k) {
                int out = nums[left++];
                if (freq.merge(out, -1, Integer::sum) == 0) freq.remove(out);
            }
            // every subarray ending at 'right' starting >= left
            count += right - left + 1;
        }
        return count;
    }
}

TIME O(n)

SPACE O(k)

Two passes of the same window routine.

J. Interview Tips

INTERVIEW

Start by stating the validity condition and why it is monotone. Interviewers listen for this more than for code.

Narrate the invariant: "[left, right] always satisfies the condition after the while loop; I update the answer here."

Name the amortisation: left never goes back, so total work is O(n) even with the inner while.

Follow-ups: return the window itself (track bestStart), handle Unicode (HashMap<Character,Integer> rather than int[128]), stream input (window state is O(Σ)), allow negatives (switch to prefix sums or deque), find all anagram positions (record start when counts match).element identical, duplicates in t.
Edge cases to announce: empty string, t longer than s, k larger than the array, every
Optimisations: replace Arrays.equals by a running matches counter to make permutation check strictly O(1) per step; use int[128/256] instead of HashMap for ASCII.

CHAPTER SUMMARY

Sliding window = a contiguous range whose summary is updated incrementally; each element enters and leaves once, so O(n).

Pick the template: fixed, longest valid (shrink when invalid), shortest valid (shrink while valid), counting (add r-l+1).

Requires monotone validity: negatives with sum constraints break it. Use prefix sums or a deque there.

Exactly K = at most K − at most K−1.
