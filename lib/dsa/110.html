XOR Trie (Binary Trie)

Store numbers as bit paths and greedily walk the opposite bit to maximise XOR.

A. Pattern Overview

A binary trie inserts each number as its bit string from the most significant bit down. Because a higher bit outweighs all lower bits together, the best partner for x can be found greedily: at each level prefer the child with the opposite bit (it makes that bit of x ^ y equal to 1). Each query costs O(B) where B is the bit width, independent of the number of stored values.

KEY IDEA

Max XOR is a greedy over bits: the top bit dominates, so decide it first and never revisit.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Maximum XOR" of a pair, a subarray (via prefix XOR), or a path (via root-to-node XOR).
A constraint on the partner (y <= m, index order, an interval) that rules out a plain sort.
Counting pairs whose XOR is below a bound.
Values below 2^30, so a trie has at most 30 levels.
Queries arriving offline, which lets you sort them and build the trie incrementally.
ONE-LINE TEST

XOR optimisation plus a pair or subarray: prefix XORs and a binary trie.

C. Core Intuition with Illustrations

Greedy opposite-bit walk

With 5-bit numbers {3, 10, 5, 25, 2, 8}, the best partner of 5 = 00101 is 25 = 11001: the walk picks the opposite bit at every level where it can.

The maximum over all x is 28 (from 5 ^ 25).

Why greedy is correct

Suppose a stored number offers the opposite bit at position i. Any pair that sets bit i of the XOR beats every pair that does not, by at least 2^i, which exceeds the total of all lower bits (2^i - 1). So committing to the opposite child never loses.

Counting pairs below a limit

Walk x and limit together. At a level where limit's bit is 1: all stored values that make this XOR bit 0 (same child as x) are strictly smaller, so add that child's subtree count and continue into the opposite child. Where limit's bit is 0: the XOR bit must be 0, so continue into the same child.

Offline with a cap on the partner

For max(x ^ y) with y <= m, sort numbers ascending and queries by m. Before answering a query, insert every number <= m. If the trie is empty the answer is -1.

TRAP

Prefix XORs convert subarray problems to pair problems: xor(l..r) = p[r+1] ^ p[l]. Remember to insert the empty prefix 0 first.

The trie size is the real cost: up to 30 x n nodes for 30-bit values. The Java version uses flat arrays (child[2][nodes], cnt[nodes]) allocated up front instead of a million small objects.

E. Java Implementation

Array-backed XOR trie: insert, maxXor, countLess, plus the three classic applications

XorTrie.java: binary trie for max XOR, offline caps and counting pairs

import java.util.*;

/** Ch 95: binary trie for XOR queries; LeetCode 421, 1707, 1803. */
public class XorTrie {
    private static final int BITS = 30;       // values below 2^30

    private int[][] child;                     // child[node][bit]
    private int[] cnt;                         // numbers passing through node
    private int size = 1;

Java 17+

    public XorTrie(int capacityNumbers) {
        int nodes = capacityNumbers * BITS + 2;
        child = new int[nodes][2];
        cnt = new int[nodes];
    }

    public void insert(int x) {
        int cur = 0;
        for (int b = BITS - 1; b >= 0; b--) {
            int bit = x >> b & 1;
            if (child[cur][bit] == 0) child[cur][bit] = size++;
            cur = child[cur][bit];
            cnt[cur]++;
        }
    }

    /** Largest x ^ y over inserted y, or -1 if the trie is empty. */
    public int maxXor(int x) {
        if (size == 1) return -1;
        int cur = 0, res = 0;
        for (int b = BITS - 1; b >= 0; b--) {
            int want = (x >> b & 1) ^ 1;       // the opposite bit makes a 1
            if (child[cur][want] != 0 && cnt[child[cur][want]] > 0) {
                res |= 1 << b;
                cur = child[cur][want];
            } else {
                cur = child[cur][want ^ 1];
            }
        }
        return res;
    }

    /** Number of inserted y with (x ^ y) < limit. */
    public int countLess(int x, int limit) {
        int cur = 0, res = 0;
        for (int b = BITS - 1; b >= 0 && cur != -1; b--) {
            int xb = x >> b & 1, lb = limit >> b & 1;
            if (lb == 1) {
                int same = child[cur][xb];      // xor bit 0 < limit bit 1
                if (same != 0) res += cnt[same];
                int nxt = child[cur][xb ^ 1];   // xor bit 1 == limit bit, go on
                cur = nxt == 0 ? -1 : nxt;
            } else {
                int nxt = child[cur][xb];       // xor bit must be 0
                cur = nxt == 0 ? -1 : nxt;
            }
        }
        return res;
    }

    /** LeetCode 421: maximum XOR of two array elements. */
    public static int findMaximumXOR(int[] nums) {
        XorTrie t = new XorTrie(nums.length);
        int best = 0;
        for (int v : nums) {
            t.insert(v);
            best = Math.max(best, t.maxXor(v));
        }
        return best;
    }

    /** LeetCode 1707: max x ^ nums[i] over nums[i] <= m, offline by m. */
    public static int[] maximizeXor(int[] nums, int[][] queries) {
        int[] sorted = nums.clone();
        Arrays.sort(sorted);
        Integer[] order = new Integer[queries.length];
        for (int i = 0; i < order.length; i++) order[i] = i;
        Arrays.sort(order, Comparator.comparingInt(i -> queries[i][1]));
        XorTrie t = new XorTrie(nums.length);
        int[] ans = new int[queries.length];
        int p = 0;
        for (int qi : order) {
            while (p < sorted.length && sorted[p] <= queries[qi][1])
                t.insert(sorted[p++]);
            ans[qi] = t.maxXor(queries[qi][0]);
        }
        return ans;
    }

    /** LeetCode 1803: pairs i < j with low <= nums[i] ^ nums[j] <= high. */
    public static int countPairs(int[] nums, int low, int high) {
        XorTrie t = new XorTrie(nums.length);
        int total = 0;
        for (int v : nums) {
            total += t.countLess(v, high + 1) - t.countLess(v, low);
            t.insert(v);
        }
        return total;
    }
}

TIME O(B) per op, O(n B) total

has 1, take it. Bit 2 wants 0; 25 has 0, take it. Bit 1 wants 1; 25 has 0, so we take 0. Bit 0 wants 0; 25 has 1, forced. XOR is 11100 = 28.

count(< 2) over earlier elements.

G. Variations of the Pattern

Maximum XOR subarray

Insert prefix XORs one by one and query each new prefix against the earlier ones. O(n B).

Maximum XOR path in a tree

Root-to-node XOR r[v]; path XOR between u, v is r[u] ^ r[v] (the LCA part cancels). Same trie.

Persistent / versioned trie

To restrict the partner to an index range [l, r], store a count per node in a persistent trie (one version per prefix) and walk versions r and l - 1 together. Needs O(n B) nodes.

Minimum XOR

Prefer the same child at every level instead of the opposite one.

XOR with a bound on both sides

Combine countLess(high + 1) - countLess(low); this is LeetCode 1803.

CHAPTER SUMMARY

A binary trie stores numbers by their bits, so the greedy opposite-bit walk finds the maximum XOR partner in O(B).

Subtree counts let you count partners below a limit, and countLess(high+1) - countLess(low) counts a range.

Sort queries offline to apply caps on the partner by inserting values incrementally.

Prefix XORs turn subarray and tree-path XOR problems into pair problems.

Use flat arrays for the nodes; 30 n object nodes are expensive.
