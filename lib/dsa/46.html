Word Search and Grid Backtracking

DFS on a grid: mark the cell, explore four ways, restore it.

A. Pattern Overview

Grid backtracking searches for a path through a matrix in which no cell may be used twice. It is DFS (Part VIII) with one difference that makes it backtracking: the visited mark is removed when the call returns, because a cell that failed on one path may well succeed on another.

KEY IDEA

Visited-while-on-the-path ≠ visited-ever. Plain graph DFS marks a node visited forever (each node is processed once). Path-enumeration marks a cell only while it is on the current path and unmarks it on return. Using the permanent version here finds fewer paths; using the temporary version in a plain traversal makes DFS exponential.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Find a path of adjacent cells that spells / sums to / visits …" with no reuse of a cell.
"Each cell may be used at most once in a word": Word Search.
Small grids (m, n ≤ 12 for word search; ≤ 20 cells for Hamiltonian-style problems).
"Find all words from a dictionary on a board" → trie plus grid DFS.
"Maximum gold / longest path" where a path may start anywhere and may not revisit.
ONE-LINE TEST

Grid + simple path (no revisits) + small size = backtracking with a temporary visited mark. Grid + reachability or shortest steps = BFS/DFS with a permanent mark.

C. Core Intuition with Illustrations

Mark, explore, restore

At cell (r, c) with index k into the word: reject if out of bounds or b[r][c] != word[k]; accept if k is the last letter. Otherwise save the letter, overwrite the cell with a sentinel ('#') so it cannot be re-entered, try the four neighbours with k + 1, then restore the saved letter. The sentinel doubles as the visited array, saving O(mn) space.

Many words at once: the trie

Searching each word separately repeats work on shared prefixes. A trie (prefix tree) stores all words; one DFS carries a pointer to the current trie node and prunes the moment the current prefix has no node. A word is reported when the node is marked as a word end; clearing the marker avoids reporting it twice.

E. Java Implementation

Word Search

WordSearch.java: LeetCode 79

Java 17+

/**
 * LeetCode 79 - Word Search. DFS from every cell; mark a cell as used while it is on the
 * current path.
 */
public class WordSearch {
    private static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public static boolean exist(char[][] board, String word) {
        int rows = board.length, cols = board[0].length;
        for (int r = 0; r < rows; r++)
            for (int c = 0; c < cols; c++)
                if (dfs(board, word, 0, r, c)) return true;
        return false;
    }

    private static boolean dfs(char[][] b, String word, int k, int r, int c) {
        if (r < 0 || c < 0 || r >= b.length || c >= b[0].length
                || b[r][c] != word.charAt(k)) return false;
        if (k == word.length() - 1) return true;
        char saved = b[r][c];
        b[r][c] = '#';                                    // choose: cell is on the path
        for (int[] d : DIRS)
            if (dfs(b, word, k + 1, r + d[0], c + d[1])) { b[r][c] = saved;
                    return true; }
        b[r][c] = saved;                                  // unchoose
        return false;
    }
}

TIME O(mn · 3ᴸ)

SPACE O(L)

L = word length. The recursion depth is at most L. The board is restored on every exit path, including the early true.

Word Search II with a trie

WordSearchII.java: LeetCode 212

Java 17+

import java.util.ArrayList;
import java.util.List;

/**
 * LeetCode 212 - Word Search II. One DFS over the grid walks a trie of all words
 * simultaneously.
 */
public class WordSearchII {
    private static final class Node {
        Node[] next = new Node[26];
        String word;                                      // non-null when a word ends here
    }

    public static List<String> findWords(char[][] board, String[] words) {
        Node root = new Node();
        for (String w : words) {
            Node cur = root;
            for (char ch : w.toCharArray()) {
                if (cur.next[ch - 'a'] == null) cur.next[ch - 'a'] = new Node();
                cur = cur.next[ch - 'a'];
            }
            cur.word = w;
        }
        List<String> out = new ArrayList<>();
        for (int r = 0; r < board.length; r++)
            for (int c = 0; c < board[0].length; c++)
                dfs(board, r, c, root, out);
        return out;
    }

    private static void dfs(char[][] b, int r, int c, Node parent,
            List<String> out) {
        if (r < 0 || c < 0 || r >= b.length || c >= b[0].length) return;
        char ch = b[r][c];
        // off the trie: prune the whole subtree
        if (ch == '#' || parent.next[ch - 'a'] == null) return;
        Node node = parent.next[ch - 'a'];
        // report each word once
        if (node.word != null) { out.add(node.word); node.word = null; }
        b[r][c] = '#';
        dfs(b, r + 1, c, node, out);
        dfs(b, r - 1, c, node, out);
        dfs(b, r, c + 1, node, out);
        dfs(b, r, c - 1, node, out);
        b[r][c] = ch;
    }
}

TIME O(mn · 3ᴸ)

SPACE O(total word length)

L = longest word. Clearing node.word after reporting guarantees each word appears once. Pruning dead trie branches (removing leaves) is a further optimisation for large dictionaries.

Unique Paths III: visit every empty cell once

UniquePathsIII.java: LeetCode 980

Java 17+

/**
 * LeetCode 980 - Unique Paths III. Count walks from start (1) to end (2) that visit every
 * empty cell (0) exactly once.
 */
public class UniquePathsIII {
    public static int uniquePathsIII(int[][] grid) {
        // `empty` counts the start cell too
        int rows = grid.length, cols = grid[0].length, empty = 1, sr = 0, sc = 0;
        for (int r = 0; r < rows; r++)
            for (int c = 0; c < cols; c++) {
                if (grid[r][c] == 0) empty++;
                else if (grid[r][c] == 1) { sr = r; sc = c; }
            }
        return walk(grid, sr, sc, empty);
    }

    private static int walk(int[][] g, int r, int c, int left) {
        if (r < 0 || c < 0 || r >= g.length || c >= g[0].length
                || g[r][c] == -1) return 0;
        // the end is valid only after everything else is visited
        if (g[r][c] == 2) return left == 0 ? 1 : 0;
        int saved = g[r][c];
        g[r][c] = -1;
        int total = walk(g, r + 1, c, left - 1) + walk(g, r - 1, c, left - 1)
                  + walk(g, r, c + 1, left - 1) + walk(g, r, c - 1, left - 1);
        g[r][c] = saved;
        return total;
    }
}

TIME O(4^(mn))

SPACE O(mn)

Counting empty cells first lets the end cell succeed only when left == 0. Cells are marked -1 while on the path and restored after.

Path with Maximum Gold

PathWithMaximumGold.java: LeetCode 1219

Java 17+

/**
 * LeetCode 1219 - Path with Maximum Gold: best sum of a simple path through non-zero cells,
 * starting anywhere.
 */
public class PathWithMaximumGold {
    public static int getMaximumGold(int[][] grid) {
        int best = 0;
        for (int r = 0; r < grid.length; r++)
            for (int c = 0; c < grid[0].length; c++)
                best = Math.max(best, collect(grid, r, c));
        return best;
    }

    private static int collect(int[][] g, int r, int c) {
        if (r < 0 || c < 0 || r >= g.length || c >= g[0].length
                || g[r][c] == 0) return 0;
        int gold = g[r][c];
        // mined: cannot be revisited on this path
        g[r][c] = 0;
        int bestNext = Math.max(Math.max(collect(g, r + 1, c), collect(g, r - 1,
                c)),
                                Math.max(collect(g, r, c + 1), collect(g, r,
                                        c - 1)));
        g[r][c] = gold;
        return gold + bestNext;
    }
}

TIME O(mn · 3^G)

SPACE O(G)

G ≤ 25 gold cells. The cell is set to 0 while on the path (a natural visited mark) and restored with the saved gold.

G. Variations of the Pattern

Direction sets

Eight neighbours (kings) instead of four: Word Search variants, Boggle. Change the DIRS table; nothing else.

Grid DFS without backtracking

Number of Islands (200) and Flood Fill (733) mark cells permanently: no undo, O(mn) total (Part VIII).

Hamiltonian-style problems

Unique Paths III is a Hamiltonian path on a small grid; O(4^(mn)) is acceptable only because

mn ≤ 20.

Optimising paths

Path with Maximum Gold returns the best of the four branches (a maximum, not a boolean). Memoising on (cell, visited mask) turns it into bitmask DP for small grids.

Trie pruning

For large dictionaries, remove a trie node when its subtree no longer contains an unfound word; the search then shrinks as words are found.

J. Interview Tips

INTERVIEW

Say the difference from flood fill out loud: "the visited mark is temporary because I want simple paths, not reachability."

Mention the sentinel trick (overwrite the cell) and its caveat if the alphabet could contain the sentinel.

For Word Search II, go straight to the trie and say why separate searches repeat prefix work.

Follow-ups: diagonal moves; reuse allowed (then it is plain DFS with memo on (cell, index)); find the path itself; huge dictionary (prune trie); reduce the search by checking letter frequencies.
Edge cases: 1 × 1 board, word of length 1, word longer than the board, repeated letters forcing reuse, all cells equal.

CHAPTER SUMMARY

Grid backtracking enumerates simple paths: the visited mark is temporary, set on entry and cleared on return.

Overwrite the cell with a sentinel (and restore it) instead of keeping a visited array; restore on every exit path.

Word Search costs O(mn · 3ᴸ); check bounds before reading the cell; stop on the first mismatch.

Word Search II: one DFS carrying a trie node prunes missing prefixes and finds all words together; null out found words.

Counting paths (Unique Paths III) and maximising (gold) use the same mark-recurse-restore body with a different return value.
