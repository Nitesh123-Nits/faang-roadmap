Connected Components

Partition the vertices into islands that reach only each other.

A. Pattern Overview

In an undirected graph, reachability is an equivalence relation (reflexive, symmetric, transitive), so it splits the vertices into connected components: maximal sets in which every pair is connected. Finding them is one traversal per unvisited vertex, O(n + m) in total. Many problems are components in disguise: provinces, friend circles, islands, account merging, minimum edges to connect a network.

KEY IDEA

A spanning forest of a graph with c components has exactly n − c edges. Every extra edge closes a cycle. This single identity solves Number of Operations to Make Network Connected (1319): feasible iff m ≥ n − 1, answer c − 1.

ONE-LINE TEST

Whenever a statement says group, cluster or connected, and edges are symmetric, count components with DFS, BFS or Union-Find (Chapter 52).

C. Core Intuition with Illustrations

Label every vertex

Scan vertices 0..n−1. Each time you meet an unlabelled vertex, you have found a new component: give it the next id and flood its whole component.

Counting without labels

If only the number is needed, keep a single count++ each time a traversal starts. If you need to answer many connected(u, v) queries, either store comp[] (static graph) or use Union-Find (edges arriving over time).

Adjacency matrix input

Number of Provinces (547) gives an n × n matrix. The traversal scans a row to find neighbours: O(n²) total, which is optimal for that input size.

Components from implicit relations

Most Stones Removed (947): stones that share a row or a column are connected; in each component all but one stone can be removed, so the answer is stones − components. The trick is to treat row r and column c as vertices and each stone as an edge between them, so the graph has at most 20 002 vertices instead of n² stone pairs.

Reachable-pair counting

Count Unreachable Pairs (2316): component sizes s₁, …, s_c; pairs in different components number ½ Σ sᵢ (n − sᵢ). Use long because n can be 10⁵.

E. Java Implementation

Labelling, counting, sizes, provinces, spare edges

ConnectedComponents.java: LeetCode 323, 547, 1319
import java.util.*;
/** Ch 48: connected components; LeetCode 323, 547, 1319, plus sizes. */
public class ConnectedComponents {
    /** comp[v] = component id (0-based, in order of discovery). */

Java 17+

    public static int[] label(List<List<Integer>> g) {
        int n = g.size();
        int[] comp = new int[n];
        Arrays.fill(comp, -1);
        int id = 0;
        Deque<Integer> stack = new ArrayDeque<>();
        for (int s = 0; s < n; s++) {
            if (comp[s] >= 0) continue;
            comp[s] = id;
            stack.push(s);
            while (!stack.isEmpty()) {
                int u = stack.pop();
                for (int v : g.get(u))
                    if (comp[v] < 0) {
                        comp[v] = id;
                        stack.push(v);
                    }
            }
            id++;
        }
        return comp;
    }

    /** LeetCode 323. */
    public static int countComponents(int n, int[][] edges) {
        int[] comp = label(GraphRepresentation.adjList(n, edges, false));
        int max = -1;
        for (int c : comp) max = Math.max(max, c);
        return max + 1;
    }

    /** LeetCode 547: the graph arrives as an adjacency matrix. */
    public static int findCircleNum(int[][] isConnected) {
        int n = isConnected.length, count = 0;
        boolean[] seen = new boolean[n];
        Deque<Integer> stack = new ArrayDeque<>();
        for (int s = 0; s < n; s++) {
            if (seen[s]) continue;
            count++;
            seen[s] = true;
            stack.push(s);
            while (!stack.isEmpty()) {
                int u = stack.pop();
                for (int v = 0; v < n; v++)
                    if (isConnected[u][v] == 1 && !seen[v]) {
                        seen[v] = true;
                        stack.push(v);
                    }
            }
        }
        return count;
    }

    /** Sizes of all components, in label order. */
    public static int[] sizes(List<List<Integer>> g) {
        int[] comp = label(g);
        int k = 0;
        for (int c : comp) k = Math.max(k, c + 1);
        int[] size = new int[k];
        for (int c : comp) size[c]++;
        return size;
    }

    /** LeetCode 1319: n - 1 edges connect everything; extras can be moved. */
    public static int makeConnected(int n, int[][] connections) {
        if (connections.length < n - 1) return -1;
        return countComponents(n, connections) - 1;
    }
}

TIME O(n + m) (matrix: O(n²))

SPACE O(n)

label uses an explicit stack, so a component that is a 10⁵-vertex chain is safe.

makeConnected first checks m ≥ n − 1.

F. Detailed Dry Run

The table in section C shows the labelling of the sample graph: start 0 finds {0, 1, 2, 3, 4}; vertices 1 to 4 are already labelled and skipped; start 5 finds {5, 6}. Apply the identities: n = 7, c = 2, so a spanning forest has n − c = 5 edges. The graph has m = 6 edges, so exactly 1 edge is redundant (the square 0–1–3–2–0), and connecting the two components needs c − 1 = 1 new edge: the redundant edge could be moved, so Make Connected would answer 1.

G. Variations of the Pattern

Union-Find version

Process edges one by one and merge sets; sets() is the live component count (Chapter 52). Ideal when edges arrive online or when you need the first edge that closes a cycle.

Grid components

Islands, regions and enclaves are components of an implicit graph (Chapter 55).

Merging by shared attributes

Accounts Merge (721), Similar String Groups (839), Smallest String With Swaps (1202): connect items that share a key, then process each component separately (sort letters, union emails).

Component size questions

Making a Large Island (827): compute every island size once, then for each water cell add the sizes of distinct neighbouring islands + 1.

Removing nodes

Minimize Malware Spread (924): count how many infected nodes each component has; only components with exactly one infected node can be saved by removing it.

J. Interview Tips

INTERVIEW

State the identity edges in a spanning forest = n − components; it often replaces a whole algorithm.

Mention Union-Find as the alternative and when you would prefer it (edges arriving online).

Clarify direction: if edges are directed and the question says connected, ask whether weak or strong connectivity is meant.

Follow-ups: components after deleting an edge (offline reverse Union-Find), dynamic connectivity with deletions (link-cut trees, out of scope), largest component only.
Edge cases: n = 1, no edges, all isolated vertices, a single giant component, duplicate edges.

CHAPTER SUMMARY

Reachability in an undirected graph partitions vertices into components: one traversal per unvisited vertex, O(n + m).

A spanning forest has n − c edges; extra edges are redundant; connecting c components needs c − 1 edges.

Model implicit relations as graphs: rows and columns as vertices, stones as edges; emails as vertices, accounts as hyperedges.

Use an explicit stack or Union-Find for huge components; use long for pair counts.

Directed mutual reachability is a different problem: strongly connected components (Chapter 58).
