Gas Station

Circular tours, two-pass constraints and one-scan feasibility.

A. Pattern Overview

Gas Station is the model problem for a family of greedy arguments built on running totals: when a prefix of the scan becomes infeasible, you can discard all starting points in that prefix at once. Related problems (Candy, Lemonade Change, Hand of Straights) share the flavour: make the locally forced choice, never look back, and prove it with a short exchange or counting argument.

Gas Station: one pass
long total = 0, tank = 0;
int start = 0;
for (int i = 0; i < gas.length; i++) {
    int diff = gas[i] - cost[i];
    total += diff;
    tank += diff;
    if (tank < 0) {          // cannot reach station i + 1 from `start`
        start = i + 1;       // so no station in [start, i] can be a start either
        tank = 0;
    }
}
return total >= 0 ? start : -1;

KEY IDEA

A failing prefix eliminates all its starts. If starting at s first fails at i, then starting at

any s' ∈ (s, i] also fails: each of those prefixes had a non-negative tank on arrival

(otherwise the failure would have occurred earlier), so beginning with an empty tank is no better.

B. When to Recognize This Pattern

Pattern Recognition Signals

A circular array and the question "from which index can you complete the loop?".
Running balance must stay non-negative (fuel, cash, inventory).
Total ≥ 0 means feasible somewhere: the question is only where to start.
Each element must be better than a neighbour (ratings, heights): two directional passes.
Forced greedy choice by smallest / largest first (straight hands, change-making with a

nice denominations system).

ONE-LINE TEST

Circular tour or running balance with a constraint: compute total and a running tank; restart the candidate start when tank < 0.

Why one candidate suffices

Two facts. (1) If total ≥ 0, the candidate chosen by the scan (the index after the last failure)

completes the circuit: the suffix from start to n − 1 has non-negative balance (it never failed), and the prefix before it has total balance total − suffix, which is a deficit at most the suffix surplus, because total ≥ 0. (2) Every earlier start was eliminated by a failure. So the candidate is the unique answer (the problem guarantees uniqueness; otherwise it is an answer).

Prefix-sum view

Let P[i] be the prefix sum of gas − cost. The correct start is the index right after the minimum prefix sum: starting there turns every partial sum into P[i] − P[min] ≥ 0. This is the same computation as the greedy, expressed with an argmin.

Candy: two passes, one constraint each

Each child has ≥ 1 candy and a child with a higher rating than a neighbour needs more candy than that neighbour. A left-to-right pass enforces the left constraint; a right-to-left pass enforces the right constraint using max so the left result is not destroyed.

Figure 111. Ratings [1,0,2,2,3,1] need 9 candies in total.

Lemonade change: prefer the bills you will need least

Customers pay 5, 10 or 20 for a 5-dollar lemonade. A 5 needs no change, a 10 needs one 5, and a 20 needs 15: either 10 + 5 or 5 + 5 + 5. Give 10 + 5 first because fives are useful for every future 10 and 20, while tens are useful only for 20s. Keeping fives is never worse.

Hand of Straights: the smallest card has no choice

Whatever the arrangement, the smallest remaining card must be the start of its group (nothing smaller is left to precede it). Remove first, first + 1, ..., first + groupSize − 1; if any is missing, fail. A TreeMap keeps the counts sorted.

INTUITION

A candy count is not a sum of independent choices, but the minimum assignment is the least fixed point of the constraints: start with all 1s and raise values only when forced. The two-pass algorithm computes that fixed point in two sweeps because the constraints form a chain.

E. Java Implementation

Gas station, candy, lemonade change, hand of straights

GasStation.java: LeetCode 134, 135, 860, 846
import java.util.*;

/** Ch 68: circular greedy and one-pass feasibility; LeetCode 134, 135, 860, 846. */
public class GasStation {

    /** LeetCode 134: the unique start that completes the circuit, else -1. */
    public static int canCompleteCircuit(int[] gas, int[] cost) {
        long total = 0, tank = 0;
        int start = 0;
        for (int i = 0; i < gas.length; i++) {
            int diff = gas[i] - cost[i];
            total += diff;
            tank += diff;
            // cannot get past i from this start
            if (tank < 0) {
                // so no start in (start..i] works
                start = i + 1;
                tank = 0;
            }
        }
        return total >= 0 ? start : -1;
    }

    /**
     * LeetCode 135: minimum candies, higher rating than a neighbour means more
     * candy.

Java 17+

     */
    public static int candy(int[] ratings) {
        int n = ratings.length;
        int[] candies = new int[n];
        Arrays.fill(candies, 1);
        // left to right: beat the left neighbour
        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i - 1]) candies[i] = candies[i - 1] + 1;
        }
        // right to left: beat the right neighbour
        for (int i = n - 2; i >= 0; i--) {
            if (ratings[i] > ratings[i + 1])
                candies[i] = Math.max(candies[i], candies[i + 1] + 1);
        }
        long sum = 0;
        for (int c : candies) sum += c;
        return (int) sum;
    }

    /**
     * LeetCode 860: every ticket costs 5; bills are 5, 10 or 20. Can we give
     * change?
     */
    public static boolean lemonadeChange(int[] bills) {
        int fives = 0, tens = 0;
        for (int b : bills) {
            if (b == 5) fives++;
            else if (b == 10) {
                if (fives == 0) return false;
                fives--; tens++;
            // 20: prefer 10 + 5, it keeps the 5s
            } else {
                if (tens > 0 && fives > 0) { tens--; fives--; }
                else if (fives >= 3) fives -= 3;
                else return false;
            }
        }
        return true;
    }

    /** LeetCode 846: split into groups of groupSize consecutive values. */
    public static boolean isNStraightHand(int[] hand, int groupSize) {
        if (hand.length % groupSize != 0) return false;
        TreeMap<Integer, Integer> count = new TreeMap<>();
        for (int h : hand) count.merge(h, 1, Integer::sum);
        while (!count.isEmpty()) {
            // smallest card must start a group
            int first = count.firstKey();
            for (int v = first; v < first + groupSize; v++) {
                Integer c = count.get(v);
                if (c == null) return false;
                if (c == 1) count.remove(v); else count.put(v, c - 1);
            }
        }
        return true;
    }
}

F. Detailed Dry Run

Gas table: at i = 0 the tank is −2 < 0, so the candidate start moves to 1 and the tank resets to

The same happens at i = 1 and i = 2. At i = 3 the tank becomes 3 and at i = 4 it becomes

6; no failure follows. The total balance is −2 − 2 − 2 + 3 + 3 = 0 ≥ 0, so the answer is the

last candidate, 3. Verifying: from 3 the tank goes 4 − 1 = 3, then 3 + 5 − 2 = 6, then 6 + 1 − 3 = 4, then 4 + 2 − 4 = 2, then 2 + 3 − 5 = 0. The loop completes.

Candy: the left pass yields [1, 1, 2, 1, 2, 1] (index 1 is not higher than index 0; index 2 beats index 1, and so on). The right pass raises index 0 from 1 to 2 (rating 1 > 0) and leaves the rest. Total 9.

G. Variations of the Pattern

Maximum Sum Circular Subarray (918)

max(maxSubarray, total − minSubarray); if all values are negative, the second term would select an empty subarray, so return maxSubarray.

Minimum Number of Refueling Stops (871)

The version where stations can be skipped: max-heap of passed fuel (Chapter 63).

Two City Scheduling (1029) and assignment greedy

Sort by the difference costA − costB; send the first half to city A. The exchange argument is the same as in activity selection.

Patching Array (330)

Maintain the largest reach such that [1, reach] is representable; if the next number exceeds reach + 1, patch with reach + 1 (doubling the reach).

Queue Reconstruction (406) and Assign Cookies (455)

Place by height then by count; match the smallest cookie that satisfies the least greedy child. Each follows "decide the most constrained item first".

J. Interview Tips

INTERVIEW

Explain the elimination step ("a failure at i rules out every start in [start, i]"): that single sentence is the proof.

Mention the prefix-sum view as a second explanation; it shows the greedy is an argmin in disguise.

For Candy, draw the two passes on a small ratings array and highlight which cells the right pass raises.

Follow-ups: all valid starting stations (not unique: collect indices where P[i] − P[min] ≥ 0 on the doubled array); candy on a circle; fuel capacity limit; cost can be negative.
Edge cases: single station, total exactly 0, zero gas everywhere, all costs 0, ratings all

equal, strictly increasing and strictly decreasing ratings.

CHAPTER SUMMARY

Gas Station: keep total and tank; when tank < 0 restart the candidate at i + 1. If

total ≥ 0 the last candidate is the answer. O(n) time, O(1) space.

Why it works: a failing prefix eliminates every start in it; total ≥ 0 guarantees the suffix surplus covers the prefix deficit.

Equivalent view: the start is the index after the minimum prefix sum of gas − cost.

Candy: left-to-right then right-to-left with max; strict > for ties. Lemonade: prefer 10 + 5. Straights: the smallest card starts a group.

Related circular tools: max(maxSub, total − minSub) for the circular maximum subarray.
