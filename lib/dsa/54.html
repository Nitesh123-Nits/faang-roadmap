Tree DP

Return a small state per subtree and combine it at the parent.

A. Pattern Overview

Tree DP is dynamic programming where the subproblems are subtrees. There is no table to index: the recursion order (postorder) guarantees both children are solved before the parent, and each node is computed once, so the total cost is O(n). The craft is choosing the state a subtree reports to its parent.

KEY IDEA

The state must make the parent's decision independent of the subtree's internals. Ask: what is the least the parent needs to know? House Robber III needs only "best if I took the child" and "best if I didn't", not which grandchildren were robbed.

B. When to Recognize This Pattern

Pattern Recognition Signals

Optimise over a tree with a local constraint: no two adjacent nodes chosen, cover every node, maximise a path.
"Path" between two arbitrary nodes with a sum or length objective: bend + arm.
Each node's decision depends on its children's decisions and nothing else.
Greedy on a tree (cameras, coins): a postorder pass that fixes the leaves first.
The brute force explores subsets or paths, and a node's best value is the same each time it is reached.
ONE-LINE TEST

"Maximum / minimum / count, over a tree, with a rule linking a node to its neighbours" means a postorder pass that returns a tuple.

C. Core Intuition with Illustrations

House Robber III: two states per node

Houses form a tree; robbing a node forbids robbing its children. Each node returns (rob, skip):

rob = node.val + left.skip + right.skip (children must be skipped).
skip = max(left.rob, left.skip) + max(right.rob, right.skip) (children are free to

be either).

INTUITION

Why not memoise on the node? You can (Map<TreeNode, Integer>), and it is also O(n), but the pair-return form avoids the hash map and the double recursion over grandchildren.

Maximum Path Sum: arms and bends

A path may start and end anywhere. At each node: the best arm going down is node.val + max(0, left, right), which is what we return, because a path continuing upward uses only one side. The best bent path through the node is node.val + max(0, left) + max(0, right), which updates a global. Negative arms are clipped to 0 (we simply do not extend them).

Binary Tree Cameras: a three-state greedy

A camera covers its parent, itself and its children. Greedy from the bottom: never put a camera on a leaf (its parent covers more). Each node reports one of 0 not covered, 1 has a camera, 2 covered (no camera). Rules, given children states l, r (a null is treated as 2, covered):

If the root ends up exposed (state 0) add one more camera. Here the total is 1.

Distribute Coins: excess flows along edges

Every node must end with exactly one coin. Define excess(node) = node.coins + excess(left) + excess(right) − 1: positive means coins must move up across the edge to the parent, negative means coins must come down. Each unit crossing costs one move, so add |excess(left)| + |excess(right)| at every node. The total is exact because every edge is crossed only by the net flow.

Other shapes

Longest Univalue Path clips the arm to 0 when the child's value differs. Longest ZigZag Path returns (startsLeft, startsRight) lengths. Count Good Nodes passes the maximum ancestor value down.

E. Java Implementation

All seven tree-DP solvers

TreeDP.java: LeetCode 337, 124, 687, 968, 979, 1372, 1448
/**
  * Tree DP: each call returns a small summary of its subtree, and the parent
  * combines the summaries.
  * 337 House Robber III, 124 Maximum Path Sum, 687 Longest Univalue Path, 968
  * Cameras, 979 Distribute Coins,

Java 17+

  * 1372 Longest ZigZag Path, 1448 Count Good Nodes (the last one pushes information
  * down instead of up).
 */
public class TreeDP {
    // ---- 337: summary = {best if this node is robbed, best if it is skipped}
    public static int houseRobberIII(TreeNode root) {
        int[] r = rob(root);
        return Math.max(r[0], r[1]);
    }

    private static int[] rob(TreeNode n) {
        if (n == null) return new int[]{0, 0};
        int[] l = rob(n.left), r = rob(n.right);
        // children must be skipped
        int robbed = n.val + l[1] + r[1];
        // children are free to be either
        int skipped = Math.max(l[0], l[1]) + Math.max(r[0], r[1]);
        return new int[]{robbed, skipped};
    }

    // ---- 124: summary = best downward path starting at this node; the answer
    // bends at some node
    public static int maxPathSum(TreeNode root) {
        int[] best = {Integer.MIN_VALUE};
        gain(root, best);
        return best[0];
    }

    private static int gain(TreeNode n, int[] best) {
        if (n == null) return 0;
        // a negative arm is better dropped
        int left = Math.max(0, gain(n.left, best));
        int right = Math.max(0, gain(n.right, best));
        // path bending at n
        best[0] = Math.max(best[0], n.val + left + right);
        // only one arm continues to the parent
        return n.val + Math.max(left, right);
    }

    // ---- 687: length in edges of the longest path whose nodes all share one value
    public static int longestUnivaluePath(TreeNode root) {
        int[] best = {0};
        univalue(root, best);
        return best[0];
    }

    private static int univalue(TreeNode n, int[] best) {
        if (n == null) return 0;
        int l = univalue(n.left, best), r = univalue(n.right, best);
        int left = (n.left != null && n.left.val == n.val) ? l + 1 : 0;
        int right = (n.right != null && n.right.val == n.val) ? r + 1 : 0;
        best[0] = Math.max(best[0], left + right);
        return Math.max(left, right);
    }

    // ---- 968: states 0 = not covered, 1 = has a camera, 2 = covered without a
    // camera
    public static int minCameras(TreeNode root) {
        int[] cameras = {0};
        int state = cover(root, cameras);
        // an uncovered root needs its own camera
        return cameras[0] + (state == 0 ? 1 : 0);
    }
    private static int cover(TreeNode n, int[] cameras) {
        // null counts as covered
        if (n == null) return 2;
        int l = cover(n.left, cameras), r = cover(n.right, cameras);
        // a child is exposed: put a camera here
        if (l == 0 || r == 0) { cameras[0]++; return 1; }
        // a child's camera covers this node
        if (l == 1 || r == 1) return 2;
        // both children covered but not watching: stay uncovered
        return 0;
    }

    // ---- 979: every node must end with one coin; moves = total |excess| crossing
    // each edge
    public static int distributeCoins(TreeNode root) {
        int[] moves = {0};
        excess(root, moves);
        return moves[0];
    }

    private static int excess(TreeNode n, int[] moves) {
        if (n == null) return 0;
        int e = excess(n.left, moves) + excess(n.right, moves) + n.val - 1;
        // |e| coins cross the edge above n
        moves[0] += Math.abs(e);
        return e;
    }

    // ---- 1372: summary = longest zigzag path starting here, going left first /
    // right first
    public static int longestZigZag(TreeNode root) {
        int[] best = {0};
        zig(root, best);
        return best[0];
    }

    private static int[] zig(TreeNode n, int[] best) {
        if (n == null) return new int[]{-1, -1};
        int[] l = zig(n.left, best), r = zig(n.right, best);
        // step left, then the path must turn right
        int goLeft = l[1] + 1;
        int goRight = r[0] + 1;
        best[0] = Math.max(best[0], Math.max(goLeft, goRight));
        return new int[]{goLeft, goRight};
    }

    // ---- 1448: a node is good if no ancestor is larger (information flows down)
    public static int goodNodes(TreeNode root) {
        return good(root, Integer.MIN_VALUE);
    }

    private static int good(TreeNode n, int maxSoFar) {
        if (n == null) return 0;
        int here = n.val >= maxSoFar ? 1 : 0;
        int next = Math.max(maxSoFar, n.val);
        return here + good(n.left, next) + good(n.right, next);
    }
}

TIME O(n) each

SPACE O(h)

Each method is one postorder (or preorder for goodNodes) pass. Pairs are returned as int[2]; long sums are not needed under LeetCode's constraints but would be for adversarial inputs.

F. Detailed Dry Run

Section C contains four generated traces; each lists nodes in postorder. To audit the cameras table by hand: the two leaves report covered to their parents only through null children, so the leaf nodes themselves are exposed (state 0). The parent of two exposed leaves must place a camera (+1 → 1 camera) and reports state 1; the root sees a child with a camera and is covered, so no extra camera is needed: total 1.

For max path sum, check the root row: left gain 9, right gain 35 (the arm 20 + 15), bent path −10 + 9 + 35 = 34, less than the current best 42.

G. Variations of the Pattern

Rerooting

When the answer is needed for every node as root (Sum of Distances in Tree, 834), do one DP down to compute subtree values, then a second pass rerooting from parent to child. It is O(n) instead of O(n²).

DP on general trees

Tree Diameter (1245) and Minimum Height Trees (310) run on undirected trees stored as adjacency lists; the DFS carries a parent to avoid walking back.

Knapsack on trees

Tree knapsack merges child tables of size ≤ k (O(n·k) total with size bounds): used when the constraint is "choose at most k nodes".

Counting

Unique BSTs (96), All Possible Full Binary Trees (894): the count at size n is a convolution of counts at smaller sizes (Catalan-type recurrences).

Game / interval flavour

Binary Tree Coloring Game (1145): compare the three component sizes around the opponent's first move.

J. Interview Tips

INTERVIEW

Define the state in one sentence before coding, e.g. "for each subtree return (best if root taken, best if not)."

Separate what you return from what you record: the arm goes up, the bend goes into the global. Interviewers look for this.

Prove the greedy for cameras briefly: a leaf's camera can always be moved to its parent without losing coverage.

Follow-ups: return the actual path or chosen nodes (store a parent pointer or rebuild);

n-ary trees; add edge weights; rerooting for all roots; iterative postorder for deep trees.

Edge cases: empty tree, single node, all-negative values, skewed tree, root as the only exposed node.

CHAPTER SUMMARY

Tree DP = postorder pass that returns a small state; each node is solved once, O(n).

Choose the minimal state: pair (take, skip), enum (cameras), signed excess (coins), or arm returned / bend recorded (paths).

For path problems clip negative arms to 0 and start the global at Integer.MIN_VALUE.

Greedy proofs (leaf camera moves to its parent; coins flow along edges) turn exponential searches into one pass.

To answer for every root, compute subtree values then reroot in a second pass.
