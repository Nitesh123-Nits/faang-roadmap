Tree Construction

Rebuild trees from traversals, strings and sorted data.

A. Pattern Overview

Construction problems give you a description of a tree (two traversals, a serialized string, a sorted array) and ask for the tree. All of them are solved by the same recursion: pick the root, split the remaining data into a left part and a right part, recurse. What differs is how the root and the split are found.

KEY IDEA

Preorder alone (or postorder alone) does not determine a tree, nor does inorder alone. Preorder + inorder does, provided the values are distinct. Preorder + postorder determines it only when every internal node has two children (otherwise left-only and right-only are ambiguous). A preorder with explicit null markers is self-sufficient.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Construct a binary tree from …" traversal arrays, or "serialize and deserialize".
"Height-balanced BST from a sorted array / list": always the middle.
"The root is the maximum / the first / the last" of a range.
Two traversals of the same tree: one gives roots, the other gives sizes of the left and right

parts.

ONE-LINE TEST

Whenever a problem hands you an inorder sequence, the inorder index of the root is the size of the left subtree. That one fact solves four problems in this chapter.

C. Core Intuition with Illustrations

Preorder + inorder

Preorder lists the root first; inorder places the root between its left and right subtrees. So pre[0] is the root; its position m in inorder splits the window into in[lo..m−1] (left) and in[m+1..hi] (right). The preorder pointer simply advances: after the root comes the whole left subtree, then the right one. Build the left subtree before the right so the pointer is in the right place.

TIP

Build a value → inorder index map first. Scanning inorder for the root at every call makes the algorithm O(n²) on a skewed tree; the map makes the split O(1).

Inorder + postorder

Postorder lists the root last. Walk it from the right; the order of roots is root, right subtree, then left subtree, so recurse into the right child first. Everything else is identical.

Serialize and deserialize

Write a preorder walk and emit # for each null. This single sequence is unambiguous: reading it back, the next token is the root, then recursively the whole left subtree, then the whole right subtree; a # ends a branch.

Tree (level order)Serialized (preorder with #)
[1, 2, 3, null, null, 4, 5]1,2,#,#,3,4,#,#,5,#,#

Level-order serialization (LeetCode's own format) also works with a queue; preorder is shorter to code. Values are separated by commas, so negative numbers are safe; never use a digit-only separator-free format.

Sorted array to a height-balanced BST

Choose the middle element as the root so both halves differ by at most one element; recurse

on each half. The depth is ⌊log₂ n⌋ + 1. For a sorted linked list you cannot index the middle

in O(1). Instead build the left half first, consuming the list in order, so the list pointer always sits at the inorder position of the next root: O(n) time, O(log n) stack.

Maximum Binary Tree

The maximum of the array is the root; the part left of it builds the left subtree, the part right of it the right. Naively this is O(n²) for a sorted array. A monotonic stack (Chapter 7) does it in O(n): keep a decreasing stack of nodes; a new value pops smaller nodes, which become its left child, and then becomes the right child of the new stack top.

E. Java Implementation

Preorder + inorder and inorder + postorder

BuildTree.java: LeetCode 105, 106
import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 105 / 106 - rebuild a tree of distinct values from two traversals; a
 * value-to-index map finds the root in O(1).
 */
public class BuildTree {
    public static TreeNode fromPreIn(int[] pre, int[] in) {
        Map<Integer, Integer> pos = indexOf(in);
        return pre(pre, new int[]{0}, 0, in.length - 1, pos);
    }

    /**
     * pre[next] is the root of in[lo..hi]; the root's index in `in` splits the left
     * and right subtrees.
     */
    private static TreeNode pre(int[] pre, int[] next, int lo, int hi,
                                Map<Integer, Integer> pos) {
        if (lo > hi) return null;
        TreeNode root = new TreeNode(pre[next[0]++]);
        int mid = pos.get(root.val);
        // preorder: left subtree is consumed before the right
        root.left = pre(pre, next, lo, mid - 1, pos);
        root.right = pre(pre, next, mid + 1, hi, pos);
        return root;
    }

Java 17+

    public static TreeNode fromInPost(int[] in, int[] post) {
        Map<Integer, Integer> pos = indexOf(in);
        return post(post, new int[]{post.length - 1}, 0, in.length - 1, pos);
    }

    /**
     * Postorder read from the end is root, right, left: build the right subtree
     * first.
     */
    private static TreeNode post(int[] post, int[] next, int lo, int hi,
                                 Map<Integer, Integer> pos) {
        if (lo > hi) return null;
        TreeNode root = new TreeNode(post[next[0]--]);
        int mid = pos.get(root.val);
        root.right = post(post, next, mid + 1, hi, pos);
        root.left = post(post, next, lo, mid - 1, pos);
        return root;
    }

    private static Map<Integer, Integer> indexOf(int[] a) {
        Map<Integer, Integer> m = new HashMap<>();
        for (int i = 0; i < a.length; i++) m.put(a[i], i);
        return m;
    }
}

TIME O(n)

SPACE O(n)

The map costs O(n); the recursion adds O(h). Index bounds replace array copies.

Serialize and deserialize

Codec.java: LeetCode 297
import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Queue;

/**
 * LeetCode 297 - Serialize and Deserialize Binary Tree, in preorder with explicit
 * "#" for null (the nulls make it unambiguous).
 */
public class Codec {
    public static String serialize(TreeNode root) {
        StringBuilder sb = new StringBuilder();
        write(root, sb);
        return sb.toString();
    }

    private static void write(TreeNode n, StringBuilder sb) {
        if (sb.length() > 0) sb.append(',');
        if (n == null) { sb.append('#'); return; }
        sb.append(n.val);
        write(n.left, sb);
        write(n.right, sb);
    }

    public static TreeNode deserialize(String data) {
        Queue<String> tokens = new ArrayDeque<>(Arrays.asList(data.split(",")));
        return read(tokens);
    }

Java 17+

    private static TreeNode read(Queue<String> tokens) {
        String t = tokens.poll();
        if (t.equals("#")) return null;
        TreeNode n = new TreeNode(Integer.parseInt(t));
        // same order as write: root, left, right
        n.left = read(tokens);
        n.right = read(tokens);
        return n;
    }
}

TIME O(n)

SPACE O(n)

StringBuilder for output and an ArrayDeque of tokens for input. Recursion depth is h; use an explicit stack if the tree can be a 10⁵-node chain.

Sorted array / list to balanced BST

SortedToBST.java: LeetCode 108, 109
/**
 * LeetCode 108 / 109 - height-balanced BST from a sorted array, or from a sorted
 * linked list.
 */
public class SortedToBST {
    public static TreeNode fromArray(int[] a) {
        return build(a, 0, a.length - 1);
    }

    private static TreeNode build(int[] a, int lo, int hi) {
        if (lo > hi) return null;
        // the middle keeps both halves within one element of each other
        int mid = lo + (hi - lo) / 2;
        TreeNode root = new TreeNode(a[mid]);
        root.left = build(a, lo, mid - 1);
        root.right = build(a, mid + 1, hi);
        return root;
    }

    /**
     * Linked list: build the left subtree first, consuming the list in order, so
     * every node is visited once (O(n)).
     */
    public static TreeNode fromList(ListNode head) {
        int n = 0;
        for (ListNode p = head; p != null; p = p.next) n++;
        ListNode[] cursor = {head};
        return inorderBuild(cursor, 0, n - 1);
    }

    private static TreeNode inorderBuild(ListNode[] cursor, int lo, int hi) {
        if (lo > hi) return null;
        int mid = lo + (hi - lo) / 2;
        TreeNode left = inorderBuild(cursor, lo, mid - 1);
        // the list cursor is exactly at the inorder position of root
        TreeNode root = new TreeNode(cursor[0].val);
        cursor[0] = cursor[0].next;
        root.left = left;

        return root;

Maximum binary tree

MaximumBinaryTree.java: LeetCode 654
import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 654 - Maximum Binary Tree in O(n): a decreasing stack of nodes (the
 * monotonic stack of Chapter 7).
 */
public class MaximumBinaryTree {
    public static TreeNode construct(int[] nums) {
        // values decreasing from bottom to top
        Deque<TreeNode> stack = new ArrayDeque<>();
        for (int x : nums) {
            TreeNode node = new TreeNode(x);
            // smaller values become the left subtree
            while (!stack.isEmpty() && stack.peek().val < x)
                node.left = stack.pop();
            // node hangs on the right of a larger value
            if (!stack.isEmpty()) stack.peek().right = node;
            stack.push(node);
        }
        return stack.peekLast();
    }
}

Java 17+

TIME O(n)

SPACE O(n)

Each value is pushed and popped at most once.

F. Detailed Dry Run

The table in section C traces 105 on pre = [3, 9, 20, 15, 7], in = [9, 3, 15, 20, 7]: the root 3 sits at in[1], so the left subtree has 1 node (9) and the right subtree has 3 (20, 15, 7); 20 sits at in[3], giving 15 on the left and 7 on the right. The preorder pointer visits 3, 9, 20, 15, 7 in exactly the order the rows were created.

Deserialize 1,2,#,#,3,4,#,#,5,#,#: read 1 (root); recurse left: 2, then # (no left), # (no right); back at 1, recurse right: 3, left 4 with two #, right 5 with two #. All 11 tokens are consumed, which is a good self-check: n nodes always produce 2n + 1 tokens.

G. Variations of the Pattern

Other traversal pairs

Construct from Preorder and Postorder (889): needs the next preorder element as the left child's root to find the split. Construct BST from Preorder (1008): bounds-based, no inorder needed, because inorder is the sorted preorder.

Other serializations

Serialize and Deserialize BST (449): preorder without # markers, since the BST bounds disambiguate. Serialize N-ary Tree (428): write the child count after each value.

Unique trees

Unique Binary Search Trees II (95) generates all trees for keys 1..n by choosing each key as root and combining every left with every right list.

Tree from other structures

Convert Sorted List to BST, Flatten Binary Tree to Linked List (114, the reverse direction), Construct Binary Tree from String (536), Construct Quad Tree (427).

Verifying a serialization

Verify Preorder Serialization (331) needs no tree: keep a count of open slots, 1 initially; each token consumes one and a non-# adds two. It must never reach 0 early and must end at 0.

J. Interview Tips

INTERVIEW

Start with the invariant: "the first preorder element is the root; its position in inorder gives the left subtree size." Then draw the window split.

Mention the map and the index bounds before coding; both are what make it linear.

For serialization, discuss the format: preorder with null markers vs level order; delimiter choice; and why recursion depth matters.

Follow-ups: why inorder alone is insufficient; construct without extra space; handle

duplicates; compress the serialization (BST needs no null markers).

Edge cases: empty arrays, a single node, a left-only or right-only chain, negative values, mismatched array lengths.

CHAPTER SUMMARY

Construction = pick the root, split the rest, recurse. Inorder's root position is the left subtree's size.

Pre + in: consume preorder left to right, build left first. In + post: consume postorder from the end, build right first.

A value → index map and index bounds keep it O(n); copying subarrays or scanning inorder makes it O(n²).

Serialize with null markers and commas; a valid preorder of n nodes has 2n + 1 tokens.

Sorted data → balanced BST: middle as root; for linked lists, simulate inorder with a cursor.
