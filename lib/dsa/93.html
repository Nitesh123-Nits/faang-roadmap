Memoization vs Tabulation

Top-down caches what is asked; bottom-up fills everything in order.

A. Pattern Overview

Both styles compute the same recurrence. Memoization (top-down) writes the natural recursion and caches results; only the states the question reaches are computed. Tabulation (bottom-up) loops over states in dependency order and fills a table; every state is computed, but there is no recursion and the loop can be compressed to rolling rows. Choosing between them is an engineering decision about reachable states, stack depth and space, not a different algorithm.

KEY IDEA

Write the recursion first, then decide. The recursion proves the recurrence is right; the table is an optimisation of how it is evaluated.

B. When to Recognize This Pattern

Pattern Recognition Signals

You have a recurrence but not an obvious loop order: start top-down.
Only a fraction of the states matter (a target far from the base): memoisation skips the

rest.

n up to 10^5 or more with a linear chain: bottom-up, or the recursion overflows the stack.
You need only the previous row: bottom-up with rolling arrays.
Transitions jump irregularly (word break, partitions): memo with a HashMap can be simpler than a full table.
ONE-LINE TEST

Dense and deep: tabulate. Sparse or awkward order: memoise.

E. Java Implementation

MemoVsTab.java: LeetCode 322, 120
import java.util.*;

/** Ch 79: memoisation vs tabulation; LeetCode 322, 120. */
public class MemoVsTab {

    /** Plain recursion: exponential. Kept to show what memoisation removes. */
    public static int coinChangeNaive(int[] coins, int amount) {
        if (amount == 0) return 0;
        int best = Integer.MAX_VALUE;
        for (int c : coins) {
            if (c > amount) continue;
            int sub = coinChangeNaive(coins, amount - c);
            if (sub != Integer.MAX_VALUE) best = Math.min(best, sub + 1);
        }
        return best;
    }

    /** Top-down: cache by the only changing argument, the remaining amount. */
    public static int coinChangeMemo(int[] coins, int amount) {
        int[] memo = new int[amount + 1];
        Arrays.fill(memo, -2);                              // -2 = not computed
        int r = solve(coins, amount, memo);
        return r == Integer.MAX_VALUE ? -1 : r;
    }

    private static int solve(int[] coins, int rem, int[] memo) {
        if (rem == 0) return 0;
        if (memo[rem] != -2) return memo[rem];
        int best = Integer.MAX_VALUE;
        for (int c : coins) {
            if (c > rem) continue;
            int sub = solve(coins, rem - c, memo);
            if (sub != Integer.MAX_VALUE) best = Math.min(best, sub + 1);
        }
        return memo[rem] = best;
    }

    /** Bottom-up: amounts 1..amount in increasing order. */
    public static int coinChangeTab(int[] coins, int amount) {

Java 17+

        int[] dp = new int[amount + 1];
        Arrays.fill(dp, Integer.MAX_VALUE);
        dp[0] = 0;
        for (int a = 1; a <= amount; a++)
            for (int c : coins)
                if (c <= a && dp[a - c] != Integer.MAX_VALUE)
                    dp[a] = Math.min(dp[a], dp[a - c] + 1);
        return dp[amount] == Integer.MAX_VALUE ? -1 : dp[amount];
    }

    /** LeetCode 120, top-down: state (row, col), cached in a 2D array. */
    public static int minimumTotalMemo(List<List<Integer>> tri) {
        int n = tri.size();
        Integer[][] memo = new Integer[n][n];
        return down(tri, 0, 0, memo);
    }

    private static int down(List<List<Integer>> tri, int r, int c,
            Integer[][] memo) {
        if (r == tri.size()) return 0;
        if (memo[r][c] != null) return memo[r][c];
        int best = tri.get(r).get(c)
                + Math.min(down(tri, r + 1, c, memo), down(tri, r + 1, c + 1,
                        memo));
        return memo[r][c] = best;
    }

    /** LeetCode 120, bottom-up with the full table, built from the last row. */
    public static int minimumTotalTab(List<List<Integer>> tri) {
        int n = tri.size();
        int[][] dp = new int[n][n];
        for (int c = 0; c < n; c++) dp[n - 1][c] = tri.get(n - 1).get(c);
        for (int r = n - 2; r >= 0; r--)
            for (int c = 0; c <= r; c++)
                dp[r][c] =
                        tri.get(r).get(c) + Math.min(dp[r + 1][c],
                                dp[r + 1][c + 1]);
        return dp[0][0];
    }

    /** LeetCode 120, one row: row r only reads row r + 1. */
    public static int minimumTotalRolling(List<List<Integer>> tri) {
        int n = tri.size();
        int[] dp = new int[n];
        for (int c = 0; c < n; c++) dp[c] = tri.get(n - 1).get(c);
        for (int r = n - 2; r >= 0; r--)
            for (int c = 0; c <= r; c++)
                dp[c] = tri.get(r).get(c) + Math.min(dp[c], dp[c + 1]);
        return dp[0];
    }
}

SPACE O(a)

Coin change is O(amount x coins) time and O(amount) space in both styles. The triangle is O(n^2) time; the rolling version uses O(n) space.

F. Detailed Dry Run

coinChangeMemo([1,2,5], 11): ask best(11). Try coin 5, call best(6); try coin 5, call best(1)

which tries coin 1, calls best(0) = 0, so best(1) = 1; back in best(6): 1 + 1 = 2 via coins 5 and 1. Coin 2 from 11 asks best(9), coin 1 asks best(10); every sub-amount they need (best(4), best(5), best(6)...) is computed once and afterwards answered from the cache. Final: best(11) = 1 + best(6) = 3.

minimumTotalRolling: start with the last row [4,1,8,3]. Row 2: [6+1, 5+1, 7+3] = [7,6,10]. Row 1: [3+6, 4+6] = [9,10]. Row 0: 2 + 9 = 11.

G. Variations of the Pattern

Memo with a HashMap

When states are sparse or keys are strings or pairs, a HashMap<Long, Integer> avoids a huge dense table. Encode (i, j) into a long for speed.

Forward versus backward tabulation

Pull style computes dp[i] from earlier states; push style sends dp[i] forward to later states. Push is natural for counting reachability; pull is natural for min/max.

Iterative deepening of states

Some problems have no clean order (game states). Memoised recursion with cycle detection (a visiting marker) handles them where tables cannot.

Memo hit rate as a diagnostic

If the memo is almost never hit, the state is too detailed (it contains information that does not affect the future). Remove it.

Avoiding recursion depth

Java's default stack handles roughly 10^4 frames. For chains of 10^5 states, tabulate or run the recursion in a thread with a larger stack.

J. Interview Tips

INTERVIEW

Open with the recursion, then say: "I will memoise on these parameters". It is the fastest correct answer.

Offer the bottom-up version when asked about stack depth or space, and name the loop order and why.

Mention the sentinel and infinity pitfalls before they bite.

Follow-ups: print the coins used; count the ways instead (Chapter 82); reduce space;

handle amount = 10^9 with few coins (then BFS or number theory, not DP).

Edge cases: amount = 0 (answer 0), no coins, coin larger than amount, unreachable amount.

CHAPTER SUMMARY

Memoisation caches a recursion and visits only reachable states; tabulation fills all states in dependency order.

Both are states x work per state; the difference is stack depth, constant factors and how easily space can be reduced.

Pick the recursion first to get the recurrence right; convert to a table for large n or for rolling rows.

Sentinels and infinity cause most bugs: never treat a legitimate 0 as unvisited and never add to Integer.MAX_VALUE.

The loop direction comes from the dependency arrows.
