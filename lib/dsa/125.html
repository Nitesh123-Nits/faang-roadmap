What we are counting

Complexity analysis answers one question: how does the cost grow as the input grows? We count basic steps (comparisons, array reads and writes, arithmetic) rather than seconds, because seconds depend on the machine, the JIT and the data, while growth rates do not. Constants matter in practice, but they cannot rescue a growth rate that is too steep: O(n²) on 10⁵ elements is 10¹⁰ steps whatever the hardware.

Big O, Omega and Theta

The three symbols describe bounds on a function, not cases of an algorithm. This distinction is the most common source of confusion in interviews.

Symbo lMeaning for f(n)Formal statementRead it as

Insertion sort illustrates the difference. Its worst case (reverse-sorted input) takes Θ(n²) steps; its best case (already sorted) takes Θ(n). So "insertion sort is O(n²)" is true for every

input, "insertion sort is Ω(n)" is true for every input, and "insertion sort is Θ(n²)" is true only

if you say in the worst case. In interviews "the complexity" nearly always means the tight worst-case upper bound, written with O.

COMMON MISCONCEPTION

O is not "the worst case". The worst case is a scenario; O, Ω and Θ are bounds you can attach to the worst case, the best case or the average case separately.

Time, space, and what "extra" means

Time complexity counts steps. Space complexity counts memory, and the convention matters: unless stated otherwise, interviewers mean auxiliary space, the memory your algorithm allocates beyond the input. The input itself (O(n) for an array of n numbers) is input space and is not charged to you.

Recursion stack space

Every active call occupies a stack frame, so a recursion that goes d levels deep uses O(d) space even if it allocates nothing else. Java does not perform tail-call elimination, so a tail-recursive loop still costs one frame per iteration.

Amortised analysis

Some operations are usually cheap and occasionally expensive. Amortised cost is the average cost per operation over any sequence of operations in the worst case: it is a guarantee about the whole sequence, with no randomness and no assumption about the input. That is different from average-case cost, which averages over a distribution of inputs.

Example: appending to a dynamic array

ArrayList.add writes into spare capacity in O(1). When the array is full it allocates a bigger one and copies every element. With doubling, the copies for n appends are 1 + 2 + 4 + ... + 2^k < 2n, so the total work is below 3n writes and the amortised cost per append is O(1).

Figure 157. Cost of each append to a doubling array (bars) and the running average (line). Spikes at 2, 3, 5, 9, 17, 33 are the resizes; the average stays below 3.

The instrumented CountingArray confirms this by counting writes: for 1,000,000 appends, a doubling array performs 2,048,575 writes (about 2.05 per append) and a 1.5x array performs 3,099,753 (about 3.10 per append). The growth factor changes the constant, never the class. OpenJDK's ArrayList grows by about 1.5x; that is an implementation detail, not a documented guarantee.

WHY GEOMETRIC GROWTH

Growing by a fixed amount (say +10) is not amortised O(1): the number of resizes is

n / 10, each copying up to n elements, so n appends cost Θ(n²). Growth must be

geometric (multiply by a constant greater than 1).

Quicksort with the first element as pivot shows how much the case matters. On 2,000 already-sorted elements it makes 1,999,000 comparisons (n(n-1)/2); the same is true when all keys are equal. The standard cures are a random pivot, median-of-three, or three-way partitioning for duplicates (Ch. 99).

CHOOSING A DEQUE

ArrayDeque is the default for both stack and queue. Its Javadoc says it is "likely to be faster than Stack when used as a stack, and faster than LinkedList when used as a queue". DEEPER

Knapsack-style DP is O(n · W), which looks polynomial but is pseudo-polynomial: W is a numeric value, and its size in bits is log W. Interviewers who ask "is that polynomial?" are checking whether you know the difference.

The instrumented code

Every measured number in this chapter comes from this class. The tests compare each counter with its closed form for every n up to 300 to 400 and check the random-input behaviour of quicksort statistically.

ComplexityDemos.java
import java.util.*;

/** Complexity Masterclass: instrumented loops so every claim can be counted. */
public class ComplexityDemos {

    /** for i in [0, n): for j in (i, n): the inner body runs n(n-1)/2 times. */
    public static long triangular(int n) {
        long ops = 0;

Java 17+

        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++) ops++;
        return ops;
    }

    /** i doubles each round: floor(log2 n) + 1 iterations for n >= 1. */
    public static int doubling(int n) {
        int ops = 0;
        for (long i = 1; i <= n; i *= 2) ops++;
        return ops;
    }

    /** j steps by i: the inner loop runs floor(n / i) times, total about n ln n. */
    public static long harmonic(int n) {
        long ops = 0;
        for (int i = 1; i <= n; i++)
            for (int j = i; j <= n; j += i) ops++;
        return ops;
    }

    /**
     * Nested loops that are still O(n): each element enters and leaves once.
     * Returns the total pointer moves, which never exceeds 2n.
     */
    public static int windowPointerMoves(int[] a, int limit) {
        int moves = 0, left = 0, sum = 0;
        for (int right = 0; right < a.length; right++) {
            sum += a[right];
            moves++;
            while (sum > limit && left <= right) {
                sum -= a[left++];
                moves++;
            }
        }
        return moves;
    }

    /** A growable array that counts every element it writes (amortised cost). */
    public static final class CountingArray {
        private int[] data = new int[1];
        private int size = 0;
        private long writes = 0;
        private final int growthNumerator, growthDenominator;

        public CountingArray() { this(2, 1); }

        /** Growth factor numerator / denominator, e.g. 3 / 2 for 1.5. */
        public CountingArray(int numerator, int denominator) {
            growthNumerator = numerator;
            growthDenominator = denominator;
        }

        public void add(int x) {
            if (size == data.length) {
                int cap = Math.max(data.length + 1,
                        data.length * growthNumerator / growthDenominator);
                data = Arrays.copyOf(data, cap);
                writes += size;                   // elements copied by the resize
            }
            data[size++] = x;
            writes++;                             // the new element itself
        }

        public int size() { return size; }
        public long writes() { return writes; }
    }

    /** Number of calls made by the plain recursion fib(n) = fib(n-1) + fib(n-2). */
    public static long fibCallsNaive(int n) {
        if (n < 2) return 1;
        return 1 + fibCallsNaive(n - 1) + fibCallsNaive(n - 2);
    }

    /** Calls made when results are cached: O(n). */
    public static int fibCallsMemo(int n) {
        long[] memo = new long[n + 2];
        int[] calls = {0};
        fibMemo(n, memo, calls);
        return calls[0];
    }

    private static long fibMemo(int n, long[] memo, int[] calls) {
        calls[0]++;
        if (n < 2) return n;
        if (memo[n] != 0) return memo[n];
        return memo[n] = fibMemo(n - 1, memo, calls) + fibMemo(n - 2, memo, calls);
    }

    /** Recursion depth of a linear recursion on n: n frames of stack space. */
    public static int linearDepth(int n) {
        return n == 0 ? 1 : 1 + linearDepth(n - 1);
    }

    /** Recursion depth when the range halves each call: about log2 n frames. */
    public static int halvingDepth(int lo, int hi) {
        if (hi - lo <= 1) return 1;
        int mid = lo + (hi - lo) / 2;
        return 1 + Math.max(halvingDepth(lo, mid), halvingDepth(mid, hi));
    }

    /** Quicksort comparisons, first element as pivot (Lomuto partition). */
    public static long quicksortComparisons(int[] a) {
        long[] count = {0};
        sort(a.clone(), 0, a.length - 1, count);
        return count[0];
    }

    private static void sort(int[] a, int lo, int hi, long[] count) {
        if (lo >= hi) return;
        int pivot = a[lo], store = lo;
        for (int i = lo + 1; i <= hi; i++) {
            count[0]++;
            if (a[i] < pivot) {
                store++;
                int t = a[store]; a[store] = a[i]; a[i] = t;
            }
        }
        int t = a[lo]; a[lo] = a[store]; a[store] = t;
        sort(a, lo, store - 1, count);
        sort(a, store + 1, hi, count);
    }

    /** Bit flips caused by n increments of a binary counter: O(1) amortised. */
    public static long counterFlips(int n) {
        long flips = 0;
        long counter = 0;
        for (int i = 0; i < n; i++) {
            long before = counter;
            counter++;
            flips += Long.bitCount(before ^ counter);
        }
        return flips;
    }

    /** Swaps made building a min-heap bottom-up (sift-down from n/2 - 1 to 0). */
    public static long buildHeapSwaps(int[] a) {
        int[] h = a.clone();
        long swaps = 0;
        for (int i = h.length / 2 - 1; i >= 0; i--) {
            int k = i;
            while (true) {

                swaps++;

        return swaps;
    }

CHAPTER SUMMARY

O, Ω, Θ bound a function; best, worst and average case are scenarios. Say "worst-case O(...)" to be unambiguous.

Auxiliary space excludes the input; recursion depth counts, and Java does not eliminate tail calls.

Amortised cost guarantees the average over any sequence: geometric growth makes dynamic-array appends O(1), fixed growth does not.

Count the total work of a pointer, not the work per outer iteration: nested loops with monotone pointers stay linear.

Quicksort, hash tables and TimSort differ between average and worst case; know what the library guarantees (heap-sort guard, stable merge-based object sort).

Default to ArrayDeque for stacks and queues, HashMap for lookup, TreeMap for ordered queries and PriorityQueue for repeated extremes; avoid list.remove(0), string += in loops and contains inside loops.
