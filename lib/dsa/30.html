Merge and Partition

Weave sorted lists, split by a pivot, sort in O(1) extra space, and add digit lists.

A. Pattern Overview

Arrays are easy to sort and merge because you can index them. Linked lists are the opposite: merging is O(1) space (relink nodes, never copy), and indexing is impossible. That makes them the natural home of merge-based algorithms. This chapter covers the family: merge two lists, merge k lists, partition around a value, merge sort a list, and add two numbers digit by digit.

KEY IDEA

The dummy-head idiom. Create dummy = new ListNode(0) and a tail = dummy. Append by tail.next = node; tail = node. Return dummy.next. It removes the "is this the first node?" branch from every merge, partition and filter in this part of the book.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Merge two (or k) sorted lists": dummy head plus comparison; heap or divide and conquer for k > 2.
"Sort a linked list in O(n log n)", especially with constant extra space (bottom-up) or no

array copy: merge sort.

"Rearrange so that all nodes less than x come before the others, preserving relative order": two chains, then concatenate.
"Numbers stored as lists of digits": simulate column addition; carry may outlive both

lists.

"Merge sorted data from k sources / streams / files": the k-way merge, the heart of external sorting.
The input is already sorted in pieces: merging is cheaper than re-sorting.
QUICK RULE

Sorted + linked list + O(1) extra space almost always means relinking with a dummy head. k sorted inputs means heap (online) or divide and conquer (offline).

C. Core Intuition with Illustrations

Merge two sorted lists

Maintain tail, the last node of the merged list. Compare the two heads and steal the smaller node: no node is copied. When one list is exhausted, attach the other in one step, because the remainder is already sorted.

Figure 44. The result is built from the original nodes; teal nodes came from a, amber from b.

Merge k sorted lists: heap or tournament

With k lists and N nodes in total, merging them one after another costs O(kN), because the accumulated list is re-walked k times. Two efficient plans:

PlanIdeaTimeSpacePrefer when
Min-heap of headsPoll the smallest head, push its successorO(N log k)O(k)Streaming input, or k is small

Partition: two chains

Walk the list once; append each node to the less chain or the greater-or-equal chain, each with its own dummy head. Finally attach the second chain to the first and null-terminate the second: its last node may still point into the old list.

Figure 45. Both chains keep their original order (stable), which is why this is not quicksort's partition step.

Merge sort fits linked lists

Merge sort needs split and merge. On an array, merging needs O(n) scratch space; on a list, merging is relinking. The split uses the fast / slow pointers of Chapter 21 (first-middle form, so both halves are non-empty). Total O(n log n) time, O(log n) recursion stack; a bottom-up version removes the stack and uses O(1) space.

Figure 46. Splitting is O(n) by walking, merging is O(n) by relinking; there are log n levels.

Adding numbers: column by column

With digits in reverse order (least significant first), the list order is the column order: add digit by digit with a carry. Keep looping while either list has nodes or the carry is non-zero: [9, 9] + [1] ends with a new node for the final carry.

D. Brute Force to Optimal Solution

Example: Merge k Sorted Lists (LeetCode 23)

Brute force: collect all N values, sort, rebuild a list: O(N log N) time, O(N) space.
Sequential merge: fold the lists with merge: the answer list is walked up to k times: O(kN).
Min-heap: only the k current heads can be next, so keep them in a heap: O(N log k), O(k) space.
Divide and conquer: log k rounds of pairwise merges, each round touching every node once: O(N log k), O(log k) stack, no heap overhead.

The same ladder explains external sorting (merge sorted runs from disk with a heap) and log aggregation across k shards.

E. Java Implementation

Merge two sorted lists

MergeTwoLists.java: LeetCode 21

Java 17+

/**
 * LeetCode 21 - Merge Two Sorted Lists. A dummy head removes the "which list starts" special
 * case.
 */
public class MergeTwoLists {

    public static ListNode merge(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0), tail = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) {                        // <= keeps the merge stable
                tail.next = a;
                a = a.next;
            } else {
                tail.next = b;
                b = b.next;
            }
            tail = tail.next;
        }
        tail.next = (a != null) ? a : b;                 // append the leftover run in one step
        return dummy.next;
    }
}

TIME O(m + n)

SPACE O(1)

<= takes from a on ties, making the merge stable, which merge sort relies on.

Merge k sorted lists

MergeKLists.java: LeetCode 23
import java.util.PriorityQueue;

/** LeetCode 23 - Merge k Sorted Lists, with a min-heap and with divide and conquer. */
public class MergeKLists {

    /** O(N log k) time, O(k) space: the heap holds one node per list. */
    public static ListNode mergeKHeap(ListNode[] lists) {
        PriorityQueue<ListNode> heap =
                new PriorityQueue<>((x, y) -> Integer.compare(x.val, y.val));
        for (ListNode h : lists) {
            if (h != null) heap.add(h);
        }
        ListNode dummy = new ListNode(0), tail = dummy;
        while (!heap.isEmpty()) {
            ListNode smallest = heap.poll();
            tail.next = smallest;
            tail = smallest;
            if (smallest.next != null) heap.add(smallest.next);
        }
        return dummy.next;
    }

    /** O(N log k) time, O(log k) stack: merge lists pairwise like a tournament. */
    public static ListNode mergeKDivide(ListNode[] lists) {
        return lists.length == 0 ? null : mergeRange(lists, 0, lists.length - 1);
    }

    private static ListNode mergeRange(ListNode[] lists, int lo, int hi) {
        if (lo == hi) return lists[lo];
        int mid = (lo + hi) >>> 1;
        return merge(mergeRange(lists, lo, mid), mergeRange(lists, mid + 1, hi));
    }

    private static ListNode merge(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0), tail = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) {
                tail.next = a;
                a = a.next;
            } else {
                tail.next = b;
                b = b.next;
            }
            tail = tail.next;
        }
        tail.next = (a != null) ? a : b;
        return dummy.next;
    }
}

Java 17+

TIME O(N log k)

SPACE O(k) heap or O(log k) stack

Skip null lists when seeding the heap. The heap stores nodes, so no wrapper object is needed.

Partition list

PartitionList.java: LeetCode 86

Java 17+

/** LeetCode 86 - Partition List. Two dummy-headed chains keep the relative order (stable). */
public class PartitionList {

    public static ListNode partition(ListNode head, int x) {
        ListNode lessHead = new ListNode(0), geHead = new ListNode(0);
        ListNode less = lessHead, ge = geHead;
        for (ListNode c = head; c != null; c = c.next) {
            if (c.val < x) {
                less.next = c;
                less = c;
            } else {
                ge.next = c;
                ge = c;
            }
        }
        // cut the old tail link, or a cycle appears
        ge.next = null;
        less.next = geHead.next;
        return lessHead.next;
    }
}

TIME O(n)

SPACE O(1)

ge.next = null is essential: the last >= node may still point to a node now in the less chain, which would create a cycle.

Sort list

SortList.java: LeetCode 148

Java 17+

/** LeetCode 148 - Sort List: top-down merge sort, O(n log n) time with O(log n) stack. */
public class SortList {

    public static ListNode sortList(ListNode head) {
        if (head == null || head.next == null) return head;
        // fast starts one ahead: slow = first middle
        ListNode slow = head, fast = head.next;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode right = slow.next;
        slow.next = null;                                // split into two independent lists
        return merge(sortList(head), sortList(right));
    }

    private static ListNode merge(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0), tail = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) {
                tail.next = a;
                a = a.next;
            } else {
                tail.next = b;
                b = b.next;
            }
            tail = tail.next;
        }
        tail.next = (a != null) ? a : b;
        return dummy.next;
    }
}

TIME O(n log n)

SPACE O(log n) stack

fast = head.next makes slow the first middle, so a two-node list splits into one and one (a recursion on the full list would never terminate).

Add two numbers

AddTwoNumbers.java: LeetCode 2, 445

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/** LeetCode 2 / 445 - Add Two Numbers (digits in reverse order, and in forward order). */
public class AddTwoNumbers {

    /** Least significant digit first: add column by column, carrying. */
    public static ListNode addTwoNumbers(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0), tail = dummy;
        int carry = 0;
        while (a != null || b != null || carry != 0) {
            int sum = carry;
            if (a != null) {
                sum += a.val;
                a = a.next;
            }
            if (b != null) {
                sum += b.val;
                b = b.next;
            }
            tail.next = new ListNode(sum % 10);
            tail = tail.next;
            carry = sum / 10;
        }
        return dummy.next;
    }

    /** Most significant digit first: stacks give the digits back in reverse, no mutation. */
    public static ListNode addTwoNumbersII(ListNode a, ListNode b) {
        Deque<Integer> sa = new ArrayDeque<>(), sb = new ArrayDeque<>();
        for (; a != null; a = a.next) sa.push(a.val);
        for (; b != null; b = b.next) sb.push(b.val);
        ListNode head = null;
        int carry = 0;
        while (!sa.isEmpty() || !sb.isEmpty() || carry != 0) {
            int sum = carry;
            if (!sa.isEmpty()) sum += sa.pop();
            if (!sb.isEmpty()) sum += sb.pop();
            // insert at the front: builds MSD-first
            head = new ListNode(sum % 10, head);
            carry = sum / 10;
        }
        return head;
    }
}

TIME O(max(m, n))

SPACE O(1) auxiliary, plus the result

list; O(m + n) for the stacks in the II
version

The loop condition includes carry != 0. Digits are sum % 10, carry is sum / 10.

G. Variations of the Pattern

Add Two Numbers II: most significant digit first

Columns appear in the wrong order. Two choices: reverse both lists (mutates the input; restore if required), or push the digits onto two stacks and pop to add from the least significant end, inserting each result digit at the front of the answer list. The listing above implements the stack version.

Insertion Sort List

Take nodes one by one and insert each into a sorted prefix: O(n²) time, O(1) space, and O(n) when the input is already sorted. Use a dummy head and walk from the dummy until prev.next.val >= cur.val; add a shortcut that compares with the current sorted tail first.

Merge In Between and Merge Nodes in Between Zeros

Merge In Between Linked Lists (1669) splices list b into a between positions i and j: find the node before i, the node after j, and the tail of b. Merge Nodes in Between Zeros (2181) sums each run between zeros into one node: a segment-reduction with one writer pointer.

Merge sorted arrays from the back

Merge Sorted Array (88) is the array twin of this chapter: with room at the end of nums1, fill from the largest end so no unread element is overwritten: O(m + n), O(1) space.

Bottom-up merge sort for O(1) space

Merge runs of length 1, then 2, then 4, … by cutting a run of the current size, merging it with the next run, and reattaching the result to a running tail. It needs a helper split(head, size) that detaches the first size nodes and returns the rest. It trades readability for removing the recursion stack: mention it as the follow-up, implement the top-down version.

k-way merge beyond lists

Merge k sorted arrays, find the smallest range covering one element from each list, and kth smallest in a sorted matrix all keep one cursor per source in a heap. The heap version of this chapter is the template (Part IX: Heap and Greedy).

J. Interview Tips

INTERVIEW

Open with the dummy-head idiom and say why: it removes the first-node special case. It signals experience with pointer code.

For merge-k, state the whole ladder (concatenate and sort, sequential O(kN), heap, divide and conquer) and pick one; interviewers want to hear the trade-off, not only the best answer.

For Sort List, note that quicksort is a poor fit (no random access, bad pivots) and merge sort is natural; mention the bottom-up variant for O(1) space.

Follow-ups: merge two lists recursively; merge k lists in a streaming fashion; remove

duplicates while merging; sort a linked list in O(1) space; add numbers without reversing; handle numbers with leading zeros.

Edge cases: one or both lists empty, all values equal, k = 0 or k = 1, lists of very different lengths, carry out of the last column, duplicates across lists.

CHAPTER SUMMARY

On lists, merging is relinking: O(1) extra space. A dummy head plus a tail pointer removes the first-node special case.

Merge two: <= for stability; attach the leftover run in one step. Merge k: min-heap of heads or pairwise tournament, both O(N log k).

Partition: two dummy-headed chains, concatenated; null-terminate the second or a cycle appears.

Sort List is merge sort: first-middle split (fast = head.next), recurse, merge; bottom-up gives O(1) space.

Add numbers: loop while either list or the carry remains; for most-significant-first input use stacks or reverse.
