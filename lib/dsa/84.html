Merge Intervals

Sort by start, then fold every overlapping neighbour into one run.

A. Pattern Overview

Merge Intervals collapses a pile of possibly overlapping intervals into the smallest set of disjoint ones that covers exactly the same points. It is the foundation of the whole interval family: once the intervals are sorted by start, overlap can only happen between neighbours, so one left-to-right pass with a current run is enough. The cost is the sort: O(n log n) time, O(n) output space.

KEY IDEA

Sort by start, and the only interval that can touch the next one is the current run. The run's end is a running maximum, so an interval that is entirely inside the run is absorbed without any special case.

B. When to Recognize This Pattern

A stream of integers that must be reported as ranges (the online version).
ONE-LINE TEST

Unsorted [start, end] pairs and a question about overlap: sort by start first.

C. Core Intuition with Illustrations

Why sorting by start is enough

Suppose the intervals are sorted by start and A comes before B before C. If C overlaps A, then C.start <= A.end; but B.start <= C.start, so B.start <= A.end and B overlaps A too. Overlap is transitive along the sorted order, which is why a single run that remembers only its maximum end is correct.

A worked example

Intervals [1,3] [8,10] [2,6] [15,18] [17,20]. After sorting by start: [1,3] [2,6] [8,10] [15,18] [17,20]. The result is [1,6] [8,10] [15,20].

Touching intervals: the one decision to state aloud

[1,2] and [2,3] share the point 2 if intervals are closed, so they merge into [1,3]. [1,2] and [3,4] do not. If the intervals are half-open ([1,2) and [2,3)), touching is not overlap and you may or may not want to merge them, depending on the problem. The code differs by one character: <= versus <. LeetCode 56 uses closed intervals and merges touching ones.

Gaps are the complement

Run the same loop but emit the gap between the current run's end and the next start whenever the next start is larger. That is Employee Free Time (759) after flattening all schedules, and Missing Ranges (163) when the intervals are single numbers.

Online version: a stream of integers (352)

Store disjoint closed intervals in a TreeMap<start, end>. For a new value v, look at floorEntry(v) (an interval starting at or before v) and at the interval that starts at v + 1. Four cases: inside an existing interval (ignore), joins only the left one (extend its end), joins only the right one (move its start down), joins both (fuse into one), or stands alone.

E. Java Implementation

Merge, union length, free time, missing ranges, stream summary

MergeIntervals.java: LeetCode 56, 163, 352, 759
import java.util.*;

/** Ch 71: merge intervals; LeetCode 56, 163, 352, 759. */
public class MergeIntervals {

    /** LeetCode 56: merge all overlapping closed intervals (touching counts). */
    public static int[][] merge(int[][] intervals) {
        if (intervals.length == 0) return new int[0][];
        int[][] sorted = intervals.clone();
        Arrays.sort(sorted, Comparator.comparingInt(iv -> iv[0]));
        List<int[]> out = new ArrayList<>();
        int[] cur = sorted[0].clone();
        for (int i = 1; i < sorted.length; i++) {
            if (sorted[i][0] <= cur[1]) cur[1] = Math.max(cur[1], sorted[i][1]);
            else { out.add(cur); cur = sorted[i].clone(); }
        }
        out.add(cur);
        return out.toArray(new int[0][]);
    }

Java 17+

    /** Total length of the union of half-open intervals [a, b). */
    public static long unionLength(int[][] intervals) {
        long total = 0;
        for (int[] iv : merge(intervals)) total += (long) iv[1] - iv[0];
        return total;
    }

    /**
     * LeetCode 759: free time common to all employees. Each schedule is a list
     * of working intervals {start, end}; the result lists the gaps, in order.
     */
    public static List<int[]> employeeFreeTime(List<List<int[]>> schedules) {
        List<int[]> all = new ArrayList<>();
        for (List<int[]> s : schedules) all.addAll(s);
        all.sort(Comparator.comparingInt(iv -> iv[0]));
        List<int[]> free = new ArrayList<>();
        if (all.isEmpty()) return free;
        int end = all.get(0)[1];
        for (int[] iv : all) {
            if (iv[0] > end) free.add(new int[]{end, iv[0]});
            end = Math.max(end, iv[1]);
        }
        return free;
    }

    /**
     * LeetCode 163: the ranges inside [lower, upper] missing from the sorted,
     * duplicate-free array nums (all of whose values lie in that range).
     */
    public static List<int[]> findMissingRanges(int[] nums, int lower, int upper) {
        List<int[]> out = new ArrayList<>();
        long prev = (long) lower - 1;
        for (int x : nums) {
            if (x - prev > 1) out.add(new int[]{(int) (prev + 1), x - 1});
            prev = x;
        }
        if (upper - prev >= 1) out.add(new int[]{(int) (prev + 1), upper});
        return out;
    }

    /**
     * LeetCode 352: a stream of integers summarised as disjoint closed
     * intervals. A TreeMap keyed by interval start keeps them sorted.
     * Assumes values stay below Integer.MAX_VALUE.
     */
    public static class SummaryRanges {
        private final TreeMap<Integer, Integer> map = new TreeMap<>();

        public void addNum(int v) {
            Map.Entry<Integer, Integer> lo = map.floorEntry(v);
            if (lo != null && lo.getValue() >= v) return;        // already inside
            boolean joinLeft = lo != null && lo.getValue() == v - 1;
            Integer hiEnd = map.get(v + 1);                      // starts at v + 1
            if (joinLeft && hiEnd != null) {
                map.put(lo.getKey(), hiEnd);
                map.remove(v + 1);
            } else if (joinLeft) {
                map.put(lo.getKey(), v);
            } else if (hiEnd != null) {
                map.remove(v + 1);
                map.put(v, hiEnd);
            } else {
                map.put(v, v);
            }
        }

        public int[][] getIntervals() {
            int[][] out = new int[map.size()][];
            int i = 0;
            for (Map.Entry<Integer, Integer> e : map.entrySet())
                out[i++] = new int[]{e.getKey(), e.getValue()};
            return out;
        }
    }
}

TIME O(n log n)

SPACE O(n)

The sort dominates; the pass is linear. merge clones the input so callers keep their order. SummaryRanges.addNum is O(log n) and getIntervals is O(k) for k stored ranges.

G. Variations of the Pattern

Total covered length

Merge, then sum end - start (half-open) or end - start + 1 (closed integer points). Use long: a few intervals near 10^9 already overflow int.

Employee Free Time (759)

Flatten, sort by start, keep the maximum end; each time the next start exceeds it you found a gap. With k schedules already sorted, a heap of k pointers gives O(n log k) (see Chapter 62).

Missing Ranges (163)

Treat the array as unit intervals. Track prev = lower - 1; a missing range is [prev + 1, x - 1] whenever x - prev > 1. Use long for prev so lower = Integer.MIN_VALUE does not overflow.

Remove Covered Intervals (1288)

Sort by start ascending and end descending so a covering interval comes first; count intervals whose end exceeds the maximum end so far. (A solution lives in Chapter 64.)

Merge with a label or weight

Carry extra data in the run (a count, a sum, a set of ids) and combine it on every extension. The structure of the loop does not change.

State the invariant: "after sorting by start, the current run's end is the only thing that can overlap the next interval."

Ask whether intervals are closed or half-open and whether touching ones should merge, before writing a comparison.

Mention the max: it is what handles an interval fully contained in the run.

CHAPTER SUMMARY

Sort by start, then keep one run: overlap is transitive along the sorted order, so next.start <= run.end is the whole test.

Extend with max(run.end, next.end): a contained interval must not shrink the run.

Closed vs half-open decides <= vs <; ask first.

Gaps are the complement: the same pass reports free time or missing ranges.

Online streams use a TreeMap of disjoint ranges with four join cases; sorted input needs no sort.
