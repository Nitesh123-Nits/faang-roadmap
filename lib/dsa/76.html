Interval Greedy

Cover, partition and thin out intervals by sorting and sweeping.

A. Pattern Overview

Interval greedy problems sort the intervals once and then make one pass, keeping a single number (the current reach or end) as the only state. They come in three families: cover a range with the fewest intervals, partition a sequence into the most independent pieces, and discard intervals that are redundant. The select the most non-overlapping intervals family (sort by end) has its own chapter, Chapter 65; merging and inserting are in Part X.

KEY IDEA

Greedy covering is the "Jump Game II" in disguise. With reach as the frontier, every interval that starts within reach is a possible next jump; take the one that ends furthest. The same "farthest reach in the current level" argument proves both.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Fewest intervals / clips / taps / segments needed to cover …" a target range.
"Partition into as many parts as possible" where a constraint ties positions together (all occurrences of a letter).
"How many intervals remain after removing those covered by another".
A single sorted sweep with one running boundary is enough: no nested loops, no DP table.
Intervals as clips, taps, sprinklers, ranges, jobs on a line.
ONE-LINE TEST

Range-covering words (cover, at least, entire) usually mean sort by start and extend the furthest reach; selection words (non-overlapping, at most one at a time) mean sort by end (Chapter 65).

Why the greedy is optimal

Let reach be the furthest point covered with c intervals. Any solution with c intervals cannot reach beyond the greedy reach, because every interval it could use starts within the previous reach (otherwise there would be a gap) and the greedy already picked the furthest end among them. By induction the greedy reaches at least as far with every c, so it needs no more intervals than any other solution.

A gap means failure

If no interval starting within reach ends beyond reach, the next point cannot be covered:

return -1. This happens when the sweep finds farthest ≤ reach after consuming all eligible

intervals.

Taps become intervals

Tap i with range r[i] waters [i − r[i], i + r[i]], clipped to [0, n]. Converting every tap to an interval turns Minimum Number of Taps (1326) into the same cover problem. Boundaries matter: clip to avoid negative starts, and remember a tap can cover the endpoints.

Partition labels: intervals defined by letters

For each letter, its occurrences span [first, last]. Positions inside one such span must be in the same part. Sweeping left to right with partEnd = max(last[c]) stretches the current part; when i == partEnd nothing crosses the boundary and we cut.

Removing covered intervals

Sort by start ascending and, for equal starts, by end descending. Then an interval is covered by an earlier one exactly when its end is not larger than the maximum end seen so far (1288). The tie-break matters: for equal starts the longer interval must come first, otherwise the shorter would be kept wrongly.

E. Java Implementation

Interval cover, video stitching, taps, covered intervals, partition labels

IntervalCover.java: LeetCode 1024, 1326, 1288, 763
import java.util.*;

/**
 * Ch 64: greedy interval covering and partitioning; LeetCode 1024, 1326, 1288, 763.
 */
public class IntervalCover {

    /**
     * Fewest intervals whose union covers [from, to]; -1 if impossible. Sweep by
     * start; always extend with the interval that reaches furthest.
     */
    public static int minIntervalsToCover(int[][] intervals, int from, int to) {
        int[][] sorted = intervals.clone();
        Arrays.sort(sorted, Comparator.comparingInt(iv -> iv[0]));
        int count = 0, i = 0, n = sorted.length;
        long reach = from, farthest = from;
        while (reach < to) {
            while (i < n && sorted[i][0] <= reach)
                farthest = Math.max(farthest, sorted[i++][1]);
            // gap: nothing extends the cover

Java 17+

            if (farthest <= reach) return -1;
            reach = farthest;
            count++;
        }
        return count;
    }

    /** LeetCode 1024: video stitching, clips[i] = {start, end}. */
    public static int videoStitching(int[][] clips, int time) {
        return minIntervalsToCover(clips, 0, time);
    }

    /** LeetCode 1326: fewest taps to water [0, n]; tap i covers [i - r, i + r]. */
    public static int minTaps(int n, int[] ranges) {
        int[][] intervals = new int[n + 1][];
        for (int i = 0; i <= n; i++) {
            intervals[i] =
                    new int[] {Math.max(0, i - ranges[i]), Math.min(n,
                            i + ranges[i])};
        }
        return minIntervalsToCover(intervals, 0, n);
    }

    /** LeetCode 1288: number of intervals left after removing covered ones. */
    public static int removeCoveredIntervals(int[][] intervals) {
        int[][] sorted = intervals.clone();
        Arrays.sort(sorted, (a, b) ->
                a[0] != b[0]
                    ? Integer.compare(a[0], b[0])
                    : Integer.compare(b[1], a[1]));
        int kept = 0;
        long maxEnd = Long.MIN_VALUE;
        for (int[] iv : sorted) {
            // not inside an earlier interval
            if (iv[1] > maxEnd) { kept++; maxEnd = iv[1]; }
        }
        return kept;
    }

    /**
     * LeetCode 763: cut s into as many parts as possible, each letter in one part.
     */
    public static List<Integer> partitionLabels(String s) {
        int[] last = new int[26];
        for (int i = 0; i < s.length(); i++) last[s.charAt(i) - 'a'] = i;
        List<Integer> sizes = new ArrayList<>();
        int partStart = 0, partEnd = 0;
        for (int i = 0; i < s.length(); i++) {
            // stretch to cover this letter
            partEnd = Math.max(partEnd, last[s.charAt(i) - 'a']);
            if (i == partEnd) {
                sizes.add(i - partStart + 1);
                partStart = i + 1;
            }
        }
        return sizes;
    }
}

TIME O(n log n)

SPACE O(1) extra

Sort dominates; the sweep is O(n) because the pointer i only advances. partitionLabels is O(n) with a 26-entry last array. reach is a long so extreme coordinates cannot overflow comparisons.

G. Variations of the Pattern

Video Stitching (1024) and Minimum Taps (1326)

Direct applications of minIntervalsToCover. Both are classic "Jump Game II over an interval array" problems.

Remove Covered Intervals (1288)

Sort by (start asc, end desc); count intervals whose end exceeds the running maximum.

Partition Labels (763) and similar boundary sweeps

Partition Array into Disjoint Intervals (915) uses prefix max and suffix min; Max Chunks To Make Sorted (769) uses max == index.

Interval list intersections and merges

Two sorted lists of intervals are intersected with two pointers, advancing the one that ends first (986); merging is Part X.

Weighted and capacity versions

If intervals have costs, covering becomes a shortest-path or DP problem (Part XI); Car Pooling (1094) and Meeting Rooms (Chapter 66) track overlap counts with a sweep line.

J. Interview Tips

INTERVIEW

Say which key you sort by and why in one sentence; picking the wrong key is the usual failure.

Connect to Jump Game II: "each BFS level is one more interval"; it shows you see the pattern behind the problem.

Prove the greedy with "stays ahead": after c picks the greedy reach is at least any other solution's.

Follow-ups: return the chosen intervals (store the argmax); weighted cover (DP or

Dijkstra); several target ranges; online arrival of intervals; circular ranges.

Edge cases: no interval starts at 0, a gap in the middle, one interval covering everything, duplicates, intervals longer than the target, T = 0.

CHAPTER SUMMARY

Interval greedy: sort once, sweep once, keep one boundary (reach, partEnd, maxEnd).

Cover a range: sort by start; among intervals starting within reach, jump to the furthest end; farthest ≤ reach means impossible.

The cover greedy is Jump Game II over intervals; the "stays ahead" argument proves it.

Partition Labels: keep a running max of last occurrences and cut when i == partEnd.

Covered intervals: sort by (start asc, end desc) and count ends above the running maximum.
