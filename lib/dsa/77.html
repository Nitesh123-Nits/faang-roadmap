Activity Selection

Sort by finish time; always take the activity that ends first.

A. Pattern Overview

Given activities with start and end times, choose the largest set that do not overlap. The greedy rule is simple and surprisingly strong: sort by end time and take every activity whose start is at or after the end of the last one taken. It is the textbook greedy algorithm, and its proof (an exchange argument) is the template for most greedy proofs in this book.

KEY IDEA

Earliest finish first leaves the maximum room for the rest. Sorting by start, by duration, or by fewest conflicts all have counter-examples; only the finish time works.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Maximum number of non-overlapping intervals / meetings / activities."
"Minimum number to remove so the rest do not overlap."
"Minimum number of points / arrows / cameras that touch every interval."
One resource used by one item at a time (a room, a CPU, a person).
Items are equally valuable (count, not weight). Weights point to DP.
ONE-LINE TEST

Equal-value intervals on one resource and a count to maximise: sort by end. If values differ, use DP with binary search (Part XI).

Exchange argument

Let g be the activity with the earliest finish time. Take any optimal solution S; let a be its first activity. Since g finishes no later than a, replacing a with g keeps S valid (nothing else in S starts before a ends, hence not before g ends) and the same size. So some optimal solution contains g. Remove g and every activity overlapping it, and the rest is the same problem on a smaller instance: induction finishes the proof.

Arrows: the same algorithm in disguise

Minimum Number of Arrows (452) asks for the fewest points that pierce every interval. Sorted by end, shoot at the end of the first balloon; that arrow also bursts every balloon starting at or before it. The next unburst balloon needs a new arrow. The count of arrows equals the maximum number of pairwise disjoint balloons: a classic min-max duality.

Events by day: earliest deadline first

In Maximum Events (1353) you may attend one event per day anywhere within its range. Sweep days; push end days of all events starting today into a min-heap; discard expired ones; attend the event with the earliest end. It is the heap form of "deadline first".

Weights break the greedy

With profits (1235) the greedy fails. Jobs [0,2) → 1, [1,10) → 100, [3,5) → 1: sorted by end

the greedy takes the two small jobs for total 2, but the single long job is worth 100. The correct method is DP: best[i] = max(best[i−1], best[p(i)] + profit[i]), where p(i) is the number of jobs ending at or before start[i], found by binary search.

import java.util.*;

/**
 * Ch 65: activity selection (sort by finish time); LeetCode 435, 452, 1353, 1235.
 */
public class ActivitySelection {

    /**
     * Indices of a maximum set of pairwise compatible activities (touching is OK).
     */
    public static List<Integer> select(int[] start, int[] end) {

Java 17+

        int n = start.length;
        Integer[] order = new Integer[n];
        for (int i = 0; i < n; i++) order[i] = i;
        // earliest finish first
        Arrays.sort(order, Comparator.comparingInt(i -> end[i]));
        List<Integer> chosen = new ArrayList<>();
        int lastEnd = Integer.MIN_VALUE;
        for (int i : order) {
            if (start[i] >= lastEnd) {
                chosen.add(i);
                lastEnd = end[i];
            }
        }
        return chosen;
    }

    /** LeetCode 435: fewest intervals to remove so the rest do not overlap. */
    public static int eraseOverlapIntervals(int[][] intervals) {
        int[][] sorted = intervals.clone();
        Arrays.sort(sorted, Comparator.comparingInt(iv -> iv[1]));
        int kept = 0;
        long lastEnd = Long.MIN_VALUE;
        for (int[] iv : sorted) {
            if (iv[0] >= lastEnd) { kept++; lastEnd = iv[1]; }
        }
        return intervals.length - kept;
    }

    /**
     * LeetCode 452: fewest arrows to burst every balloon; touching balloons share
     * one.
     */
    public static int findMinArrowShots(int[][] points) {
        if (points.length == 0) return 0;
        int[][] sorted = points.clone();
        // compare, never subtract
        Arrays.sort(sorted, (a, b) -> Integer.compare(a[1], b[1]));
        int arrows = 1;
        // shoot at the earliest right end
        long arrowAt = sorted[0][1];
        for (int[] p : sorted) {
            if (p[0] > arrowAt) { arrows++; arrowAt = p[1]; }
        }
        return arrows;
    }

    /**
     * LeetCode 1353: attend at most one event per day; events[i] = {first, last}.
     */
    public static int maxEvents(int[][] events) {
        int[][] sorted = events.clone();
        Arrays.sort(sorted, Comparator.comparingInt(e -> e[0]));
        // last days of open events
        PriorityQueue<Integer> open = new PriorityQueue<>();
        int attended = 0, i = 0, n = sorted.length;
        int day = 0;
        while (i < n || !open.isEmpty()) {
            // jump over idle days
            if (open.isEmpty()) day = sorted[i][0];
            while (i < n && sorted[i][0] <= day) open.offer(sorted[i++][1]);
            while (!open.isEmpty() && open.peek() < day) open.poll();   // expired
            if (!open.isEmpty()) { open.poll(); attended++; day++; }
        }
        return attended;
    }

    /** LeetCode 1235: weighted version. Greedy fails; use DP + binary search. */
    public static int maxProfitJobScheduling(int[] start, int[] end, int[] profit) {
        int n = start.length;
        Integer[] order = new Integer[n];
        for (int i = 0; i < n; i++) order[i] = i;
        Arrays.sort(order, Comparator.comparingInt(i -> end[i]));
        int[] ends = new int[n];
        // best[i] = best profit using first i jobs
        int[] best = new int[n + 1];
        for (int i = 0; i < n; i++) ends[i] = end[order[i]];
        for (int i = 0; i < n; i++) {
            int job = order[i];
            // jobs among the first i ending <= start
            int p = upperBound(ends, i, start[job]);
            best[i + 1] = Math.max(best[i], best[p] + profit[job]);
        }
        return best[n];
    }

    /** Number of entries in ends[0..hi) that are <= x. */
    private static int upperBound(int[] ends, int hi, int x) {
        int lo = 0;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (ends[mid] <= x) lo = mid + 1; else hi = mid;
        }
        return lo;
    }
}

TIME O(n log n)

SPACE O(n)

One sort plus a linear scan. Comparators use Integer.compare; never a[1] - b[1], which overflows for large coordinates (452 has a test with ±2³¹ endpoints). maxProfitJobScheduling adds a binary search per job.

G. Variations of the Pattern

Non-overlapping Intervals (435)

Answer n − maxCompatible. Touching intervals ([1,2], [2,3]) do not overlap.

Minimum Number of Arrows (452)

Here touching balloons do share an arrow (start ≤ arrowAt). Mind the closed vs half-open convention.

Maximum Events (1353)

Day-by-day sweep with a min-heap of end days; jump day when the heap is empty to avoid iterating over empty days.

Weighted Job Scheduling (1235)

Sort by end, best[i + 1] = max(best[i], best[p] + profit), with p from binary search (upperBound on end times). O(n log n).

Interval scheduling with k machines

Maximum compatible set on k identical machines is solved by sorting by end and assigning each activity to the machine whose last end is the largest value ≤ start (a TreeMap); with all machines the question becomes Meeting Rooms II (Chapter 66).

J. Interview Tips

INTERVIEW

Give the exchange argument in two sentences; it is the expected proof and it generalises.

Mention the wrong keys and one counter-example (earliest start, shortest duration).

Clarify touching endpoints at the start: closed vs half-open decides > vs >= and separates 435 from 452.

Follow-ups: return the chosen activities; k machines; weighted version (DP); online arrival; minimum number of activities to remove for a given conflict budget.
Edge cases: identical intervals, zero-length intervals, nested intervals, all overlapping,

CHAPTER SUMMARY

Activity selection: sort by end time and take every activity that starts at or after the last chosen end: O(n log n).

Exchange argument: the earliest-finishing activity can replace the first activity of any optimal solution, so some optimal solution contains it.

Arrows (452), erase overlaps (435), pair chains (646) and events (1353) are the same idea; touching endpoints decide > vs >=.

Weights break the greedy: use DP with binary search over end times.

Use Integer.compare, clone before sorting, and jump over idle days in the events variant.
