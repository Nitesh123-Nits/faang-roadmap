Sweep Line Algorithm

Turn intervals into +1 / -1 events and sweep left to right.

A. Pattern Overview

The sweep line replaces a messy picture of overlapping intervals with an ordered list of events: every interval contributes a start event and an end event. Sort the events by coordinate, walk through them once, and maintain a small piece of state (a counter, a sum, a multiset). Whatever you need to know about "the moment right now" is available at each event. Cost: O(n log n) for the sort, O(n) for the walk.

Events in a TreeMap, running sum
TreeMap<Integer, Integer> delta = new TreeMap<>();
for (int[] iv : intervals) {
    delta.merge(iv[0], +1, Integer::sum);          // start event
    delta.merge(iv[1], -1, Integer::sum);          // end event
}
int live = 0, peak = 0;
for (int d : delta.values()) { live += d; peak = Math.max(peak, live); }

KEY IDEA

Only the endpoints matter. Between two consecutive event coordinates nothing changes, so the sweep needs to look at 2n positions, not at every point of the number line.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Maximum number of overlapping / concurrent …": guests, trains at a station, bookings, active users.
"Which year / time has the most …".
A quantity that changes only at interval boundaries (total weight, active count, current maximum).
Coordinates are huge or sparse, which rules out a difference array over the whole range.
"Describe the result as disjoint pieces" after overlaying weighted segments (1943).
ONE-LINE TEST

A property of 'the intervals live right now': emit + at starts and - at ends, sort, sweep.

Tie-breaking at equal coordinates

This is where sweep-line solutions go wrong. The rule depends on the interval type:

Interval typeAt equal times process…Because
Half-open [a, b)ends first[1,2) and [2,3) do not overlap

Peak overlap without events: two sorted arrays

The events do not need to be objects. Sort starts and ends separately; for each start, retire every end that happens first (ends[e] <= start for half-open, < start for closed), then count the new interval. This is the peakOverlap method in the listing and needs two int[] only.

Weighted sweep: describing a painting (1943)

Segments [1,4) colour 5, [4,7) colour 7, [1,7) colour 9. Add the colour at the start and subtract it at the end; between two consecutive event coordinates the running sum identifies the mixture (colours are distinct, so the sum is unique in the problem's setting).

Result: [1,4) -> 14 and [4,7) -> 16. Pieces with sum 0 (unpainted gaps) are skipped.

Bounded coordinates: a difference array

If the coordinate range is small (say a few thousand), a difference array replaces sorting: diff[start]++, diff[end]--, one prefix sum. That is Part I's Difference Array chapter; the sweep line is the same idea when coordinates are too large to index directly.

E. Java Implementation

Peak overlap, platforms, maximum population, splitting a painting

SweepLine.java: LeetCode 1854, 1943 and the platform problem

import java.util.*;

/** Ch 74: sweep line; LeetCode 1854, 1943 and the platform / overlap family. */
public class SweepLine {

    /**
     * Peak number of simultaneously live intervals. With closed intervals
     * touching endpoints overlap (starts before ends on ties); with half-open
     * intervals they do not (ends before starts).
     */
    public static int peakOverlap(int[][] intervals, boolean closed) {
        int n = intervals.length;
        int[] starts = new int[n], ends = new int[n];
        for (int i = 0; i < n; i++) {
            starts[i] = intervals[i][0];
            ends[i] = intervals[i][1];
        }
        Arrays.sort(starts);
        Arrays.sort(ends);
        int live = 0, best = 0, e = 0;
        for (int s = 0; s < n; s++) {
            while (e < n && (closed ? ends[e] < starts[s] : ends[e] <= starts[s])) {
                e++;
                live--;
            }
            live++;
            best = Math.max(best, live);
        }
        return best;
    }

    /** Minimum platforms: a train occupies [arrival, departure] inclusive. */
    public static int minPlatforms(int[] arrival, int[] departure) {
        int[][] iv = new int[arrival.length][];
        for (int i = 0; i < iv.length; i++)
            iv[i] = new int[]{arrival[i], departure[i]};
        return peakOverlap(iv, true);
    }

    /**
     * LeetCode 1854: earliest year with the most people alive; a person is
     * alive in [birth, death). Events in a TreeMap, running sum.
     */
    public static int maximumPopulation(int[][] logs) {
        TreeMap<Integer, Integer> delta = new TreeMap<>();
        for (int[] l : logs) {
            delta.merge(l[0], 1, Integer::sum);
            delta.merge(l[1], -1, Integer::sum);
        }
        int live = 0, best = 0, year = 0;

Java 17+

        for (Map.Entry<Integer, Integer> e : delta.entrySet()) {
            live += e.getValue();
            if (live > best) { best = live; year = e.getKey(); }
        }
        return year;
    }

    /**
     * LeetCode 1943: describe a painting. segments[i] = {start, end, colour}
     * with distinct colours; the result lists {start, end, sumOfColours} for
     * every maximal piece that is painted.
     */
    public static List<List<Long>> splitPainting(int[][] segments) {
        TreeMap<Integer, Long> delta = new TreeMap<>();
        for (int[] s : segments) {
            delta.merge(s[0], (long) s[2], Long::sum);
            delta.merge(s[1], (long) -s[2], Long::sum);
        }
        List<List<Long>> out = new ArrayList<>();
        long sum = 0;
        int prev = 0;
        for (Map.Entry<Integer, Long> e : delta.entrySet()) {
            if (sum > 0) out.add(List.of((long) prev, (long) e.getKey(), sum));
            sum += e.getValue();
            prev = e.getKey();
        }
        return out;
    }
}

TIME O(n log n)

SPACE O(n)

Sorting dominates. maximumPopulation and splitPainting use a TreeMap of deltas, which sorts as it inserts (O(log n) per event). peakOverlap uses two sorted int[].

F. Detailed Dry Run

maximumPopulation([[1993,1999],[2000,2010]]): deltas 1993:+1, 1999:-1, 2000:+1,

2010:-1. Sweep: after 1993, live 1, best 1 at 1993; after 1999 live 0; after 2000 live 1 which is not greater than best, so the answer stays 1993 (earliest year wins).

splitPainting from the table: events at 1 (+14), 4 (-5 + 7 = +2), 7 (-7 - 9 = -16). At 1: sum 0, nothing emitted; sum becomes 14. At 4: sum 14 > 0, emit [1,4) 14; sum becomes 16. At 7: emit [4,7) 16; sum becomes 0.

G. Variations of the Pattern

Meeting Rooms II / Minimum Platforms

Peak overlap. Closed intervals (a train that departs at t still occupies the platform at t) put starts first on ties.

Maximum Population Year (1854)

Alive in [birth, death). Report the earliest year at the peak: update the answer only on a strictly greater count.

Describe the Painting (1943)

Weighted sweep with long sums (colours reach 10^9, sums of many colours overflow int).

Car Pooling (1094) and Corporate Flight Bookings (1109)

Weights +passengers / -passengers; with small coordinates the difference array is simplest (Part I).

Interval Graph Colouring

The minimum number of colours (rooms, machines) for overlapping intervals equals the peak overlap. Assigning actual colours needs a heap of free ids on top of the sweep.

J. Interview Tips

INTERVIEW

Say the transformation out loud: "each interval becomes two events; I sort them and keep a counter." It signals the pattern immediately.

State the tie-break and justify it with a touching example before writing the comparator.

Offer the alternatives: difference array for small ranges, heap of ends when you need room ids.

Follow-ups: return the time window of the peak; weights instead of counts; online (insertions arrive one by one: a TreeMap of deltas, Chapter 77); 2D (Chapter 75).
Edge cases: identical intervals, touching intervals, zero-length intervals, empty input,

huge coordinates, negative coordinates.

CHAPTER SUMMARY

Sweep line: convert intervals into 2n events, sort, walk once, and maintain state (counter, sum, multiset, coverage).

Tie-breaking is the bug magnet: half-open intervals process ends first, closed intervals process starts first.

Peak overlap needs only two sorted int[] (starts and ends); weights turn the events into +w / -w.

Update the answer with a strict comparison when asked for the earliest moment; use long for weighted sums.

When coordinates are small a difference array is simpler; when they are huge or sparse, sweep over events.
