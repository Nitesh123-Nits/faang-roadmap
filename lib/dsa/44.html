Combination Sum

Reuse allowed or not: target-driven search with sorted pruning.

A. Pattern Overview

Combination Sum problems ask for all multisets (or sequences) of numbers drawn from a list that add up to a target. Three variants differ only in two choices, reuse and duplicates in the input:

KEY IDEA

Sort the candidates once, then prune with break. After sorting, if c[i] > remain then every later candidate is also too large, so the loop ends (not continue). This is the single most effective optimisation in the whole family.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Return all unique combinations that sum to target".
"The same number may be chosen an unlimited number of times": recurse with the

same index.

"Each number may be used once" + duplicates in the input: i + 1 plus the same-level skip.
"Number of possible combinations" where [1, 2] and [2, 1] count separately:

Combination Sum IV, a DP on the remaining sum.

ONE-LINE TEST

Target sum + list all: backtracking over sorted candidates with remain. Target sum + count or exists: DP (coin change, subset sum), and the backtracking is the exponential baseline.

C. Core Intuition with Illustrations

Reuse means the index does not advance

For candidates [2, 3, 6, 7] and target 7: we choose a candidate, subtract it from remain, and recurse starting at the same index, so the same value can be chosen again. Starting at i (never below) keeps combinations in non-decreasing order, so [2, 2, 3] appears once and [2, 3, 2] never.

Figure 70. Each node shows the path and the remaining sum r. The two answers are [2, 2, 3] and [7].

Termination: why it cannot loop forever

Candidates are positive, so each choice strictly decreases remain; the depth is at most target / min(candidates). With a zero or a negative candidate the recursion would never end: the problem statements rule it out, and an interviewer may ask.

Each element once, with duplicates in the input

For [10, 1, 2, 7, 6, 1, 5] and target 8, sort to [1, 1, 2, 5, 6, 7, 10]. The same-level skip rule prevents choosing the second 1 as the first element again; the pair 1, 1 is still allowed on one path.

E. Java Implementation

Combination Sum (reuse allowed)

CombinationSum.java: LeetCode 39

Java 17+

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

/**
 * LeetCode 39 - Combination Sum: candidates are distinct and each may be reused any number of
 * times.
 */
public class CombinationSum {
    public static List<List<Integer>> combinationSum(int[] candidates, int target) {
        int[] c = candidates.clone();
        Arrays.sort(c);
        List<List<Integer>> out = new ArrayList<>();
        build(c, 0, target, new ArrayList<>(), out);
        return out;
    }

    private static void build(int[] c, int start, int remain, List<Integer> cur,
            List<List<Integer>> out) {
        if (remain == 0) { out.add(new ArrayList<>(cur)); return; }
        for (int i = start; i < c.length; i++) {
            // sorted: every later candidate is too large as well
            if (c[i] > remain) break;
            cur.add(c[i]);
            // i, not i + 1: the same value may be chosen again
            build(c, i, remain - c[i], cur, out);
            cur.remove(cur.size() - 1);
        }
    }
}
TIME O(N^(T/M))
SPACE O(T/M)

N candidates, target T, minimum candidate M. The depth is T/M. Passing i to the recursive call is the reuse; passing i + 1 would be Combination Sum II.

Combination Sum II (each element once)

CombinationSumII.java: LeetCode 40

Java 17+

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

/**
 * LeetCode 40 - Combination Sum II: candidates may repeat in the input, but each element is
 * used at most once.
 */
public class CombinationSumII {
    public static List<List<Integer>> combinationSum2(int[] candidates,
            int target) {
        int[] c = candidates.clone();
        Arrays.sort(c);
        List<List<Integer>> out = new ArrayList<>();
        build(c, 0, target, new ArrayList<>(), out);
        return out;
    }

    private static void build(int[] c, int start, int remain, List<Integer> cur,
            List<List<Integer>> out) {
        if (remain == 0) { out.add(new ArrayList<>(cur)); return; }
        for (int i = start; i < c.length; i++) {
            if (c[i] > remain) break;
            // skip a value already tried at this depth
            if (i > start && c[i] == c[i - 1]) continue;
            cur.add(c[i]);
            build(c, i + 1, remain - c[i], cur, out);     // i + 1: each element at most once
            cur.remove(cur.size() - 1);
        }
    }
}

TIME O(2ⁿ)

SPACE O(n)

At most 2ⁿ subsets. The skip test i > start removes duplicates at the same depth only.

Combination Sum IV (ordered sequences, memoised)

CombinationSumIV.java: LeetCode 377
import java.util.Arrays;

/**
 * LeetCode 377 - Combination Sum IV: count ordered sequences. Pure backtracking is
 * exponential; memoising on `remain` is the bridge to DP.
 */
public class CombinationSumIV {
    public static int combinationSum4(int[] nums, int target) {
        int[] memo = new int[target + 1];
        Arrays.fill(memo, -1);
        return count(nums, target, memo);
    }

    private static int count(int[] nums, int remain, int[] memo) {
        if (remain == 0) return 1;
        if (memo[remain] != -1) return memo[remain];
        int total = 0;
        for (int x : nums) if (x <= remain) total += count(nums, remain - x, memo);
        return memo[remain] = total;
    }

    /** Plain backtracking, kept as a test oracle for small inputs. */
    public static int bruteForce(int[] nums, int remain) {
        if (remain == 0) return 1;
        int total = 0;
        for (int x : nums) if (x <= remain) total += bruteForce(nums, remain - x);
        return total;
    }
}

Java 17+

TIME O(T · N)
SPACE O(T)

-1 marks an uncomputed state because 0 is a legitimate count. bruteForce (exponential) is the oracle used in the tests.

G. Variations of the Pattern

Target Sum and subset sum (counting)

Target Sum (494) assigns + or − to each number: a subset-sum count in disguise. Backtracking

is O(2ⁿ); DP is O(n · S).

Coin Change variants

Coin Change (322, minimum coins), Coin Change II (518, unordered ways) and Combination Sum IV (377, ordered ways) share the recurrence over the remaining amount; they differ in loop order and in what is counted.

Combination Sum with a size limit

Add k and stop when the size is reached: Combination Sum III. Add a budget limit and prune on the remaining sum.

Closest or maximum sum

Track the best sum so far and prune when even the largest completion cannot beat it (branch and bound): Closest Subsequence Sum (1755).

Find all pairs / triplets summing to target

For fixed small size prefer sort + two pointers (Chapter 1) over enumeration: O(n²) instead of exponential.

J. Interview Tips

INTERVIEW

Start by asking the two questions: can an element be reused? can the input contain duplicates? The answers pick the start index and the skip rule.

Sort first and say why: it enables the break, and it makes the same-level duplicate test valid.

Call out the DP escape hatch: "if they only want a count, this becomes DP over the remaining sum."

CHAPTER SUMMARY

Sort the candidates, carry remain, and break as soon as c[i] > remain.

Reuse allowed → recurse with i; each element once → i + 1.

Duplicates in the input (once each): if (i > start && c[i] == c[i−1]) continue.

Counting sequences (order matters) or just how many is DP: memoise on remain, with -1 meaning unknown.

Positive candidates guarantee termination; listing answers is exponential in the worst case.
