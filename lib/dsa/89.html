Offline Interval Queries

Sort the queries too: answer them in one sweep, then restore order.

A. Pattern Overview

Many interval problems ask a question about a point for many points: how many flowers bloom at time t?, what is the smallest interval containing q?, which room is closest to my preference? Answering each query from scratch costs O(n). The offline trick: because all queries are known in advance, sort them (remembering their original indices), sweep once over intervals and queries together, and keep just enough state to answer each query as the sweep reaches it. Then write each answer back at its original index. Typical cost: O((n + q) log (n + q)).

KEY IDEA

Offline means order is yours to choose. Sort the queries so the set of relevant intervals only grows (or only shrinks); then incremental structures replace per-query scans.

B. When to Recognize This Pattern

Pattern Recognition Signals

"For each query, find …" with up to 10^5 intervals and 10^5 queries.
Queries are given all at once (an array), not one by one.
The answer for a query depends on intervals that contain or precede a point.
Constraints that make O(nq) impossible but allow O(n log n).
A natural monotonic order exists (by value, by threshold), so the relevant set grows or

shrinks.

ONE-LINE TEST

Many point queries over fixed intervals: sort both, sweep once, store each answer at its original index.

C. Core Intuition with Illustrations

Counting with two sorted arrays (2251)

A flower blooming over the closed interval [s, e] is in bloom at t iff s <= t <= e. Count flowers that started by t (s <= t) minus those that ended before t (e < t). Those that ended before t have also started before t, so the difference is exactly the in-bloom count. Two sorted arrays and two binary searches per query.

Smallest interval containing a point (1851)

Intervals [1,4] [2,4] [3,6] [4,4], queries [2,3,4,5]. Sort queries ascending. For each query, push every interval that has started (start <= q) into a min-heap ordered by size; pop heap tops that already ended (end < q); the top is the answer. Expired intervals are removed lazily: they only matter when they reach the top.

Why sorting the queries makes the heap valid

With queries ascending, an interval that has ended before the current query has ended before every later query too: dropping it is permanent. And an interval that has started stays started. The heap therefore only needs to support add and remove-top-if-expired, never arbitrary deletion.

Closest room (1847): sort by the threshold, descending

Each query wants a room with size >= minSize whose id is closest to the preference. If we process queries by decreasing minSize, the set of eligible rooms only grows: add rooms into a TreeSet<id> as the threshold drops, then answer with floor(pref) and ceiling(pref), choosing the closer (ties: the smaller id).

Prefix maximum plus binary search (2070)

For maximum beauty among items priced <= q, sort items by price, build a prefix maximum of beauties, and binary-search the last price <= q. The prefix maximum plays the role of the heap: a running summary of everything that has started.

import java.util.*;

/** Ch 76: offline queries over intervals; LeetCode 2251, 1851, 1847, 2070. */
public class OfflineQueries {

    /**
     * LeetCode 2251: for each time t, how many closed flower intervals
     * [s, e] contain t? Count(starts <= t) - count(ends < t).
     */
    public static int[] fullBloomFlowers(int[][] flowers, int[] people) {
        int n = flowers.length;
        int[] starts = new int[n], ends = new int[n];
        for (int i = 0; i < n; i++)
            { starts[i] = flowers[i][0]; ends[i] = flowers[i][1]; }
        Arrays.sort(starts);
        Arrays.sort(ends);
        int[] ans = new int[people.length];
        for (int i = 0; i < people.length; i++)
            ans[i] = upperBound(starts, people[i]) - lowerBound(ends, people[i]);
        return ans;
    }

    // first index with a[i] >= x
    private static int lowerBound(int[] a, int x) {
        int lo = 0, hi = a.length;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] >= x) hi = mid; else lo = mid + 1;
        }
        return lo;
    }

    // first index with a[i] > x
    private static int upperBound(int[] a, int x) {
        int lo = 0, hi = a.length;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;

    /**
     * LeetCode 1851: for each query q, the size (end - start + 1) of the
     * smallest closed interval containing q, or -1. Sweep queries in
     * increasing order; a min-heap keyed by size drops expired intervals lazily.
     */
    public static int[] minInterval(int[][] intervals, int[] queries) {
        int[][] sorted = intervals.clone();
        Arrays.sort(sorted, Comparator.comparingInt(iv -> iv[0]));
        Integer[] order = new Integer[queries.length];
        for (int i = 0; i < order.length; i++) order[i] = i;
        Arrays.sort(order, Comparator.comparingInt(i -> queries[i]));
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) ->
                a[0] != b[0]
                    ? Integer.compare(a[0], b[0])
                    : Integer.compare(a[1], b[1]));
        int[] ans = new int[queries.length];
        int next = 0;
        for (int qi : order) {
            int q = queries[qi];
            while (next < sorted.length && sorted[next][0] <= q) {
                int[] iv = sorted[next++];
                heap.offer(new int[]{iv[1] - iv[0] + 1, iv[1]});
            }
            while (!heap.isEmpty() && heap.peek()[1] < q) heap.poll();   // expired
            ans[qi] = heap.isEmpty() ? -1 : heap.peek()[0];
        }
        return ans;
    }

    /**
     * LeetCode 1847: rooms {id, size}; each query {preferred, minSize} wants
     * the room with size >= minSize whose id is closest to preferred (ties:
     * smaller id), or -1. Process queries by decreasing minSize and keep a
     * TreeSet of the ids of all rooms that are big enough.
     */
    public static int[] closestRoom(int[][] rooms, int[][] queries) {
        int[][] byRoomSize = rooms.clone();
        Arrays.sort(byRoomSize, (a, b) -> Integer.compare(b[1], a[1]));
        Integer[] order = new Integer[queries.length];
        for (int i = 0; i < order.length; i++) order[i] = i;
        Arrays.sort(order, (a, b) -> Integer.compare(queries[b][1], queries[a][1]));
        TreeSet<Integer> ids = new TreeSet<>();
        int[] ans = new int[queries.length];
        int next = 0;
        for (int qi : order) {
            int pref = queries[qi][0], need = queries[qi][1];
            while (next < byRoomSize.length && byRoomSize[next][1] >= need)
                ids.add(byRoomSize[next++][0]);
            Integer lo = ids.floor(pref), hi = ids.ceiling(pref);
            if (lo == null && hi == null) ans[qi] = -1;
            else if (lo == null) ans[qi] = hi;
            else if (hi == null) ans[qi] = lo;
            else ans[qi] = pref - lo <= hi - pref ? lo : hi;
        }
        return ans;
    }

    /**
     * LeetCode 2070: items {price, beauty}; for each query price, the maximum
     * beauty among items priced <= query, or 0. Sort by price, prefix maximum,
     * binary search.
     */
    public static int[] maximumBeauty(int[][] items, int[] queries) {
        int[][] sorted = items.clone();
        Arrays.sort(sorted, Comparator.comparingInt(it -> it[0]));
        int n = sorted.length;
        int[] prices = new int[n], best = new int[n];
        for (int i = 0; i < n; i++) {
            prices[i] = sorted[i][0];
            best[i] = Math.max(sorted[i][1], i > 0 ? best[i - 1] : 0);
        }
        int[] ans = new int[queries.length];
        for (int i = 0; i < queries.length; i++) {
            int idx = upperBound(prices, queries[i]) - 1;
            ans[i] = idx < 0 ? 0 : best[idx];
        }
        return ans;
    }
}

TIME O((n + q) log (n + q))

SPACE O(n + q)

Sorting intervals, queries and the auxiliary heap or set dominate. Each interval enters the heap once and leaves at most once. Answers are written to ans[originalIndex], so the order of the output matches the input.

closestRoom with rooms {id, size} = {2,2} {1,2} {3,2} and query {3, 1}: all rooms qualify, ids {1,2,3}, floor(3) = 3, ceiling(3) = 3, answer 3. For query {3, 2} the same; with a room {5, 1} it would be excluded because 1 < 2.

G. Variations of the Pattern

Number of Flowers in Full Bloom (2251)

Two sorted arrays, upperBound(starts, t) - lowerBound(ends, t). No sort of queries needed because each query is independent after the two sorts.

Minimum Interval to Include Each Query (1851)

Sorted queries plus a size-keyed min-heap with lazy expiry. The heap stores (size, end) so expiry is a peek.

Closest Room (1847)

Sort queries by minSize descending, rooms by size descending; two-pointer insertion into a TreeSet; floor/ceiling.

Two Best Non-Overlapping Events (2054)

Sort by start; keep a running best value among events that have already ended by each event's start (a heap by end time, or a sorted array with prefix max and binary search).

Maximum Number of Events That Can Be Attended (1353)

Sweep days; add events starting today to a min-heap by end day; drop expired ones; attend the soonest-ending (Chapter 65).

J. Interview Tips

INTERVIEW

Name the technique: "offline processing: I sort the queries so the candidate set only grows or only shrinks."

Explain the lazy expiry in one sentence: an expired interval cannot help any later query, so it is safe to drop it when it surfaces.

Say how you keep the output order: sort indices, not values.

Follow-ups: queries arrive online (segment tree or persistent structure); count instead of min; weighted intervals; 2D points.
Edge cases: no intervals, queries outside every interval, duplicate queries, an interval of

length 0, touching intervals at a query point.

CHAPTER SUMMARY

Offline processing: when all queries are known, sort them (by index array) and sweep once; write answers back to their original positions.

Counting containment: #starts <= t minus #ends < t with two sorted arrays and binary search.

Best interval for a point: sorted queries, a min-heap keyed by the criterion, and lazy removal of expired tops.

Threshold queries: sort so the eligible set only grows (rooms by size descending) and use an ordered set for closest-match lookups.

Closed intervals: expired means end < q, not <=; this is the usual off-by-one.
