Binary Search in 2D Matrices

Flatten it when it is one sorted list; walk the staircase when only rows and columns are sorted.

A. Pattern Overview

Two matrix shapes look alike but need different algorithms. The fully ordered matrix (each row sorted, and each row starts after the previous row ends) is one sorted array in disguise: binary search the virtual index 0 … rows·cols − 1. The row-and-column-sorted matrix (rows ascend left to right, columns ascend top to bottom, but rows overlap) has no single order, so use the staircase walk from a corner that gives an unambiguous decision at every step.

B. When to Recognize This Pattern

Pattern Recognition Signals

A matrix described as "sorted": read the exact sentence. "First integer of each row is greater than the last integer of the previous row" means flatten.
"Each row sorted left to right and each column sorted top to bottom" means staircase

(flattening would be wrong).

Constraints suggest O(log(mn)) or O(m + n), not O(mn).
"Kth smallest in a sorted matrix" with memory limits that forbid copying everything: value-range binary search.
MOST COMMON TRAP

Do not flatten a matrix whose rows overlap ([[1,4,7],[2,5,8]]). Index order is not value order, so the monotone predicate does not exist.

C. Core Intuition with Illustrations

Flatten: with cols columns, virtual index k maps to row k / cols and column k % cols. Searching 16 in the fully ordered matrix probes virtual indices 5, 8, 6 and finds it at index 6 = (1, 2).

Figure 29. Probes (1,1) → (2,0) → (1,2): three comparisons for 12 virtual positions.

Staircase: start at the top-right corner. It is the largest value in its row and the smallest in its column, so comparing it with the target eliminates a whole row or a whole column.

Figure 30. The walk visits at most m + n − 1 cells.

INTUITION

Why the corner? From the top-right, the two moves are unambiguous: left decreases the value, down increases it. From the top-left both moves increase the value, so no decision is possible.

D. Brute Force to Optimal Solution

Example: Search a 2D Matrix II (LeetCode 240)

Brute force: scan all m·n cells: O(mn).
Row-wise binary search: binary search each row: O(m log n). Better, but ignores the column order.
Skip impossible rows: only search rows where row[0] <= t <= row[n-1]. Still O(m log
worst case.
Optimal: staircase from a corner, discarding a row or column per step: O(m + n). (A divide-and-conquer binary search also exists, O(m log n) or better, but is harder to write.)

For the fully ordered matrix (LC 74) the improvement goes further: one binary search over m·n elements is O(log(mn)) = O(log m + log n), which beats the staircase.

E. Java Implementation

Fully ordered matrix: flattened binary search

SearchMatrix.java — LeetCode 74

Java 17+

/**
 * LeetCode 74 - Search a 2D Matrix. Rows sorted and each row starts above the previous row's
 * end.
 */
public class SearchMatrix {

    public static boolean searchMatrix(int[][] matrix, int target) {
        int rows = matrix.length;
        int cols = matrix[0].length;
        int lo = 0;
        int hi = rows * cols - 1;                       // treat the matrix as one sorted array
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            int value = matrix[mid / cols][mid % cols];  // 1D index -> (row, col)
            if (value == target) {
                return true;
            } else if (value < target) {
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return false;
    }
}

TIME O(log(m·n))

SPACE O(1)

Compute rows * cols - 1 once; for very large matrices use long indices if rows * cols can exceed 2³¹.

Row-and-column-sorted matrix: staircase

SearchMatrixII.java — LeetCode 240

Java 17+

/**
 * LeetCode 240 - Search a 2D Matrix II. Rows and columns sorted: staircase walk from the
 * top-right.
 */
public class SearchMatrixII {

    public static boolean searchMatrix(int[][] matrix, int target) {
        int row = 0;
        int col = matrix[0].length - 1;
        while (row < matrix.length && col >= 0) {
            int value = matrix[row][col];
            if (value == target) {
                return true;
            } else if (value > target) {
                col--;                  // everything below value in this column is even larger
            } else {
                row++;                  // everything left of value in this row is even smaller
            }
        }
        return false;
    }
}

TIME O(m + n)

SPACE O(1)

Top-right start. Bottom-left works symmetrically; top-left and bottom-right do not.

G. Variations of the Pattern

Kth smallest element in a sorted matrix

Combine both ideas: binary search the value x between matrix[0][0] and matrix[n-1][n-1];

the predicate count(≤ x) ≥ k is monotone, and count is a staircase walk. The answer is the

first x that satisfies it, and it is always a real matrix value.

KthSmallestMatrix.java — LeetCode 378

Java 17+

/**
 * LeetCode 378 - Kth Smallest Element in a Sorted Matrix. Binary search on the VALUE range.
 */
public class KthSmallestMatrix {

    public static int kthSmallest(int[][] matrix, int k) {
        int n = matrix.length;
        int lo = matrix[0][0];
        int hi = matrix[n - 1][n - 1];
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (countAtMost(matrix, mid) >= k) {
                hi = mid;               // at least k values are <= mid: the answer is <= mid
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    /** Number of entries <= x using the staircase from the bottom-left corner. O(n). */
    private static int countAtMost(int[][] matrix, int x) {
        int n = matrix.length;
        int row = n - 1;
        int col = 0;
        int count = 0;
        while (row >= 0 && col < n) {
            if (matrix[row][col] <= x) {
                count += row + 1;       // whole column segment above (and including) this cell
                col++;
            } else {
                row--;
            }
        }
        return count;
    }
}

TIME O(n · log(max − min))

SPACE O(1)

A min-heap alternative is O(k log n); value-range search wins when k is large and needs no extra memory.

Row-wise binary search with early rejection

If only rows are sorted (for example, "each row sorted" with unsorted columns), binary search each row independently: O(m log n). Rows can be skipped when the target lies outside [row[0], row[n−1]].

Count negatives / count ≤ x

The same staircase counts entries ≤ x (or negatives in a matrix sorted in both directions) in O(m + n): the building block of every "kth in a matrix" problem.

Median of a row-wise sorted matrix

Binary search the value; count ≤ x per row with upperBound (O(m log n)); the median is the smallest x with count ≥ (m·n + 1) / 2.

J. Interview Tips

INTERVIEW

Ask for the exact ordering rule before choosing the algorithm: one sentence in the statement decides between O(log mn) and O(m + n).

Justify the corner choice for the staircase: "largest in its row, smallest in its column".

Offer the lower bound: for 240 you cannot do better than Ω(min(m, n)) in the comparison model, so O(m + n) is essentially optimal.

Follow-ups: return the position, count occurrences, kth smallest, search a matrix with sorted rows only, 3D arrays.
Edge cases: 1×1, single row, single column, target smaller than the top-left or larger than

the bottom-right, duplicates.

CHAPTER SUMMARY

Read how the matrix is sorted: fully ordered → flatten; rows + columns only → staircase.

Flatten: row = k / cols, col = k % cols, O(log mn). Staircase: start top-right, step left if too big, down if too small, O(m + n).

Kth smallest: binary search the value range, count ≤ x with a staircase.

Guard empty matrices and use long for rows * cols when needed.
