Monotonic Queue / Deque

A monotonic stack with an expiry date: the window maximum in O(1) amortised.

A. Pattern Overview

A monotonic deque keeps a window's candidates in sorted order and lets elements leave from both ends: from the back when a new element makes them useless (same rule as a monotonic stack) and from the front when they slide out of the window. The front of the deque is always the current window's maximum (or minimum), readable in O(1); every element is added once and removed once, so the total is O(n).

KEY IDEA

Dominance argument. If an older element a is ≤ a newer element b, then a can never again be the maximum: b is larger and will outlive it. So a is discarded the moment b arrives. What remains is a decreasing sequence whose front is the maximum.

OperationEndReason
Remove expired indexfrontOldest index left the window
Remove dominated valuesbackSmaller-or-equal and older than the new element
Insert new indexbackNewest element
Read window max (or min)frontLargest surviving candidate

Versus monotonic stack: the stack has no expiry; it answers nearest greater/smaller neighbour. The deque answers extreme of a moving window. Versus a heap: a priority queue gives the same answer in O(n log n) with lazy deletion; the deque is O(n) and simpler to reason about.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Maximum (or minimum) of every sliding window of size k."
A window whose validity depends on both max and min (max - min <= limit): use two

deques.

Subarray sum ≥ K with negative numbers where a sliding window fails: prefix sums plus a deque of increasing prefix values.
A DP transition over a sliding range: dp[i] = nums[i] + max(dp[i-k .. i-1]) (Jump

Game VI, Constrained Subsequence Sum).

The sliding-window code almost works but needs the extreme element of the window, not just a sum or a count.
DECISION RULE

"Window" + "maximum/minimum" → deque. "Window" + "negatives" + "sum at least K" → prefix sums + deque. "DP over the last k states" → deque to get the best previous state in O(1).

C. Core Intuition with Illustrations

Figure 19. The blue deque is decreasing from front to back. Its front is the window maximum; smaller older values are evicted when a bigger one arrives.

INTUITION

Store indices, not values: you need the index to detect when the front has left the window (front <= i - k), and the value is one lookup away (nums[front]).

D. Brute Force to Optimal Solution

Example: Sliding Window Maximum (LeetCode 239)

Brute force: scan each window for its maximum: O(n · k). With n = 10⁵ and k = 5·10⁴

that is about 2.5·10⁹ steps: far too slow.

Heap: push (value, index), lazily pop the top while its index is outside the window: O(n log n), O(n) space.
Observation: an element that is both older and not larger than a newer one can never be a maximum again. Discard it immediately.
Optimal: deque of indices with decreasing values: O(n) time, O(k) space.

E. Java Implementation

SlidingWindowMaximum.java — LeetCode 239

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/** LeetCode 239 - Sliding Window Maximum. Deque of indices, values strictly decreasing. */
public class SlidingWindowMaximum {

    public static int[] maxSlidingWindow(int[] nums, int k) {
        int n = nums.length;
        if (n == 0 || k <= 0) return new int[0];
        int[] result = new int[n - k + 1];
        // front = index of current window maximum
        Deque<Integer> deque = new ArrayDeque<>();
        for (int i = 0; i < n; i++) {
            if (!deque.isEmpty() && deque.peekFirst() <= i - k) {
                deque.pollFirst();                      // front slid out of the window
            }
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
                deque.pollLast();                       // dominated: older AND not larger
            }
            deque.addLast(i);
            if (i >= k - 1) {
                result[i - k + 1] = nums[deque.peekFirst()];
            }
        }
        return result;
    }
}

TIME O(n)

SPACE O(k)

<= when evicting from the back keeps the deque strictly decreasing (equal values: keep the newer, it expires later).

G. Variations of the Pattern

Negative numbers and a sum target: Shortest Subarray with Sum at Least K

With negatives the window is not monotone, so use prefix sums P. For each end i, we want the latest start j < i with P[i] - P[j] >= K. Keep a deque of indices with increasing prefix values:

Front pops: while P[i] - P[front] >= K, record i - front and discard front. Any later

end would only yield a longer subarray with that start.

Back pops: while P[back] >= P[i], discard back: index i is later and has a smaller-or-equal prefix, so it is a better start for every future end.
ShortestSubarrayAtLeastK.java — LeetCode 862

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 862 - Shortest Subarray with Sum at Least K (negatives allowed). Prefix sums +
 * deque.
 */
public class ShortestSubarrayAtLeastK {

    public static int shortestSubarray(int[] nums, int k) {
        int n = nums.length;
        long[] prefix = new long[n + 1];
        for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];

        // indices with strictly increasing prefix values
        Deque<Integer> deque = new ArrayDeque<>();
        int best = n + 1;
        for (int i = 0; i <= n; i++) {
            // Front: the oldest start that already gives sum >= k. Using it is optimal for this
            // end, and for any later end the subarray would only be longer, so discard it.
            while (!deque.isEmpty() && prefix[i] - prefix[deque.peekFirst()] >= k) {
                best = Math.min(best, i - deque.pollFirst());
            }
            // Back: a start with prefix >= prefix[i] is older AND worse than i. Drop it.
            while (!deque.isEmpty() && prefix[deque.peekLast()] >= prefix[i]) {
                deque.pollLast();
            }
            deque.addLast(i);
        }
        return best == n + 1 ? -1 : best;
    }
}

TIME O(n)

SPACE O(n)

long prefix sums. This is the standard proof-of-mastery problem for the deque.

Two deques: Longest Subarray With Absolute Difference ≤ Limit

Validity is max - min <= limit. Maintain one decreasing deque for the window max and one increasing deque for the window min; shrink from the left while invalid.

LongestSubarrayLimit.java — LeetCode 1438

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 1438 - Longest Continuous Subarray With Absolute Diff <= Limit. Two monotonic
 * deques.
 */
public class LongestSubarrayLimit {

    public static int longestSubarray(int[] nums, int limit) {
        // values decreasing: front = window max
        Deque<Integer> maxDeque = new ArrayDeque<>();
        // values increasing: front = window min
        Deque<Integer> minDeque = new ArrayDeque<>();
        int left = 0;
        int best = 0;
        for (int right = 0; right < nums.length; right++) {
            while (!maxDeque.isEmpty() && maxDeque.peekLast() < nums[right]) maxDeque.pollLast();
            maxDeque.addLast(nums[right]);
            while (!minDeque.isEmpty() && minDeque.peekLast() > nums[right]) minDeque.pollLast();
            minDeque.addLast(nums[right]);

            while (maxDeque.peekFirst() - minDeque.peekFirst() > limit) {
                int leaving = nums[left++];
                // int vs Integer: numeric ==
                if (maxDeque.peekFirst() == leaving) maxDeque.pollFirst();
                if (minDeque.peekFirst() == leaving) minDeque.pollFirst();
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}

TIME O(n)

SPACE O(n)

Here the deques store values; when a value leaves the window it is removed from a front only if equal to it.

A reusable min-max queue

The same two deques wrap into a queue that supports enqueue, dequeue, getMin, getMax in O(1) amortised: useful for streaming problems and system-design style questions.

MinMaxQueue.java

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.NoSuchElementException;

/** A FIFO queue with O(1) amortised enqueue, dequeue, getMin and getMax. */
public class MinMaxQueue {
    private final Deque<Integer> items = new ArrayDeque<>();
    private final Deque<Integer> minDeque = new ArrayDeque<>();   // non-decreasing values
    private final Deque<Integer> maxDeque = new ArrayDeque<>();   // non-increasing values

    public void enqueue(int value) {
        items.addLast(value);
        while (!minDeque.isEmpty() && minDeque.peekLast() > value) minDeque.pollLast();
        // equal values are kept: each copy dies separately
        minDeque.addLast(value);
        while (!maxDeque.isEmpty() && maxDeque.peekLast() < value) maxDeque.pollLast();
        maxDeque.addLast(value);
    }

    public int dequeue() {
        if (items.isEmpty()) throw new NoSuchElementException("queue is empty");
        int value = items.pollFirst();
        if (minDeque.peekFirst() == value) minDeque.pollFirst();
        if (maxDeque.peekFirst() == value) maxDeque.pollFirst();
        return value;
    }

    public int getMin() {
        if (items.isEmpty()) throw new NoSuchElementException("queue is empty");
        return minDeque.peekFirst();
    }

    public int getMax() {
        if (items.isEmpty()) throw new NoSuchElementException("queue is empty");
        return maxDeque.peekFirst();
    }

    public int size() {
        return items.size();
    }
}

TIME O(1) amortised per operation

SPACE O(n)

Equal values are kept in the deques so each copy can be dequeued independently.

DP + deque: Jump Game VI

dp[i] = nums[i] + max(dp[i-k..i-1]). The inner maximum is a sliding window over dp, so a deque makes the whole DP O(n) instead of O(n · k).

JumpGameVI.java — LeetCode 1696

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 1696 - Jump Game VI. dp[i] = nums[i] + max(dp[i-k..i-1]); window max via monotonic
 * deque.
 */
public class JumpGameVI {

    public static int maxResult(int[] nums, int k) {
        int n = nums.length;
        int[] dp = new int[n];
        dp[0] = nums[0];
        Deque<Integer> deque = new ArrayDeque<>();      // indices, dp values decreasing
        deque.addLast(0);
        for (int i = 1; i < n; i++) {
            if (deque.peekFirst() < i - k) deque.pollFirst();     // out of jump range
            dp[i] = nums[i] + dp[deque.peekFirst()];
            while (!deque.isEmpty() && dp[deque.peekLast()] <= dp[i]) deque.pollLast();
            deque.addLast(i);
        }
        return dp[n - 1];
    }
}

TIME O(n)

SPACE O(k)

J. Interview Tips

INTERVIEW

Explain dominance in one sentence: "an older element that is not larger than a newer one can never be the max again, so I throw it away."

Give the heap solution first (O(n log n)), then improve to the deque: it shows the progression interviewers want.

State where each pointer end is used: back for dominance, front for expiry, front for the answer.

CHAPTER SUMMARY

Deque = monotonic stack + expiry. Back removes dominated elements; front removes expired indices and holds the answer.

Store indices; evict the front with front <= i - k; output only once the first window is full.

Sum ≥ K with negatives: prefix sums + increasing deque. DP over a sliding range: use the deque for the inner max.

Every element enters and leaves once, so O(n) total.
