Array Techniques

Voting, in-place reversal and single-pass greedy: the small tricks that turn O(n) space into O(1).

A. Pattern Overview

Not every array problem needs a named algorithm. A large family of screening-round questions is solved by one of four compact ideas, each replacing extra memory or a second pass with a clever invariant:

TechniqueIdeaClassic problemsTime / Space
Boyer-Moore votingPair off different elements; whatever survives is the only possible majorityMajority Element (169), Majority Element II (229)O(n) · O(1)

KEY IDEA

Each technique maintains a tiny summary of the prefix (a candidate and a count, the two smallest values, the best left partner, the current run length). If you can say what must be remembered about everything before index i in one or two variables, you have an O(1)-space single pass.

B. When to Recognize This Pattern

Pattern Recognition Signals

"More than ⌊n/2⌋ (or ⌊n/3⌋) times" with a space limit of O(1): Boyer-Moore voting.
"Rotate by k" in place, or a reversal that must preserve order inside segments: three

reversals.

"Unlimited transactions", or a profit that is the sum of positive adjacent differences: collect every rise.
Pair or triple conditions with ordering (i < j, a < b < c) where a hash set or DP table is

too heavy: carry the best partner so far.

Counting subarrays made of identical values (all zeros, all ones): count per run, not per pair.
The constraints say n ≤ 10⁵ and the brute force is O(n²) or O(n) extra memory.
SPACE-LIMIT HINT

The phrase "in O(1) extra space" plus a counting or ordering property almost always points to one of these five techniques. Think "what do I need to remember about the prefix?" before reaching for a map.

C. Core Intuition with Illustrations

Boyer-Moore voting. Imagine a vote where each different pair of ballots cancels out. If an element is a strict majority, it outnumbers all other elements combined, so it cannot be cancelled completely. Keep a candidate and a count: matching ballots add one, different ballots remove one, and when count hits 0 the next ballot starts a fresh candidate.

Figure 20. Green cells vote for the current candidate. The candidate can change, but the true majority always survives to the end.

Rotation by three reversals. Rotating right by k moves the last k elements to the front without changing the order inside either block. Reversing the whole array puts the blocks in the right places but backwards; reversing each block restores their order.

Figure 21. Reverse everything, then reverse the first k and the remaining n − k elements.

INTUITION

Why Boyer-Moore needs a second pass for "n/3". The voting phase only guarantees that if an element exceeds the threshold it is among the candidates. A candidate that survives may still be below the threshold ([1, 2, 3]), so verify with a counting pass. For Majority Element I the problem guarantees existence and the check is skipped.

D. Brute Force to Optimal Solution

Example: Majority Element (LeetCode 169)

Brute force: count every element against every other: O(n²).
Sorting: the majority element sits at index n / 2 after sorting: O(n log n), O(1) to O(n) space.
HashMap of counts: O(n) time, O(n) space. Good, and the right answer when space is not constrained.
Randomised: pick random elements and verify; expected O(n) but not deterministic.
Boyer-Moore voting: O(n) time and O(1) space, deterministic.

The same ladder applies to Rotate Array: copy into a new array (O(n) space), rotate one step k times (O(nk) time), cyclic replacements (O(n) time but fiddly with gcd(n, k) cycles), and finally the three-reversal solution.

E. Java Implementation

Boyer-Moore voting: Majority Element I and II

MajorityElement.java — LeetCode 169 and 229

Java 17+

import java.util.ArrayList;
import java.util.List;

/** Boyer-Moore voting: LeetCode 169 (majority > n/2) and LeetCode 229 (elements > n/3). */
public class MajorityElement {

    /** The majority element is guaranteed to exist. */
    public static int majorityElement(int[] nums) {
        int candidate = 0;
        int count = 0;
        for (int x : nums) {
            if (count == 0) {
                // previous votes cancelled out: adopt a new candidate
                candidate = x;
            }
            count += (x == candidate) ? 1 : -1;
        }
        return candidate;
    }

    /** Every element that appears more than n / 3 times: at most two such elements exist. */
    public static List<Integer> majorityElementII(int[] nums) {
        int cand1 = 0, cand2 = 1;           // distinct dummy candidates
        int count1 = 0, count2 = 0;
        for (int x : nums) {
            if (x == cand1) {
                count1++;
            } else if (x == cand2) {
                count2++;
            } else if (count1 == 0) {
                cand1 = x;
                count1 = 1;
            } else if (count2 == 0) {
                cand2 = x;
                count2 = 1;
            } else {
                count1--;                   // x votes against both candidates
                count2--;
            }
        }
        // Second pass: the voting phase only finds candidates, it does not prove the threshold.
        int c1 = 0, c2 = 0;
        for (int x : nums) {
            if (x == cand1) c1++;
            else if (x == cand2) c2++;
        }
        List<Integer> result = new ArrayList<>();
        if (c1 > nums.length / 3) result.add(cand1);
        if (c2 > nums.length / 3) result.add(cand2);
        return result;
    }
}

TIME O(n)

SPACE O(1)

For n/3 keep two candidates and two counts; a different third element cancels one vote from each. Always verify in a second pass for the n/3 variant.

Rotate Array: three reversals

RotateArray.java — LeetCode 189

Java 17+

/**
 * LeetCode 189 - Rotate Array. Three reversals rotate right by k in O(n) time and O(1) space.
 */
public class RotateArray {

    public static void rotate(int[] nums, int k) {
        int n = nums.length;
        if (n == 0) return;
        k %= n;                              // k may exceed n
        if (k == 0) return;
        reverse(nums, 0, n - 1);             // [1,2,3,4,5,6,7] -> [7,6,5,4,3,2,1]
        reverse(nums, 0, k - 1);             // reverse the first k: the new head
        reverse(nums, k, n - 1);             // reverse the rest
    }

    private static void reverse(int[] a, int lo, int hi) {
        while (lo < hi) {
            int tmp = a[lo];
            a[lo++] = a[hi];
            a[hi--] = tmp;
        }
    }
}

TIME O(n)

SPACE O(1)

k %= n is mandatory (k can exceed n); each element is moved at most twice.

G. Variations of the Pattern

Best Time to Buy and Sell Stock II: sum of rises

With unlimited transactions, any climb from a low to a high equals the sum of its daily increases, so collect every positive difference prices[i] − prices[i−1]. Contrast with Chapter 5, where a single transaction needs the running minimum.

StockProfitII.java — LeetCode 122

Java 17+

/**
 * LeetCode 122 - Best Time to Buy and Sell Stock II: unlimited transactions, so collect every
 * rise.
 */
public class StockProfitII {

    public static int maxProfit(int[] prices) {
        int profit = 0;
        for (int i = 1; i < prices.length; i++) {
            if (prices[i] > prices[i - 1]) {
                // any multi-day climb = sum of its daily rises
                profit += prices[i] - prices[i - 1];
            }
        }
        return profit;
    }
}

TIME O(n)

SPACE O(1)
Increasing Triplet Subsequence: two smallest tails

Keep first = smallest value so far and second = smallest value that has something smaller before it. Any x > second completes a triplet. This is the length-3 special case of the patience-sorting LIS tails array.

IncreasingTriplet.java — LeetCode 334
/** LeetCode 334 - Increasing Triplet Subsequence in O(n) time and O(1) space. */
public class IncreasingTriplet {

    public static boolean increasingTriplet(int[] nums) {
        int first = Integer.MAX_VALUE;      // smallest value seen so far
        // smallest value that has a smaller value before it
        int second = Integer.MAX_VALUE;
        for (int x : nums) {
            if (x <= first) {
                first = x;
            } else if (x <= second) {
                second = x;
            } else {
                return true;                // x > second > (some earlier) first
            }
        }
        return false;
    }
}

Java 17+

TIME O(n)

SPACE O(1)

Use <= so equal values do not create false triplets.

Best Sightseeing Pair: carry the best left partner

Score (v[i] + i) + (v[j] − j) splits into a part depending only on i and a part depending only on j. Scan j left to right, keeping the maximum v[i] + i. This is the same "best earlier value" trick used in Kadane and in stock problems.

BestSightseeingPair.java — LeetCode 1014

Java 17+

/**
 * LeetCode 1014 - Best Sightseeing Pair: maximise (v[i] + i) + (v[j] - j) for i < j in one
 * pass.
 */
public class BestSightseeingPair {

    public static int maxScoreSightseeingPair(int[] values) {
        int bestLeft = values[0];            // best v[i] + i seen so far
        int best = Integer.MIN_VALUE;
        for (int j = 1; j < values.length; j++) {
            best = Math.max(best, bestLeft + values[j] - j);
            bestLeft = Math.max(bestLeft, values[j] + j);
        }
        return best;
    }
}

TIME O(n)

SPACE O(1)

Update bestLeft after scoring j, so i < j always holds.

Number of Zero-Filled Subarrays: count per run

A maximal run of L zeros contains L(L+1)/2 zero-filled subarrays. Equivalently, each zero at run position p adds p new subarrays ending there. Use long.

ZeroFilledSubarrays.java — LeetCode 2348

Java 17+

/**
 * LeetCode 2348 - Number of Zero-Filled Subarrays. A run of length L contributes L*(L+1)/2.
 */
public class ZeroFilledSubarrays {

    public static long zeroFilledSubarray(int[] nums) {
        long total = 0;
        long run = 0;
        for (int x : nums) {
            // zero-filled subarrays ending here = current run length
            run = (x == 0) ? run + 1 : 0;
            total += run;
        }
        return total;
    }
}

TIME O(n)

SPACE O(1)

The count can reach n(n+1)/2 ≈ 5·10⁹: int overflows.

Related one-pass ideas
Majority in a stream or very large data: Boyer-Moore works online with O(1) memory

(verify with a second pass if allowed).

Rotate a linked list or a string: the reversal trick generalises (reverse words in place: reverse the whole string, then each word).
Jump-style greedy scans (Jump Game, Gas Station): carry the farthest reach or running

tank; developed in the Greedy chapters.

J. Interview Tips

INTERVIEW

Offer the HashMap solution first, then say "if we are limited to O(1) space, Boyer-Moore voting works because…". Explaining the cancellation argument is the real test.

Prove it in one sentence: "a strict majority outnumbers all other elements together, so pairing off different elements cannot eliminate it".

For rotation, draw the three arrays (reverse all, reverse first k, reverse rest) on the whiteboard; it takes ten seconds and removes off-by-one bugs.

Follow-ups: majority in a stream, n/k generalisation (Misra-Gries), rotate a string, rotate a linked list, the cyclic-replacement approach with gcd(n, k).
Edge cases to announce: k larger than n, empty input, no majority.

CHAPTER SUMMARY

Ask: what must I remember about the prefix? If the answer fits in one or two variables, the problem is a single O(1)-space pass.

Boyer-Moore: matching ballots add, different ballots cancel; verify when the majority is not guaranteed (always for n/3).

Rotation: k %= n, reverse all, reverse [0, k−1], reverse [k, n−1].

Greedy and best-so-far scans replace DP tables: sum of rises, first/second tails, bestLeft. Count runs with L(L+1)/2 in long.
