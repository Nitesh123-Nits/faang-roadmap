Binary Search in Rotated Arrays

One half is always sorted: use it to decide where to go, even when the whole array is not.

A. Pattern Overview

A rotated sorted array is a sorted array whose prefix was moved to the back: [0,1,2,4,5,6,7] becomes [4,5,6,7,0,1,2] (the last four elements moved to the front, i.e. a right rotation by 4). It is no longer globally sorted, but it consists of two sorted runs joined at a single "drop" (the pivot, which is also the minimum). Binary search still works because, for any mid, at least one of [lo, mid] and [mid, hi] is fully sorted, and a sorted half lets you test in O(1) whether the target lies inside it.

KEY IDEA

Two flavours: (1) find the minimum / pivot by comparing nums[mid] with nums[hi];

search a target by identifying the sorted half and checking membership. With duplicates the sorted half can be unidentifiable, and the worst case becomes O(n).

B. When to Recognize This Pattern

Pattern Recognition Signals

The statement says "sorted array rotated at an unknown pivot" and asks to search, find the minimum, or count rotations.
Required complexity O(log n) on data that is almost sorted: two ascending runs with one

drop.

A circular sorted structure (ring buffer, log files that wrap) where the logical start is unknown.
Follow-up flavour: "what if there are duplicates?" (a classic interviewer escalation).
KEY QUESTION

Whenever the array "is sorted except for one wrap-around", ask: which half of [lo, hi] is sorted right now? The answer drives every decision.

C. Core Intuition with Illustrations

Figure 28. The pivot can lie in only one of the two halves; the other half is therefore a plain sorted range.

Searching 0: the left half [4..7] is sorted but 0 is not in [4, 7), so go right. Finding the minimum: if nums[mid] > nums[hi], the drop lies strictly to the right of mid; otherwise the minimum is at mid or to its left. Comparing with hi (not lo) is what makes the minimum search correct for non-rotated input as well.

INTUITION

Why compare with nums[hi] and not nums[lo]? If the array is not rotated, nums[mid] >= nums[lo] always holds and says nothing about the pivot; nums[mid] <= nums[hi] correctly reports "no drop on the right".

D. Brute Force to Optimal Solution

Example: Search in Rotated Sorted Array (LeetCode 33)

Brute force: linear scan: O(n). Ignores the structure.
Two-step: find the pivot with one binary search, then binary search the correct run: O(log n) with two loops and index arithmetic.
Single pass: at each step decide which half is sorted; if the target lies in that half's value range, go there, else go to the other half. O(log n) with one loop.
With duplicates: when nums[lo] == nums[mid] == nums[hi] no half can be proved sorted; shrink both ends by one. Worst case O(n) (for example [1,1,1,1,1,0,1]).

E. Java Implementation

Search in Rotated Sorted Array (distinct)

SearchRotated.java — LeetCode 33

Java 17+

/**
 * LeetCode 33 - Search in Rotated Sorted Array (distinct values). One half is always sorted.
 */
public class SearchRotated {

    public static int search(int[] nums, int target) {
        int lo = 0;
        int hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) return mid;

            if (nums[lo] <= nums[mid]) {                    // left half [lo, mid] is sorted
                if (nums[lo] <= target && target < nums[mid]) {
                    // target lies inside the sorted half
                    hi = mid - 1;
                } else {
                    lo = mid + 1;
                }
            } else {                                        // right half [mid, hi] is sorted
                if (nums[mid] < target && target <= nums[hi]) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
        return -1;
    }
}

TIME O(log n)

SPACE O(1)

nums[lo] <= nums[mid] uses <= because lo can equal mid

(two-element ranges).

Find Minimum (distinct and with duplicates) and rotation count

FindMinRotated.java — LeetCode 153 / 154

Java 17+

/** LeetCode 153 / 154 - Minimum in a rotated sorted array. Compare mid with the RIGHT end. */
public class FindMinRotated {

    /** Distinct values. */
    public static int findMin(int[] nums) {
        int lo = 0;
        int hi = nums.length - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) {
                lo = mid + 1;               // the drop is to the right of mid
            } else {
                hi = mid;                   // mid may itself be the minimum
            }
        }
        return nums[lo];
    }

    /** Duplicates allowed. Worst case O(n), for example [1,1,1,1,1]. */
    public static int findMinWithDuplicates(int[] nums) {
        int lo = 0;
        int hi = nums.length - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) {
                lo = mid + 1;
            } else if (nums[mid] < nums[hi]) {
                hi = mid;
            } else {
                // equal: nums[hi] is not needed (nums[mid] is a copy)
                hi--;
            }
        }
        return nums[lo];
    }

    /**
     * Number of times a sorted array of DISTINCT values was rotated = index of the minimum.
     */
    public static int rotationCount(int[] nums) {
        int lo = 0;
        int hi = nums.length - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) lo = mid + 1; else hi = mid;
        }
        return lo;
    }
}

TIME O(log n); O(n) worst with

duplicates
SPACE O(1)

Equality case: hi-- is safe because nums[mid] still holds the same value, so the minimum is not lost.

G. Variations of the Pattern

Duplicates: Search in Rotated Sorted Array II

Example trap: [1, 0, 1, 1, 1], target 0. At the first probe nums[lo] == nums[mid] == nums[hi] == 1, so neither half can be declared sorted. Dropping lo and hi by one is safe because nums[mid] has the same value (if it was the target we would have returned already).

SearchRotatedDuplicates.java — LeetCode 81

Java 17+

/**
 * LeetCode 81 - Search in Rotated Sorted Array II (duplicates allowed). Worst case degrades
 * to O(n).
 */
public class SearchRotatedDuplicates {

    public static boolean search(int[] nums, int target) {
        int lo = 0;
        int hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) return true;

            if (nums[lo] == nums[mid] && nums[mid] == nums[hi]) {
                lo++;                       // ambiguous: cannot tell which half is sorted,
                // but both ends are useless duplicates of nums[mid]
                hi--;
            } else if (nums[lo] <= nums[mid]) {
                if (nums[lo] <= target && target < nums[mid]) {
                    hi = mid - 1;
                } else {
                    lo = mid + 1;
                }
            } else {
                if (nums[mid] < target && target <= nums[hi]) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
        return false;
    }
}

TIME O(log n) typical, O(n) worst

SPACE O(1)

State the degradation honestly: it is information-theoretically unavoidable for this input class.

Minimum with duplicates (LeetCode 154)

Already included in findMinWithDuplicates above: three-way comparison with nums[hi]. Never compare with nums[lo] for the minimum when duplicates exist.

Rotation count and un-rotating

For distinct values, the index of the minimum equals the number of positions the array was rotated right, (rotationCount in the same class). To search with it, run a plain binary search over virtual index (i + pivot) % n; this gives a cleaner implementation in some codebases.

Related shapes
Find the pivot in a bitonic array → Chapter 17.
Rotated array with a target that may appear many times → find the pivot, then two boundary searches (Chapter 12).
Sorted circular linked structures / ring buffers → same two-run reasoning.

J. Interview Tips

INTERVIEW

Say the invariant: "at least one half is sorted; I identify it, test the target against its endpoints, and keep the half that can contain it."

Offer the minimum-search first if you freeze: finding the pivot is often easier, and the target search follows.

Volunteer the duplicates caveat (O(n) worst case) before being asked. It shows depth.

Follow-ups: duplicates, find the rotation count, count occurrences of the target, rotated array of strings, rotated and unbounded array.
Edge cases: rotation 0, n = 1, n = 2, all equal, target at the pivot, target absent.

CHAPTER SUMMARY

A rotated sorted array has two ascending runs; for any mid, one of [lo, mid] / [mid, hi] is sorted.

Minimum: nums[mid] > nums[hi] → lo = mid + 1, else hi = mid. Search: test the target against the sorted half's endpoints.

Duplicates can hide the sorted half; shrink both ends on three-way equality and accept O(n) worst case.

Use <= for the sorted-half test and always check n = 1, n = 2 and an unrotated input.
