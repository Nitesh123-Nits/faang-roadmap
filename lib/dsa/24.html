KEY IDEA

The hashing bargain. A nested loop asks "is there a j such that …?" in O(n) per element. If the condition can be rewritten as "key(j) equals something I can compute from i", a hash lookup answers it in O(1). Every pattern in this chapter is that rewrite: find the key.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Find two (or four) elements that add to / differ by a target" on unsorted data, and indices matter or sorting is unwanted: complement lookup.
"Have we seen this before?", duplicate, first repeated, within distance k: a set (a window of a

set for the distance variant).

"Group / categorise / bucket the items" where equivalent items differ only in arrangement: canonical key.
"Longest sequence of consecutive integers", order-independent: a set plus only start

counting at sequence starts.

A nested loop whose inner test is an equality after algebra (a + b == t → b == t − a).
Constraints around n ≤ 10⁵ and the brute force is O(n²); memory is not tight.
CHOOSING THE TOOL

Sorted input and no indices needed → two pointers (Chapter 1) beats a map (O(1) space). Unsorted input or indices required → hash map. Range or nearest-neighbour queries → TreeMap/binary search (Part II).

C. Core Intuition with Illustrations

Complement lookup. For nums = [2, 7, 11, 15] and target = 9: at each element ask the map "is target − x already stored?" If yes, the pair is complete; otherwise store x → i. Looking up before inserting guarantees an element is never paired with itself.

Figure 33. The map stores what has been seen; each element asks a single O(1) question.

Longest consecutive sequence. Put all numbers in a set. A number x starts a run only if x − 1 is absent; walk upward from starts only. Each element is visited a constant number of times, so the loop is O(n) even though it contains a while.

Figure 34. Elements such as 2, 3, 4 are skipped immediately because their predecessor exists.

INTUITION

Why the "is it a start?" test matters. Without it, every element starts a walk and [1, 2, 3, …, n] costs O(n²). With it, each run is walked exactly once from its first element: total O(n).

Under the hood. A bucket index is hash(key) & (capacity − 1). Keys that collide share a bucket, chained as a linked list (Java 8+ converts a long chain into a balanced tree). Good hashing and a load factor around 0.75 keep chains short, giving O(1) expected time.

D. Brute Force to Optimal Solution

Example: Group Anagrams (LeetCode 49)

Brute force: compare every pair of words for anagram-ness (O(n² · L)), then merge groups.
Sorted-letters key: sort each word's characters and use it as the map key: O(n · L log L).
Count-signature key: for lowercase letters, a 26-slot count array rendered as a string (1#0#0#…) is the key: O(n · L).
Optimal in practice: the count signature; mind the separator so [1, 11] and [11, 1] do not collide.

The same "find the canonical key" step applies to Isomorphic Strings (key = pattern of first occurrences, or two-way maps), Find Duplicate File (key = content), Group Shifted Strings (key = difference sequence).

E. Java Implementation

Two Sum: complement lookup

TwoSumHash.java — LeetCode 1

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 1 - Two Sum. One pass: look up the complement BEFORE inserting the current value.
 */
public class TwoSumHash {

    public static int[] twoSum(int[] nums, int target) {
        // value -> index of its latest occurrence
        Map<Integer, Integer> indexOf = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            Integer j = indexOf.get(target - nums[i]);
            if (j != null) {
                // j < i, and j != i by construction
                return new int[]{j, i};
            }
            // insert after the lookup: no self-pairing
            indexOf.put(nums[i], i);
        }
        // the problem guarantees an answer
        return new int[0];
    }
}

TIME O(n)

SPACE O(n)

Lookup first, insert second. With duplicates ([3, 3], target 6) the later occurrence overwrites the index, which is still correct.

Group Anagrams: canonical key

GroupAnagrams.java — LeetCode 49

Java 17+

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/** LeetCode 49 - Group Anagrams. The canonical key of a word is its letter-count signature. */
public class GroupAnagrams {

    /**
     * Lowercase a-z words. Key = 26 counts; O(L) per word instead of O(L log L) for sorting.
     */
    public static List<List<String>> groupAnagrams(String[] words) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String w : words) {
            groups.computeIfAbsent(signature(w), k -> new ArrayList<>()).add(w);
        }
        return new ArrayList<>(groups.values());
    }

    static String signature(String word) {
        int[] counts = new int[26];
        for (int i = 0; i < word.length(); i++) counts[word.charAt(i) - 'a']++;
        StringBuilder key = new StringBuilder(52);
        // '#' keeps "1,11" distinct from "11,1"
        for (int c : counts) key.append(c).append('#');
        return key.toString();
    }
}

TIME O(n · L)

SPACE O(n · L)

computeIfAbsent creates the bucket once. Keep the separator in the signature.

Longest Consecutive Sequence: set + starts only

LongestConsecutive.java — LeetCode 128
import java.util.HashSet;
import java.util.Set;

/**
 * LeetCode 128 - Longest Consecutive Sequence in O(n): only start counting at sequence
 * starts.
 */

Java 17+

public class LongestConsecutive {

    public static int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) set.add(x);

        int best = 0;
        for (int x : set) {
            if (set.contains(x - 1)) continue;        // x is not the start of a run: skip it
            int end = x;
            // each element is walked at most once overall
            while (set.contains(end + 1)) end++;
            best = Math.max(best, end - x + 1);
        }
        return best;
    }
}

TIME O(n)

SPACE O(n)

Iterate over the set, not the array, so duplicates do not repeat work.

G. Variations of the Pattern

Contains Duplicate II: a sliding window of a set

Duplicates within distance k means the set only needs the last k values: add the new one, evict nums[i − k] when the size exceeds k.

Valid Anagram, Ransom Note, Isomorphic Strings

Counting with a 26-slot array is faster than a HashMap<Character, Integer>. Isomorphic needs a mapping that is one-to-one in both directions, hence two maps (or two arrays of last-seen positions).

HashBasics.java — LeetCode 219, 242, 383, 205

Java 17+

import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Set;

/** Everyday hash-based checks: LeetCode 217/219, 242, 383, 205, 290-style bijection. */
public class HashBasics {

    /**
     * LeetCode 219 - Contains Duplicate II: duplicates within distance k. Window = a set of
     * the last k values.
     */
    public static boolean containsNearbyDuplicate(int[] nums, int k) {
        Set<Integer> window = new HashSet<>();
        for (int i = 0; i < nums.length; i++) {
            if (!window.add(nums[i])) return true;            // already inside the window
            if (window.size() > k) window.remove(nums[i - k]);
        }
        return false;
    }

    /** LeetCode 242 - Valid Anagram. Lowercase letters: a 26-slot counting array. */
    public static boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;
        int[] counts = new int[26];
        for (int i = 0; i < s.length(); i++) {
            counts[s.charAt(i) - 'a']++;
            counts[t.charAt(i) - 'a']--;
        }
        for (int c : counts) if (c != 0) return false;
        return true;
    }

    /**
     * LeetCode 383 - Ransom Note: the magazine must supply at least as many of each letter.
     */
    public static boolean canConstruct(String ransomNote, String magazine) {
        int[] available = new int[26];
        for (char c : magazine.toCharArray()) available[c - 'a']++;
        for (char c : ransomNote.toCharArray()) {
            if (--available[c - 'a'] < 0) return false;
        }
        return true;
    }

    /**
     * LeetCode 205 - Isomorphic Strings: a character mapping that must be one-to-one in BOTH
     * directions.
     */
    public static boolean isIsomorphic(String s, String t) {
        if (s.length() != t.length()) return false;
        Map<Character, Character> forward = new HashMap<>();
        Map<Character, Character> backward = new HashMap<>();
        for (int i = 0; i < s.length(); i++) {
            char a = s.charAt(i);
            char b = t.charAt(i);
            Character mappedA = forward.putIfAbsent(a, b);
            Character mappedB = backward.putIfAbsent(b, a);
            // a was already mapped elsewhere
            boolean forwardClash = mappedA != null && mappedA != b;
            // b was already claimed by another a
            boolean backwardClash = mappedB != null && mappedB != a;
            if (forwardClash || backwardClash) return false;
        }
        return true;
    }
}

TIME O(n)

SPACE O(1) for fixed alphabets; O(k) for

the window

putIfAbsent returns the previous mapping: the cleanest way to test consistency.

4Sum II: meet in the middle

Four arrays, count tuples summing to zero. Store all a + b sums with counts, then for every

c + d look up −(c + d): O(n²) instead of O(n⁴).

FourSumII.java — LeetCode 454

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 454 - 4Sum II. Meet in the middle with a map of pair sums: O(n^2) instead of
 * O(n^4).
 */
public class FourSumII {

    public static int fourSumCount(int[] a, int[] b, int[] c, int[] d) {
        Map<Integer, Integer> pairSums = new HashMap<>();
        for (int x : a) {
            for (int y : b) {
                pairSums.merge(x + y, 1, Integer::sum);       // how many (i, j) give this sum
            }
        }
        int count = 0;
        for (int x : c) {
            for (int y : d) {
                // complement from the other two arrays
                count += pairSums.getOrDefault(-(x + y), 0);
            }
        }
        return count;
    }
}

TIME O(n²)

SPACE O(n²)

Counts, not lists: the answer is a number of tuples.

Design HashMap: build the structure itself

A frequent interview follow-up. Use an array of buckets, separate chaining, a power-of-two capacity (& replaces %), bit-spreading of the hash, and resize at load factor 0.75 by re-linking nodes.

MyHashMap.java — LeetCode 706

Java 17+

/**
 * LeetCode 706 - Design HashMap: separate chaining, power-of-two table, resize at load factor
 * 0.75.
 */
public class MyHashMap {

    private static final class Node {
        final int key;
        int value;
        Node next;

        Node(int key, int value, Node next) {
            this.key = key;
            this.value = value;
            this.next = next;
        }
    }

    private Node[] table = new Node[16];
    private int size;

    private int indexFor(int key, int length) {
        // spread high bits into the low bits (as java.util.HashMap does)
        int h = key ^ (key >>> 16);
        return h & (length - 1);                   // length is a power of two, so & replaces %
    }

    public void put(int key, int value) {
        int i = indexFor(key, table.length);
        for (Node n = table[i]; n != null; n = n.next) {
            if (n.key == key) {
                n.value = value;                   // overwrite
                return;
            }
        }
        table[i] = new Node(key, value, table[i]); // insert at the head of the chain
        if (++size > table.length * 3 / 4) resize();
    }

    public int get(int key) {
        for (Node n = table[indexFor(key, table.length)]; n != null; n = n.next) {
            if (n.key == key) return n.value;
        }
        return -1;
    }

    public void remove(int key) {
        int i = indexFor(key, table.length);
        Node prev = null;
        for (Node n = table[i]; n != null; prev = n, n = n.next) {
            if (n.key == key) {
                if (prev == null) table[i] = n.next; else prev.next = n.next;
                size--;
                return;
            }
        }
    }

    private void resize() {
        Node[] bigger = new Node[table.length * 2];
        for (Node head : table) {
            for (Node n = head; n != null; ) {
                Node next = n.next;                // save before relinking
                int i = indexFor(n.key, bigger.length);
                n.next = bigger[i];
                bigger[i] = n;
                n = next;
            }
        }
        table = bigger;
    }

    public int size() {
        return size;
    }
}

TIME O(1) expected per operation

SPACE O(n)

hash ^ (hash >>> 16) mixes high bits so that power-of-two masks still distribute well, as in java.util.HashMap.

J. Interview Tips

INTERVIEW

Start with the brute force, then name the rewrite: "the inner loop asks whether target − x exists; a map answers that in O(1)". That sentence is the whole pattern.

State the space cost and offer the two-pointer alternative when the input is sorted.

Know how HashMap works (buckets, collisions, load factor 0.75, treeification at chain length 8): it is the most common follow-up.

Follow-ups: return all pairs (handle duplicates), 3Sum with a set, streaming Two Sum (a

Set plus a Map of counts), Two Sum on a BST, custom hashCode/equals contract.

Edge cases: duplicates ([3, 3]), negative numbers, empty array, single element, target not reachable, very large values.

CHAPTER SUMMARY

Hash patterns replace an inner loop by an O(1) lookup of a computed key: complement (target − x), membership, canonical key, or count.

Two Sum: lookup before insert. Longest Consecutive: a set, walking only from starts (x − 1 absent) in O(n).

Group by a canonical key (sorted letters, count signature with a separator); use immutable keys.

Know the internals: buckets, hash & (cap − 1), chaining, load factor 0.75, resize; and when a sorted array with two pointers saves the memory.
