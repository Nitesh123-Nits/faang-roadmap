PART I · ARRAY & INDEX-BASED PATTERNS

01

Two Pointers

Two indices, one pass: turn O(n²) pair searches into O(n).

A. Pattern Overview

Two Pointers keeps two indices into the same sequence and moves them according to a rule, so that each step permanently rules out a set of candidates. Instead of testing every pair (i, j) with a nested loop, the pointers walk a path through the pair space and the rule guarantees that nothing you skipped could have been the answer.

The pattern exists because many array and string problems ask about a pair, triplet or partition whose quality changes monotonically as an index moves. When moving an index in one direction can only make a quantity larger (or only smaller), you always know which pointer to move, and the quadratic search collapses to a linear scan.

KEY IDEA

A two-pointer solution is really an elimination argument. Before you code it, be able to finish the sentence: "when the pointers are at (L, R) and the condition says X, every pair involving L (or R) and anything still inside the window is useless, so I can move that pointer."

How it differs from neighbours. Sliding window also uses two indices, but both only move forward and the pointers delimit a contiguous subarray whose contents you maintain. In two pointers the indices usually represent two separate elements (a pair), often at opposite

ends. Binary search discards half the range per step; two pointers discards one element per step, but needs no mid and works on pair conditions that binary search cannot express.

B. When to Recognize This Pattern

Pattern Recognition Signals

The input is sorted, or sorting it first costs only O(n log n) and does not destroy the

answer (pair sums, triplets, closest values).

The question asks for a pair / triplet / quadruplet with a target sum, difference or product, or a best pair under a formula such as (j-i) * min(h[i], h[j]).
You are told to modify the array in place with O(1) extra space (remove, compact,

partition, reorder).

The brute force is a double loop over i < j, and you can argue that increasing i (or decreasing j) changes the evaluated quantity in one known direction.
A palindrome-like or symmetric check: compare the front with the back, moving inward.
Linked structures or implicit graphs where you need the middle, a cycle, or the k-th from the end (fast/slow, covered again in Part IV).
CONSTRAINT HINT

Constraints such as n ≤ 10⁵ rule out O(n²) and hint at O(n) or O(n log n). Combined

with the word sorted or in-place, two pointers should be your first guess. If the array is unsorted and you need the original indices, reach for a HashMap instead (Part III).

A 20-second interview checklist

Is the data sorted, or can I sort it without losing information I need?
Can I name a rule that says which pointer to move after looking at the current pair?
Can I justify why the discarded candidates cannot be optimal? (If not, it is not two pointers.)

C. Core Intuition with Illustrations

Take the sorted array [2, 3, 5, 8, 11, 15] and target = 16. Start with the widest pair. The sum 2 + 15 = 17 is too big. Because the array is sorted, 15 paired with any element at or to the right of left is at least 17, so 15 can never be part of the answer: move right inward. Next, 2 + 11 = 13 is too small, and 2 paired with anything at or left of right is at most 13, so 2 is useless: move left.

A second picture shows why this is correct. Every cell below is one candidate pair (L, R) and shows its sum. The four visited cells (solid colour) eliminate every other cell in their row or column without ever computing it.

INTUITION

Why the discard is safe (exchange argument). Suppose nums[L] + nums[R] >

target and the optimal pair were (i, R) with i ≥ L. Then nums[i] ≥ nums[L] gives

nums[i] + nums[R] ≥ nums[L] + nums[R] > target: contradiction. So no optimal

pair uses R. The symmetric argument handles <. Sortedness is what makes the sum monotone in each pointer.

D. Brute Force to Optimal Solution

Example: 3Sum (LeetCode 15)

Find all unique triplets with sum 0.

Brute force: three nested loops, plus a Set of sorted triplets to deduplicate. O(n³) time and O(k) extra space for the set. For n = 3000 that is 4.5×10⁹ operations: too slow.
Bottleneck: the innermost loop searches for -(a+b). Searching a sorted array is what two pointers does in O(n) for a whole row of answers.
Step up: fix one element a[i] and solve Two Sum II on the suffix a[i+1..] with target -a[i]. Time drops to O(n²).
Alternative: fix a[i], store seen values in a HashSet while scanning j. Also O(n²), but needs O(n) space and awkward duplicate handling. Two pointers handles duplicates by skipping equal neighbours in a sorted array.
Optimal: sort + anchor + two pointers. O(n log n + n²) = O(n²) time, O(1) extra space (ignoring the output and sort).

Figure 4. Why the brute force fails. On log-log axes, each step from O(n³) to O(n²) to O(n) buys orders of magnitude at n = 10⁴–10⁵.

E. Java Implementation

Two Sum II: the canonical opposite-pointer loop

TwoSumSorted.java — LeetCode 167
/** LeetCode 167 - Two Sum II (sorted input). Opposite-direction two pointers. */
public class TwoSumSorted {

    /** Returns 1-based indices of the pair that sums to target, or an empty array. */
    public static int[] twoSum(int[] numbers, int target) {
        int left = 0;
        int right = numbers.length - 1;
        while (left < right) {
            long sum = (long) numbers[left] + numbers[right];   // long: avoid overflow
            if (sum == target) {
                return new int[]{left + 1, right + 1};
            } else if (sum < target) {
                left++;     // need a larger sum: only moving left rightwards can help
            } else {
                right--;    // need a smaller sum: only moving right leftwards can help
            }
        }
        return new int[0];
    }
}

3Sum: sort, anchor, two pointers

ThreeSum.java — LeetCode 15
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

/** LeetCode 15 - 3Sum. Sort, fix one element, two pointers on the rest. */
public class ThreeSum {

    public static List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        if (nums == null || nums.length < 3) return result;

        int[] a = nums.clone();
        Arrays.sort(a);
        int n = a.length;

        for (int i = 0; i < n - 2; i++) {
            // smallest is positive: no zero sum left
            if (a[i] > 0) break;
            if (i > 0 && a[i] == a[i - 1]) continue;    // skip duplicate anchors

            int left = i + 1;
            int right = n - 1;
            while (left < right) {
                long sum = (long) a[i] + a[left] + a[right];
                if (sum == 0) {
                    result.add(List.of(a[i], a[left], a[right]));
                    left++;
                    right--;
                    // skip duplicates
                    while (left < right && a[left] == a[left - 1]) left++;
                    // skip duplicates
                    while (left < right && a[right] == a[right + 1]) right--;
                } else if (sum < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }
        return result;
    }
}

Java 17+

TIME O(n²)

SPACE O(1) extra

Sorting is O(n log n). Output list excluded. We clone the input so the caller's array is not mutated.

INTUITION

Duplicate handling has exactly two places: skip an anchor equal to the previous anchor, and after recording a triplet skip over equal values on both sides. Skipping only one side leaves duplicate triplets such as [-2, 0, 2] appearing twice for [-2, 0, 0, 2, 2].

G. Variations of the Pattern

Container With Most Water (opposite pointers + greedy discard)

Choose two lines to maximise (j - i) * min(h[i], h[j]). Start with the widest container. The shorter wall caps the height, so any container that keeps that wall but is narrower is strictly no better; the shorter wall can be thrown away. Move the pointer at the shorter wall.

Figure 5. The dashed rectangle is the optimal container (width 7, height min(8,7) = 7).

ContainerWithMostWater.java — LeetCode 11

Java 17+

/** LeetCode 11 - Container With Most Water. Opposite pointers with a greedy discard rule. */
public class ContainerWithMostWater {

    public static int maxArea(int[] height) {
        int left = 0;
        int right = height.length - 1;
        int best = 0;
        while (left < right) {
            int width = right - left;
            int h = Math.min(height[left], height[right]);
            best = Math.max(best, width * h);
            // The shorter wall limits the area. Any container that keeps it but has a
            // smaller width can only be worse, so that wall can never be useful again.
            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }
        return best;
    }
}

Trapping Rain Water (brute force → arrays → two pointers)

Figure 6. Blue is trapped water. The tallest bar (3) acts as a wall for everything to its left that is bounded by a shorter right side.

Brute force: for each i scan left and right for the maxima: O(n²) time, O(1) space.
Bottleneck: the two maxima are recomputed from scratch for every index.
Optimisation 1: precompute leftMax[] and rightMax[]: O(n) time, O(n) space.
Optimisation 2: you only need min(leftMax, rightMax). If height[left] <

height[right], then rightMax ≥ height[right] > height[left], so the left side is the binding one and its water level is already known from leftMax. Process that side and move on: O(n) time, O(1) space.

TrappingRainWater.java — LeetCode 42 (two approaches)

Java 17+

/** LeetCode 42 - Trapping Rain Water: prefix/suffix arrays, then O(1)-space two pointers. */
public class TrappingRainWater {

    /** Approach 1: precompute max-to-the-left and max-to-the-right. O(n) time, O(n) space. */
    public static int trapWithArrays(int[] height) {
        int n = height.length;
        if (n < 3) return 0;
        int[] leftMax = new int[n];
        int[] rightMax = new int[n];
        leftMax[0] = height[0];
        for (int i = 1; i < n; i++) leftMax[i] = Math.max(leftMax[i - 1], height[i]);
        rightMax[n - 1] = height[n - 1];
        for (int i = n - 2; i >= 0; i--) rightMax[i] = Math.max(rightMax[i + 1], height[i]);

        int water = 0;
        for (int i = 0; i < n; i++) {
            water += Math.min(leftMax[i], rightMax[i]) - height[i];
        }
        return water;
    }

    /** Approach 2: two pointers. O(n) time, O(1) space. */
    public static int trap(int[] height) {
        int left = 0;
        int right = height.length - 1;
        int leftMax = 0;
        int rightMax = 0;
        int water = 0;
        while (left < right) {
            if (height[left] < height[right]) {
                // The right side already holds a wall at least as tall as height[left],
                // so the water level at 'left' is decided by leftMax alone.
                if (height[left] >= leftMax) leftMax = height[left];
                else water += leftMax - height[left];
                left++;
            } else {
                if (height[right] >= rightMax) rightMax = height[right];
                else water += rightMax - height[right];
                right--;
            }
        }
        return water;
    }
}

4Sum and the k-Sum generalisation

Add one more anchor loop. Each extra level multiplies by n, so k-Sum costs O(n^(k-1)) with two pointers at the bottom: 3Sum is O(n²), 4Sum is O(n³). The only new trap is overflow: four int values near 10⁹ do not fit in an int, so accumulate in long.

public class FourSum {

    public static List<List<Integer>> fourSum(int[] nums, int target) {

                    } else {
                        right--;
                    }

RemoveDuplicatesSorted.java — LeetCode 26

/**
 * LeetCode 26 - Remove Duplicates from Sorted Array. Same-direction (reader/writer) pointers.
 */
public class RemoveDuplicatesSorted {

    /** Compacts unique values to the front and returns their count. */
    public static int removeDuplicates(int[] nums) {
        if (nums.length == 0) return 0;
        int write = 1;                                   // next slot for a new unique value
        for (int read = 1; read < nums.length; read++) {
            if (nums[read] != nums[write - 1]) {         // differs from last kept value
                nums[write++] = nums[read];
            }
        }
        return write;
    }
}

/** LeetCode 283 - Move Zeroes. Stable in-place partition with reader/writer pointers. */
public class MoveZeroes {

    public static void moveZeroes(int[] nums) {
        int write = 0;
        for (int read = 0; read < nums.length; read++) {
            if (nums[read] != 0) {
                int tmp = nums[write];       // swap keeps zeros accumulating behind 'write'
                nums[write] = nums[read];
                nums[read] = tmp;
                write++;
            }
        }
    }
}

TIME O(n)

SPACE O(1)

Swapping (instead of overwriting then zero-filling) does at most one write per non-zero and keeps relative order.

Three-way partition: Dutch National Flag (Sort Colors)

Three pointers split the array into four zones: [0, low) are 0s, [low, mid) are 1s, [mid, high] is still unknown, and (high, n) are 2s. Because a value swapped in from high has not been inspected, mid must not advance after that swap.

Figure 8. Dutch National Flag on [2,0,2,1,1,0]. Pointer labels that share a cell are shown together (for example low,mid).

/** LeetCode 75 - Sort Colors. Dutch National Flag: three pointers, one pass. */
public class SortColors {

    public static void sortColors(int[] nums) {
        int low = 0;                    // next slot for a 0
        int mid = 0;                    // element under inspection
        int high = nums.length - 1;     // next slot for a 2
        while (mid <= high) {
            if (nums[mid] == 0) {
                swap(nums, low++, mid++);
            } else if (nums[mid] == 1) {
                mid++;
            } else {
                swap(nums, mid, high--);   // do NOT advance mid: swapped-in value is unchecked
            }
        }
    }

Fast and slow pointers on an array

Treat i → nums[i] as a linked list. With n + 1 values in [1, n], two indices must point at the

same value, so the list has a cycle whose entrance is the duplicate. Floyd's algorithm finds it without modifying the array and in O(1) space.

FindDuplicateFloyd.java — LeetCode 287

Java 17+

/**
 * LeetCode 287 - Find the Duplicate Number. Fast/slow pointers on an implicit graph i ->
 * nums[i].
 */
public class FindDuplicateFloyd {

    /**
     * Requires n+1 values in [1, n] with exactly one repeated value; array is not modified.
     */
    public static int findDuplicate(int[] nums) {
        int slow = nums[0];
        int fast = nums[0];
        do {                                // phase 1: find a meeting point inside the cycle
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);

        slow = nums[0];                     // phase 2: walk from start and meeting point
        while (slow != fast) {              // together; they meet at the cycle entrance
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }
}

TIME O(n)

SPACE O(1)

Phase 1 finds a meeting point; phase 2 works because distance(start → entrance) equals distance(meeting → entrance) modulo the cycle length.

J. Interview Tips

INTERVIEW

Say the invariant out loud: "left and right bound the region that may still contain an answer; everything outside is ruled out because the array is sorted."

Derive it, do not recall it: write the O(n²) double loop first, circle the inner loop, and ask what information the last comparison gave about the rest of the row.

State complexity with the sort: O(n log n) for the sort, then O(n) or O(n²) for the scan; mention O(1) extra space if you sort in place.

Follow-ups to expect: return indices instead of values (HashMap), count pairs instead of listing them (add right - left counts when sum < target), closest sum to target (3Sum Closest), k-Sum for arbitrary k (recursion on top of the 2-pointer base case), data stream too big to sort (hash + external sort).
Edge cases to mention before coding: empty or single-element arrays, all equal values, all negatives, target unreachable, duplicates, int overflow.
Potential optimisations: early break when the smallest remaining value exceeds a

positive target (3Sum), skipping when the minimum or maximum possible sum already misses the target (4Sum).

CHAPTER SUMMARY

Two pointers works when moving a pointer provably discards candidates (monotonic quantity, usually from sortedness).

Three templates: opposite (pairs / best-of-ends), reader-writer (in-place filtering), fast-slow (cycles, midpoints).

k-Sum costs O(n^(k-1)); use long for sums and skip duplicates on both sides after a hit.

Prove the discard with an exchange argument; say it aloud in the interview.
