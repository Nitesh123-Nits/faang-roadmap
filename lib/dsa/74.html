K-Way Merge

Merge k sorted sources by always taking the smallest front element.

A. Pattern Overview

Merging two sorted sequences needs two pointers. Merging k sorted sequences needs to find the smallest of k front elements at every step. A min-heap holding one "front" per source answers that in O(log k), so merging N total elements costs O(N log k) time and O(k) extra space. The same machine finds the k-th smallest of many sorted rows, the smallest pairs from two sorted arrays, and the smallest range that touches every list.

K-way merge: the template
PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
for (int i = 0; i < lists.length; i++)
    // {value, list, index}
    if (lists[i].length > 0) heap.offer(new int[] {lists[i][0], i, 0});

while (!heap.isEmpty()) {
    int[] cur = heap.poll();                       // smallest front overall
    out.add(cur[0]);
    int next = cur[2] + 1;
    if (next < lists[cur[1]].length)               // advance only that list
        heap.offer(new int[] {lists[cur[1]][next], cur[1], next});
}

Java 17+

KEY IDEA

The heap holds at most one element per source. Pop the smallest, then push the successor of the same source. The heap size never exceeds k, so each operation is O(log k), independent of how long the lists are.

B. When to Recognize This Pattern

Pattern Recognition Signals

"k sorted lists / arrays / streams" to merge, or an iterator over several sorted files.
"k-th smallest" in a sorted matrix (rows and columns sorted): each row is a sorted list.
"k smallest sums / pairs" from two sorted arrays: row i of the implicit matrix is a[i] + b[·].
"Smallest range covering one element from each list".
External sorting, log merging, database merge joins: merge many sorted runs on disk.
ONE-LINE TEST

Why it is correct

At every step the smallest not-yet-emitted element is the front of some list (lists are sorted), and every list front is in the heap. So the heap minimum is the global minimum of the remaining elements. Emitting it and exposing its successor preserves that invariant.

Merging linked lists reuses the nodes

For ListNode inputs the heap holds the nodes themselves, ordered by val. Polling a node, linking it to the output tail and offering its next merges everything in place, with O(1) extra nodes. Remember to skip null heads.

A matrix is k sorted lists in disguise

In a row-sorted matrix, each row is a sorted list. For the k-th smallest, seed the heap with the first element of the first min(n, k) rows and pop k times, each time pushing the right neighbour (378). Time O(k log min(n, k)). If the matrix is also column-sorted, binary search on the value is O(n log(max − min)) and uses no heap.

Smallest pairs: an implicit sorted matrix

Pairs (a[i], b[j]) form a matrix whose rows i are sorted by j (because b is sorted). Seed with (i, 0) for the first k indices of a; popping (i, j) pushes (i, j + 1). We never build all |a| · |b| pairs (373).

Smallest range covering all lists

Keep one element per list in the heap and track their maximum. The window [heap minimum, max] covers every list. Record it, then advance the list that supplied the minimum; stop when a list runs out (632).

KWayMerge.java: LeetCode 23, 378, 373, 632
import java.util.*;

/** Ch 62: merge k sorted sources with a min-heap; LeetCode 23, 378, 373, 632. */
public class KWayMerge {

    /** Merges k sorted int arrays. O(N log k) for N total elements. */
    public static int[] mergeSortedArrays(int[][] lists) {
        int total = 0;
        for (int[] l : lists) total += l.length;
        int[] out = new int[total];
        PriorityQueue<int[]> heap =
                new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        for (int i = 0; i < lists.length; i++) {
            if (lists[i].length > 0) heap.offer(new int[] {lists[i][0], i, 0});
        }
        int pos = 0;
        while (!heap.isEmpty()) {
            int[] cur = heap.poll();                  // {value, list, index}
            out[pos++] = cur[0];
            int next = cur[2] + 1;
            if (next < lists[cur[1]].length) {
                heap.offer(new int[] {lists[cur[1]][next], cur[1], next});
            }
        }
        return out;
    }

    /** LeetCode 23: merge k sorted linked lists. */
    public static ListNode mergeKLists(ListNode[] lists) {
        PriorityQueue<ListNode> heap =
                new PriorityQueue<>((a, b) -> Integer.compare(a.val, b.val));
        for (ListNode head : lists) if (head != null) heap.offer(head);
        ListNode dummy = new ListNode(0), tail = dummy;
        while (!heap.isEmpty()) {
            ListNode node = heap.poll();
            tail.next = node;
            tail = node;
            if (node.next != null) heap.offer(node.next);
        }
        return dummy.next;
    }

    /** LeetCode 378: k-th smallest in a row- and column-sorted matrix. */
    public static int kthSmallest(int[][] matrix, int k) {
        int n = matrix.length;
        PriorityQueue<int[]> heap =
                new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        for (int r = 0; r < Math.min(n, k); r++)
            heap.offer(new int[] {matrix[r][0], r, 0});
        int value = 0;
        for (int i = 0; i < k; i++) {
            int[] cur = heap.poll();
            value = cur[0];
            if (cur[2] + 1 < n)
                heap.offer(new int[] {matrix[cur[1]][cur[2] + 1], cur[1],
                        cur[2] + 1});
        }

        return value;
    }

    /** LeetCode 373: k pairs (u from a, v from b) with the smallest sums. */
    public static List<int[]> kSmallestPairs(int[] a, int[] b, int k) {
        List<int[]> out = new ArrayList<>();
        if (a.length == 0 || b.length == 0) return out;
        PriorityQueue<int[]> heap = new PriorityQueue<>(
                (x, y) -> Long.compare((long) a[x[0]] + b[x[1]],
                        (long) a[y[0]] + b[y[1]]));
        for (int i = 0; i < Math.min(a.length, k); i++)
            heap.offer(new int[] {i, 0});
        while (!heap.isEmpty() && out.size() < k) {
            int[] cur = heap.poll();                   // {index in a, index in b}
            out.add(new int[] {a[cur[0]], b[cur[1]]});
            if (cur[1] + 1 < b.length) heap.offer(new int[] {cur[0], cur[1] + 1});
        }
        return out;
    }

    /**
     * LeetCode 632: smallest range containing at least one number from each list.
     */
    public static int[] smallestRange(List<List<Integer>> nums) {
        PriorityQueue<int[]> heap =
                new PriorityQueue<>((x, y) -> Integer.compare(x[0], y[0]));
        int max = Integer.MIN_VALUE;
        for (int i = 0; i < nums.size(); i++) {
            int v = nums.get(i).get(0);
            heap.offer(new int[] {v, i, 0});
            max = Math.max(max, v);
        }
        int bestLo = heap.peek()[0], bestHi = max;
        while (true) {
            int[] cur = heap.poll();                   // the current minimum
            if (max - cur[0] < bestHi - bestLo) { bestLo = cur[0]; bestHi = max; }
            List<Integer> list = nums.get(cur[1]);
            // a list is exhausted: no more cover
            if (cur[2] + 1 == list.size()) break;
            int v = list.get(cur[2] + 1);
            heap.offer(new int[] {v, cur[1], cur[2] + 1});
            max = Math.max(max, v);
        }
        return new int[] {bestLo, bestHi};
    }
}

TIME O(N log k)

SPACE O(k)

N is the total number of emitted elements. Every heap entry stores {value, source, index}, so advancing needs no search. kSmallestPairs and kthSmallest stop after k pops, so they cost O(k log k)-ish rather than O(N log k).

G. Variations of the Pattern

Merge k sorted linked lists (23)

Heap of nodes, or divide and conquer. Null heads must be skipped; an empty lists array returns null.

K-th smallest in a sorted matrix (378)

Heap of {value, row, col} over the first min(n, k) rows. Alternative: binary search on the value with a staircase count, O(n log range), no heap.

Find K pairs with smallest sums (373)

Seed (i, 0) for i < min(|a|, k); pop (i, j), emit, push (i, j + 1). Compare sums as long.

Smallest range covering elements from k lists (632)

Heap of fronts plus a running max. Each advance updates the max; stop when the popped list has no successor.

Ugly numbers and other generated sequences

Ugly Number II (264) and Super Ugly Number (313) merge k implicit sorted streams (×2, ×3, ×5, …); Kth Smallest Prime Fraction (786) treats each denominator as a sorted list of fractions.

Offer divide and conquer as the alternative for linked lists, with the same O(N log

Mention external sorting: merging many sorted runs on disk is this pattern in production (database sort, LSM-tree compaction).

CHAPTER SUMMARY

K-way merge keeps a min-heap with one front per sorted source: pop the smallest, push that source's successor.

O(N log k) time, O(k) space; the heap never holds more than k entries, however long the lists are.

Store {value, source, index} (or the node) so advancing the right source is O(1).

Many problems are k-way merges in disguise: sorted matrices, smallest pairs, ugly numbers, smallest range.

Alternatives: pairwise divide and conquer (same bound), binary search on the value (matrices), a loser tree (external sort).
