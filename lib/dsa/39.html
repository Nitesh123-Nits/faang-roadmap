Basic Recursion Patterns

Base case, smaller problem, combine: three shapes of recursion.

A. Pattern Overview

A recursive function solves a problem by calling itself on a smaller instance of the same problem. Every correct recursion has the same three parts:

Base case: an input small enough to answer directly (it stops the recursion).
Recursive step: reduce the input and call the function (trust that the call returns the right answer: the recursive leap of faith).
Combine: turn the sub-answers into the answer for this input.

The shape of the recursion (how many calls, and how fast the input shrinks) decides the cost. Almost every recursive problem in this book is one of these three shapes:

KEY IDEA

Cost of a recursion = (number of calls) × (work per call). Draw the recursion tree: one node per call. Count the nodes, multiply by the work done in a node excluding its recursive calls. Everything in Part VI (subsets, permutations, N-Queens, Sudoku) is analysed this way.

B. When to Recognize This Pattern

Pattern Recognition Signals

The answer for n is described using the answer for a smaller input: x^n from x^(n/2), row n of a grammar from row n − 1, the winner of n players from the winner of n − 1.
Self-similar structure: nested brackets, trees, folders, fractal patterns, "do the same

thing to the rest".

A natural halving: "divide the exponent / range / string in two" gives O(log n) depth.
"Move n things using a helper" (Tower of Hanoi): the sub-problem uses the same rules

with different roles.

Overlapping sub-calls (the same arguments appear again and again) mean the plain recursion is exponential and the memoised version is a DP (Part XI).
ONE-LINE TEST

Ask: "If I had a magic function that solved every smaller input, how would I use it to solve this one?" If the answer takes one sentence, write that sentence as the recursive step.

C. Core Intuition with Illustrations

The call stack: recursion unwinds in reverse

Each call gets its own frame on the call stack holding its parameters and local variables. Calls are pushed on the way down and popped on the way back, so the combine step of the

deepest call runs first. Trace pow(2, 10): the halving calls go 10 → 5 → 2 → 1 → 0, and the

answers are combined on the way back up.

The recursion tree and why Fibonacci explodes

fib(n) = fib(n − 1) + fib(n − 2) makes two calls per node. The tree for fib(5) has 15 nodes; the same sub-problems (f(3), f(2)) are solved repeatedly, and the node count grows

like φⁿ ≈ 1.618ⁿ.

Figure 60. Plain recursion recomputes f(3) twice, f(2) three times.

Caching each answer the first time (memoisation) removes every repeated sub-tree: only the first call for each argument expands, the rest (grey) return at once, so there are O(n)

expansions instead of O(φⁿ).

Halving: one call, not two

x^n = (x^(n/2))² · (x if n is odd). Computing x^(n/2) once and squaring it keeps the recursion a single path of depth log n. Writing pow(x, n/2) * pow(x, n/2) makes two calls and silently restores O(n) work: store the half in a variable.

Trusting the recurrence: Hanoi

To move n disks from A to C using B: (1) move the top n − 1 disks A → B, (2) move the largest A

C, (3) move the n − 1 disks B → C. Steps 1 and 3 are the same problem with the pegs

relabelled. The move count satisfies M(n) = 2·M(n − 1) + 1, so M(n) = 2ⁿ − 1.

E. Java Implementation

Fast power by halving the exponent

FastPower.java: LeetCode 50

Java 17+

/** LeetCode 50 - Pow(x, n). Halve the exponent: x^n = (x^(n/2))^2 * (x if n is odd). */
public class FastPower {
    public static double myPow(double x, int n) {
        long e = n;                       // -Integer.MIN_VALUE overflows int
        if (e < 0) { x = 1 / x; e = -e; }
        return pow(x, e);
    }

    private static double pow(double x, long e) {
        if (e == 0) return 1;
        double half = pow(x, e / 2);      // one recursive call, depth O(log n)
        return (e % 2 == 0) ? half * half : half * half * x;
    }
}

TIME O(log n)

SPACE O(log n)

Recursion depth is log₂|n|. Convert n to long before negating: -Integer.MIN_VALUE overflows int.

K-th symbol in the grammar

KthSymbol.java: LeetCode 779

Java 17+

/** LeetCode 779 - K-th Symbol in Grammar. Row n is row n-1 with 0 -> 01 and 1 -> 10. */
public class KthSymbol {
    /** k is 1-based. The k-th symbol is the parent's symbol, flipped when k is even. */
    public static int kthGrammar(int n, int k) {
        if (n == 1) return 0;
        int parent = kthGrammar(n - 1, (k + 1) / 2);
        return (k % 2 == 1) ? parent : 1 - parent;
    }
}

TIME O(n)

SPACE O(n)

Symbol k of row n comes from symbol ⌈k/2⌉ of row n − 1; an

even k is the flipped second half of its parent's pair.

Josephus recurrence

Josephus.java: LeetCode 1823

Java 17+

/**
 * LeetCode 1823 - Find the Winner of the Circular Game. Recurrence f(n) = (f(n-1) + k) mod n,
 * 0-based.
 */
public class Josephus {
    public static int findTheWinner(int n, int k) {
        return winner(n, k) + 1;
    }

    private static int winner(int n, int k) {
        if (n == 1) return 0;
        return (winner(n - 1, k) + k) % n;
    }

    /** Direct simulation used as a test oracle. */
    public static int simulate(int n, int k) {
        java.util.ArrayList<Integer> ring = new java.util.ArrayList<>();
        for (int i = 1; i <= n; i++) ring.add(i);
        int idx = 0;
        while (ring.size() > 1) {
            idx = (idx + k - 1) % ring.size();
            ring.remove(idx);
        }
        return ring.get(0);
    }
}

TIME O(n)

SPACE O(n)

After the first removal, the circle has n − 1 people and the counting restarts k places later: the winner's index shifts by k modulo n. The simulate method is the oracle used by the tests.

Tower of Hanoi

Hanoi.java

Java 17+

import java.util.ArrayList;
import java.util.List;

/**
 * Tower of Hanoi: to move n disks, park n-1 on the spare peg, move the largest, then stack
 * n-1 on top.
 */
public class Hanoi {
    public static List<String> moves(int n) {
        List<String> out = new ArrayList<>();
        solve(n, 'A', 'C', 'B', out);
        return out;
    }

    private static void solve(int n, char from, char to, char via,
            List<String> out) {
        if (n == 0) return;
        solve(n - 1, from, via, to, out);          // clear the way
        out.add(n + ":" + from + "->" + to);       // move the largest
        solve(n - 1, via, to, from, out);          // rebuild on top of it
    }
}

TIME O(2ⁿ)

SPACE O(n)

The output has 2ⁿ − 1 moves, so exponential time is

unavoidable; the stack is only n deep.

G. Variations of the Pattern

Divide and conquer

Split the input into independent parts, solve each, merge: merge sort (T(n) = 2T(n/2) + O(n) = O(n log n)), quick select, Different Ways to Add Parentheses (241), Special Binary String (761). The parts must not overlap; otherwise memoise.

Tail recursion and conversion to loops

If the recursive call is the very last action (return f(n − 1, acc * n)), the function can become a loop. The JVM does not optimise tail calls, so a depth of 10⁵ throws StackOverflowError; convert such recursions into loops, or use an explicit Deque as the stack.

Mutual recursion

Two functions call each other (isEven / isOdd, a recursive-descent parser from Chapter 26). The same three parts apply.

Recursion on structure (preview)

Trees (Part VII), graphs (Part VIII, DFS) and linked lists (Part IV) are recursive structures: their natural algorithms are recursions on left / right or on next.

Memoisation: when sub-calls repeat

If a recursion on (i, j, …) is called twice with the same arguments, cache the result keyed by the arguments. A pure function with k distinct states and w work per state costs O(k·w). This is top-down DP (Part XI).

J. Interview Tips

INTERVIEW

State the three parts out loud (base case, step, combine) before writing code. Interviewers listen for the base case first.

Draw the recursion tree for a tiny input, count the nodes, and give the complexity from it. Then say whether sub-problems repeat.

Mention the stack depth and the JVM's lack of tail-call optimisation when the depth can be n.

Follow-ups: convert to iteration; handle n = 10⁹ (depth 30) vs a linear recursion on 10⁹

(impossible); compute x^n mod m; print the Hanoi moves with a StringBuilder; why is fib(50) slow and how do you fix it.

Edge cases: n = 0, negative n, Integer.MIN_VALUE, x = 0, x = ±1, k = 1 in Josephus, n = 1

rows.

CHAPTER SUMMARY

A recursion needs a base case, a smaller sub-problem and a combine step; trust the recursive call.

Cost = number of calls × work per call: draw the recursion tree. Linear recursion has depth n, halving has depth log n, branching can be exponential.

Call once, reuse the result (half = pow(x, n/2)); two calls restore the cost you were trying to remove.

If sub-calls repeat, memoise: this converts exponential recursion to polynomial (Part XI).

Java does not eliminate tail calls; keep depth small or convert to loops. Promote to long before negating an int.
