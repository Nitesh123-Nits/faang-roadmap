Calendar and Booking Problems

Online booking: keep intervals in a TreeMap and test two neighbours.

A. Pattern Overview

Calendar problems are online versions of the interval patterns: bookings arrive one at a time and each must be answered immediately. Three questions cover the family: can I book without any overlap (My Calendar I), can I book without a triple booking (My Calendar II), and what is the maximum number of simultaneous bookings so far (My Calendar III). A TreeMap of start to end (or time to delta) answers each in O(log n) or O(n) without sorting again. A related problem, Count Integers in Intervals, keeps a merged set and a running total.

KEY IDEA

In a set of disjoint intervals only two neighbours can conflict with a new one: the interval that starts last before it and the interval that starts first after it. That is why one lowerEntry and one ceilingKey suffice.

B. When to Recognize This Pattern

Pattern Recognition Signals

A class with book(start, end) that must answer on every call.
"Double booking", "triple booking", "k-booking".
Overlap limits: at most one, at most two, the maximum so far.
Room, seat, or slot reservation systems with intervals.
Dynamic sets of ranges (add, count covered) where the number of operations is large.
ONE-LINE TEST

book(start, end) called many times: sorted map, test the neighbours (or keep deltas).

C. Core Intuition with Illustrations

My Calendar I: disjoint set plus two checks

Bookings [10,20), [15,25), [20,30). Booking [10,20) succeeds. [15,25): the predecessor [10,20) ends at 20 > 15, so it overlaps: false. [20,30): predecessor [10,20) ends at 20, not > 20; no booking starts in [20,30): true.

Figure 121. My Calendar I: the middle booking collides with the first.

My Calendar II: keep the double-booked ranges

A third booking is forbidden wherever two already exist. Keep booked (all accepted bookings) and doubled (the ranges covered at least twice). A new [s, e) is rejected if it overlaps any range in doubled. Otherwise accept it and add its intersection with every booked range to doubled.

My Calendar III: deltas and the maximum

After each booking, add +1 at start and -1 at end to a sorted map and walk it with a running sum. The maximum prefix sum is the largest number of simultaneous bookings. Same sample sequence:

Each call is O(n) here because we re-walk the map; a segment tree with lazy range add and global max makes it O(log C).

Count Integers in Intervals (2276)

Keep disjoint closed intervals in a TreeMap and a running total. add(l, r): if the predecessor reaches l, extend left; absorb every interval starting in [l, r], subtracting their old lengths; insert the merged interval and add its length.

Choosing the structure

TreeMap neighbour checks need the invariant disjoint. Once overlaps are allowed (II and III), the neighbour trick no longer works and you either keep derived data (the doubled ranges) or work with deltas and a sweep.

E. Java Implementation

My Calendar I, II, III and Count Integers in Intervals

Booking.java: LeetCode 729, 731, 732, 2276
import java.util.*;

/** Ch 77: calendar and booking problems; LeetCode 729, 731, 732, 2276. */
public class Booking {

    /** LeetCode 729: book [start, end) only if it overlaps nothing booked. */
    public static class MyCalendar {
        private final TreeMap<Integer, Integer> map = new TreeMap<>();

        public boolean book(int start, int end) {
            Map.Entry<Integer, Integer> before = map.lowerEntry(start);
            if (before != null && before.getValue() > start) return false;
            Integer after = map.ceilingKey(start);
            if (after != null && after < end) return false;
            map.put(start, end);
            return true;
        }
    }

    /** LeetCode 731: allow double bookings, reject any triple booking. */
    public static class MyCalendarTwo {
        private final List<int[]> booked = new ArrayList<>();
        private final List<int[]> doubled = new ArrayList<>();

        public boolean book(int start, int end) {
            for (int[] d : doubled)
                if (start < d[1] && d[0] < end) return false;   // would be a triple
            for (int[] b : booked) {

Java 17+

                int lo = Math.max(start, b[0]), hi = Math.min(end, b[1]);
                if (lo < hi) doubled.add(new int[]{lo, hi});
            }
            booked.add(new int[]{start, end});
            return true;
        }
    }

    /** LeetCode 732: after each booking, the maximum k-booking so far. */
    public static class MyCalendarThree {
        private final TreeMap<Integer, Integer> delta = new TreeMap<>();

        public int book(int start, int end) {
            delta.merge(start, 1, Integer::sum);
            delta.merge(end, -1, Integer::sum);
            int live = 0, best = 0;
            for (int d : delta.values()) {
                live += d;
                best = Math.max(best, live);
            }
            return best;
        }
    }

    /**
     * LeetCode 2276: add closed integer intervals; count the integers covered.
     * Disjoint intervals in a TreeMap; each add absorbs what it overlaps.
     */
    public static class CountIntervals {
        private final TreeMap<Integer, Integer> map = new TreeMap<>();
        private int total = 0;

        public void add(int l, int r) {
            Map.Entry<Integer, Integer> f = map.floorEntry(l);
            if (f != null && f.getValue() >= l) {
                l = f.getKey();
                r = Math.max(r, f.getValue());
            }
            Map<Integer, Integer> inside = map.subMap(l, true, r, true);
            for (Map.Entry<Integer, Integer> e : inside.entrySet()) {
                total -= e.getValue() - e.getKey() + 1;
                r = Math.max(r, e.getValue());
            }
            inside.clear();
            map.put(l, r);
            total += r - l + 1;
        }

        public int count() { return total; }
    }
}

G. Variations of the Pattern

My Calendar I (729)

Half-open intervals: [a, b) and [b, c) are compatible. The two-neighbour test uses strict comparisons accordingly.

My Calendar II and III (731, 732)

Overlaps are allowed, so neighbours are not enough. Keep doubled ranges (II) or deltas (III). For many calls use a segment tree over compressed coordinates.

Count Integers in Intervals (2276)

Closed integer intervals with a running total; the same absorbing structure as Range Module (Chapter 72).

Exam Room (855) and seat managers

Maintain the set of occupied seats (or gaps) in a sorted structure; the best new seat is in the largest gap, found with a heap of gaps or a TreeSet.

Interval scheduling with k resources

A booking succeeds iff the peak overlap stays <= k: maintain the delta map and test the maximum (generalises II to any k).

J. Interview Tips

INTERVIEW

Start from the invariant: for Calendar I, disjoint intervals in a sorted map, so only two neighbours can conflict.

Clarify half-open before writing comparisons: the examples use [start, end).

For II and III, say why the neighbour trick fails and what you keep instead (double-booked ranges, deltas).

Follow-ups: support cancellation (store ids or remove from the map); thread safety; k-booking with a limit; large C with a dynamic segment tree.
Edge cases: identical bookings, touching bookings, a booking containing all others,

zero-length requests, calls in decreasing order of start.

CHAPTER SUMMARY

Online booking answers every book(start, end) call immediately; sorted maps replace re-sorting.

Calendar I: disjoint intervals in a TreeMap; only the predecessor and the successor can conflict (O(log n)).

Calendar II: keep the double-booked ranges; reject any booking that overlaps one, otherwise add its intersections with existing bookings.

Calendar III: keep time to delta; the maximum running sum is the answer (segment tree for scale).

Count Intervals and Range Module are the same absorbing map with a running total or add/remove/query operations.
