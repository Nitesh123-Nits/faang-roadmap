Permutations

All arrangements: n!, with duplicates, next order, k-th order.

A. Pattern Overview

A permutation is an arrangement of all n elements where order matters; there are n! of them (n = 8 gives 40 320, n = 10 gives 3 628 800). At depth d the search chooses which unused element goes in position d, so the tree has n children at the root, n − 1 at depth 1, and so on.

KEY IDEA

Listing needs backtracking, but finding one specific permutation (next, k-th) does not: use the structure of lexicographic order instead. Interviewers like candidates who notice the difference.

B. When to Recognize This Pattern

Pattern Recognition Signals

"All possible orderings / arrangements / rearrangements / permutations".
Every element is used exactly once and order matters ([1, 2] and [2, 1] are different answers).
"Rearrange the numbers into the next greater arrangement" → next permutation.
"Return the k-th …" over permutations → factorial number system, no enumeration.
Duplicates in the input and "unique" results → sort and skip same-level repeats.
ONE-LINE TEST

If every element must appear and swapping two of them gives a different answer, it is a permutation problem. If the answer is a selection, it is subsets or combinations.

C. Core Intuition with Illustrations

The permutation tree

Each level fixes one more position. For [1, 2, 3] there are 3 · 2 · 1 = 6 leaves, and the tree has 3 + 6 + 6 = 15 nodes below the root.

Figure 67. Level 1 has 3 choices, level 2 has 2, level 3 has 1: the leaf count is 3!.

Two ways to track what is used
used[] flags: simple; a loop over all n indices at every level, skipping used ones. Output order follows the input order.
Swap into place: the prefix a[0..pos) is fixed; swap each a[i] (i ≥ pos) into position pos,

recurse, swap back. No extra array, but output order is not lexicographic.

Duplicates: the leftmost unused twin goes first

Sort so equal values are adjacent. When position d is filled, an element a[i] equal to a[i−1] may be used only if a[i−1] is already used on the current path; otherwise we would be picking the right twin before the left twin, which yields the same arrangement twice.

Figure 68. Three unique permutations instead of six.

Next permutation: three moves

To step to the next arrangement in lexicographic order: (1) find the rightmost ascent a[i] < a[i+1]; the suffix after i is non-increasing, so it is already the largest arrangement of its elements. (2) Swap a[i] with the smallest suffix element larger than it. (3) Reverse the suffix (it is still non-increasing after the swap) to make it the smallest. If there is no ascent, the array is the last permutation: reversing the whole array gives the first.

The k-th permutation: the factorial number system

Permutations of n elements in lexicographic order split into n blocks of size (n − 1)!, one

per leading digit. So the leading digit is index ⌊(k−1) / (n−1)!⌋ of the remaining digits, and

k becomes (k−1) mod (n−1)! for the rest. Example: n = 4, k = 9.

E. Java Implementation

Permutations: used flags and swaps

Permutations.java: LeetCode 46

Java 17+

import java.util.ArrayList;
import java.util.List;

/** LeetCode 46 - Permutations. Two standard formulations. */
public class Permutations {
    /** 1. used[] flags: at each position try every unused element. */
    public static List<List<Integer>> withUsed(int[] nums) {
        List<List<Integer>> out = new ArrayList<>();
        build(nums, new boolean[nums.length], new ArrayList<>(), out);
        return out;
    }

    private static void build(int[] nums, boolean[] used, List<Integer> cur,
            List<List<Integer>> out) {
        if (cur.size() == nums.length) { out.add(new ArrayList<>(cur)); return; }
        for (int i = 0; i < nums.length; i++) {
            if (used[i]) continue;
            used[i] = true;
            cur.add(nums[i]);
            build(nums, used, cur, out);
            cur.remove(cur.size() - 1);
            used[i] = false;
        }
    }

    /**
     * 2. In-place swaps: the prefix [0, pos) is fixed; swap each candidate into position pos.
     */
    public static List<List<Integer>> withSwaps(int[] nums) {
        List<List<Integer>> out = new ArrayList<>();
        swapBuild(nums.clone(), 0, out);
        return out;
    }

    private static void swapBuild(int[] a, int pos, List<List<Integer>> out) {
        if (pos == a.length) {
            List<Integer> p = new ArrayList<>(a.length);
            for (int x : a) p.add(x);
            out.add(p);
            return;
        }
        for (int i = pos; i < a.length; i++) {
            swap(a, pos, i);
            swapBuild(a, pos + 1, out);
            swap(a, pos, i);
        }
    }

    private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j];
            a[j] = t; }
}

TIME O(n · n!)

SPACE O(n)

withUsed keeps input order; withSwaps clones the array first and swaps back after each recursive call (the unchoose).

Permutations II: sort and skip twins

PermutationsII.java: LeetCode 47

Java 17+

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

/**
 * LeetCode 47 - Permutations II. Sort; among equal values only the leftmost unused one may
 * start a branch.
 */
public class PermutationsII {
    public static List<List<Integer>> permuteUnique(int[] nums) {
        int[] a = nums.clone();
        Arrays.sort(a);
        List<List<Integer>> out = new ArrayList<>();
        build(a, new boolean[a.length], new ArrayList<>(), out);
        return out;
    }

    private static void build(int[] a, boolean[] used, List<Integer> cur,
            List<List<Integer>> out) {
        if (cur.size() == a.length) { out.add(new ArrayList<>(cur)); return; }
        for (int i = 0; i < a.length; i++) {
            if (used[i]) continue;
            // duplicate: its twin must be taken first
            if (i > 0 && a[i] == a[i - 1] && !used[i - 1]) continue;
            used[i] = true;
            cur.add(a[i]);
            build(a, used, cur, out);
            cur.remove(cur.size() - 1);
            used[i] = false;
        }
    }
}

TIME O(n · n!)

SPACE O(n)

The condition !used[i−1] means the left twin is not on the current path, so choosing a[i] now would duplicate an arrangement.

Next permutation in place

NextPermutation.java: LeetCode 31

Java 17+

/** LeetCode 31 - Next Permutation, in place, O(n) time and O(1) space. */
public class NextPermutation {
    public static void nextPermutation(int[] a) {
        int i = a.length - 2;
        while (i >= 0 && a[i] >= a[i + 1]) i--;          // rightmost ascent a[i] < a[i+1]
        if (i >= 0) {
            int j = a.length - 1;
            // smallest value in the suffix that exceeds a[i]
            while (a[j] <= a[i]) j--;
            swap(a, i, j);
        }
        // suffix is descending: make it ascending
        reverse(a, i + 1, a.length - 1);
    }

    private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j];
            a[j] = t; }

    private static void reverse(int[] a, int l, int r) {
        while (l < r) swap(a, l++, r--);
    }
}

TIME O(n)

SPACE O(1)

>= in the ascent scan makes equal elements behave correctly ([1,1,5] → [1,5,1]). The suffix is non-increasing, so one reversal sorts it.

Permutation sequence (k-th)

PermutationSequence.java: LeetCode 60

Java 17+

import java.util.ArrayList;
import java.util.List;

/**
 * LeetCode 60 - Permutation Sequence. Factorial number system: the leading digit is (k-1) /
 * (n-1)!.
 */
public class PermutationSequence {
    public static String getPermutation(int n, int k) {
        int[] fact = new int[n];
        fact[0] = 1;
        for (int i = 1; i < n; i++) fact[i] = fact[i - 1] * i;
        List<Integer> digits = new ArrayList<>();
        for (int d = 1; d <= n; d++) digits.add(d);
        StringBuilder sb = new StringBuilder();
        k--;                                              // switch to 0-based rank
        for (int pos = n - 1; pos >= 0; pos--) {
            int idx = k / fact[pos];
            sb.append(digits.remove(idx));
            k %= fact[pos];
        }
        return sb.toString();
    }
}

TIME O(n²)

SPACE O(n)

List.remove(int) is O(n), giving O(n²) overall, which is fine for n ≤ 9. Convert k to 0-based first.

Letter tile possibilities

LetterTilePossibilities.java: LeetCode 1079

Java 17+

/**
 * LeetCode 1079 - Letter Tile Possibilities. Count non-empty sequences by branching on letter
 * counts (no duplicates by construction).
 */
public class LetterTilePossibilities {
    public static int numTilePossibilities(String tiles) {
        int[] count = new int[26];
        for (char c : tiles.toCharArray()) count[c - 'A']++;
        return dfs(count);
    }

    private static int dfs(int[] count) {
        int total = 0;
        for (int c = 0; c < 26; c++) {
            if (count[c] == 0) continue;
            count[c]--;                                   // choose a letter
            // this sequence, plus every extension
            total += 1 + dfs(count);
            count[c]++;                                   // unchoose
        }
        return total;
    }
}

TIME O(sequences)

SPACE O(1) + depth

Branching on letter counts (not positions) cannot produce the same sequence twice, so no set is needed.

G. Variations of the Pattern

Partial permutations

Arrangements of k out of n stop at depth k: n!/(n−k)! leaves. Letter Tile Possibilities counts every depth.

Permutations with constraints

Beautiful Arrangement (526) and Permutations with a divisibility rule test each placement and prune, which turns n! into a much smaller search (Chapter 39). Permutation in String (567) is a sliding window, not enumeration.

Previous permutation and ranking

Previous Permutation With One Swap (1053) mirrors next permutation. The rank of a permutation (the inverse of the k-th problem) uses the same factorial weights.

Heap's algorithm

Generates all permutations with one swap per step; useful when only the transition matters. It is an iterative alternative to recursive swapping.

Cyclic and circular arrangements

Fix one element to remove rotations: (n − 1)! circular arrangements. Find the Winner of the Circular Game (Chapter 30) uses a recurrence instead.

J. Interview Tips

INTERVIEW

Say which problem you are solving: list all (backtracking) vs find one (next / k-th: direct formula). Choosing the direct method for the latter is the senior answer.

For duplicates, justify the rule with [1, 1]: two identical leaves come from taking the right 1 first.

For next permutation, narrate the suffix: "the suffix is non-increasing, so it is the largest arrangement of those elements; I need the next larger prefix and then the smallest suffix."

Follow-ups: previous permutation; rank of a permutation; permutations of a string with

duplicates in sorted order; generate with O(1) extra space (Heap's algorithm); count

unique permutations without listing (n! / ∏ cᵢ!).

Edge cases: n = 0 or 1, all elements equal, already descending (wrap-around), n = 9, k = n!.

CHAPTER SUMMARY

Permutations = every arrangement; at each position try every unused element. Count n!; listing is Θ(n · n!).

Track usage with used[] or by swapping into place (and swapping back).

Duplicates: sort; use a[i] only if i == 0, a[i] != a[i−1], or the left twin a[i−1] is already used.

Next permutation is O(n): rightmost ascent, swap with the next larger suffix element, reverse the suffix.

k-th permutation needs no enumeration: divide k − 1 by (n−1)!, (n−2)!, … to pick digits (factorial number system).
