Meeting Rooms

How many meetings overlap at once? Heap of end times or a sweep line.

A. Pattern Overview

The meeting-rooms family asks two questions about a list of [start, end) intervals: can one person attend all of them (no overlap), and how many rooms are needed (the maximum number of meetings in progress at the same instant). Both reduce to ordering events in time. There are two standard solutions to the second: a min-heap of end times and a sweep line over sorted starts and ends; both are O(n log n).

KEY IDEA

The number of rooms equals the maximum overlap. Intervals form an interval graph, which is perfect: the chromatic number equals the clique number. No cleverness is needed beyond counting how many meetings are live at the busiest instant.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Minimum number of rooms / platforms / machines / CPUs" for time intervals.
"Can a person attend all meetings" (any overlap fails).
"Maximum number of simultaneous …" (guests at a party, trains at a station, overlapping bookings).
Intervals plus a capacity (car pooling): the same sweep with weights.
"Employee free time" / gaps between merged intervals (a sweep or merge).
ONE-LINE TEST

Count of resources = peak concurrency: sort starts and ends, or keep a heap of end times.

C. Core Intuition with Illustrations

The timeline

Meetings [0,30) [5,10) [15,20) [7,12) [25,35). At time 8 three meetings are live ([0,30), [5,10), [7,12)); that is the peak, so 3 rooms are needed.

Maximum rooms in use: 3. The heap's size is the number of rooms allocated; it never shrinks below the number of live meetings.

Why the heap works

Process meetings by start time. The heap holds one end time per occupied room. The smallest end time is the room that frees up first. If it is ≤ the new start, reuse it (pop, then push the new end); otherwise a new room is needed (push). The heap size after processing is the number of rooms in use.

Sweep line without a heap

Sort all starts and all ends separately. Walk the starts; for each start, first retire every meeting whose end is ≤ that start (ties: ends first, because [a, b) and [b, c) do not overlap), then count the new meeting. Track the maximum count. No heap and no objects, only two sorted int[].

Events form: +1 and −1

The sweep line generalises: emit an event (time, +1) at each start and (time, −1) at each end, sort by time (−1 before +1 on ties), and keep a running sum. The maximum prefix sum is the peak. With weights (Car Pooling) the ±1 becomes ±passengers.

Rooms with identities (2402)

When meetings must take the lowest-numbered free room, and a delayed meeting keeps its duration, use two heaps: free rooms ordered by index and busy rooms ordered by (end time, index). Before each meeting, release every busy room that has ended; if no room is free, take the busy room that ends first and delay the meeting.

E. Java Implementation

Attend all, rooms with a heap, rooms with a sweep, most booked room

MeetingRooms.java: LeetCode 252, 253, 2402
import java.util.*;

/** Ch 66: meeting rooms; LeetCode 252, 253, 2402 (and the sweep-line idea). */
public class MeetingRooms {

    /**
     * LeetCode 252: can one person attend every meeting? Touching ends are fine.
     */
    public static boolean canAttendMeetings(int[][] intervals) {
        int[][] sorted = intervals.clone();
        Arrays.sort(sorted, Comparator.comparingInt(iv -> iv[0]));
        for (int i = 1; i < sorted.length; i++) {
            if (sorted[i][0] < sorted[i - 1][1]) return false;   // overlap
        }
        return true;
    }

    /** LeetCode 253 with a min-heap of end times: one entry per room in use. */
    public static int minMeetingRoomsHeap(int[][] intervals) {
        int[][] sorted = intervals.clone();
        Arrays.sort(sorted, Comparator.comparingInt(iv -> iv[0]));
        PriorityQueue<Integer> ends = new PriorityQueue<>();
        for (int[] iv : sorted) {
            // reuse that room
            if (!ends.isEmpty() && ends.peek() <= iv[0]) ends.poll();
            ends.offer(iv[1]);
        }
        return ends.size();
    }

    /** LeetCode 253 with two sorted arrays (a sweep line): no heap, O(n log n). */
    public static int minMeetingRoomsSweep(int[][] intervals) {
        int n = intervals.length;
        int[] starts = new int[n], ends = new int[n];
        for (int i = 0; i < n; i++)
            { starts[i] = intervals[i][0]; ends[i] = intervals[i][1]; }
        Arrays.sort(starts);
        Arrays.sort(ends);
        int rooms = 0, best = 0, e = 0;
        for (int s = 0; s < n; s++) {
            // ends first on ties
            while (e < n && ends[e] <= starts[s]) { e++; rooms--; }
            rooms++;
            best = Math.max(best, rooms);
        }
        return best;
    }

    /**
     * LeetCode 2402: meetings take the lowest-numbered free room, or wait for the
     * earliest room to free up. Returns the room that hosted the most meetings.
     */
    public static int mostBooked(int n, int[][] meetings) {
        int[][] sorted = meetings.clone();
        Arrays.sort(sorted, Comparator.comparingInt(m -> m[0]));
        PriorityQueue<Integer> free = new PriorityQueue<>();
        for (int r = 0; r < n; r++) free.offer(r);

Java 17+

        PriorityQueue<long[]> busy = new PriorityQueue<>((a, b) ->
                a[0] != b[0] ? Long.compare(a[0], b[0]) : Long.compare(a[1], b[1]));
        int[] count = new int[n];
        for (int[] m : sorted) {
            while (!busy.isEmpty() && busy.peek()[0] <= m[0])
                free.offer((int) busy.poll()[1]);
            long start = m[0];
            int room;
            if (!free.isEmpty()) room = free.poll();
            else {
                // wait for the earliest room
                long[] first = busy.poll();
                start = first[0];
                room = (int) first[1];
            }
            count[room]++;
            busy.offer(new long[] {start + (m[1] - m[0]), room});
        }
        int best = 0;
        for (int r = 1; r < n; r++) if (count[r] > count[best]) best = r;
        return best;
    }
}

TIME O(n log n)

SPACE O(n)

Sorting dominates in all three versions. The heap variant never holds more than the answer's number of rooms; the sweep variant stores two sorted copies. mostBooked uses long end times because delays can push meetings far beyond the input range.

F. Detailed Dry Run

Sorted by start: [0,30) [5,10) [7,12) [15,20) [25,35). [0,30): heap [30]. [5,10): smallest end 30 > 5, so a new room: [10, 30]. [7,12): smallest end 10 > 7, new room: [10, 12, 30] (3 rooms). [15,20): smallest end 10 ≤ 15, so reuse: pop 10, push 20 → [12, 20, 30]. [25,35): smallest end 12 ≤ 25, reuse: [20, 30, 35]. Maximum size 3.

Sweep version: starts [0,5,7,15,25], ends [10,12,20,30,35]. At start 0: 1 room. 5: ends ≤ 5 none, 2 rooms. 7: 3 rooms. 15: retire ends 10 and 12 → 1 live, +1 = 2. 25: retire 20 → 1, +1 = 2. Peak 3.

G. Variations of the Pattern

Meeting Rooms (252)

Sort by start and check adjacent pairs; or compare the number of rooms with 1.

Car Pooling (1094)

Weights on the events: +passengers at pickup, −passengers at drop-off; check that the running sum never exceeds capacity. With stops in [0, 1000] a difference array is simplest. (A CarPooling solution already exists in Part I.)

Divide Intervals Into Minimum Number of Groups (2406)

Identical to Meeting Rooms II, with closed intervals: touching intervals overlap, so retire ends < start, not ≤.

Employee Free Time (759)

Flatten all schedules, sort by start, sweep keeping the maximum end so far; gaps between that end and the next start are free time.

My Calendar I / II / III (729, 731, 732)

Online booking with overlap limits: a sorted map of start → delta, or a segment tree; Chapter 77 builds this.

J. Interview Tips

INTERVIEW

Open with the invariant: "rooms needed = maximum overlap"; then offer both solutions and the tie-breaking rule at equal timestamps.

Clarify half-open vs closed intervals before writing < or <=.

For 2402, name the two heaps and what each one orders by: free rooms by index, busy rooms by end time then index.

Follow-ups: return an actual room assignment (store room ids in the heap); online

bookings (sorted map or segment tree); weighted capacity (car pooling); lowest-index room preference (2402); minimise the number of room changes.

Edge cases: identical meetings, back-to-back meetings, one meeting spanning everything, n = 0 or n = 1, huge timestamps.

CHAPTER SUMMARY

Rooms needed = maximum number of meetings in progress at once. Two O(n log

methods: a min-heap of end times or a sweep over sorted starts and ends.

Heap rule: if the earliest end is ≤ the new start, reuse that room (pop), then push the new end; the heap size is the room count.

Tie-break at equal timestamps (half-open: retire ends first; closed: starts first) is the classic bug.

Weights turn the sweep into ±amount events (Car Pooling); room identities need {end, room} entries (Meeting Rooms III).

Contrast: select the most meetings (Chapter 65, sort by end) vs allocate resources for all of them (this chapter).
