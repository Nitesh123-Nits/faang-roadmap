Unbounded and Unknown-Size Search

No length? Double the boundary until it overshoots, then binary search the bracket.

A. Pattern Overview

Binary search needs a right end. When the array length is unknown (a stream, a paged API, an ArrayReader with no length()) or the domain is unbounded ("smallest x such that f(x) ≥ target" with no upper limit), first find a bracket [lo, hi] that must contain the answer by doubling hi, then run an ordinary binary search inside it. This is exponential search (also called galloping or doubling search).

KEY IDEA

Two phases: (1) Grow: lo = hi; hi *= 2 until get(hi) >= target. (2) Shrink: binary search [lo, hi]. If the answer is at position p, phase 1 takes O(log p) probes and the bracket has size O(p), so phase 2 also takes O(log p). Total O(log p), independent of the (possibly enormous or infinite) array size.

B. When to Recognize This Pattern

Pattern Recognition Signals

The statement says "unknown size", "infinite", "you cannot call length()", or hides the array behind an interface with get(i).
Out-of-range reads return a sentinel (Integer.MAX_VALUE, null, an error code) instead of

throwing.

The search domain is all positive integers and a monotone function decides if a candidate is too small.
You need O(log p) where p is the answer's position, not the container size.
DECISION RULE

Sorted + "no right bound" → first manufacture the right bound by doubling. Then it is Chapter 12 again.

INTUITION

Out-of-range handling is the trick. If reads past the end return Integer.MAX_VALUE, they behave like an enormous value, so the doubling loop stops and the binary search steers left. If the real API throws, catch it (or call a bounds check) and treat it as "too large".

D. Brute Force to Optimal Solution

Example: Search in a Sorted Array of Unknown Size (LeetCode 702, premium)

Brute force: scan get(0), get(1), … until found or the sentinel appears: O(p).
Fixed big right bound: set hi = 10⁴ and binary search. Works only because theconstraints cap the size; reads O(log 10⁴) always, and fails if the cap is wrong.
Optimal: doubling to find the bracket (O(log p)), then binary search (O(log p)): correct for any size.

E. Java Implementation

SearchUnknownSize.java — LeetCode 702 (ArrayReader interface supplied by the judge)

Java 17+

/** Provided by the judge: returns Integer.MAX_VALUE for any index past the end. */
interface ArrayReader {
    int get(int index);
}

/**
 * LeetCode 702 - Search in a Sorted Array of Unknown Size (premium). Exponential search +
 * binary search.
 */
public class SearchUnknownSize {

    public static int search(ArrayReader reader, int target) {
        if (reader.get(0) == target) return 0;

        int lo = 0;
        int hi = 1;
        // Phase 1: double the right edge until it reaches or passes the target.
        while (hi < (1 << 30) && reader.get(hi) < target) {
            lo = hi;                    // everything up to hi is too small
            hi <<= 1;
        }
        // Phase 2: ordinary binary search inside [lo, hi]. Out-of-range reads return MAX_VALUE,
        // which behaves like "too large" and steers the search left.
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            int value = reader.get(mid);
            if (value == target) {
                return mid;
            } else if (value > target) {
                hi = mid - 1;
            } else {
                lo = mid + 1;
            }
        }
        return -1;
    }
}

TIME O(log p)

SPACE O(1)

The guard hi < (1 << 30) prevents int overflow while doubling. The search never calls length().

G. Variations of the Pattern

Monotone function with no upper bound

"Find the smallest x ≥ 1 with f(x) ≥ goal" where f is increasing and x may reach 10¹².

Double hi until f(hi) ≥ goal, then binary search (hi/2, hi]. Use long, and cap the

doubling.

Template: smallest x with f(x) >= goal, unbounded domain
long hi = 1;
while (f(hi) < goal) {          // grow phase
    hi <<= 1;                   // guard against overflow in production code
}
long lo = hi >> 1;              // answer is in (lo, hi]
while (lo + 1 < hi) {           // shrink phase
    long mid = lo + (hi - lo) / 2;
    if (f(mid) >= goal) hi = mid; else lo = mid;
}
return hi;

Java 17+

First Bad Version with unknown n

If n is not given, gallop 1, 2, 4, 8, … until isBadVersion becomes true, then binary search the last interval (Chapter 12, LC 278).

Galloping merge

To merge a short sorted list into a very long one, advance in the long list by exponentially growing strides, then binary search the last stride. This is the "galloping mode" used by TimSort (Java's Arrays.sort(Object[])) and gives O(k log(n/k)) instead of O(n).

Searching with a known cost per probe

When each probe is a network call or disk page, doubling minimises round-trips for targets near the front, which is exactly the common case for hot keys.

J. Interview Tips

INTERVIEW

Name it: "exponential search: double until I overshoot, then binary search the bracket." Interviewers recognise the term.

Mention O(log p) (position of the target), not O(log n).

Discuss the sentinel and overflow guards; they are the two places this solution usually breaks.

Follow-ups: descending data, unknown size with duplicates (find first occurrence after

bracketing), finite memory, concurrent writers.

Edge cases: target at index 0, target beyond the last element, empty-like arrays (get(0) is the sentinel), duplicates.

CHAPTER SUMMARY

No right bound? Double hi (moving lo = hi) until get(hi) >= target, then binary search [lo, hi].

Cost is O(log p) where p is the answer's position, independent of the array size.

Check index 0 first, start doubling at 1, cap or widen the index to avoid overflow, and treat out-of-range reads as +∞.

Same technique works for any monotone function over an unbounded numeric domain.
