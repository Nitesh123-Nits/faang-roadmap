Queue Patterns and Conversions

First in, first out: ring buffers, windows and stack-queue duality.

A. Pattern Overview

A queue serves the oldest item first. Interview problems use it in four ways: (1) simulation of turns or rounds, (2) a time window that evicts expired entries, (3) building the structure itself from other structures, and (4) level-by-level exploration (BFS), which arrives in Part VII and Part VIII.

KEY IDEA

Queue vs. stack in one line: a stack answers "what did I see last?", a queue answers "what has waited longest?". If fairness, arrival order, or a sliding time horizon appears in the statement, think queue.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Process in the order they arrived", round-robin, each person takes a turn, the first to act bans the next: queue of indices.
"In the last t seconds / last k elements" over a stream: a queue with eviction; keep a

running aggregate so each query is O(1).

"Fixed capacity buffer", wrap around, circular: ring buffer with head and size.
"Implement a queue using stacks" (or the reverse): you are asked about amortisation.
"First unique / first non-repeating" in a stream: a queue plus a count map, lazily discarding duplicates from the front.
"Level by level", shortest number of steps: BFS (Parts VII and VIII).
JAVA CHOICE

In Java use ArrayDeque for both queues and stacks. LinkedList allocates a node per element and allows null; java.util.Queue is the interface, ArrayDeque the implementation.

C. Core Intuition with Illustrations

A queue from two stacks: lazy transfer

Pushes go onto in. Pops and peeks use out, whose top is the oldest element. When out is empty, move everything from in to out (this reverses the order, turning newest-first into oldest-first). Never move while out is non-empty, or the order breaks. Each element moves at most once, so every operation is amortised O(1), although one pop can cost O(n).

Figure 53. Transferring only when out is empty keeps the order correct and the cost amortised.

The ring buffer

Store the queue in an array of capacity k, with head (index of the front) and size. The next free slot is (head + size) % k; the rear is (head + size − 1) % k. Tracking size (instead of two indices) removes the classic ambiguity that empty and full look the same when head == tail.

Figure 54. Indices wrap with the modulo; size distinguishes empty from full.

A sliding time window

Append each timestamp. Before answering, evict from the front every timestamp older than t − 3000. The queue size is the answer. Each timestamp is added and removed once, so

a million pings cost O(10⁶), not O(10⁶ · window). For Moving Average keep a running sum: add

the new value, subtract the evicted one.

Turn-based simulation with indices

In Dota2 Senate, each senator, on their turn, bans the next opponent. Put each side's indices in its own queue. Compare the fronts: the smaller index acts first, removes the other front, and re-enters its queue with index + n (its turn in the next round). The side whose queue empties loses.

E. Java Implementation

Queue using stacks

QueueUsingStacks.java: LeetCode 232

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 232 - Implement Queue using Stacks: lazy transfer gives amortised O(1) per
 * operation.
 */
public class QueueUsingStacks {

    private final Deque<Integer> in = new ArrayDeque<>();    // receives pushes
    private final Deque<Integer> out = new ArrayDeque<>();   // serves pops, oldest on top

    public void push(int x) {
        in.push(x);
    }

    public int pop() {
        shift();
        return out.pop();
    }

    public int peek() {
        shift();
        return out.peek();
    }

    public boolean empty() {
        return in.isEmpty() && out.isEmpty();
    }

    /** Refill `out` only when it is empty: each element moves at most once. */
    private void shift() {
        if (out.isEmpty()) {
            while (!in.isEmpty()) out.push(in.pop());
        }
    }
}

TIME amortised O(1)

SPACE O(n)

Worst case for a single pop is O(n); a sequence of m operations costs O(m).

Stack using one queue

StackUsingQueue.java: LeetCode 225
import java.util.ArrayDeque;
import java.util.Queue;

/** LeetCode 225 - Implement Stack using Queues: one queue; rotate after every push. */
public class StackUsingQueue {

    private final Queue<Integer> q = new ArrayDeque<>();

    // O(n): the new element goes to the front
    public void push(int x) {
        q.add(x);
        for (int i = q.size() - 1; i > 0; i--) q.add(q.remove());
    }

    public int pop() {
        return q.remove();
    }

    public int top() {
        return q.peek();
    }

    public boolean empty() {
        return q.isEmpty();
    }
}

Java 17+

TIME push O(n), pop / top O(1)

SPACE O(n)

After adding x, rotate the other size − 1 elements behind it so the newest is at the front.

Circular queue

MyCircularQueue.java: LeetCode 622

Java 17+

/** LeetCode 622 - Design Circular Queue: fixed array, head index and size (no wasted slot). */
public class MyCircularQueue {

    private final int[] data;
    private int head, size;

    public MyCircularQueue(int k) {
        data = new int[k];
    }

    public boolean enQueue(int value) {
        if (isFull()) return false;
        data[(head + size) % data.length] = value;       // tail = (head + size) mod capacity
        size++;
        return true;
    }

    public boolean deQueue() {
        if (isEmpty()) return false;
        head = (head + 1) % data.length;
        size--;
        return true;
    }

    public int Front() {
        return isEmpty() ? -1 : data[head];
    }

    public int Rear() {
        return isEmpty() ? -1 : data[(head + size - 1) % data.length];
    }

    public boolean isEmpty() {
        return size == 0;
    }

    public boolean isFull() {
        return size == data.length;
    }
}

TIME O(1) per operation

SPACE O(k)

size replaces a separate tail index; the next write slot is (head + size) % capacity.

Number of recent calls

RecentCounter.java: LeetCode 933

Java 17+

import java.util.ArrayDeque;
import java.util.Queue;

/**
 * LeetCode 933 - Number of Recent Calls: a queue of timestamps; evict the ones older than
 * 3000 ms.
 */
public class RecentCounter {

    private final Queue<Integer> window = new ArrayDeque<>();

    /** t is strictly increasing across calls. */
    public int ping(int t) {
        window.add(t);
        while (window.peek() < t - 3000) window.remove();    // amortised O(1)
        return window.size();
    }
}

TIME amortised O(1)

SPACE O(window)

Evict with peek() < t − 3000; the queue never becomes empty because the newest t stays.

Moving average from a data stream

MovingAverage.java: LeetCode 346 (premium)

Java 17+

import java.util.ArrayDeque;
import java.util.Queue;

/** LeetCode 346 - Moving Average from Data Stream: a fixed-size window with a running sum. */
public class MovingAverage {
    private final Queue<Integer> window = new ArrayDeque<>();
    private final int capacity;
    private long sum;

    public MovingAverage(int size) {
        capacity = size;
    }

    public double next(int val) {
        window.add(val);
        sum += val;
        if (window.size() > capacity) sum -= window.remove();   // evict the oldest value
        return (double) sum / window.size();
    }
}
TIME O(1)

SPACE O(size)

Keep sum as a long so that large values cannot overflow, and divide as double.

G. Variations of the Pattern

Time Needed to Buy Tickets: count instead of simulate

Person i buys one ticket per pass until they finish or until person k finishes. Anyone at or before k buys min(tickets[i], tickets[k]) tickets; anyone after k buys min(tickets[i], tickets[k] − 1), because k finishes before they get another turn.

TimeNeededToBuyTickets.java: LeetCode 2073

Java 17+

/**
 * LeetCode 2073 - Time Needed to Buy Tickets: simulate the queue, or count each person's
 * contribution.
 */
public class TimeNeededToBuyTickets {

    /**
     * O(n): person i is served min(tickets[i], tickets[k]) times, minus one if i is behind k.
     */
    public static int timeRequiredToBuy(int[] tickets, int k) {
        int time = 0;
        for (int i = 0; i < tickets.length; i++) {
            int rounds = tickets[k];
            time += Math.min(tickets[i], i <= k ? rounds : rounds - 1);
        }
        return time;
    }
}

TIME O(n)

SPACE O(1)

The queue simulation is O(n · max); the formula comes from asking how many times does each person reach the front.

Dota2 Senate
DotaSenate.java: LeetCode 649

Java 17+

import java.util.ArrayDeque;
import java.util.Queue;

/**
 * LeetCode 649 - Dota2 Senate. Two queues of indices; the earlier senator bans the other
 * side's next one.
 */
public class DotaSenate {

    public static String predictPartyVictory(String senate) {
        int n = senate.length();
        Queue<Integer> radiant = new ArrayDeque<>(), dire = new ArrayDeque<>();
        for (int i = 0; i < n; i++) {
            (senate.charAt(i) == 'R' ? radiant : dire).add(i);
        }
        while (!radiant.isEmpty() && !dire.isEmpty()) {
            int r = radiant.remove(), d = dire.remove();
            // r acts first, bans d, and votes again next round
            if (r < d) radiant.add(r + n);
            else dire.add(d + n);
        }
        return radiant.isEmpty() ? "Dire" : "Radiant";
    }
}

TIME O(n)

SPACE O(n)

Each round removes at least one senator, and each senator is re-queued at most once per ban they cause: linear in total.

Stack using queues, and the reverse

Stack using queues with one queue makes push O(n) (rotate after insertion); the two-queue version has the same cost. A stack built this way is the standard answer to "what is the cost trade-off". Queue using stacks is amortised O(1): remember to say amortised.

First Unique Number and First Non-Repeating Character in a Stream

Keep a count map and a queue of candidates. On showFirstUnique(), discard from the front while the front's count exceeds 1. Each element is enqueued once and dequeued once: amortised O(1).

Design Hit Counter, Logger Rate Limiter

A queue of timestamps with eviction (as in RecentCounter), or a fixed array of 300 one-second buckets with the time stamped in each bucket for O(1) space. The bucket version is what a production rate limiter uses (the sliding-window counter).

Circular Deque and bounded blocking queues

A deque in a ring buffer adds insertFront (head = (head − 1 + k) % k) and deleteLast. A bounded blocking queue adds locks and conditions (ArrayBlockingQueue in Java): the same ring, plus wait / notify when full or empty.

J. Interview Tips

INTERVIEW

Ask about capacity and thread safety for any "design a queue" prompt: bounded or unbounded, single-threaded or blocking. It scopes the answer.

State the amortised argument when you build a queue from stacks: each element is moved at most once, so m operations cost O(m).

Prefer counting over simulating when the numbers are large (tickets problem); mention both and why the formula is correct.

Follow-ups: make the queue thread-safe (ReentrantLock + two Conditions); make peek worst-case O(1); implement a deque in a ring; a queue that returns the minimum in O(1) (two min-stacks, Chapter 28); rate-limit per user with a map of queues.
Edge cases: empty queue, capacity 1, wrap-around, many events at the same timestamp, k at the first or last position, one party only.

CHAPTER SUMMARY

A queue serves the oldest item first: use it for arrival-order simulation, time windows with front eviction, and ring buffers.

Two stacks make a queue: push to in; move to out only when out is empty; each element moves once, so operations are amortised O(1).

Ring buffer: head + size; next slot (head + size) % k; size tells empty from full.

Window aggregates: add the new value, evict from the front, keep the running sum: O(1) per query.

Turn simulations use queues of indices; re-queue with index + n to represent the next round, or replace the simulation by a counting formula.
