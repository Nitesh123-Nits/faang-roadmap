Task Scheduler

Cooldowns: the most frequent task decides the length.

A. Pattern Overview

Given tasks (letters) and a cooldown n, the same task must be separated by at least n other slots, and the CPU may idle. What is the least time to finish? Two solutions: a closed formula driven by the most frequent task, and a simulation with a max-heap of remaining counts plus a cooldown queue. The same machinery rearranges strings so equal letters are k apart (Reorganize String, Rearrange String k Distance Apart).

KEY IDEA

The busiest task is the bottleneck. If task A appears m times, between its m copies there are m − 1 gaps of at least n slots each. Everything else is packed into those gaps; only if the gaps overflow does the answer become the number of tasks.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Cooldown", "at least k apart", "no two adjacent equal" in a scheduling or arrangement problem.
The answer depends on the most frequent item and on how many items tie for the

maximum.

Counts, not order, matter (letters are interchangeable except for their type).
Idle time may be inserted and you minimise the total length.
"Return any valid arrangement or empty string": feasibility is maxFreq ≤ ⌈(len + k − 1)/ k⌉-style.
ONE-LINE TEST

Equal items must be spaced apart: count frequencies and place the most frequent first (heap of counts), or use the frame formula.

C. Core Intuition with Illustrations

Frames of n + 1 slots

Tasks AAABBB, cooldown n = 2. The most frequent tasks A and B (3 each) define m − 1 = 2 frames of n + 1 = 3 slots, plus a final row holding one copy of each tied task:

Figure 112. Two frames of three slots plus a last row of two tied tasks; _ marks idle.

Formula: (maxFreq − 1) · (n + 1) + tied = (3 − 1) · 3 + 2 = 8 slots (idle slots included); simulation gives 8.

When the formula is too small

With many different tasks the gaps overflow and no idle time is needed: the answer is just the number of tasks. Example: AAABBBCCCDDD with n = 2 has frame length (3 − 1) · 3 + 4 = 10 < 12, so the answer is 12. That is why the code returns max(tasks.length, frame).

The simulation

Each time slot: move a task from the cooldown queue back into the heap if its cooldown ended, then run the task with the highest remaining count, put it in the queue with

ready-time time + n + 1, or idle if the heap is empty but the queue is not. Running the highest count first is what keeps the busiest tasks from being starved.

Reorganize and k-distance as the same machine

Reorganize String is the k = 2 case: after using a letter, hold it out for one step. Rearrange String k Distance Apart holds it out for k − 1 steps using a queue; if the heap empties before all letters are placed, the arrangement is impossible. A quick feasibility check for k = 2 is

maxFreq ≤ (len + 1) / 2.

Task Scheduler II and Minimum Rounds: counting shortcuts

Task Scheduler II (tasks in a fixed order) only needs lastDay[type]: if the current day is within space of the last run, jump to last + space + 1. Minimum Rounds (2244) is a pure counting greedy: a type with c tasks needs ⌈c / 3⌉ rounds (use as many triples as possible, and c mod 3 ∈ {1, 2} is absorbed by one extra round); c = 1 is impossible.

INTUITION

The formula and the heap agree because filling idle slots can only be done with other tasks: the number of other tasks beyond the m − 1 gaps' capacity is exactly the overflow that makes T the answer.

E. Java Implementation

Task Scheduler (formula and simulation), k-distance, Scheduler II, minimum rounds

TaskScheduler.java: LeetCode 621, 358, 2365, 2244
import java.util.*;

/**
 * Ch 69: cooldown scheduling; LeetCode 621, 358, 2365, 2244 (767 is
 * ReorganizeString).
 */
public class TaskScheduler {

    /** LeetCode 621 in O(n): idle slots are forced by the most frequent task(s). */
    public static int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        int maxFreq = 0;
        for (char t : tasks) maxFreq = Math.max(maxFreq, ++freq[t - 'A']);
        int tied = 0;
        for (int f : freq) if (f == maxFreq) tied++;
        // frames of n + 1 slots
        long frame = (long) (maxFreq - 1) * (n + 1) + tied;
        // never fewer than the tasks
        return (int) Math.max(tasks.length, frame);
    }

    /** LeetCode 621 by simulation: max-heap of counts plus a cooldown queue. */
    public static int leastIntervalSimulation(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char t : tasks) freq[t - 'A']++;
        PriorityQueue<Integer> ready =
                new PriorityQueue<>(Comparator.reverseOrder());
        for (int f : freq) if (f > 0) ready.offer(f);
        // {count left, time it is ready}
        Deque<int[]> cooling = new ArrayDeque<>();
        int time = 0;
        while (!ready.isEmpty() || !cooling.isEmpty()) {
            time++;
            if (!cooling.isEmpty() && cooling.peekFirst()[1] == time)
                ready.offer(cooling.poll()[0]);
            if (!ready.isEmpty()) {
                // run the most frequent task
                int left = ready.poll() - 1;
                if (left > 0) cooling.add(new int[] {left, time + n + 1});
            }
        }
        return time;
    }

    /**
     * LeetCode 358: rearrange so equal letters are at least k apart; "" if
     * impossible. Greedy: place the most frequent available letter each step.
     */
    public static String rearrangeKDistance(String s, int k) {
        if (k <= 1) return s;
        int[] freq = new int[26];
        for (char c : s.toCharArray()) freq[c - 'a']++;
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) ->
                a[1] != b[1]
                    ? Integer.compare(b[1], a[1])
                    : Integer.compare(a[0], b[0]));
        for (int c = 0; c < 26; c++)
            if (freq[c] > 0) heap.offer(new int[] {c, freq[c]});
        StringBuilder out = new StringBuilder();
        Deque<int[]> wait = new ArrayDeque<>();
        while (!heap.isEmpty()) {
            int[] cur = heap.poll();

Java 17+

            out.append((char) ('a' + cur[0]));
            cur[1]--;
            wait.add(cur);
            // k steps passed: usable again
            if (wait.size() >= k) {
                int[] back = wait.poll();
                if (back[1] > 0) heap.offer(back);
            }
        }
        return out.length() == s.length() ? out.toString() : "";
    }

    /**
     * LeetCode 2365: tasks run in order; same type needs `space` days between runs.
     */
    public static long taskSchedulerII(int[] tasks, int space) {
        Map<Integer, Long> lastDay = new HashMap<>();
        long day = 0;
        for (int t : tasks) {
            day++;
            Long last = lastDay.get(t);
            // wait it out
            if (last != null && day <= last + space) day = last + space + 1;
            lastDay.put(t, day);
        }
        return day;
    }

    /** LeetCode 2244: rounds of 2 or 3 equal tasks; -1 when a type appears once. */
    public static int minimumRounds(int[] tasks) {
        Map<Integer, Integer> count = new HashMap<>();
        for (int t : tasks) count.merge(t, 1, Integer::sum);
        int rounds = 0;
        for (int c : count.values()) {
            if (c == 1) return -1;
            // ceil(c / 3): leftovers fit as 2s
            rounds += (c + 2) / 3;
        }
        return rounds;
    }
}

F. Detailed Dry Run

Simulation of AAABBB, n = 2: slot 1 runs A (count 3 → 2, ready at slot 4). Slot 2 runs B (3 → 2, ready at 5). Slot 3: the heap is empty but the cooldown queue is not: idle. Slot 4: A returns, runs (2 → 1). Slot 5: B returns, runs. Slot 6 idles. Slot 7 runs A, slot 8 runs B. Result A B _ A B _ A B: 8 slots, matching (3 − 1)(2 + 1) + 2 = 8.

Counting rounds: [2,2,3,3,2,4,4,4,4,4] has counts 2→3, 3→2, 4→5: ⌈3/3⌉ + ⌈2/3⌉ + ⌈5/3⌉

G. Variations of the Pattern

Reorganize String (767)

Max-heap of (count, letter); take the top, then the next, alternate. Impossible if some

letter exceeds ⌈len / 2⌉.

Rearrange String k Distance Apart (358)

Heap + queue holding letters until k − 1 further letters have been placed. Return "" if the output ends short.

Longest Happy String (1405) and String Without AAA or BBB (984)

Greedy with counts of a, b, c: append the most frequent letter unless it would create three in a row, then use the next one.

Distant Barcodes (1054)

Sort values by frequency, fill the even indices first then the odd ones: no heap is needed.

Maximum Number of Weeks for Which You Can Work (1953)

If the longest project has more than rest + 1 milestones, the answer is 2 · rest + 1; otherwise all milestones can be done. A direct counting version of the same "most frequent is the bottleneck" argument.

J. Interview Tips

INTERVIEW

Give the formula and explain the frames; then say "or simulate with a heap if we need the actual schedule". Both show depth.

Always mention the max(T, formula) guard and why it exists.

State the feasibility check for arrangement problems before coding the heap loop.

Follow-ups: output the schedule; different cooldowns per task type; priorities with deadlines; multiple CPUs (replace the idle by the next available CPU).
Edge cases: one task type, all tasks distinct, n = 0, n larger than the number of tasks, T =

1.

CHAPTER SUMMARY

Cooldown scheduling: the most frequent task creates m − 1 frames of n + 1 slots; the answer is max(T, (m − 1)(n + 1) + tied).

tied is the number of tasks that share the maximum frequency; the max(T, …)

guard covers the case with no idle slots.

A max-heap of counts plus a cooldown queue produces the actual schedule (and handles k-distance rearrangement).

Reorganize String is the k = 2 case; infeasible when one letter exceeds ⌈len / 2⌉.

Related counting greedies: Task Scheduler II (last + space + 1), Minimum Rounds

(⌈count / 3⌉), Distant Barcodes (even/odd fill).
