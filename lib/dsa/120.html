Meet in the Middle

Split the input in half, enumerate each half, and join the halves with sorting or hashing.

A. Pattern Overview

Some problems have a search space of 2^n with n around 30 to 40: too large to enumerate (2^40 ~ 10^12) but too small for a polynomial algorithm to apply. Meet in the middle splits the input into two halves of size n/2, enumerates all 2^(n/2) subsets of each (about 10^6 for n = 40), and combines the two lists with a sort + two pointers, binary search or hash map. Time falls from O(2^n) to O(2^(n/2) * n).

KEY IDEA

The signature is small n (<= 40) combined with huge values or a target that rules out a sum-indexed DP. The constraints announce the technique.

B. When to Recognize This Pattern

Pattern Recognition Signals

n <= 40 (or 36, 30, 2n with n <= 20).
Values up to 10^9 or negative, so a DP over the sum is impossible.
"Closest subsequence sum to a goal", "split into two equal-size groups", "count subsets

with sum S".

Two independent halves interact only through one aggregate (a sum, XOR, count).
The answer needs the best pair (x from left, y from right) under a combining rule.
ONE-LINE TEST

n <= 40, values huge: enumerate two halves and join them.

C. Core Intuition with Illustrations

Closest subset sum to a goal

Enumerate all 2^h subset sums of the left half and of the right half; sort the right sums. For each left sum s we need a right sum closest to goal - s: binary search for it and check its neighbours. For a = [5, -7, 3, 5], goal = 6:

Left sums sorted: [-7, -2, 0, 5]. Right sums sorted: [0, 3, 5, 8].

The minimum distance is 0 (left sum -2 plus right sum 8: the whole array sums to exactly 6).

Two pointers instead of binary search

If both lists are sorted, walk i upward over the left sums and j downward over the right sums: when s_i + t_j > goal decrement j, otherwise increment i. This saves a log factor after the sorts.

Equal-size split (Partition Array into Two Arrays to Minimise Sum Difference)

The groups must have size exactly n out of 2n, so group left subsets by size: a left subset of size k must pair with a right subset of size n - k. For each k sort the right sums of that size and binary search for the value that makes 2(x + y) closest to the total.

.........
n0Only the empty right subset
Counting subsets with a given sum

Count right sums in a HashMap<Long, Integer>; for each left sum s add map[target - s]. Counting runs in O(2^(n/2)) expected; sorting and binary search gives the same with a log factor and no hashing.

Why two halves of equal size

The cost is 2^a + 2^b + (join); with a + b = n it is minimised at a = b = n/2. Unequal splits are useful only when the join step is expensive on one side.

ENUMERATION

Generate subset sums iteratively: sums = [0]; for each element v, sums += [x + v for x in sums]. No recursion, and the list is built in O(2^h).

MeetInMiddle.java: enumerate halves and join
import java.util.*;

/** Ch 105: meet in the middle; LeetCode 1755, 2035, and subset-sum counting. */
public class MeetInMiddle {
    /** All subset sums of a[from, to). */
    private static long[] subsetSums(int[] a, int from, int to) {
        int n = to - from;
        long[] sums = new long[1 << n];
        for (int mask = 1; mask < (1 << n); mask++) {
            int low = Integer.numberOfTrailingZeros(mask);
            sums[mask] = sums[mask & (mask - 1)] + a[from + low];
        }
        return sums;
    }

    /** LeetCode 1755: subsequence sum closest to goal, n <= 40. */
    public static long closestSubsequenceSum(int[] nums, long goal) {

Java 17+

        int h = nums.length / 2;
        long[] left =
                subsetSums(nums, 0, h), right = subsetSums(nums, h, nums.length);

            int i = lowerBound(right, need);            // first right >= need
            if (i < right.length)

            if (i > 0) best = Math.min(best, Math.abs(x + right[i - 1] - goal));
        }
        return best;
    }

    private static int lowerBound(long[] a, long x) {
        int lo = 0, hi = a.length;
        while (lo < hi) {
            int m = (lo + hi) >>> 1;
            if (a[m] < x) lo = m + 1; else hi = m;
        }
        return lo;
    }

    /**
     * Number of subsets (including the empty one) whose sum equals target, n <= 40.
     */
    public static long countSubsetsWithSum(int[] nums, long target) {
        int h = nums.length / 2;
        Map<Long, Long> freq = new HashMap<>();
        for (long s : subsetSums(nums, 0, h)) freq.merge(s, 1L, Long::sum);
        long total = 0;
        for (long s : subsetSums(nums, h, nums.length))
            total += freq.getOrDefault(target - s, 0L);
        return total;
    }

    /**
     * LeetCode 2035: split 2n numbers into two groups of n, minimise |sum
     * difference|.
     */
    public static int minimumDifference(int[] nums) {
        int n = nums.length / 2;
        int total = 0;
        for (int v : nums) total += v;
        // sums by subset size for each half
        List<List<Integer>> left =
                bySize(nums, 0, n), right = bySize(nums, n, 2 * n);
        for (List<Integer> l : right) Collections.sort(l);
        int best = Integer.MAX_VALUE;
        for (int k = 0; k <= n; k++) {
            List<Integer> r = right.get(n - k);
            for (int x : left.get(k)) {
                // pick y from r so that 2 * (x + y) is closest to total
                long want = ((long) total - 2L * x) / 2;
                int i = Collections.binarySearch(r, (int) want);
                if (i < 0) i = -i - 1;
                if (i < r.size())
                    best = Math.min(best, Math.abs(total - 2 * (x + r.get(i))));
                if (i > 0)
                    best = Math.min(best, Math.abs(total - 2 * (x + r.get(i - 1))));
            }
        }
        return best;
    }

    private static List<List<Integer>> bySize(int[] a, int from, int to) {
        int n = to - from;
        List<List<Integer>> out = new ArrayList<>();
        for (int i = 0; i <= n; i++) out.add(new ArrayList<>());
        for (int mask = 0; mask < (1 << n); mask++) {
            int sum = 0;
            for (int i = 0; i < n; i++)
                if ((mask >> i & 1) == 1) sum += a[from + i];
            out.get(Integer.bitCount(mask)).add(sum);
        }
        return out;
    }

    /** Is there a subset with exactly this sum? n <= 40, larger values allowed. */
    public static boolean subsetSumExists(int[] nums, long target) {
        return countSubsetsWithSum(nums, target) > 0;
    }
}

TIME O(2^(n/2) n)

SPACE O(2^(n/2))

Each half has 2^(n/2) sums, sorting costs n 2^(n/2), and the join does one binary search per left sum. For n = 40 that is about 10^6 sums per side and tens of millions of operations.

G. Variations of the Pattern

4Sum II and k-Sum

Split k arrays into two groups, store pair sums of one group in a map and look up the complement for the other: O(n^(k/2)).

Knapsack with huge weights

Items n <= 40, weights 10^9: split items, enumerate (weight, value) pairs per half, sort one by weight and keep a prefix maximum of values, then binary search for the best compatible partner (Horowitz-Sahni, 1974).

Search problems

Bidirectional BFS is the same idea on graphs: grow from both ends and meet in the middle (Word Ladder, Chapter 47), replacing b^d with 2 b^(d/2).

Discrete logarithm (baby-step giant-step)

Solve g^x = h (mod p) with x = i m - j: store h g^j for j < m = sqrt(p) and look up g^(i m). O(sqrt p) instead of O(p).

XOR and equal-sum variants

Replace sums by XORs: count subsets with XOR t, or find a subset pair with equal sums, using the same two-list approach.

J. Interview Tips

INTERVIEW

Read the constraints aloud: "n is 40 and the values are 10^9, so a sum-indexed DP is out; 2^40 is too much; split in half".

State the cost: O(2^(n/2) n) time, O(2^(n/2)) memory, and say the memory is the real limit.

Mention group-by-size for equal-split problems; it is the detail interviewers listen for.

Follow-ups: three-way splits (2^(n/3) per part, harder join); reduce memory with Schroeppel-Shamir (O(2^(n/4))); counting instead of optimising.
Edge cases: all negative values, n = 1, target zero, duplicates, empty subset counted or not.

CHAPTER SUMMARY

n <= 40 with huge values is the signature of meet in the middle: enumerate 2^(n/2) per half and join.

Joins use sorting + binary search/two pointers or a hash map; equal-size splits also group by subset size.

Time drops from 2^n to 2^(n/2) n; memory 2^(n/2) is the practical limit.

Always include the empty subset and use long sums.

The idea generalises: 4Sum II, bidirectional BFS, baby-step giant-step, knapsack with large weights.
