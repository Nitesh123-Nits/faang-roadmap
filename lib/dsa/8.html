Difference Array

Apply a thousand range updates in O(1) each, then read the final array once.

A. Pattern Overview

A difference array diff stores how much each position changes relative to its left neighbour: diff[i] = value[i] - value[i-1]. Adding v to every element in [l, r] then needs only two writes, diff[l] += v and diff[r+1] -= v, regardless of the range length. A single prefix-sum pass at the end reconstructs the real values.

KEY IDEA

Difference array is the inverse of prefix sum. Prefix sum turns point values into running totals (fast reads of ranges). Difference array turns range writes into point changes. Prefix-summing a difference array gives the original array back.

Add v to [l, r]O(r − l + 1)O(1): diff[l] += v; diff[r+1] -= v

updatesthis)

Use it when updates come first and reads come at the end (offline). If reads are interleaved with updates, you need a Fenwick or segment tree (Part XII).

B. When to Recognize This Pattern

Pattern Recognition Signals

A list of range updates (left, right, delta) followed by a request for the final array, a

maximum, or a feasibility check.

Bookings, reservations, flights, trips, meetings with a start and end that each add a load over an interval.
"How many intervals cover point x?", "peak occupancy", "capacity never exceeded":

counting overlaps.

Naive solution is for each update: for i in [l, r]: a[i] += v, giving O(q · n) with q, n ≤ 10⁵.
Updates are additive (can be undone by subtraction). Non-invertible updates such as

max= do not work.

KEYWORD

Whenever the statement says "for each booking add seats to flights first through last", the O(1) endpoint trick is the intended solution.

C. Core Intuition with Illustrations

Think of diff as marking where the level steps up and where it steps down. A +v at l raises the "water level" for everything to the right; a −v at r+1 lowers it back. The prefix sum is the running level.

Figure 13. Three range updates cost six array writes. One sweep recovers [10, 55, 45, 25, 25].

INTUITION

Why does it work? After the prefix sum, result[i] = Σ_{j≤i} diff[j]. An update

(l, r, v) contributes +v to every i ≥ l and −v to every i ≥ r+1; the two cancel for i

> r, leaving +v exactly on [l, r].

D. Brute Force to Optimal Solution

Example: Corporate Flight Bookings (LeetCode 1109)

Brute force: for each of q bookings loop over its flights: O(q · n). With q = n = 2·10⁴ that is 4·10⁸ additions.
Bottleneck: every booking redoes work that is identical for each flight inside its range.
Idea: record only the boundaries of each range. Interior values are implied by the running sum.
Optimal: O(q + n) time, O(n) space.

E. Java Implementation

A reusable difference array

DifferenceArray.java

Java 17+

/** Reusable 1D difference array: O(1) range add, O(n) materialisation. */
public class DifferenceArray {
    private final long[] diff;      // diff[i] = value[i] - value[i-1]; one extra slot for r+1

    public DifferenceArray(int size) {
        diff = new long[size + 1];
    }

    /** Adds delta to every position in [left, right], inclusive. */
    public void add(int left, int right, long delta) {
        diff[left] += delta;
        diff[right + 1] -= delta;           // cancel the effect after 'right'
    }

    /** Rebuilds the real values with one prefix-sum pass. */
    public long[] build() {
        int n = diff.length - 1;
        long[] values = new long[n];
        long running = 0;
        for (int i = 0; i < n; i++) {
            running += diff[i];
            values[i] = running;
        }
        return values;
    }
}

TIME add O(1) · build O(n)

SPACE O(n)

One spare slot at the end lets r + 1 be written when r == n - 1 without a bounds check.

Corporate Flight Bookings

FlightBookings.java — LeetCode 1109
/**
 * LeetCode 1109 - Corporate Flight Bookings. Each booking is a range update (1-indexed
 * flights).
 */
public class FlightBookings {

    public static int[] corpFlightBookings(int[][] bookings, int n) {
        int[] diff = new int[n + 1];
        for (int[] b : bookings) {
            int first = b[0] - 1;                // convert to 0-indexed
            int last = b[1] - 1;
            diff[first] += b[2];
            diff[last + 1] -= b[2];
        }
        int[] seats = new int[n];
        int running = 0;
        for (int i = 0; i < n; i++) {
            running += diff[i];
            seats[i] = running;
        }
        return seats;
    }
}

Java 17+

TIME O(q + n)

SPACE O(n)

Bookings are 1-indexed: convert to 0-indexed once, at the boundary.

G. Variations of the Pattern

Car Pooling: feasibility over time

Each trip adds passengers on [from, to). After the sweep, check that the running load never exceeds capacity. Note the half-open interval: passengers leave at to, so write diff[to] -= passengers.

CarPooling.java — LeetCode 1094

Java 17+

/**
 * LeetCode 1094 - Car Pooling. Difference array over positions; check running load <=
 * capacity.
 */
public class CarPooling {

    /** trips[i] = {passengers, from, to}; passengers leave the car AT 'to'. */
    public static boolean carPooling(int[][] trips, int capacity) {
        int maxPos = 0;
        for (int[] t : trips) maxPos = Math.max(maxPos, t[2]);

        int[] diff = new int[maxPos + 2];
        for (int[] t : trips) {
            diff[t[1]] += t[0];        // board at 'from'
            diff[t[2]] -= t[0];        // leave at 'to' (so the load covers [from, to-1])
        }
        int load = 0;
        for (int pos = 0; pos <= maxPos; pos++) {
            load += diff[pos];
            if (load > capacity) return false;
        }
        return true;
    }
}

TIME O(q + maxPosition)

SPACE O(maxPosition)

If positions are huge or sparse, use a TreeMap of events instead (sweep line, Part X).

Rectangles: the 2D difference array

To add v to a whole rectangle, change four corners with inclusion–exclusion. A 2D prefix sum restores the grid. This solves problems such as Increment Submatrices by One (LeetCode 2536).

Matrix2DDifference.java

Java 17+

/**
 * 2D difference array: add a value to a whole rectangle in O(1), materialise once in O(R*C).
 */
public class Matrix2DDifference {
    private final int rows;
    private final int cols;
    private final long[][] diff;
    public Matrix2DDifference(int rows, int cols) {
        this.rows = rows;
        this.cols = cols;
        this.diff = new long[rows + 1][cols + 1];
    }

    /** Adds delta to every cell in the rectangle (r1,c1)-(r2,c2), inclusive. */
    public void addRect(int r1, int c1, int r2, int c2, long delta) {
        diff[r1][c1] += delta;
        diff[r1][c2 + 1] -= delta;
        diff[r2 + 1][c1] -= delta;
        diff[r2 + 1][c2 + 1] += delta;       // inclusion-exclusion corner
    }

    public long[][] build() {
        long[][] out = new long[rows][cols];
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                long up = r > 0 ? out[r - 1][c] : 0;
                long left = c > 0 ? out[r][c - 1] : 0;
                long upLeft = (r > 0 && c > 0) ? out[r - 1][c - 1] : 0;
                out[r][c] = diff[r][c] + up + left - upLeft;    // 2D prefix sum of diff
            }
        }
        return out;
    }
}

TIME add O(1) · build O(R·C)

SPACE O(R·C)

J. Interview Tips

INTERVIEW

Say it as the inverse of prefix sums. It shows you understand both, not just a trick.

State the two writes (diff[l] += v, diff[r+1] -= v) before coding, and explain why they cancel for indices past r.

Ask about the interval convention (inclusive/half-open) and indexing (0/1): it is the most common source of bugs.

Follow-ups: coordinates up to 10⁹ (sort events / TreeMap), queries between updates

(Fenwick tree), find the position of the maximum overlap (track argmax during the sweep), 2D version.

Edge cases: l == r, r == n - 1, overlapping or identical ranges, zero or negative deltas, empty update list.

CHAPTER SUMMARY

diff[l] += v; diff[r+1] -= v makes a range update O(1); one prefix-sum pass restores the array.

Best for offline workloads: many updates, one read. Interleaved reads need a Fenwick/segment tree.

Watch the spare slot, the interval convention (inclusive vs half-open) and 0 vs 1 indexing.
