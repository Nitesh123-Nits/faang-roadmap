Introduction to DP and State Modeling

Define a state, write the transition, fix the base case, order the work.

A. Pattern Overview

Dynamic programming (DP) solves a problem by combining answers to smaller instances of the same problem, each solved once. It applies when two properties hold: overlapping subproblems (the same smaller question is asked many times) and optimal substructure (an optimal answer is built from optimal answers to smaller questions). Every DP solution is described by four decisions, in this order: the state (what a subproblem is), the transition (how a state is computed from smaller states), the base cases (states answered directly) and the evaluation order (so that dependencies are ready).

TransitionHow does a state reduce to smaller ones?f(n) = f(n-1) + f(n-2)dp[i] = min(dp[i-1] + c[i-1], dp[i-2] + c[i-2])
Base casesWhich states need no recursion?f(0) = 0, f(1) = 1dp[0] = dp[1] = 0
OrderWhich states must exist first?Increasing nIncreasing i

KEY IDEA

A DP is a recursion whose parameters are small enough to enumerate. If the number of distinct states times the work per state is polynomial, memoising the recursion turns an exponential algorithm into a polynomial one.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Count the number of ways" to reach a target, tile a board, decode a string.
"Minimum / maximum" over choices where each choice leaves a smaller version of the

same problem.

"Is it possible" with a budget (sum, capacity, length).
A greedy choice that fails on a counter-example, while brute force is exponential.
A recursion that recomputes the same arguments: draw its call tree and look for repeated nodes.
The input size is small in one or two dimensions (n <= 1000, n * m <= 10^6), which

allows a table.

ONE-LINE TEST

Ask: what is the smallest piece of information I must remember to finish the problem? That piece is the state.

STATE DISCOVERY

When a recurrence needs an auxiliary quantity (the protruding-cell count g), that quantity is part of the state. Either keep it as a second array or algebraically eliminate it as above, then verify with the first few brute-force values.

D. Brute Force to Optimal Solution

The standard progression for any DP problem has four rungs. Moving down the table never changes the recurrence; only the bookkeeping.

E. Java Implementation

Fibonacci three ways, Tribonacci, Min Cost Climbing Stairs, Domino Tiling

DPFramework.java: LeetCode 509, 1137, 746, 790
import java.util.*;

/** Ch 78: the DP framework; LeetCode 509, 1137, 746, 790. */
public class DPFramework {
    private static final int MOD = 1_000_000_007;

    /** Top-down: the recursion is the recurrence, the array is the cache. */
    public static long fibMemo(int n) {
        long[] memo = new long[n + 2];
        Arrays.fill(memo, -1);
        return fib(n, memo);
    }

    private static long fib(int n, long[] memo) {
        if (n < 2) return n;
        if (memo[n] >= 0) return memo[n];
        return memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
    }

    /** Bottom-up: fill the table in dependency order. */
    public static long fibTab(int n) {
        if (n < 2) return n;
        long[] dp = new long[n + 1];
        dp[1] = 1;
        for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
        return dp[n];
    }

    /** Only the last two states are ever read, so keep two variables. */
    public static long fibRolling(int n) {
        long a = 0, b = 1;
        for (int i = 0; i < n; i++) {
            long next = a + b;
            a = b;
            b = next;
        }
        return a;
    }

    /** LeetCode 1137: T(n) = T(n-1) + T(n-2) + T(n-3), with T = 0, 1, 1. */
    public static int tribonacci(int n) {
        if (n == 0) return 0;
        int a = 0, b = 1, c = 1;
        for (int i = 3; i <= n; i++) {
            int next = a + b + c;
            a = b;

Java 17+

            b = c;
            c = next;
        }
        return c;
    }

    /**
     * LeetCode 746: cost[i] is paid when leaving step i; start on step 0 or 1,
     * reach the top (index n). dp[i] = cheapest cost to stand on i.
     */
    public static int minCostClimbingStairs(int[] cost) {
        int n = cost.length;
        int prev2 = 0, prev1 = 0;                       // dp[0], dp[1]
        for (int i = 2; i <= n; i++) {
            int cur = Math.min(prev1 + cost[i - 1], prev2 + cost[i - 2]);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }

    /**
     * LeetCode 790: tilings of a 2 x n board with dominoes and L-trominoes,
     * modulo 1e9 + 7. State modelling: f(n) = 2 f(n-1) + f(n-3).
     */
    public static int numTilings(int n) {
        if (n <= 2) return n;
        long[] f = new long[n + 1];
        f[0] = 1;
        f[1] = 1;
        f[2] = 2;
        for (int i = 3; i <= n; i++) f[i] = (2 * f[i - 1] + f[i - 3]) % MOD;
        return (int) f[n];
    }
}

TIME O(n)

SPACE O(1)

Each method visits states 0..n once. fibMemo uses O(n) for the cache and stack; fibTab keeps the table; the rolling versions keep only the last two or three values. numTilings works modulo 1_000_000_007.

F. Detailed Dry Run

fibMemo(5) evaluates fib(5) -> fib(4) -> fib(3) -> fib(2) -> fib(1) going down and stores each value as the recursion unwinds: memo[2] = 1, memo[3] = 2, memo[4] = 3, memo[5] = 5. The sibling calls fib(0), fib(1), fib(2), fib(3) are then served from the cache or the base cases, giving the 9 calls drawn above.

numTilings(4): f(1)=1, f(2)=2, f(3)=5; f(4) = 2 * 5 + f(1) = 11, matching the table. The same loop with f(0) = 1 as the empty-board base case handles n = 3 as 2 * 2 + 1 = 5.

G. Variations of the Pattern

Linear recurrences with a fixed window

Fibonacci, Tribonacci (1137) and Climbing Stairs (70) look back a constant distance and need only rolling variables.

Costs on states versus costs on edges

In 746 the cost belongs to the step you leave. Writing dp[i] as cost to arrive at i keeps the transition symmetric; always state clearly whether dp[i] includes cost[i].

Counting modulo a prime

Counting problems overflow quickly. Reduce after every addition and use long for intermediate sums.

Transition derived by elimination

790 shows how an auxiliary state can be removed algebraically. Check the closed recurrence against a brute-force enumeration for small n before trusting it.

The matrix-power view

A fixed linear recurrence can be raised to the n-th power with a k x k matrix in O(k^3 log n). It is beyond interview scope, but it shows why Fibonacci is O(log n) in theory.

J. Interview Tips

INTERVIEW

Say the four decisions aloud: state, transition, base cases, order. Interviewers grade the model more than the code.

Start with the recursion, show the repeated calls, then add the memo. Convert to a table only if asked or if depth is a risk.

State the complexity as states x work per state.

Follow-ups: reduce space; reconstruct the actual choices (keep parent pointers or walk

back through the table); count instead of optimise.

Edge cases: n = 0, n = 1, arrays of length 1 or 2, values that make the answer zero, modulo arithmetic.

CHAPTER SUMMARY

DP = overlapping subproblems + optimal substructure. Memoise a recursion, or fill a table in dependency order.

The four decisions: state, transition, base cases, evaluation order. Write the state in one sentence before any code.

Complexity = number of states x work per state. Fibonacci falls from O(2^n) to O(n).

If the transition needs extra information, that information belongs in the state.

Rolling variables reduce space when transitions look back a fixed distance.
