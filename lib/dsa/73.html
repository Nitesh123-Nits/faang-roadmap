Two Heaps

Split the data at the median: a max-heap below, a min-heap above.

A. Pattern Overview

The two-heaps pattern keeps a collection split into a lower half in a max-heap and an upper half in a min-heap. Every element in the lower half is ≤ every element in the upper half, and the heaps differ in size by at most one. The median is read from the two roots in O(1); each insertion costs O(log n). Any problem asking for the median (or any fixed percentile) of a changing collection is a candidate.

Running median: the whole pattern

Java 17+

PriorityQueue<Integer> lo = new PriorityQueue<>(Comparator.reverseOrder()); // max-heap
PriorityQueue<Integer> hi = new PriorityQueue<>();                          // min-heap

void addNum(int num) {
    lo.offer(num);
    hi.offer(lo.poll());                      // 1. route through lo: keeps lo <= hi
    if (hi.size() > lo.size()) lo.offer(hi.poll());   // 2. rebalance: |lo| = |hi| or |hi| + 1
}
double median() {
    return lo.size() > hi.size() ? lo.peek() : ((long) lo.peek() + hi.peek()) / 2.0;
}
KEY IDEA

Two invariants, always: (1) max(lo) ≤ min(hi); (2) |lo| = |hi| or |lo| = |hi| + 1. Inserting through the other heap first guarantees (1) without any comparison; a single size check restores (2).

B. When to Recognize This Pattern

Pattern Recognition Signals

"Median" of a stream, a sliding window, or a changing set.
Balance a collection into two halves and query the boundary between them.
"Choose the best project / task now, then unlock more" (IPO): one structure of locked items sorted by a threshold, one heap of available items sorted by value.
Both the smallest of the large half and the largest of the small half matter.
Insertions interleaved with queries: sorting each time would cost O(n log n) per query.
ONE-LINE TEST

Median or boundary of a changing set: two heaps. Threshold unlocking items into a best-first pool: a sorted list plus one heap (the "two structures" cousin).

C. Core Intuition with Illustrations

Why the median sits at the boundary

Sorted order is [small half | large half]. The median is the largest of the small half (odd count) or the average of the two boundary elements (even count). A max-heap exposes the largest of the small half; a min-heap exposes the smallest of the large half. Nothing else in either half matters for the median, which is why heaps (partial order) are enough and a fully sorted structure is unnecessary.

Routing through the other heap

lo.offer(num); hi.offer(lo.poll()); pushes num into the low half, then moves that half's largest to the high half. Whatever num was, the element that ends up in hi is at least as large as everything left in lo, so invariant (1) holds without comparing num to either root. One if then fixes the size.

Sliding window: deletion is the hard part

PriorityQueue.remove(x) is O(k), which makes a window of size k cost O(nk). The standard fix is lazy deletion: record the outgoing value in a HashMap of pending removals and only discard it when it reaches the top of its heap. Two counters track the valid size of each heap so rebalancing ignores dead entries (LeetCode 480). Total O(n log k).

IPO: a sorted list plus a heap

Projects need capital[i] to start and add profits[i]. Sort projects by capital; as capital w grows, push every newly affordable project's profit into a max-heap; take the best. It is the same "two structures on either side of a threshold" idea: locked items on the left, available items in a heap on the right.

Overflow in the median

Two int roots can sum past Integer.MAX_VALUE. Add as long before dividing by 2.0, as in the listing. This is a favourite edge case in tests.

MedianFinder, sliding-window median, IPO

TwoHeaps.java: LeetCode 295, 480, 502
import java.util.*;

/** Ch 61: two heaps split a collection at its median; LeetCode 295, 480, 502. */
public class TwoHeaps {

    /**
     * LeetCode 295: running median. Invariant: |lo| == |hi| or |lo| == |hi| + 1.
     */
    public static class MedianFinder {
        private final PriorityQueue<Integer> lo =
                new PriorityQueue<>(Comparator.reverseOrder());
        private final PriorityQueue<Integer> hi = new PriorityQueue<>();

        public void addNum(int num) {
            lo.offer(num);
            // the largest of the low half moves up
            hi.offer(lo.poll());
            if (hi.size() > lo.size()) lo.offer(hi.poll());
        }

        public double findMedian() {
            if (lo.isEmpty()) throw new IllegalStateException("no numbers yet");
            if (lo.size() > hi.size()) return lo.peek();
            // long: avoid int overflow
            return ((long) lo.peek() + hi.peek()) / 2.0;
        }
    }

    /** LeetCode 480: sliding-window median with lazy deletion. O(n log k). */
    public static double[] medianSlidingWindow(int[] nums, int k) {
        DualHeap dh = new DualHeap(k);
        for (int i = 0; i < k; i++) dh.insert(nums[i]);
        double[] ans = new double[nums.length - k + 1];
        ans[0] = dh.median();
        for (int i = k; i < nums.length; i++) {
            dh.insert(nums[i]);
            dh.erase(nums[i - k]);
            ans[i - k + 1] = dh.median();
        }
        return ans;
    }

    private static final class DualHeap {
        private final PriorityQueue<Integer> lo =
                new PriorityQueue<>(Comparator.reverseOrder());
        private final PriorityQueue<Integer> hi = new PriorityQueue<>();

Java 17+

        private final Map<Integer, Integer> delayed = new HashMap<>();
        private final int k;
        // sizes without delayed elements
        private int loSize, hiSize;

        DualHeap(int k) { this.k = k; }

        double median() {
            if ((k & 1) == 1) return lo.peek();
            return ((long) lo.peek() + hi.peek()) / 2.0;
        }

        void insert(int num) {
            if (lo.isEmpty() || num <= lo.peek()) { lo.offer(num); loSize++; }
            else { hi.offer(num); hiSize++; }
            rebalance();
        }

        // mark now, remove when it surfaces
        void erase(int num) {
            delayed.merge(num, 1, Integer::sum);
            if (num <= lo.peek()) {
                loSize--;
                if (num == lo.peek()) prune(lo);
            } else {
                hiSize--;
                if (num == hi.peek()) prune(hi);
            }
            rebalance();
        }

        private void rebalance() {
            if (loSize > hiSize + 1) {
                hi.offer(lo.poll()); loSize--; hiSize++;
                prune(lo);
            } else if (loSize < hiSize) {
                lo.offer(hi.poll()); hiSize--; loSize++;
                prune(hi);
            }
        }

        private void prune(PriorityQueue<Integer> heap) {
            while (!heap.isEmpty()) {
                int top = heap.peek();
                Integer cnt = delayed.get(top);
                if (cnt == null) break;
                if (cnt == 1) delayed.remove(top); else delayed.put(top, cnt - 1);
                heap.poll();
            }
        }
    }

    /**
     * LeetCode 502 (IPO): at most k projects; each needs capital[i], gains
     * profits[i].
     */
    public static int findMaximizedCapital(int k, int w, int[] profits,
            int[] capital) {
        int n = profits.length;
        Integer[] order = new Integer[n];
        for (int i = 0; i < n; i++) order[i] = i;
        Arrays.sort(order, Comparator.comparingInt(i -> capital[i]));
        PriorityQueue<Integer> affordable =
                new PriorityQueue<>(Comparator.reverseOrder());
        int next = 0;
        for (int round = 0; round < k; round++) {
            while (next < n && capital[order[next]] <= w)
                affordable.offer(profits[order[next++]]);
            if (affordable.isEmpty()) break;         // nothing else is affordable
            w += affordable.poll();
        }
        return w;
    }
}

TIME O(log n) per add

SPACE O(n)

MedianFinder stores every element once across both heaps. medianSlidingWindow runs in O(n log k) with lazy deletion; each value is pushed once and removed at most once. IPO sorts once, then at most k heap operations.

F. Detailed Dry Run

Stream 5, 15, 1, 3, 8. Add 5: lo = [5], hi = [ ], median 5. Add 15: it goes into lo, the largest of lo (15) moves to hi, and the sizes are already balanced: lo = [5], hi = [15], median (5 + 15) / 2 = 10. Add 1: it passes through lo and hi (1 comes back down as the smaller value) and the size rule moves it into lo: lo = [5, 1], hi = [15], median 5. Add 3: after routing, 5 has moved up to hi, giving lo = [3, 1], hi = [5, 15]; medians (3 + 5) / 2 =

4. Add 8: lo = [5, 3, 1], hi = [8, 15], median 5. The medians are 5, 10, 5, 4, 5.

For the IPO run, capital starts at 0: only the free project is affordable, then capital 1 unlocks two projects whose profits wait in the heap until the better one is chosen.

G. Variations of the Pattern

Sliding window median

Lazy deletion with a HashMap<Integer, Integer> of pending removals and valid-size counters (480). Alternative: a TreeMap multiset with an iterator pointing at the median, or two TreeSets with a tie-breaking index.

Percentiles other than 50

Resize the target ratio: keep lo at ⌈p · n⌉ elements to track any percentile.

Maximise capital (IPO) and similar threshold-unlocking problems

Sort by the unlock key, sweep, push into a best-first heap. Maximum Performance of a Team and Course Schedule III use the same "sorted sweep + heap" shape (Chapter 63).

Sum of the k smallest in a window

Maintain a lo of exactly k elements and a running sum; the rest live in hi. Used for Sliding Window Median style follow-ups and Finding MK Average (1825).

Two-sided scheduling

Find Right Interval, Minimum Number of Refueling Stops and Meeting Rooms II put "not yet started" items in a sorted list and "in progress" items in a heap; same architecture, different invariants.

J. Interview Tips

INTERVIEW

State the two invariants out loud before coding; they are your correctness proof and your debugging checklist.

Explain why routing through the other heap works: it removes the case analysis.

For the sliding window, name lazy deletion and the valid-size counters; that is the point where candidates stumble.

Follow-ups: most numbers in a small range (counting array); percentiles; deletions (lazy

deletion or balanced BST); streaming from disk (approximate quantile sketches such as t-digest or GK).

Edge cases: one element, two elements, duplicates (equal median), negatives, Integer.MAX_VALUE pairs, k = 1 windows.

CHAPTER SUMMARY

Two heaps split a collection into a max-heap of the lower half and a min-heap of the upper half; the median is at the roots.

Invariants: max(lo) ≤ min(hi) and |lo| = |hi| or |hi| + 1. Insert through the other heap, then rebalance by size.

O(log n) per insertion, O(1) median. Add as long to avoid overflow.

Sliding windows need lazy deletion (a pending-removal map and valid-size counters): O(n log k) instead of O(nk).

IPO shape: sort by the unlock key, sweep, push into a best-first heap: the same "threshold plus heap" idea as many scheduling problems.
