Merge Sort and Inversion Counting

Count cross-pairs while merging: divide and conquer for order-based counting problems.

A. Pattern Overview

Merge sort splits an array, sorts each half and merges. At the merge step, both halves are already sorted, so a question of the form "how many pairs (i, j), i in the left half and j in the right half, satisfy a condition between a[i] and a[j]?" can be answered with one linear scan or a two-pointer sweep. Every pair is split exactly once, at the level where i and j first land in different halves, so the total cost is O(n log n).

KEY IDEA

The merge step turns a quadratic cross-count into a linear one because sortedness makes the counts monotone: advancing in one half never decreases the matching prefix of the other.

B. When to Recognize This Pattern

Pattern Recognition Signals

"For each element count how many later elements are smaller/larger", or total such pairs.
Pairs (i, j) with i < j and a relation between values (not between indices).
Order statistics over prefix sums (Count of Range Sum).
n up to 10^5: O(n^2) fails, O(n log n) fits.
The relation allows a sorted-order sweep (monotone in the sorted halves).
ONE-LINE TEST

Count pairs by index order and value relation: merge sort, or a Fenwick tree over ranks.

C. Core Intuition with Illustrations

Counting inversions during the merge

Merge the sorted halves L and R. When L[i] <= R[j] take from the left. When R[j] < L[i], then R[j] is smaller than all remaining left elements L[i..] (they are sorted), so it forms len(L) - i inversions with them. Add that and take R[j].

MergeResultCross inversions
[4] + [2][2, 4]1
[8] + [2, 4][2, 4, 8]2
[5] + [3][3, 5]1
[1] + [3, 5][1, 3, 5]0
[2, 4, 8] + [1, 3, 5][1, 2, 3, 4, 5, 8]6

The total for [8, 4, 2, 1, 5, 3] is 10 inversions.

Reverse pairs: count before merging

The condition a[i] > 2 a[j] does not match the merge order, so count it in a separate pass over the two sorted halves: for each i in the left, advance j while a[i] > 2 a[j]; since the left side is increasing, j never moves back. Then perform the ordinary merge. Use long for 2 a[j].

Count of smaller numbers after self: carry the indices

Sort an array of indices by value. In the merge, whenever an element from the left half is placed, add the number of right-half elements already placed (they are smaller and were originally to its right). Store counts per original index.

Count of range sum

With prefix sums p, count pairs i < j such that lower <= p[j] - p[i] <= upper. In each merge, for each p[i] in the sorted left half find, using two moving pointers lo and hi in the right half, the range of p[j] with p[j] - p[i] >= lower (starting at lo) and p[j] - p[i] > upper (ending at hi). Add hi - lo.

Global vs local inversions

A permutation of 0..n-1 has every local inversion as a global one. Counts are equal exactly when no element is more than one position from its sorted place: check |a[i] - i| <= 1 in O(n). Merge sort counting confirms it but is overkill.

TRAP

Count before or during the merge as each problem requires, but never after: once the halves are merged the left/right distinction is gone.

MergeSortCounting.java: divide and conquer counting
import java.util.*;

/** Ch 106: counting while merging; LeetCode 912, 493, 315, 327, 775. */
public class MergeSortCounting {
    /** Counts inversions (i < j, a[i] > a[j]) while sorting a copy. */
    public static long countInversions(int[] a) {
        int[] work = a.clone();
        return sortCount(work, new int[work.length], 0, work.length);
    }

    private static long sortCount(int[] a, int[] tmp, int lo, int hi) {
        if (hi - lo < 2) return 0;
        int mid = (lo + hi) >>> 1;
        long inv = sortCount(a, tmp, lo, mid) + sortCount(a, tmp, mid, hi);
        int i = lo, j = mid, k = lo;
        while (i < mid || j < hi) {
            if (j == hi || (i < mid && a[i] <= a[j])) tmp[k++] = a[i++];
            else {
                // a[j] jumps over all remaining left items
                inv += mid - i;
                tmp[k++] = a[j++];
            }
        }
        System.arraycopy(tmp, lo, a, lo, hi - lo);
        return inv;
    }

    /** LeetCode 493: pairs i < j with nums[i] > 2 * nums[j]. */
    public static int reversePairs(int[] nums) {
        return (int) reverse(nums.clone(), new int[nums.length], 0, nums.length);
    }

    private static long reverse(int[] a, int[] tmp, int lo, int hi) {
        if (hi - lo < 2) return 0;
        int mid = (lo + hi) >>> 1;
        long cnt = reverse(a, tmp, lo, mid) + reverse(a, tmp, mid, hi);
        // both halves are sorted now
        for (int i = lo, j = mid; i < mid; i++) {
            while (j < hi && (long) a[i] > 2L * a[j]) j++;
            cnt += j - mid;
        }
        merge(a, tmp, lo, mid, hi);
        return cnt;
    }

    private static void merge(int[] a, int[] tmp, int lo, int mid, int hi) {
        int i = lo, j = mid, k = lo;
        while (i < mid && j < hi) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
        while (i < mid) tmp[k++] = a[i++];
        while (j < hi) tmp[k++] = a[j++];
        System.arraycopy(tmp, lo, a, lo, hi - lo);
    }

    /** LeetCode 315 by merge sort on indices. */
    public static List<Integer> countSmaller(int[] nums) {
        int n = nums.length;
        int[] idx = new int[n], tmp = new int[n], res = new int[n];
        for (int i = 0; i < n; i++) idx[i] = i;
        smaller(nums, idx, tmp, res, 0, n);
        List<Integer> out = new ArrayList<>(n);
        for (int v : res) out.add(v);
        return out;

    private static void smaller(int[] a, int[] idx, int[] tmp, int[] res, int lo,
            int hi) {
        if (hi - lo < 2) return;
        int mid = (lo + hi) >>> 1;
        smaller(a, idx, tmp, res, lo, mid);
        smaller(a, idx, tmp, res, mid, hi);
        int i = lo, j = mid, k = lo;
        while (i < mid || j < hi) {
            if (j == hi || (i < mid && a[idx[i]] <= a[idx[j]])) {
                // right items already placed are smaller
                res[idx[i]] += j - mid;
                tmp[k++] = idx[i++];
            } else tmp[k++] = idx[j++];
        }
        System.arraycopy(tmp, lo, idx, lo, hi - lo);
    }

    /**
     * LeetCode 327: subarray sums in [lower, upper] by merge sort on prefix sums.
     */
    public static int countRangeSum(int[] nums, int lower, int upper) {
        long[] pre = new long[nums.length + 1];
        for (int i = 0; i < nums.length; i++) pre[i + 1] = pre[i] + nums[i];
        return rangeSort(pre, new long[pre.length], 0, pre.length, lower, upper);
    }

    private static int rangeSort(long[] a, long[] tmp, int lo, int hi, int lower,
            int upper) {
        if (hi - lo < 2) return 0;
        int mid = (lo + hi) >>> 1;
        int cnt =
                rangeSort(a, tmp, lo, mid, lower, upper) + rangeSort(a, tmp, mid,
                        hi, lower, upper);
        int l = mid, r = mid;
        for (int i = lo; i < mid; i++) {
            while (l < hi && a[l] - a[i] < lower) l++;
            while (r < hi && a[r] - a[i] <= upper) r++;
            cnt += r - l;
        }
        int i = lo, j = mid, k = lo;
        while (i < mid && j < hi) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
        while (i < mid) tmp[k++] = a[i++];
        while (j < hi) tmp[k++] = a[j++];
        System.arraycopy(tmp, lo, a, lo, hi - lo);
        return cnt;
    }

    /**
     * LeetCode 775: global inversions equal local inversions iff no a[i] > a[j]
*withj>i+1.
     */
    public static boolean isIdealPermutation(int[] a) {
        int maxBefore = -1;
        for (int i = 2; i < a.length; i++) {
            maxBefore = Math.max(maxBefore, a[i - 2]);
            if (maxBefore > a[i]) return false;
        }
        return true;
    }

    /** LeetCode 912: stable merge sort. */
    public static int[] sortArray(int[] nums) {
        int[] a = nums.clone();
        sortCount(a, new int[a.length], 0, a.length);
        return a;
    }
}

SPACE O(n)

G. Variations of the Pattern

Stable sorting

Merge sort is stable (take from the left on ties) and the natural choice for linked lists (O(1) extra space with relinking, Chapter 23) and external sorting.

Bottom-up merge sort

Merge runs of width 1, 2, 4, ... iteratively: no recursion, same O(n log n).

Counting with value ranges and conditions

Any condition f(a[i], a[j]) monotone in the sorted order works: pairs with |a[i] - a[j]| <= k, count of pairs with a[i] + a[j] > t.

CDQ divide and conquer

Handle 3D dominance counts: sort by the first key, recurse, sort halves by the second key and use a Fenwick tree for the third. Advanced; mention if asked about 3-dimensional counting.

Parallel and external sorting

Merge sort parallelises naturally and works with data on disk, since the merge is a sequential scan.

J. Interview Tips

INTERVIEW

Say "every pair is separated exactly once" and the O(n log n) bound follows.

Pick the structure by the follow-up: "updates" means Fenwick or segment tree; "offline, no extra rank structure" means merge sort.

Mention overflow in both the total (long) and the comparison (2L * a[j]).

Follow-ups: return the inversion pairs; distribute across machines (sum counts of partitions plus cross counts); handle duplicates and ties.
Edge cases: sorted array (0 inversions), reverse-sorted (n(n-1)/2), all equal, empty input,

negatives.

CHAPTER SUMMARY

Count cross-pairs while merging: sorted halves make the match count monotone, so the pass is linear.

Inversions: when the right element wins, add the number of remaining left elements.

Conditions that don't match the merge order (reverse pairs, range sums) get a separate two-pointer pass over the sorted halves.

Carry indices to attribute counts to original positions (smaller after self).

Use long for totals and for doubled values; a Fenwick tree is the shorter alternative.
