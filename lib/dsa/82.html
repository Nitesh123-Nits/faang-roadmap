Huffman Coding

Repeatedly merge the two lightest: optimal prefix codes.

A. Pattern Overview

Huffman coding assigns shorter bit strings to more frequent symbols so that the total encoded length is minimal among all prefix codes (no code is a prefix of another, so decoding needs no separators). The algorithm is the canonical heap-driven greedy: put every symbol in a min-heap by weight, repeatedly merge the two lightest trees into one whose weight is their sum, and read the codes from the root-to-leaf paths (left = 0, right = 1).

}

KEY IDEA

The total cost of merging equals the weighted path length of the merge tree. Every merge adds the combined weight once, and a leaf's weight is added once per ancestor, i.e. once per level of depth. Minimising total merge cost is minimising Σ weight · depth.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Minimum total cost to combine all items" where combining two items costs their sum and produces a new item.
Variable-length encoding / compression with known frequencies.
Merge files / sticks / ropes pairwise with cost proportional to size.
Cost structure is additive over merges and the order of merging is free.
"Always combine the two smallest" feels natural: a heap plus a loop.
ONE-LINE TEST

Repeatedly combine two items, cost = their sum, order is free: always merge the two smallest (min-heap).

Total encoded length: 45·1 + 13·3 + 12·3 + 16·3 + 9·4 + 5·4 = 224 bits per 100 symbols, versus 300 for a fixed 3-bit code: a 25% saving. The exact bit strings depend on tie-breaking; the cost does not.

Why prefix-free codes are a tree

Place symbols at the leaves of a binary tree. A code is the path from the root. No leaf is an ancestor of another, so no code is a prefix of another. Decoding walks the tree bit by bit and restarts at the root on reaching a leaf.

Why the greedy is optimal
The two lightest symbols x, y can be siblings at the deepest level of some optimal tree: if they were shallower than another symbol z at max depth, swapping x with z cannot increase the cost (weight(x) ≤ weight(z) and depth decreases for z). (2) Merging them into

one symbol of weight w(x) + w(y) gives a smaller instance whose optimal cost plus w(x) + w(y) is the original optimum. Induction on the number of symbols finishes the proof.

Kraft's inequality

A prefix code with lengths ₁ … ₙ exists iff Σ 2^(−ᵢ) ≤ 1. Huffman codes are complete:

the sum equals exactly 1 (every internal node has two children). The test suite checks this for every random alphabet.

Decoding and the single-symbol case

Decode by walking from the root; each leaf emits a symbol. With one distinct symbol the tree is a single leaf with an empty path; the implementation assigns the code 0 so every symbol still costs one bit.

Cost-only problems: no tree needed

Connect Sticks only needs the total merge cost: poll two, add their sum to the answer, push the sum. Use long: with many large sticks the cost exceeds int quickly.

INTUITION

import java.util.*;

/**
 * Ch 70: Huffman coding and "merge the two smallest"; LeetCode 1167, 1962, 2335.
 */
public class Huffman {

    private static final class Node {
        final long weight;
        final int order;              // insertion order: deterministic tie-breaks
        final char symbol;
        final Node left, right;

        Node(long weight, int order, char symbol, Node left, Node right) {
            this.weight = weight; this.order = order; this.symbol = symbol;
            this.left = left; this.right = right;
        }

        boolean isLeaf() { return left == null; }
    }

    /** A code table plus a decoder; build it once per frequency table. */
    public static final class Code {
        private final Map<Character, String> table;
        private final Node root;

        private Code(Map<Character, String> table, Node root) {
            this.table = table; this.root = root;
        }

        public Map<Character, String> table() { return table; }

        public String encode(String text) {
            StringBuilder sb = new StringBuilder();
            for (char c : text.toCharArray()) {
                String bits = table.get(c);
                if (bits == null)
                    throw new IllegalArgumentException("unknown symbol " + c);
                sb.append(bits);
            }
            return sb.toString();
        }

        public String decode(String bits) {
            StringBuilder sb = new StringBuilder();
            Node cur = root;
            // single symbol: every bit is that symbol
            if (root.isLeaf()) {
                for (int i = 0; i < bits.length(); i++) sb.append(root.symbol);
                return sb.toString();
            }
            for (int i = 0; i < bits.length(); i++) {
                cur = bits.charAt(i) == '0' ? cur.left : cur.right;
                if (cur.isLeaf()) { sb.append(cur.symbol); cur = root; }
            }
            return sb.toString();
        }
    }

    /** Builds an optimal prefix code from symbol frequencies (all > 0). */

Java 17+

    public static Code build(Map<Character, Integer> freq) {
        if (freq.isEmpty()) throw new IllegalArgumentException("no symbols");
        PriorityQueue<Node> heap = new PriorityQueue<>((a, b) ->
                a.weight != b.weight ? Long.compare(a.weight, b.weight)
                                     : Integer.compare(a.order, b.order));
        int order = 0;
        for (Map.Entry<Character, Integer> e : new TreeMap<>(freq).entrySet()) {
            heap.offer(new Node(e.getValue(), order++, e.getKey(), null, null));
        }
        while (heap.size() > 1) {
            Node a = heap.poll(), b = heap.poll();      // the two lightest trees
            heap.offer(new Node(a.weight + b.weight, order++, '\0', a, b));
        }
        Node root = heap.poll();
        Map<Character, String> table = new TreeMap<>();
        assign(root, "", table);
        return new Code(table, root);
    }

    private static void assign(Node node, String prefix, Map<Character,
            String> table) {
        if (node.isLeaf()) {
            table.put(node.symbol, prefix.isEmpty() ? "0" : prefix);
            return;
        }
        assign(node.left, prefix + "0", table);
        assign(node.right, prefix + "1", table);
    }

    /** Convenience: frequency table of a text. */
    public static Map<Character, Integer> frequencies(String text) {
        Map<Character, Integer> freq = new TreeMap<>();
        for (char c : text.toCharArray()) freq.merge(c, 1, Integer::sum);
        return freq;
    }

    /** LeetCode 1167: minimum cost to connect sticks = Huffman merge cost. */
    public static long connectSticks(int[] sticks) {
        PriorityQueue<Long> heap = new PriorityQueue<>();
        for (int s : sticks) heap.offer((long) s);
        long cost = 0;
        while (heap.size() > 1) {
            long merged = heap.poll() + heap.poll();
            cost += merged;
            heap.offer(merged);
        }
        return cost;
    }

    /**
     * LeetCode 2335: seconds to fill cups; each second fills 2 different types or
     * 1.
     */
    public static int fillCups(int[] amount) {
        PriorityQueue<Integer> heap =
                new PriorityQueue<>(Comparator.reverseOrder());
        for (int a : amount) if (a > 0) heap.offer(a);
        int seconds = 0;
        while (heap.size() >= 2) {
            int a = heap.poll() - 1, b = heap.poll() - 1;
            if (a > 0) heap.offer(a);
            if (b > 0) heap.offer(b);
            seconds++;
        }
        return seconds + (heap.isEmpty() ? 0 : heap.peek());
    }

    /**
     * LeetCode 1962: remove stones k times, halving (rounded down) the largest
     * pile.
     */
    public static int minStoneSum(int[] piles, int k) {
        PriorityQueue<Integer> heap =
                new PriorityQueue<>(Comparator.reverseOrder());
        int sum = 0;
        for (int p : piles) { heap.offer(p); sum += p; }
        for (int i = 0; i < k; i++) {
            int top = heap.poll();
            sum -= top / 2;                             // removes floor(top / 2)
            heap.offer(top - top / 2);
        }
        return sum;
    }
}

TIME O(n log n)

SPACE O(n)

Building the tree uses n − 1 merges on a heap of at most n nodes. Encoding is linear in the text length; decoding is linear in the number of bits. Ties are broken by insertion order, so the same frequencies always give the same code table.

F. Detailed Dry Run

Heap {f5, e9, c12, b13, d16, a45}. Poll f5 and e9, push 14 (cost so far 14). Poll c12 and b13, push 25 (cost 39). Poll 14 and d16, push 30 (cost 69). Poll 25 and 30, push 55 (cost 124). Poll 45 and 55, push 100 (cost 224). The accumulated merge cost 224 equals Σ freq · depth (the table above): 45·1 + 12·3 + 13·3 + 16·3 + 5·4 + 9·4 = 224.

Encoding abc with the table gives 0 + 101 + 100 = 0101100; decoding walks: bit 0 reaches leaf a; bits 101 reach b; bits 100 reach c.

G. Variations of the Pattern

Minimum Cost to Connect Sticks (1167)

Total of all merge sums with a min-heap. Identical to Huffman cost with sticks as symbols.

k-ary Huffman

To merge k items at a time, pad with zero-weight dummies until (n − 1) mod (k − 1) = 0, then merge the k lightest each time.

Minimum Cost to Merge Stones (1000)

Only adjacent stones may be merged: the free-order greedy no longer applies, and it becomes an interval DP (Part XI). A good contrast.

Canonical Huffman and real formats

DEFLATE (gzip, PNG), JPEG and many codecs transmit only the code lengths and rebuild canonical codes by sorting (length, symbol). This reduces the table size and makes decoding table-driven.

Limits

Huffman is optimal among codes that assign a whole number of bits per symbol. Arithmetic coding and ANS can approach the entropy bound −Σ p log₂ p when probabilities are not powers of 1/2; adaptive Huffman updates the tree while streaming.

J. Interview Tips

INTERVIEW

Say "always merge the two smallest" and justify it with the exchange argument: the two lightest can be sibling leaves at the deepest level.

Connect cost and depth: total merge cost equals Σ weight · depth; it explains why the greedy also gives the best code.

Mention the limits: whole bits per symbol, prefix property, and where Huffman is used in practice (DEFLATE, JPEG).

Follow-ups: produce canonical codes; ternary Huffman; limit the maximum code length (package-merge); stream decoding with a lookup table; compare with the entropy bound.
Edge cases: one symbol, two symbols, all equal frequencies (a balanced tree), extremely skewed frequencies (a linear chain of depth n − 1).

CHAPTER SUMMARY

Huffman coding: merge the two lightest trees until one remains; codes are the root-to-leaf paths; the result minimises Σ freq · depth among prefix codes.

Why it works: the two lightest symbols can be deepest siblings in some optimal tree (exchange argument); merging them gives a smaller instance of the same problem.

Cost view: the total merge cost equals the weighted path length, so Connect Sticks needs only a min-heap and a long total.

Codes are prefix-free (symbols at leaves) and complete (Kraft sum = 1); a single symbol gets the code 0.

Where merging is restricted to neighbours (Minimum Cost to Merge Stones), the greedy fails and DP takes over.
