Combinations

Choose k of n: increasing order, bound pruning, lexicographic iteration.

A. Pattern Overview

A combination is a selection of exactly k elements from n, order ignored: C(n, k) = n! / (k!(n−k)!) of them (C(20, 10) = 184 756). It is the subsets pattern with a size limit, and the limit enables a powerful kind of pruning: if too few elements remain to reach size k, stop.

IdeaRuleEffect
Increasing orderNext element index ≥ last + 1Each combination is produced once, as a sorted list
Size limitRecord only when size == kLeaves sit at depth k
Bound pruningLoop x only up to n − (k − size) + 1No branch is explored that cannot be completed
Remaining-sum pruningStop when the digit exceeds what is left (Combination Sum III)Cuts the tail of every loop (digits ascend)
KEY IDEA

Prune with the feasibility bound, not with the answer. Before recursing, ask: can this prefix still become a full answer? For combinations the test is arithmetic: need = k − size elements are still required, so the next pick can be at most n − need + 1.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Choose k numbers / items out of n", order irrelevant: Combinations (77).
"Find all combinations of k numbers that sum to n, using each digit at most once":

Combination Sum III (216).

"Iterator over combinations in lexicographic order": Iterator for Combination (1286).
Fixed-size subsets with a property (team selection, committee, k-subset with bounded sum).
ONE-LINE TEST

If the problem fixes the size of a selection and does not care about order, enumerate with a start index and prune when n − start + 1 < need.

C. Core Intuition with Illustrations

The pruned tree for C(4, 2)

With n = 4, k = 2: after choosing the first element, need = 1, so the second can be any of the later numbers. For the first pick need = 2, so x stops at n − 2 + 1 = 3: starting with 4 can never produce two elements. The ✗ shows the pruned pick.

Figure 69. Without the bound the first loop would also try 4, creating a node that dies immediately; at larger n such dead nodes dominate.

How much does the bound save?

For n = 20, k = 10 the answer has 184 756 leaves. Without the bound the tree contains every prefix of every increasing sequence, including many that cannot reach length 10; with the bound, every internal node has at least one leaf below it, so the work is O(C(n, k) · k).

Lexicographic iteration without recursion

Iterator for Combination keeps the index set idx[0] < idx[1] < … < idx[k−1]. To advance: find the rightmost i with idx[i] < n − k + i (it can still move right), increment it, and reset everything after it to consecutive values. This is the combination analogue of next permutation.

E. Java Implementation

Combinations (LeetCode 77)

Combinations.java: LeetCode 77
import java.util.ArrayList;
import java.util.List;

/** LeetCode 77 - Combinations: all k-subsets of 1..n in increasing order. */
public class Combinations {
    public static List<List<Integer>> combine(int n, int k) {
        List<List<Integer>> out = new ArrayList<>();
        build(1, n, k, new ArrayList<>(), out);
        return out;
    }

Java 17+

    private static void build(int start, int n, int k, List<Integer> cur,
            List<List<Integer>> out) {
        if (cur.size() == k) { out.add(new ArrayList<>(cur)); return; }
        int need = k - cur.size();
        // prune: fewer than `need` numbers remain beyond this bound
        for (int x = start; x <= n - need + 1; x++) {
            cur.add(x);
            build(x + 1, n, k, cur, out);
            cur.remove(cur.size() - 1);
        }
    }
}

TIME O(C(n, k) · k)

SPACE O(k)

need = k − cur.size() and the loop bound n − need + 1

are the entire optimisation.

Combination Sum III (LeetCode 216)

CombinationSumIII.java: LeetCode 216
import java.util.ArrayList;
import java.util.List;

/** LeetCode 216 - Combination Sum III: k distinct digits 1..9 that add to n. */
public class CombinationSumIII {
    public static List<List<Integer>> combinationSum3(int k, int n) {
        List<List<Integer>> out = new ArrayList<>();
        build(1, k, n, new ArrayList<>(), out);
        return out;
    }

    private static void build(int start, int k, int remain, List<Integer> cur,
            List<List<Integer>> out) {
        if (cur.size() == k) {
            if (remain == 0) out.add(new ArrayList<>(cur));
            return;
        }
        for (int d = start; d <= 9; d++) {
            // digits only grow: nothing further can fit
            if (d > remain) break;
            cur.add(d);
            build(d + 1, k, remain - d, cur, out);
            cur.remove(cur.size() - 1);
        }
    }
}

Java 17+

TIME O(C(9, k) · k)

SPACE O(k)

At most C(9, k) ≤ 126 combinations, so the search is tiny;

the break on d > remain is valid because digits ascend.

Iterator for Combination (LeetCode 1286)

CombinationIterator.java: LeetCode 1286

Java 17+

/**
 * LeetCode 1286 - Iterator for Combinations. Keeps the current index set and advances it
 * lexicographically.
 */
public class CombinationIterator {
    private final String chars;
    // idx[i] = position in chars of the i-th chosen character
    private final int[] idx;
    private boolean hasNext;

    public CombinationIterator(String characters, int combinationLength) {
        this.chars = characters;
        this.idx = new int[combinationLength];
        for (int i = 0; i < combinationLength; i++) idx[i] = i;
        this.hasNext = combinationLength <= characters.length();
    }

    public String next() {
        StringBuilder sb = new StringBuilder();
        for (int i : idx) sb.append(chars.charAt(i));
        advance();
        return sb.toString();
    }

    public boolean hasNext() { return hasNext; }

    private void advance() {
        int k = idx.length, n = chars.length();
        int i = k - 1;
        // rightmost index that can still move right
        while (i >= 0 && idx[i] == n - k + i) i--;
        if (i < 0) { hasNext = false; return; }
        idx[i]++;
        for (int j = i + 1; j < k; j++) idx[j] = idx[j - 1] + 1;
    }
}

TIME O(k) per next()

SPACE O(k)

hasNext() is O(1). Assumes the characters are given in sorted order and are distinct, as the problem guarantees.

G. Variations of the Pattern

Combinations with repeats allowed

Recurse with x instead of x + 1: Combination Sum (Chapter 35) and combinations with replacement, C(n + k − 1, k) of them.

Combinations from groups

One element per group is the Cartesian product (Letter Combinations, Chapter 31); one per row of a matrix is the same loop.

Count only

C(n, k) follows Pascal's rule C(n, k) = C(n−1, k−1) + C(n−1, k): include n or not. With a sum or other state, the count becomes DP (Target Sum, Partition Equal Subset Sum).

Combinations by bitmask and Gosper's hack

next = (x + c) | (((x ^ (x + c)) >> 2) / c) where c = x & −x yields the next integer with the same number of set bits. Useful for subset DP restricted to a fixed size.

Team formation and scheduling

Pick k workers minimising a cost, with n ≤ 20: enumerate combinations and evaluate, or

use DP if the objective decomposes.

J. Interview Tips

INTERVIEW

Write the bound as a sentence: "I need need more numbers, so the next pick cannot exceed n − need + 1." It shows you see why it is correct.

Contrast with permutations in one line: increasing indices means order is ignored.

For the iterator, mention the analogy to next permutation; it is a mutation of the index set, not recursion.

Follow-ups: repeats allowed; sum constraint; n large with k = 2 or 3 (use two pointers

or hashing instead of enumeration); lazily produce combinations; count C(n, k) mod p (Part XII).

Edge cases: k = 0 (one empty combination), k = n (one combination), k > n (none), n = 1.

CHAPTER SUMMARY

A combination is an unordered selection of size k: C(n, k) of them. Enumerate with increasing indices and record when size == k.

Bound pruning: need = k − size; the next pick is at most n − need + 1. Every node then leads to at least one answer.

Combination Sum III: digits ascend, so d > remain is a break.

Iterator: keep an index set; advance the rightmost index that can move, then reset the tail to consecutive values.

Contrast: subsets (any size), permutations (order matters), combination sum (reuse allowed).
