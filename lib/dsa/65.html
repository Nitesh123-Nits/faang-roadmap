Minimum Spanning Tree

Connect everything as cheaply as possible: Kruskal sorts, Prim grows.

A. Pattern Overview

A spanning tree of a connected undirected graph is a subset of n − 1 edges that connects all vertices without a cycle. A minimum spanning tree (MST) is a spanning tree of least total weight. It models "connect all sites with the least cable", and underlies clustering and approximation algorithms.

KEY IDEA

Greedy works here because of the cut property. At every step the algorithm adds the lightest edge that crosses some cut, which is always safe. (This is why greedy fails for shortest paths with negative edges or for the travelling salesman problem: they lack such a property.)

B. When to Recognize This Pattern

Pattern Recognition Signals

"Connect all nodes / cities / points with minimum total cost".
"Minimum cable / road / pipe length" and every node must be reachable.
Cost of an edge is given, the answer is a total, not a path.
"Minimise the maximum edge" to connect two nodes: the minimax path lies on the MST.
"Clusters": remove the k − 1 heaviest MST edges to get k groups (single-linkage clustering).
A complete graph on points with Manhattan or Euclidean distances: dense Prim, O(n²).
ONE-LINE TEST

"Connect everything" + "minimum total" = MST. "Shortest route from A to B" = shortest path. Do not confuse them: the MST does not give shortest paths.

Dense graphs: Prim in O(n²)

For Min Cost to Connect All Points (1584) the graph is complete with n²/2 edges. Never build the edge list (n = 1000 gives 500 000 edges and a sort). Keep dist[v] = cheapest edge into the tree, and each round scan for the minimum: O(n²) time, O(n) memory.

Why the cycle property is the Kruskal rejection rule

When Kruskal examines edge e = (u, v) and u, v are already connected, all edges on that path are no heavier than e (they were examined earlier). So e is the heaviest edge on a cycle and is safe to discard.

Minimax paths

The path between two vertices in the MST minimises the largest edge weight among all paths between them. That is how Path With Minimum Effort can also be solved, and it is the key to "minimum bottleneck" queries.

E. Java Implementation

Kruskal, Prim (heap), dense Prim, connecting points

MinimumSpanningTree.java: LeetCode 1584, 1135
import java.util.*;

/** Ch 54: Kruskal and Prim; LeetCode 1584, 1135. */
public class MinimumSpanningTree {

    /**
     * Kruskal: sort edges, keep each edge that joins two components. -1 if
     * disconnected.
     */
    public static long kruskal(int n, int[][] edges) {
        int[][] sorted = edges.clone();
        Arrays.sort(sorted, Comparator.comparingInt(e -> e[2]));
        UnionFind uf = new UnionFind(n);
        long total = 0;
        int used = 0;
        for (int[] e : sorted)
            if (uf.union(e[0], e[1])) {
                total += e[2];
                if (++used == n - 1) break;
            }
        return used == n - 1 ? total : -1;
    }

Java 17+

    /** Prim with a heap, growing from node 0. -1 if disconnected. */
    public static long prim(int n, int[][] edges) {
        List<List<int[]>> g = GraphRepresentation.weightedAdjList(n, edges, false);
        boolean[] in = new boolean[n];
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
        pq.add(new int[] {0, 0});
        long total = 0;
        int taken = 0;
        while (!pq.isEmpty() && taken < n) {
            int[] top = pq.poll();
            if (in[top[0]]) continue;                  // already in the tree
            in[top[0]] = true;
            total += top[1];
            taken++;
            for (int[] e : g.get(top[0]))
                if (!in[e[0]]) pq.add(new int[] {e[0], e[1]});
        }
        return taken == n ? total : -1;
    }

    /**
     * LeetCode 1584: complete graph on points, Manhattan distance. Dense Prim
     * O(n^2).
     */
    public static int minCostConnectPoints(int[][] pts) {
        int n = pts.length;
        int[] dist = new int[n];
        boolean[] in = new boolean[n];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[0] = 0;
        int total = 0;
        for (int round = 0; round < n; round++) {
            int u = -1;
            for (int v = 0; v < n; v++)
                if (!in[v] && (u < 0 || dist[v] < dist[u])) u = v;
            in[u] = true;
            total += dist[u];
            for (int v = 0; v < n; v++)
                if (!in[v]) {
                    int w = Math.abs(pts[u][0] - pts[v][0])
                            + Math.abs(pts[u][1] - pts[v][1]);
                    if (w < dist[v]) dist[v] = w;
                }
        }
        return total;
    }

    /** LeetCode 1135 (cities 1..n): Kruskal on 1-based input. */
    public static int minimumCost(int n, int[][] connections) {
        int[][] e = new int[connections.length][];
        for (int i = 0; i < e.length; i++)
            e[i] = new int[] {connections[i][0] - 1, connections[i][1] - 1,
                              connections[i][2]};
        return (int) kruskal(n, e);
    }
}

G. Variations of the Pattern

Second-best MST and critical edges

Find Critical and Pseudo-Critical Edges in MST (1489): an edge is critical if the MST weight rises when it is removed; pseudo-critical if forcing it in keeps the weight. Run Kruskal m times,

O(m² α).

Minimum cost with extras

Optimize Water Distribution (1168): add a virtual vertex 0 connected to every house with the well cost; then it is a plain MST.

Maximum spanning tree

Sort descending (or negate weights) and run the same algorithm.

Clustering

Stop Kruskal when k components remain: the k groups maximise the smallest distance between two different groups (single-linkage clustering). Equivalently, delete the k − 1 heaviest edges of the finished MST.

Directed graphs

The directed analogue, a minimum arborescence (Chu-Liu/Edmonds), needs a different algorithm; Kruskal and Prim do not apply.

Name both algorithms and the deciding factor (sparse → Kruskal, dense → array Prim); mention the cut property for correctness.

Check connectivity out loud: used == n − 1.

For point sets, skip the edge list: "complete graph, so O(n²) Prim without building edges."

Follow-ups: prove Kruskal (cycle property); second-best MST; MST with some edges forced; dynamic MST; Borůvka's algorithm (parallel, O(m log n)).

CHAPTER SUMMARY

An MST has n − 1 edges, connects everything, and has the least total weight; it does not give shortest paths.

Kruskal: sort edges, accept an edge iff Union-Find says its ends are in different components. O(m log m).

Prim: grow from a vertex with a min-heap (or an array scan for O(n²)).

Correctness rests on the cut property (lightest crossing edge is safe) and the cycle property (heaviest cycle edge is discardable).

For point sets use dense Prim with no edge list; always check connectivity (used == n − 1) and use long totals.
