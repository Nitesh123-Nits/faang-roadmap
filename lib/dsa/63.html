Union-Find (DSU)

Merge sets and ask "same set?" in almost constant time.

A. Pattern Overview

Union-Find (disjoint set union, DSU) maintains a partition of n elements under two operations: union(a, b) merges the sets of a and b; find(a) returns a representative of a's set. Each set is stored as a tree of parent pointers; the root is the representative. Two

optimisations make both operations O(α(n)), effectively constant (α is the inverse

Ackermann function, below 5 for any real input):

OptimisationWhat it doesEffect
Path compression / halvingWhile walking up in find, point nodes closer to the rootFlattens trees for later queries
Union by size or rankAttach the smaller tree under the larger rootKeeps height O(log n)
Both togetherAmortised O(α(n)) per operation
KEY IDEA

Union-Find only merges. It answers "are they connected now?" for edges arriving online, but cannot delete an edge. For deletions, process offline in reverse (turn deletions into insertions).

B. When to Recognize This Pattern

Pattern Recognition Signals

"Are X and Y connected?" with edges, equalities, friendships or swaps given as a list or arriving over time.
"Merge groups" of items that share an attribute (accounts, emails, equivalent strings).
"Which edge creates a cycle" / "redundant connection": the first union that returns false.
"Number of components after each operation" (islands appearing one by one).
Equality constraints (a == b, a != b) and equivalence classes.
Kruskal's MST needs a fast cycle test (Chapter 54).
ONE-LINE TEST

Symmetric relations that only ever join things, and queries "same group?" → Union-Find. If you must also split groups, think offline-reverse or a different structure.

C. Core Intuition with Illustrations

Forest of parent pointers

Start with n singletons: parent[i] = i. find follows parents to a root. union links one root under another. Here is the sample run on 5 elements.

Figure 92. Arrows point from a vertex to its parent; the root has no outgoing arrow.

The last operation union(0, 3) finds the same root (0) for both, so it is redundant: in Redundant Connection this is the edge to return. Final parent[] = [0, 0, 0, 0, 4]; 4 stays a singleton.

Why path halving works

while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; } makes every other node on the path point to its grandparent. It needs no recursion, no stack and no second pass, and gives the same amortised bound as full compression.

Union by size

Attaching the smaller tree under the larger keeps the height at most log₂ n. Store

size[root] too: sizeOf(x) becomes O(α), and you can track the largest group (Making a Large

Island, Largest Component Size).

Weighted Union-Find

Store with each node its ratio (or offset) to its parent. find multiplies ratios along the path while compressing it; union(a, b, k) sets ratio[rootA] = k · ratio[b] / ratio[a]. Then a / b = ratio[a] / ratio[b] when both share a root. The same idea handles parity (Is Graph Bipartite, Possible Bipartition) with XOR.

E. Java Implementation

UnionFind class and the classic problems

UnionFind.java: LeetCode 684, 1202, 990, 947, 399
import java.util.*;

/** Ch 52: disjoint set union; LeetCode 684, 1202, 990, 947, 399. */
public class UnionFind {
    private final int[] parent, size;
    private int sets;

    public UnionFind(int n) {
        parent = new int[n];
        size = new int[n];
        sets = n;
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            size[i] = 1;
        }
    }

    /** Root of x with path halving: every other node jumps to its grandparent. */
    public int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }

    /** Union by size. Returns false if a and b were already connected. */
    public boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        size[ra] += size[rb];
        sets--;
        return true;
    }

    public boolean connected(int a, int b) { return find(a) == find(b); }
    public int sets() { return sets; }
    public int sizeOf(int x) { return size[find(x)]; }

    /** LeetCode 684: nodes 1..n; the edge that closes a cycle (the last such). */
    public static int[] findRedundantConnection(int[][] edges) {
        UnionFind uf = new UnionFind(edges.length + 1);
        for (int[] e : edges) if (!uf.union(e[0], e[1])) return e;
        return new int[0];
    }

    /** LeetCode 1202: swap characters inside connected index groups, sort each. */
    public static String smallestStringWithSwaps(String s,
                                                 List<List<Integer>> pairs) {
        int n = s.length();
        UnionFind uf = new UnionFind(n);
        for (List<Integer> p : pairs) uf.union(p.get(0), p.get(1));

    /** LeetCode 990: equations like "a==b" and "a!=b" over lowercase letters. */
    public static boolean equationsPossible(String[] equations) {
        UnionFind uf = new UnionFind(26);
        for (String e : equations)
            if (e.charAt(1) == '=') uf.union(e.charAt(0) - 'a', e.charAt(3) - 'a');
        for (String e : equations)
            if (e.charAt(1) == '!'
                    && uf.connected(e.charAt(0) - 'a', e.charAt(3) - 'a'))
                return false;
        return true;
    }

    /**
     * LeetCode 947: stones sharing a row or column are connected; answer n - sets.
     */
    public static int removeStones(int[][] stones) {
        // columns are offset by 10001
        UnionFind uf = new UnionFind(20002);
        Set<Integer> used = new HashSet<>();
        for (int[] s : stones) {
            uf.union(s[0], s[1] + 10001);
            used.add(s[0]);
            used.add(s[1] + 10001);
        }
        Set<Integer> roots = new HashSet<>();
        for (int x : used) roots.add(uf.find(x));
        return stones.length - roots.size();
    }

    /**
     * LeetCode 399 by weighted union-find: value[x] = x / root(x).
     * Unknown variables give -1.0.
     */
    public static double[] calcEquation(List<List<String>> equations,
                                        double[] values,
                                        List<List<String>> queries) {
        Map<String, String> parent = new HashMap<>();
        Map<String, Double> ratio = new HashMap<>();   // ratio of x to parent[x]
        for (int i = 0; i < equations.size(); i++) {
            String a = equations.get(i).get(0), b = equations.get(i).get(1);
            parent.putIfAbsent(a, a);
            ratio.putIfAbsent(a, 1.0);
            parent.putIfAbsent(b, b);
            ratio.putIfAbsent(b, 1.0);
            String ra = findW(parent, ratio, a), rb = findW(parent, ratio, b);
            if (!ra.equals(rb)) {
                // a/ra = ratio[a], b/rb = ratio[b], a/b = values[i]
                parent.put(ra, rb);
                ratio.put(ra, values[i] * ratio.get(b) / ratio.get(a));
            }
        }
        double[] out = new double[queries.size()];
        for (int i = 0; i < out.length; i++) {
            String a = queries.get(i).get(0), b = queries.get(i).get(1);
            if (!parent.containsKey(a) || !parent.containsKey(b)) {
                out[i] = -1.0;
                continue;
            }
            String ra = findW(parent, ratio, a), rb = findW(parent, ratio, b);
            out[i] = ra.equals(rb) ? ratio.get(a) / ratio.get(b) : -1.0;
        }
        return out;
    }

    /** Find with full compression; afterwards ratio[x] is x / root. */
    private static String findW(Map<String, String> parent,
                                Map<String, Double> ratio, String x) {
        Deque<String> path = new ArrayDeque<>();
        String r = x;
        while (!parent.get(r).equals(r)) {
            path.push(r);
            r = parent.get(r);
        }
        double acc = 1.0;                              // product from the top down
        while (!path.isEmpty()) {
            String v = path.pop();
            acc *= ratio.get(v);
            ratio.put(v, acc);
            parent.put(v, r);
        }
        return r;
    }
}

TIME O(α(n)) per op

SPACE O(n)

union returns false when the ends were already connected, which is exactly the cycle test. calcEquation uses a weighted DSU over strings; findW compresses the whole path and rescales ratios.

F. Detailed Dry Run

Replay the table in section C. union(0, 1): both singletons, equal size, so root 1 goes under root 0 (parent = [0, 0, 2, 3, 4], size[0] = 2). union(2, 3) likewise (parent[3] = 2). union(1, 2): find(1) = 0, find(2) = 2, both trees have size 2, tie goes to ra = 0, so root 2 is attached under 0 (parent = [0, 0, 0, 2, 4]). Finally union(0, 3): find(3) follows 3 → 2 → 0 (halving rewrites parent[3] = 0) and equals find(0), so the answer is false. Final printed parent is [0, 0, 0, 0, 4].

G. Variations of the Pattern

Component tracking

Keep sets and size: Number of Islands II (305) adds land one cell at a time and reports the

count after each addition in O(k α).

Offline reverse

To support deletions, read the operations backwards: deleting an edge becomes inserting it (Bricks Falling When Hit, Remove Max Number of Edges).

Parity / bipartite DSU

Store parity to the root. union(a, b) with a and b differ checks parity consistency; a contradiction means an odd cycle (Possible Bipartition).

Grouping by common factor or key

Largest Component Size by Common Factor (952): union each number with its prime factors; groups come from shared primes. Regions Cut by Slashes (959): each cell is split into 4 triangles that are unioned.

Kruskal

Sort edges by weight; add an edge iff union succeeds. Minimum spanning tree in O(m log m) (Chapter 54).

CHAPTER SUMMARY

Union-Find supports union and find in amortised O(α(n)) with path halving + union by size.

union returns false when the ends are already connected: the cycle test, and Kruskal's accept/reject.

It handles online merges; it cannot split. For deletions, process offline in reverse.

Model implicit relations as elements: letters, indices, rows and columns, sub-cells; weighted / parity variants carry a value to the root.

Write find iteratively and compare roots, never raw parents.
