Prefix Sum

Pay O(n) once, answer every range question in O(1), and turn subarray sums into a lookup.

A. Pattern Overview

A prefix sum array stores prefix[i] = nums[0] + … + nums[i-1]. Because the sum of any range is a difference of two prefixes (sum(l..r) = prefix[r+1] - prefix[l]), a range query costs O(1) after an O(n) build. Combine it with a HashMap and it solves "how many subarrays satisfy X" questions in one pass, even with negative numbers.

Versus sliding window. A window maintains one moving range and needs monotone validity. Prefix sums describe all ranges at once and work with negatives, but they require the quantity to be subtractable (sums, counts, XOR, remainders), not arbitrary properties such as "distinct count".

B. When to Recognize This Pattern

Pattern Recognition Signals

Many range-sum (or range-count) queries on a static array: "sum between i and j", answered repeatedly.
"Number of subarrays with sum / XOR / balance equal to k", especially when the array

has negative numbers or zeros.

"Longest subarray with equal 0s and 1s" or another balance condition: map the values to ±1 and look for sum 0.
"Divisible by k" subarray sums: equal prefix remainders mean the difference is divisible

by k.

You catch yourself computing sum(nums[i..j]) inside two loops.
An answer at index i needs an aggregate of everything to the left and everything to the

right (product except self, pivot index).

DECISION RULE

If a problem says "subarray" and "sum equals" and the numbers can be negative, think prefix sum + HashMap first and sliding window never.

C. Core Intuition with Illustrations

Figure 11. The teal range sums to 4 + 1 + 5 = 10. Subtracting two prefixes cancels everything outside the range.

The HashMap idea. A subarray nums[i..j] sums to k exactly when prefix[j+1] - prefix[i] = k, i.e. when an earlier prefix equals prefix[j+1] - k. Scan left to right keeping a map prefixValue → how many times seen; at each index look up currentPrefix - k.

INTUITION

Seed the map with {0: 1}. It represents the empty prefix, which makes subarrays that start at index 0 countable. Query before you insert the current prefix, or a subarray of length 0 would be counted when k = 0.

D. Brute Force to Optimal Solution

Example: Subarray Sum Equals K (LeetCode 560)

Brute force: for each start i, extend j and keep a running sum: O(n²) time, O(1) space.With n = 2·10⁴ it passes; with n = 10⁵ it does not.
Sliding window? Not valid: the values may be negative, so extending can lower the sum and shrinking can raise it.
Reformulate: sum(i..j) = P[j+1] - P[i]. We need pairs (i, j+1) with P[j+1] - P[i] = k. That is a two-sum on prefix values.
Optimal: one pass with Map<prefix, count>: O(n) time, O(n) space.

E. Java Implementation

Range sum queries (1D)

NumArray.java — LeetCode 303
/** LeetCode 303 - Range Sum Query - Immutable. prefix[i] = sum of nums[0..i-1]. */
public class NumArray {
    private final long[] prefix;

    public NumArray(int[] nums) {
        // prefix[0] = 0 is the empty-prefix sentinel
        prefix = new long[nums.length + 1];
        for (int i = 0; i < nums.length; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
    }

    /** Sum of nums[left..right], both inclusive, in O(1). */
    public long sumRange(int left, int right) {
        return prefix[right + 1] - prefix[left];
    }
}

Prefix sum + HashMap (counting): Subarray Sum Equals K

SubarraySumEqualsK.java — LeetCode 560

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 560 - Subarray Sum Equals K. Prefix sums + frequency HashMap. Works with
 * negatives.
 */
public class SubarraySumEqualsK {

    public static int subarraySum(int[] nums, int k) {
        Map<Long, Integer> seen = new HashMap<>();
        // the empty prefix: lets subarrays start at index 0
        seen.put(0L, 1);
        long prefix = 0;
        int count = 0;
        for (int x : nums) {
            prefix += x;
            // A subarray ending here sums to k iff an earlier prefix equals (prefix - k).
            count += seen.getOrDefault(prefix - k, 0);
            // record AFTER querying: subarray must be non-empty
            seen.merge(prefix, 1, Integer::sum);
        }
        return count;
    }
}

TIME O(n)

SPACE O(n)

long prefix and Long keys avoid overflow for large inputs.

G. Variations of the Pattern

Remainders: Continuous Subarray Sum (length ≥ 2, multiple of k)

If two prefixes have the same remainder mod k, the elements between them sum to a multiple of k. Store the earliest index per remainder (to maximise length) and require a gap of at least 2.

ContinuousSubarraySum.java — LeetCode 523

Java 17+

import java.util.HashMap;
import java.util.Map;

/** LeetCode 523 - Continuous Subarray Sum. Prefix remainders; need length >= 2. */
public class ContinuousSubarraySum {

    public static boolean checkSubarraySum(int[] nums, int k) {
        Map<Long, Integer> firstIndex = new HashMap<>();
        firstIndex.put(0L, -1);                  // remainder 0 "before" index 0
        long remainder = 0;
        for (int i = 0; i < nums.length; i++) {
            remainder = (remainder + nums[i]) % k;
            Integer prev = firstIndex.get(remainder);
            if (prev == null) {
                firstIndex.put(remainder, i);    // keep the EARLIEST index to maximise length
            } else if (i - prev >= 2) {
                return true;
            }
        }
        return false;
    }
}

TIME O(n)

SPACE O(min(n, k))

Seed {0 → -1}: remainder 0 "before" the array. long keeps remainder + nums[i] from overflowing when k is near 2³¹.

Negative remainders: Subarray Sums Divisible by K (counting)
SubarraysDivByK.java — LeetCode 974

Java 17+

/**
 * LeetCode 974 - Subarray Sums Divisible by K. Count equal prefix remainders; fix negative
 * mods.
 */
public class SubarraysDivByK {

    public static int subarraysDivByK(int[] nums, int k) {
        int[] remainderCount = new int[k];
        remainderCount[0] = 1;                       // empty prefix
        int remainder = 0;
        int count = 0;
        for (int x : nums) {
            remainder = ((remainder + x) % k + k) % k;   // Java % can be negative: normalise
            count += remainderCount[remainder];
            remainderCount[remainder]++;
        }
        return count;
    }
}

TIME O(n)

SPACE O(k)

In Java -3 % 5 == -3. Normalise with ((r % k) + k) % k or equal remainders will not match.

Balance trick: Contiguous Array

Map 0 → −1 and 1 → +1. A subarray with equal zeros and ones has balance 0, so equal prefix

balances mark its ends. Store the first index of each balance.

ContiguousArray.java — LeetCode 525

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 525 - Contiguous Array. Map 0 -> -1 so "equal zeros and ones" becomes "sum equals
 * 0".
 */
public class ContiguousArray {

    public static int findMaxLength(int[] nums) {
        Map<Integer, Integer> firstIndex = new HashMap<>();
        firstIndex.put(0, -1);
        int balance = 0;
        int best = 0;
        for (int i = 0; i < nums.length; i++) {
            balance += nums[i] == 1 ? 1 : -1;
            Integer prev = firstIndex.get(balance);
            if (prev != null) {
                best = Math.max(best, i - prev);
            } else {
                firstIndex.put(balance, i);
            }
        }
        return best;
    }
}

TIME O(n)

SPACE O(n)

Prefix and suffix products: Product of Array Except Self
answer[i] = (product of everything left of i) × (product of everything right of i).

First fill answer with left products, then sweep from the right multiplying by a running suffix. No division, so zeros are handled automatically.

ProductExceptSelf.java — LeetCode 238

Java 17+

/** LeetCode 238 - Product of Array Except Self. Prefix and suffix products, no division. */
public class ProductExceptSelf {

    public static int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] answer = new int[n];

        answer[0] = 1;                                   // answer[i] = product of nums[0..i-1]
        for (int i = 1; i < n; i++) {
            answer[i] = answer[i - 1] * nums[i - 1];
        }
        int suffix = 1;                                  // running product of nums[i+1..n-1]
        for (int i = n - 1; i >= 0; i--) {
            answer[i] *= suffix;
            suffix *= nums[i];
        }
        return answer;
    }
}

TIME O(n)

SPACE O(1) extra

The output array is not counted as extra space. Overflow is guaranteed not to occur by the problem constraints.

2D prefix sums: Range Sum Query 2D
NumMatrix.java — LeetCode 304

Java 17+

/** LeetCode 304 - Range Sum Query 2D - Immutable. 2D prefix sums + inclusion-exclusion. */
public class NumMatrix {
    private final int[][] prefix;    // prefix[r][c] = sum of matrix[0..r-1][0..c-1]

    public NumMatrix(int[][] matrix) {
        int rows = matrix.length;
        int cols = rows == 0 ? 0 : matrix[0].length;
        prefix = new int[rows + 1][cols + 1];
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                prefix[r + 1][c + 1] = matrix[r][c]
                        // inclusion-exclusion
                        + prefix[r][c + 1] + prefix[r + 1][c] - prefix[r][c];
            }
        }
    }

    public int sumRegion(int row1, int col1, int row2, int col2) {
        return prefix[row2 + 1][col2 + 1] - prefix[row1][col2 + 1]
             - prefix[row2 + 1][col1] + prefix[row1][col1];
    }
}

TIME Build O(R·C) · query O(1)

SPACE O(R·C)

J. Interview Tips

INTERVIEW

Verbalise the reduction: "subarray sum = difference of two prefixes, so this is two-sum over prefix values." That one sentence signals mastery.

Justify the map seed ({0: 1}) and the query-then-insert order before writing code; they are where most bugs live.

Offer the space trade-off: O(n) map versus O(1) for the brute force, and why the map is worth it.

Follow-ups: return the subarray (store indices), longest vs count vs existence (change what the map stores), subarray XOR equals K (same idea with XOR), 2D version (fix two rows, run 1D on columns: LeetCode 1074).large k versus remainders.
Edge cases: empty array, k = 0, all zeros, negative values, single element equal to k,
Optimisation: replace the HashMap with an int[k] when keys are remainders in [0, k).
