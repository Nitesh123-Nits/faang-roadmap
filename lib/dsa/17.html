Classic Binary Search

Halve the search space every step by keeping an invariant: O(log n) from a sorted order.

A. Pattern Overview

Binary search finds a position in a sorted (more generally, monotone) sequence by comparing the middle element with the target and discarding the half that cannot contain the answer. Each step halves the search space, so n = 10⁹ needs at most 30 comparisons. Everything in Part II is a variation of one idea: keep an invariant that says where the answer must be, and shrink the range while preserving it.

KEY IDEA

Think of binary search as finding the boundary of a predicate. For a sorted array and a target t, the predicate nums[i] >= t is false … false true … true. The first true is the lower bound. Exact search, insert position, first/last occurrence and sqrt are all "find the first true" in disguise.

B. When to Recognize This Pattern

Pattern Recognition Signals

The input is sorted (or sorted after a cheap pre-step) and the statement asks to find, locate, count or insert.
The required complexity is O(log n), or n is so large (10⁹+) that a linear scan is

impossible.

You can define a yes/no question about an index whose answer flips exactly once: false … false true … true.
Phrases: "first/last position", "smallest index such that", "insert position", "closest to", "how

many times does x appear".

Linear search works but the interviewer says "can you do better?" on sorted data.
DECISION RULE

Sorted input + O(log n) hint → binary search. No sorted input but a monotone yes/no answer over a numeric range → binary search on the answer (Chapter 13).

INTUITION

Choose the loop shape to match the question. Closed range [lo, hi] with while (lo <= hi) suits exact match (the answer may be mid, and we exclude it when wrong). Half-open range [lo, hi) with while (lo < hi) suits boundary search (mid can still be the answer, so hi = mid, never mid - 1).

D. Brute Force to Optimal Solution

Example: First and Last Position of an Element (LeetCode 34)

Brute force: scan once, record the first and last index equal to t: O(n). Correct, but the statement demands O(log n).
Binary search then expand: find any occurrence and walk outwards. Looks fast, but with n equal elements it degrades to O(n).
Observation: the first occurrence is the first index with nums[i] >= t; the last occurrence is the first index with nums[i] > t, minus one.
Optimal: two boundary searches sharing one helper: O(log n) time, O(1) space.

E. Java Implementation

Exact search, lower bound and upper bound

BinarySearchClassic.java — LeetCode 704 and the two boundary templates

Java 17+

/** Classic binary search family on a sorted int[]: exact match, lower bound, upper bound. */
public class BinarySearchClassic {

    /** LeetCode 704. Returns an index of target, or -1. Closed interval [lo, hi]. */
    public static int search(int[] nums, int target) {
        int lo = 0;
        int hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;            // never (lo + hi) / 2: that can overflow
            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return -1;
    }

    /** First index i with nums[i] >= target, or nums.length if none. Half-open [lo, hi). */
    public static int lowerBound(int[] nums, int target) {
        int lo = 0;
        int hi = nums.length;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] < target) {
                lo = mid + 1;        // mid is too small: the answer is strictly to the right
            } else {
                hi = mid;            // mid might be the answer: keep it in range
            }
        }
        return lo;
    }

    /** First index i with nums[i] > target, or nums.length if none. */
    public static int upperBound(int[] nums, int target) {
        int lo = 0;
        int hi = nums.length;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] <= target) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }
        return lo;
    }
}

TIME O(log n)

SPACE O(1)

Always lo + (hi - lo) / 2. (lo + hi) / 2 overflows int once lo + hi > 2³¹ − 1, which happens for arrays near 10⁹ elements.

First and Last Position

FirstLastPosition.java — LeetCode 34

Java 17+

/**
 * LeetCode 34 - Find First and Last Position of Element in Sorted Array. Two boundary
 * searches.
 */
public class FirstLastPosition {

    public static int[] searchRange(int[] nums, int target) {
        int first = firstIndexAtLeast(nums, target, false);
        if (first == nums.length || nums[first] != target) {
            return new int[]{-1, -1};
        }
        // one before the first element > target
        int last = firstIndexAtLeast(nums, target, true) - 1;
        return new int[]{first, last};
    }

    /**
     * strict = false: first index with nums[i] >= target; strict = true: first index with
     * nums[i] > target.
     */
    private static int firstIndexAtLeast(int[] nums, int target, boolean strict) {
        int lo = 0;
        int hi = nums.length;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            boolean goRight = strict ? nums[mid] <= target : nums[mid] < target;
            if (goRight) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }
        return lo;
    }
}

TIME O(log n)

SPACE O(1)

One helper with a strict flag removes the classic copy-paste bug between the two searches.

The insert position is the lower bound: the index where the target is (if present) or where it would keep the array sorted. Note the upper limit hi = n: inserting after the last element is legal.

Integer square root: binary search on a numeric range

No array exists, but the predicate m * m <= x is true … true false … false over m. We want the last true. Remember the cast to long before multiplying.

MySqrt.java — LeetCode 69

Java 17+

/** LeetCode 69 - Sqrt(x). Binary search on the answer: the largest m with m*m <= x. */
public class MySqrt {

    public static int mySqrt(int x) {
        if (x < 2) return x;
        int lo = 1;
        int hi = x / 2;                     // for x >= 2, sqrt(x) <= x / 2
        int answer = 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if ((long) mid * mid <= x) {    // long: mid * mid can exceed Integer.MAX_VALUE
                answer = mid;               // feasible: remember it and try larger
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return answer;
    }
}

TIME O(log x)

SPACE O(1)

The same "is this candidate feasible?" idea powers Chapter 13.

First Bad Version: minimising an expensive oracle

The array is hidden behind an API that costs money per call, so the number of probes is the

metric. Binary search needs ⌈log₂ n⌉ calls; a linear scan needs up to n.

/** Provided by the judge. */
interface VersionControl {
    boolean isBadVersion(int version);
}

/**
 * LeetCode 278 - First Bad Version. Find the first true in a false...false true...true
 * sequence.
 */
public class FirstBadVersion {

    public static int firstBadVersion(int n, VersionControl api) {

        int lo = 1;
        int hi = n;

            int mid = lo + (hi - lo) / 2;
            if (api.isBadVersion(mid)) {

Closest element and counting
Closest to a target: compute lowerBound(t); the answer is nums[idx] or nums[idx - 1], whichever is nearer (guard both ends).
Count occurrences: upperBound(t) - lowerBound(t).
Floor / ceiling: ceiling = nums[lowerBound(t)], floor = nums[upperBound(t) - 1].

J. Interview Tips

INTERVIEW

State the invariant out loud: "the answer, if it exists, is always inside [lo, hi]" (or [lo, hi)). It proves termination and correctness in one sentence.

Pick one template and stay with it. Interviewers care that you do not mix closed and half-open conventions.

Dry-run on two tiny inputs (size 1 and size 2) before running a bigger one: that is where off-by-one bugs live.

Follow-ups: count occurrences, closest element, search in a rotated array (Chapter 14),

unknown length (Chapter 16), a monotone function instead of an array (Chapter 13).

If asked about complexity: O(log n) time and O(1) space iteratively; recursion would use O(log n) stack.

CHAPTER SUMMARY

Binary search finds the boundary of a monotone predicate; exact search is the special case where the boundary is also a match.

Closed range [lo, hi] + lo <= hi + mid ± 1 for exact match; half-open [lo, hi) + lo < hi + hi = mid for boundaries.

Duplicates: lower bound (>= t) and upper bound (> t); occurrences are [lower, upper).

Always compute mid = lo + (hi - lo) / 2; always test sizes 0, 1 and 2.
