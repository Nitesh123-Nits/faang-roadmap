Fast and Slow Pointers

Two runners at different speeds: middle, cycles, and n-th from the end.

A. Pattern Overview

A singly linked list has no random access: to reach the middle you must walk there. The fast and slow pointer pattern (also called the tortoise and hare, after Floyd) moves two references through the structure at different speeds, or with a fixed gap, so that their relative position answers a question about the whole list in one pass and O(1) extra space.

Every list in this part uses the node below. It is shown once; later chapters refer to it as ListNode and never redefine it.

ListNode.java: shared by every list chapter
/** Singly linked list node shared by every list chapter. */
public class ListNode {
    public int val;
    public ListNode next;

    public ListNode(int val) {
        this.val = val;
    }

    public ListNode(int val, ListNode next) {
        this.val = val;
        this.next = next;
    }

    /** Builds 1 -> 2 -> 3 from of(1, 2, 3); returns null when no values are given. */
    public static ListNode of(int... vals) {
        ListNode dummy = new ListNode(0), tail = dummy;
        for (int v : vals) {
            tail.next = new ListNode(v);
            tail = tail.next;
        }
        return dummy.next;
    }

    /** Copies the values into an array (the list must be acyclic). */
    public static int[] toArray(ListNode head) {
        int n = 0;
        for (ListNode c = head; c != null; c = c.next) n++;

KEY IDEA

The invariant. After t steps, fast has travelled exactly twice as far as slow. When fast falls off the end, slow is halfway. If the structure loops, fast gains one node per step on slow inside the loop, so it must catch it. Both facts follow from the speed ratio alone.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Find the middle" of a list whose length is unknown, or "split the list in half": slow lands

there when fast finishes.

"Detect a cycle", "where does the cycle begin", "is the sequence eventually periodic": Floyd's algorithm, O(1) space instead of a HashSet.
"n-th node from the end", "remove the k-th last": a gap of n nodes between two pointers,

one pass.

"Do two lists meet", "first common node": switching heads so both pointers travel lenA + lenB.
A function f applied repeatedly to a value (digit squares, nums[i], next index) and a

question about repetition: the sequence is a linked list in disguise.

The constraint says O(1) extra space and the obvious answer uses a set, a counter pass, or an array copy.
FIRST QUESTION TO ASK

Whenever a list problem says "without knowing the length" or "in one pass", ask first: can the answer be read off the distance between two pointers?

C. Core Intuition with Illustrations

Slow lands on the middle

Move slow one node and fast two nodes per step. When fast can no longer move two nodes, slow has covered half the distance.

Figure 37. For length 6 the loop ends with slow on the second middle (value 4). Start fast one node ahead, or stop when fast.next.next is null, to get the first middle.

Loop A is while (fast != null && fast.next != null); loop B is while (fast.next != null && fast.next.next != null).

Use the first-middle form when you will cut the list at slow (so the left half is not shorter than the right); use the second-middle form when the question asks for the middle node itself (LeetCode 876).

Floyd's cycle detection: why the pointers must meet

Suppose the list has a tail of a nodes before the cycle, and the cycle has c nodes. Once slow enters the cycle, fast is already somewhere inside it. Each step fast moves one node closer to slow (it gains 2 − 1 = 1 node of distance), so the gap shrinks by one per step and reaches zero within c steps. They cannot jump over each other, because the gap changes by exactly one.

Figure 38. Floyd's meeting on a tail-3, cycle-6 list: the pointers meet at G, three nodes past the entrance D.

Finding the entrance. Let b be the distance from the entrance to the meeting point. When

they meet, slow has walked a + b, and fast has walked a + b + k·c for some k ≥ 1 (it

completed k extra laps). Since fast is twice as fast, 2(a + b) = a + b + k·c, so

INTUITION

a = k·c − b = (k − 1)·c + (c − b). Walking a nodes from the head and walking a nodes from the meeting point therefore lands both pointers on the entrance: the second walk goes c − b nodes to reach the entrance, then (k − 1) full laps. Phase 2 of the algorithm is exactly this: one pointer back to the head, both move one node at a time until they meet.

In the figure a = 3, b = 3, c = 6, k = 1, so a = c − b = 3: the head pointer and the meeting-point pointer both reach D after three steps.

A fixed gap finds the n-th node from the end

Advance lead by n nodes, then move both pointers until lead is on the last node. lag is then exactly n nodes behind the end, so lag.next is the target. Starting both at a dummy head handles the case where the head itself is removed.

Figure 39. The gap between the pointers never changes, so lag stops exactly before the target.

An array is a linked list: Find the Duplicate Number

For nums = [1, 3, 4, 2, 2] treat index i as a node whose next is nums[i]. Because every value is in 1..n, node 0 is never the target of an edge, and some node has two incoming edges: that node is the duplicated value, and it is the entrance of a cycle.

Figure 40. Two edges (3 → 2 and 4 → 2) point at node 2, so 2 is both the cycle entrance and the duplicated value.

E. Java Implementation

Middle of the list

MiddleOfList.java: LeetCode 876

Java 17+

/** LeetCode 876 - Middle of the Linked List. Fast moves two steps while slow moves one. */
public class MiddleOfList {

    /** Second middle for even lengths: 1,2,3,4 -> node 3 (this is LeetCode 876). */
    public static ListNode middleNode(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        return slow;
    }

    /** First middle for even lengths: 1,2,3,4 -> node 2. Use it to split a list in half. */
    public static ListNode firstMiddle(ListNode head) {
        if (head == null) return null;
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        return slow;
    }
}

TIME O(n)

SPACE O(1)

Check fast != null before fast.next, or an even-length list throws a NullPointerException.

Cycle detection and cycle start

LinkedListCycle.java: LeetCode 141, 142

Java 17+

/** LeetCode 141 / 142 - Linked List Cycle I and II (Floyd's tortoise and hare). */
public class LinkedListCycle {

    public static boolean hasCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) return true;               // the hare lapped the tortoise
        }
        return false;                                    // the hare fell off the end
    }

    /** Returns the node where the cycle begins, or null when there is no cycle. */
    public static ListNode detectCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                // phase 2: both walk one step at a time
                ListNode p = head;
                while (p != slow) {
                    p = p.next;
                    slow = slow.next;
                }
                return p;                                // they meet at the cycle entrance
            }
        }
        return null;
    }

    /** Number of nodes on the cycle, or 0 when there is none. */
    public static int cycleLength(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                int len = 1;
                for (ListNode p = slow.next; p != slow; p = p.next) len++;
                return len;
            }
        }
        return 0;
    }
}

TIME O(n)

SPACE O(1)

Phase 2 relies on a = (k − 1)c + (c − b): the walk from the head and the walk from the meeting point must have the same step size.

Remove the n-th node from the end

RemoveNthFromEnd.java: LeetCode 19

Java 17+

/**
 * LeetCode 19 - Remove Nth Node From End of List. Keep a gap of n nodes between two pointers.
 */
public class RemoveNthFromEnd {

    public static ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        ListNode lead = dummy, lag = dummy;
        for (int i = 0; i < n; i++) {
            lead = lead.next;                            // open a gap of n nodes
        }
        while (lead.next != null) {
            lead = lead.next;
            lag = lag.next;                              // lag stops just before the target
        }
        lag.next = lag.next.next;
        // dummy also handles removing the head
        return dummy.next;
    }
}
TIME O(L)
SPACE O(1)

The dummy node makes lag valid when the head is the target. n is guaranteed 1 ≤ n ≤ L.

Intersection of two lists

IntersectionOfLists.java: LeetCode 160

Java 17+

/** LeetCode 160 - Intersection of Two Linked Lists. Switching heads equalises the lengths. */
public class IntersectionOfLists {

    public static ListNode getIntersectionNode(ListNode a, ListNode b) {
        if (a == null || b == null) return null;
        ListNode p = a, q = b;
        // each pointer walks lenA + lenB in total
        while (p != q) {
            p = (p == null) ? b : p.next;
            q = (q == null) ? a : q.next;
        }
        // shared node, or null if they never meet
        return p;
    }
}

TIME O(m + n)

SPACE O(1)

If the lists never meet, both pointers reach null together after m + n steps, so the loop ends with null.

G. Variations of the Pattern

Cycle length

After the pointers meet, walk one pointer around the loop until it returns: the count is c. (cycleLength in the listing above.)

Happy Number: the digit-square map is a linked list

Replace each number by the sum of the squares of its digits. Either the sequence reaches 1 (and stays there) or it enters a cycle. Floyd detects the repetition without a HashSet. The values stay small (a 10-digit input maps to at most 9²·10 = 810), so the sequence must repeat quickly.

HappyNumber.java: LeetCode 202

Java 17+

/**
 * LeetCode 202 - Happy Number. The digit-square map is a "linked list" that either hits 1 or
 * cycles.
 */
public class HappyNumber {

    private static int next(int n) {
        int sum = 0;
        while (n > 0) {
            int d = n % 10;
            sum += d * d;
            n /= 10;
        }
        return sum;
    }

    public static boolean isHappy(int n) {
        int slow = n, fast = next(n);
        while (fast != 1 && slow != fast) {
            slow = next(slow);                           // one step
            fast = next(next(fast));                     // two steps
        }
        return fast == 1;
    }
}

TIME O(log n)

SPACE O(1)

Test fast != 1 before slow != fast: 1 is a fixed point, so the pointers would also "meet" at 1.

Find the Duplicate Number: i → nums[i]

n + 1 values in 1..n, one value repeated, no modification, O(1) space: binary search on the value (Chapter 13) works in O(n log n); Floyd works in O(n). Start from index 0, not from a value, because no value equals 0.

FindDuplicate.java: LeetCode 287

Java 17+

/**
 * LeetCode 287 - Find the Duplicate Number. Treat i -> nums[i] as a linked list and find its
 * cycle.
 */
public class FindDuplicate {

    /** nums has n + 1 values in 1..n, so some value has two incoming edges. */
    public static int findDuplicate(int[] nums) {
        int slow = 0, fast = 0;
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);
        slow = 0;                                        // phase 2: find the cycle entrance
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        // entrance index = the duplicated value
        return slow;
    }
}

TIME O(n)

SPACE O(1)

The second phase returns the entrance index, which equals the repeated value: that node has two predecessors.

Palindrome Linked List in O(1) space

Find the first middle, reverse the second half, compare the halves from both ends, then reverse the half back so the caller's list is unchanged (interviewers ask).

PalindromeLinkedList.java: LeetCode 234

Java 17+

/**
 * LeetCode 234 - Palindrome Linked List in O(1) space: find middle, reverse half, compare,
 * restore.
 */
public class PalindromeLinkedList {

    public static boolean isPalindrome(ListNode head) {
        if (head == null || head.next == null) return true;
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode half = reverse(slow.next);              // reverse the second half
        boolean ok = true;
        for (ListNode a = head, b = half; b != null; a = a.next, b = b.next) {
            if (a.val != b.val) {
                ok = false;
                break;
            }
        }
        slow.next = reverse(half);                       // restore the caller's list
        return ok;
    }

    private static ListNode reverse(ListNode head) {
        ListNode prev = null;
        while (head != null) {
            ListNode nxt = head.next;
            head.next = prev;
            prev = head;
            head = nxt;
        }
        return prev;
    }
}

TIME O(n)

SPACE O(1)

Compare while the reversed half has nodes: the middle node of an odd-length list needs no partner.

J. Interview Tips

INTERVIEW

Say the invariant out loud: "fast is always twice as far as slow, so when fast ends, slow is in the middle". Interviewers listen for the reason, not only the code.

Be ready to prove phase 2. Write a, b, c on the board and derive a = (k − 1)c + (c − b). It takes 30 seconds and separates memorising from understanding.

Offer the hash-set solution first if you are unsure, state its O(n) space, then improve it: it shows the trade-off.

Follow-ups: cycle length, the node before the entrance (to break the cycle), intersection

when one list has a cycle, the middle of a doubly linked list, whether a different speed ratio (for example 1 and 3) still meets inside the cycle.

Edge cases: null, one node, two nodes, n equal to the length, cycle on the head (self-loop), cycle of length 1, intersection at the head, no intersection.

CHAPTER SUMMARY

Fast and slow pointers read global facts (middle, cycle, n-th from the end, intersection) from the relative position of two references: one pass, O(1) space.

Floyd: pointers meet inside a cycle; then one pointer restarts at the head and both advance one step at a time: they meet at the entrance because a = (k − 1)c + (c − b).

Middle: test fast != null before fast.next; choose the first-middle or second-middle loop according to whether you will split or return the node.

Gap pointers with a dummy head remove the n-th node from the end safely, even when it is the head.

Any x → f(x) sequence is an implicit list: Happy Number and Find the Duplicate Number reuse Floyd. Compare nodes by reference, never by value.
