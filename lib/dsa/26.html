Counting and Mathematical Hashing

Turn structure into integers: counting sort, canonical forms, reduced fractions, and bit-packed windows

KEY IDEA

The art is choosing a canonical form: a representation where two items are equivalent iff their keys are equal. Reduce fractions, normalise signs, sort or count letters, subtract the shared part of an equation. If you can compute the key in O(1) or O(L), the rest is a HashMap<key, count>.

B. When to Recognize This Pattern

Pattern Recognition Signals

Pairs (i, j) satisfying an equation where you can move all i terms to one side and all j terms to the other: hash the key of one side (a + rev(b) = b + rev(a) → a − rev(a) = b − rev(b)).normalise the sign; use squared distances instead of square roots.
"Points on the same line / same distance": reduce the slope to lowest terms with gcd and
Values bounded by a small constant (digits, 0..1000, ASCII): a counting array replaces both sorting and hash maps.
Fixed-length windows over a small alphabet (DNA, binary strings, lowercase letters):

pack into an integer so equal windows have equal ints.

"Line / cut that crosses the fewest items": maximise coincident boundaries with a gap map.
A comparison that uses floating point (slopes, ratios): replace it with an exact integer

key.

NO FLOATING POINT KEYS

Never hash a double slope. 1/3 and 2/6 may not compare equal in floating point, and 1e-9 differences create false classes. Always use a reduced integer pair or a cross-product test.

C. Core Intuition with Illustrations

Counting sort. For values in 0..9, count each value, take prefix sums to learn the end position of each value in the output, then place elements right to left so equal keys keep their relative order (stability).

Figure 36. Comparison sorts need Ω(n log n); counting sort beats it whenever the key range is O(n).

Normalising a slope. Points (1,1), (2,2), (3,3) seen from the pivot (1,1) have offsets (1,1) and (2,2). Dividing each by gcd gives (1,1) for both: same key, same line. Offsets (−1,−1) and (1,1) are the same line but opposite directions, so flip the sign when dx < 0 (or dx = 0 and dy < 0).

Pivot (1, 1): slope key 1/1 collects 2 other points, so a line through the pivot holds 2 + 1 = 3 points.

INTUITION

Why fix a pivot? Two points define a line; the pivot plus a slope pins the same line through every other point, because all lines through the pivot with equal slope are identical. That reduces O(n³) triple tests to O(n²) hash updates.

D. Brute Force to Optimal Solution

Example: Max Points on a Line (LeetCode 149)

Brute force: for every pair of points, count how many others are collinear via a cross product: O(n³).
Pivot + slope map with double: O(n²) but unsafe: dy / dx loses precision.
Pivot + reduced fraction: dx /= g, dy /= g, normalise the sign, key = "dx/dy": O(n² log C) (the gcd cost) and exact.
Early exit: once the best found ≥ n − i (not enough points left), stop.

The same method as Count Nice Pairs: rewrite nums[i] + rev(nums[j]) = nums[j] + rev(nums[i]) as nums[i] − rev(nums[i]) = nums[j] − rev(nums[j]) and count equal keys: a two-sum-like pass in O(n).

E. Java Implementation

Counting sort and Relative Sort Array

CountingSortAndRelative.java — counting sort, LeetCode 1122

Java 17+

import java.util.Arrays;

/** Counting-based sorting: a plain counting sort and LeetCode 1122 - Relative Sort Array. */
public class CountingSortAndRelative {

    /**
     * Counting sort for non-negative values up to maxValue: O(n + maxValue). Stable variant
     * via prefix sums.
     */
    public static int[] countingSort(int[] nums, int maxValue) {
        int[] counts = new int[maxValue + 1];
        for (int x : nums) counts[x]++;
        // counts[v] = number of elements <= v
        for (int v = 1; v <= maxValue; v++) counts[v] += counts[v - 1];
        int[] out = new int[nums.length];
        // right to left keeps equal keys stable
        for (int i = nums.length - 1; i >= 0; i--) {
            out[--counts[nums[i]]] = nums[i];
        }
        return out;
    }

    /**
     * LeetCode 1122: order arr1 by the order of arr2; leftover values are appended in
     * ascending order.
     */
    public static int[] relativeSortArray(int[] arr1, int[] arr2) {
        // values are in [0, 1000]
        int[] counts = new int[1001];
        for (int x : arr1) counts[x]++;
        int[] out = new int[arr1.length];
        int idx = 0;
        for (int x : arr2) {
            while (counts[x]-- > 0) out[idx++] = x;
        }
        for (int v = 0; v <= 1000; v++) {
            while (counts[v] > 0) {
                out[idx++] = v;
                counts[v]--;
            }
        }
        return out;
    }
}

TIME O(n + R)

SPACE O(R)

R is the key range. The right-to-left placement loop keeps the sort stable.

Good Pairs and Nice Pairs: counting with an algebraic key

GoodPairs.java — LeetCode 1512 and 1814

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 1512 - Number of Good Pairs, and LeetCode 1814 - Count Nice Pairs in an Array
 * (transform the key).
 */
public class GoodPairs {

    /**
     * Pairs (i < j) with nums[i] == nums[j]. Each new element pairs with every earlier equal
     * element.
     */
    public static int numIdenticalPairs(int[] nums) {
        Map<Integer, Integer> seen = new HashMap<>();
        int pairs = 0;
        for (int x : nums) {
            int before = seen.getOrDefault(x, 0);
            pairs += before;
            seen.put(x, before + 1);
        }
        return pairs;
    }

    /**
     * Pairs (i < j) with nums[i] + rev(nums[j]) == nums[j] + rev(nums[i]), i.e. nums[i] -
     * rev(nums[i]) is equal.
     */
    public static int countNicePairs(int[] nums) {
        final int MOD = 1_000_000_007;
        Map<Integer, Integer> seen = new HashMap<>();
        long pairs = 0;
        for (int x : nums) {
            // rearranged equation: a canonical key per element
            int key = x - reverse(x);
            int before = seen.getOrDefault(key, 0);
            pairs += before;
            seen.put(key, before + 1);
        }
        return (int) (pairs % MOD);
    }
    private static int reverse(int x) {
        int r = 0;
        while (x > 0) {
r=r*10+x%10;
            x /= 10;
        }
        return r;
    }
}

SPACE O(n)

Max Points on a Line: reduced slopes

MaxPointsOnLine.java — LeetCode 149

Java 17+

import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 149 - Max Points on a Line. Hash the slope as a reduced fraction (dy/g, dx/g): no
 * floating point.
 */
public class MaxPointsOnLine {

    public static int maxPoints(int[][] points) {
        int n = points.length;
        if (n <= 2) return n;
        int best = 2;
        for (int i = 0; i < n; i++) {
            // slopes of lines through points[i]
            Map<String, Integer> slopes = new HashMap<>();
            int localBest = 0;
            for (int j = i + 1; j < n; j++) {
                int dx = points[j][0] - points[i][0];
                int dy = points[j][1] - points[i][1];
                int g = gcd(Math.abs(dx), Math.abs(dy));
                dx /= g;
                dy /= g;
                // normalise the sign: (1,2) and (-1,-2) are the same line
                if (dx < 0 || (dx == 0 && dy < 0)) {
                    dx = -dx;
                    dy = -dy;
                }
                int count = slopes.merge(dx + "/" + dy, 1, Integer::sum);
                localBest = Math.max(localBest, count);
            }
            best = Math.max(best, localBest + 1);            // +1 for points[i] itself
        }
        return best;
    }

    private static int gcd(int a, int b) {
        return b == 0 ? a : gcd(b, a % b);                   // points are distinct, so g > 0
    }
}

TIME O(n² log C)

SPACE O(n)

n ≤ 2 is returned directly. Points are distinct, so gcd(dx, dy) >

0. The + 1 accounts for the pivot itself.

Number of Boomerangs: squared distances

NumberOfBoomerangs.java — LeetCode 447
import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 447 - Number of Boomerangs: for each pivot, group other points by squared
 * distance.
 */
public class NumberOfBoomerangs {

    public static int numberOfBoomerangs(int[][] points) {
        int total = 0;
        for (int i = 0; i < points.length; i++) {
            Map<Integer, Integer> byDistance = new HashMap<>();
            for (int j = 0; j < points.length; j++) {
                if (i == j) continue;
                int dx = points[i][0] - points[j][0];
                int dy = points[i][1] - points[j][1];
                // squared distance: no sqrt needed
                byDistance.merge(dx * dx + dy * dy, 1, Integer::sum);
            }
            // ordered pairs among c equidistant points
            for (int c : byDistance.values()) total += c * (c - 1);
        }
        return total;
    }
}

Java 17+

TIME O(n²)

SPACE O(n)

A group of c equidistant points yields c · (c − 1) ordered boomerangs. No sqrt: compare squared distances exactly.

G. Variations of the Pattern

Repeated DNA Sequences: bit-packed rolling window

With four letters, each needs 2 bits; a window of 10 letters is a 20-bit integer. Slide by shifting left two bits, OR-ing in the new code, and masking to 20 bits. Using an int key instead of a String avoids allocating a substring per window.

RepeatedDnaSequences.java — LeetCode 187

Java 17+

import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

/**
 * LeetCode 187 - Repeated DNA Sequences: 2 bits per nucleotide, so a 10-letter window is a
 * 20-bit int key.
 */
public class RepeatedDnaSequences {

    public static List<String> findRepeatedDnaSequences(String s) {
        final int LEN = 10;
        final int MASK = (1 << (2 * LEN)) - 1;               // keep the lowest 20 bits
        List<String> result = new ArrayList<>();
        if (s.length() < LEN) return result;

        Set<Integer> seen = new HashSet<>();
        Set<Integer> added = new HashSet<>();
        int window = 0;
        for (int i = 0; i < s.length(); i++) {
            window = ((window << 2) | code(s.charAt(i))) & MASK;   // rolling update in O(1)
            if (i >= LEN - 1) {
                // second time seen, report once
                if (!seen.add(window) && added.add(window)) {
                    result.add(s.substring(i - LEN + 1, i + 1));
                }
            }
        }
        return result;
    }

    private static int code(char c) {
        switch (c) {
            case 'A': return 0;
            case 'C': return 1;
            case 'G': return 2;
            default:  return 3;                               // 'T'
        }
    }
}

TIME O(n)

SPACE O(n)

Two sets: seen and added, so each repeated sequence is reported once.

Brick Wall: hash cumulative gap positions

A vertical line crosses rows − (rows with a gap at that position) bricks, so maximise gap coincidences. Skip each row's last brick; use long positions when widths are large.

BrickWall.java — LeetCode 554
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * LeetCode 554 - Brick Wall: the best vertical line crosses the fewest bricks = passes
 * through the most gaps.
 */
public class BrickWall {

    public static int leastBricks(List<List<Integer>> wall) {
        // edge position -> number of rows with a gap there
        Map<Long, Integer> gapsAt = new HashMap<>();
        int mostGaps = 0;
        for (List<Integer> row : wall) {
            long position = 0;
            // skip the last brick: the wall's right edge is not allowed
            for (int i = 0; i < row.size() - 1; i++) {
                position += row.get(i);
                mostGaps = Math.max(mostGaps, gapsAt.merge(position, 1, Integer::sum));
            }
        }
        return wall.size() - mostGaps;
    }
}

Java 17+

TIME O(total bricks)

SPACE O(distinct positions)

Polynomial rolling hash (the idea behind Rabin-Karp)

Compare long substrings in O(1): h(s[i..j]) = Σ s[k] · B^(j−k) mod M, updated by h = (h

B − out · B^L + in) mod M. Always verify a hash hit with a direct comparison, or use two moduli, because collisions exist. Developed in Part XII.
Two-way and sign-normalised keys
Isomorphic / Word Pattern: key = index of first occurrence of each symbol.
Group Shifted Strings: key = sequence of differences modulo 26.
Pairs with sum divisible by k: key = remainder, matched with (k − r) mod k (see Chapter 3).

J. Interview Tips

INTERVIEW

Say the key out loud: "I'll hash the reduced slope", "the key is a − rev(a)". Naming the canonical form is the pattern.

Mention exactness: "I avoid floating point by reducing with gcd and normalising the sign". Interviewers watch for this.

Offer the cross-product brute force first (O(n³)), then the pivot optimisation.

Follow-ups: duplicate points, vertical lines, return the points on the best line, 3D points,

longer DNA windows (rolling hash with collision check), stable counting sort for records with satellite data.

Edge cases: n ≤ 2, all points identical (if allowed), vertical and horizontal lines, negative coordinates, empty input.

CHAPTER SUMMARY

Hashing structure = finding a canonical key: equal keys iff equivalent items. Then count or group on it.

Counting sort when the key range is O(n): counts, prefix sums, right-to-left placement for stability.

Exact keys, never floating point: reduced (dy/g, dx/g) with a normalised sign, squared distances, rearranged equations.

Bit-pack short windows over small alphabets into an int and update in O(1); mask after each shift; verify collisions for long rolling hashes.
