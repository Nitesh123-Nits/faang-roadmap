Designing Data Structures

Augment a stack, array or map so that one extra operation is also O(1).

A. Pattern Overview

Design problems ask for a class with a specified API and a complexity target (usually O(1) or O(log n) per operation). They are rarely about a clever algorithm; they are about choosing the right pair of structures and keeping them consistent. Nearly every answer is one of five moves:

KEY IDEA

Read the API as a contract. For every method write the target complexity next to it. Then ask: which operation is the bottleneck for the naive structure? The fix is the extra structure that makes exactly that operation O(1), at the price of maintaining it on every other operation.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Design a class that supports push, pop, and getMin in O(1)": add a method that a plain structure lacks.
"insert, remove, getRandom in O(1)": random access needs an array; membership needs a

hash map; deletion needs a swap-with-last trick.

"Return the value at or before time t": per-key history with binary search (timestamps arrive in order).
"Pop the most frequent element, ties broken by recency": a stack per frequency level.
"Apply an operation to the bottom k elements": tag the boundary lazily instead of looping.
"Back / forward", "undo / redo": a list with a cursor.

C. Core Intuition with Illustrations

Min Stack: every entry knows the minimum beneath it

A single min variable breaks when the minimum is popped. Store, with each element, the minimum of the stack up to and including it. Popping an element automatically restores the previous minimum.

Figure 55. The second row is the answer to getMin() for each possible stack height.

Insert / Delete / GetRandom in O(1): swap with the last

An array gives O(1) random access, but deleting the middle shifts elements. Swap the element to delete with the last one, then remove the last: order is irrelevant for a set, so this is O(1). A hash map from value to index lets you find the element and fix the moved element's index.

Figure 56. Order is sacrificed, which a set does not need; getRandom stays uniform.

Frequency Stack: a stack per frequency

The element to pop is the one with the highest frequency, and among those the most recent.

Keep freq[x] and a map level → stack. Pushing x for the f-th time puts it on the stack for

level f; the element stays on the stack for level f − 1 too, which is exactly what makes the next pop correct: after popping x from level f, its earlier push at level f − 1 is still there.

Figure 57. Each element appears on one stack per occurrence; the highest non-empty level holds the answer.

Lazy increments

increment(k, val) adds val to the bottom k elements. Instead of looping, put val on lazy[k

− 1]. When an element is popped, add its lazy value to the result and pass the tag down to the element below. Every operation is O(1).

E. Java Implementation

Min Stack

MinStack.java: LeetCode 155
import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 155 - Min Stack: every entry remembers the minimum of the stack up to and
 * including it.
 */
public class MinStack {

    private final Deque<int[]> stack = new ArrayDeque<>();   // {value, minimum so far}

    public void push(int val) {
        int min = stack.isEmpty() ? val : Math.min(val, stack.peek()[1]);
        stack.push(new int[]{val, min});
    }

    public void pop() {
        stack.pop();
    }

    public int top() {
        return stack.peek()[0];
    }

Java 17+

    public int getMin() {
        return stack.peek()[1];                          // O(1): no scan needed
    }
}

TIME O(1) per operation

SPACE O(n)

Alternative: a second stack of minima, pushed only when the value is <= the current minimum. The pair version is simpler and has the same asymptotics.

Maximum Frequency Stack

FreqStack.java: LeetCode 895

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashMap;
import java.util.Map;

/**
 * LeetCode 895 - Maximum Frequency Stack: one stack per frequency level; pop from the
 * highest.
 */
public class FreqStack {

    private final Map<Integer, Integer> freq = new HashMap<>();
    private final Map<Integer, Deque<Integer>> levels = new HashMap<>();
    private int maxFreq;

    public void push(int x) {
        int f = freq.merge(x, 1, Integer::sum);
        maxFreq = Math.max(maxFreq, f);
        levels.computeIfAbsent(f, k -> new ArrayDeque<>()).push(x);   // x joins level f
    }

    public int pop() {
        Deque<Integer> top = levels.get(maxFreq);
        int x = top.pop();                               // most recent among the most frequent
        if (top.isEmpty()) maxFreq--;                    // that level is now empty
        freq.merge(x, -1, Integer::sum);
        return x;
    }
}

TIME O(1) per operation

SPACE O(n)

maxFreq only ever decreases by one on a pop, because the level below is non-empty whenever a higher one was.

Insert Delete GetRandom O(1)

RandomizedSet.java: LeetCode 380
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Random;

/**

Java 17+

 * LeetCode 380 - Insert Delete GetRandom O(1): array for random access, map for value ->
 * index.
 */
public class RandomizedSet {

    private final List<Integer> items = new ArrayList<>();
    private final Map<Integer, Integer> indexOf = new HashMap<>();
    private final Random random = new Random();

    public boolean insert(int val) {
        if (indexOf.containsKey(val)) return false;
        indexOf.put(val, items.size());
        items.add(val);
        return true;
    }

    public boolean remove(int val) {
        Integer idx = indexOf.remove(val);
        if (idx == null) return false;
        int last = items.remove(items.size() - 1);       // O(1): removing the tail
        if (last != val) {                               // move the tail into the hole
            items.set(idx, last);
            indexOf.put(last, idx);
        }
        return true;
    }

    public int getRandom() {
        return items.get(random.nextInt(items.size()));
    }
}

TIME O(1) expected

SPACE O(n)

When the removed value is the last element, do not re-insert it into the map: the last != val guard prevents a stale entry.

Time Based Key-Value Store

TimeMap.java: LeetCode 981

Java 17+

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * LeetCode 981 - Time Based Key-Value Store: per key, timestamps are increasing; binary
 * search them.
 */
public class TimeMap {

    private static class Entry {
        final int time;
        final String value;

        Entry(int time, String value) {
            this.time = time;
            this.value = value;
        }
    }
    private final Map<String, List<Entry>> history = new HashMap<>();

    /** Timestamps passed to set() for one key are strictly increasing. */
    public void set(String key, String value, int timestamp) {
        history.computeIfAbsent(key, k -> new ArrayList<>()).add(new Entry(timestamp, value));
    }

    /** Value with the largest timestamp <= the query, or "" if none. */
    public String get(String key, int timestamp) {
        List<Entry> list = history.get(key);
        if (list == null) return "";
        // find the first entry with time > timestamp
        int lo = 0, hi = list.size();
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (list.get(mid).time <= timestamp) lo = mid + 1;
            else hi = mid;
        }
        return lo == 0 ? "" : list.get(lo - 1).value;
    }
}

TIME set O(1), get O(log n)

SPACE O(n)

The binary search finds the first time greater than the query; the answer is the entry just before it, or "" if there is none.

Design Browser History

BrowserHistory.java: LeetCode 1472

Java 17+

import java.util.ArrayList;
import java.util.List;

/**
 * LeetCode 1472 - Design Browser History: an array plus a cursor; visiting truncates the
 * forward pages.
 */
public class BrowserHistory {

    private final List<String> pages = new ArrayList<>();
    private int cur;

    public BrowserHistory(String homepage) {
        pages.add(homepage);
    }

    public void visit(String url) {
        // drop the forward history
        while (pages.size() > cur + 1) pages.remove(pages.size() - 1);
        pages.add(url);
        cur++;
    }

    public String back(int steps) {
        cur = Math.max(0, cur - steps);
        return pages.get(cur);
    }

    public String forward(int steps) {
        cur = Math.min(pages.size() - 1, cur + steps);
        return pages.get(cur);
    }
}

TIME amortised O(1)

SPACE O(n)

visit discards the forward pages; back and forward clamp the cursor with max / min.

Stack with increment

CustomStack.java: LeetCode 1381

Java 17+

/**
 * LeetCode 1381 - Design a Stack With Increment Operation: lazy increments make inc() O(1).
 */
public class CustomStack {

    private final int[] stack;
    private final int[] lazy;                            // lazy[i] is owed by elements 0..i
    private int size;

    public CustomStack(int maxSize) {
        stack = new int[maxSize];
        lazy = new int[maxSize];
    }

    public void push(int x) {
        if (size < stack.length) stack[size++] = x;
    }

    public int pop() {
        if (size == 0) return -1;
        int i = --size;
        int value = stack[i] + lazy[i];                  // apply the pending increment now
        if (i > 0) lazy[i - 1] += lazy[i];               // pass it down to the element below
        lazy[i] = 0;
        return value;
    }

    public void increment(int k, int val) {
        int i = Math.min(k, size) - 1;
        if (i >= 0) lazy[i] += val;                      // tag the top of the affected prefix
    }
}

TIME O(1) per operation

SPACE O(maxSize)

Apply the tag to the popped value, then pass it to the element below: otherwise the increment is lost.

G. Variations of the Pattern

Max Stack and Min Queue

Max Stack (716, premium) also needs popMax: a TreeMap<value, list of positions> plus a doubly linked list makes popMax O(log n). A min-queue (queue with getMin) uses two min-stacks, exactly like the two-stack queue of Chapter 27, or a monotonic deque (Chapter 8).

Insert Delete GetRandom with duplicates

(381): map each value to a set of indices. Removing a value swaps one of its indices with the last element's, updating both index sets. It is the same trick, with sets in place of single indices.

All O(1) Data Structure and LFU-style structures

All O(1) Data Structure (432, Hard) keeps a doubly linked list of buckets ordered by count, each bucket holding a set of keys: inc, dec, getMaxKey, getMinKey in O(1). It is the structure inside the LFU cache of Chapter 29.

Snapshot Array

set(index, val) and snap() where get(index, snap_id) reads an old version: store, per index, a list of (snap_id, value) pairs and binary search by snapshot (the same pattern as TimeMap), with O(1) snapshots.

Design Twitter, Design Underground System, Design Phone Directory

These are API-composition problems: a HashMap for the entities, a small heap (Top K most recent tweets, Part IX) or a map of running sums (average travel time). The method is the same: list the API, decide the data per operation, and keep the invariants in one place.

Thread safety

For a production answer add synchronized or a ReentrantLock around the compound operations (check-then-act on the map and list in RandomizedSet must be atomic), or use ConcurrentHashMap.compute. Mention it, but implement the single-threaded version.

J. Interview Tips

INTERVIEW

Write the API with target complexities first, then pick the structures. Interviewers grade the reasoning behind the pair ("list for random access, map for position").

Say what each operation must keep consistent (e.g. "after a swap-remove the moved element's index must be updated") and test that exact case.

Offer the simple version before the optimum (scan for min) and name the bottleneck it fails on.

Follow-ups: add getMax to Min Stack; support duplicates in RandomizedSet; make

TimeMap.set accept out-of-order timestamps; implement the structure thread-safely; limit memory with an eviction policy (this leads to Chapter 29).

Edge cases: empty structure operations, removing the only / last element, duplicate values, equal timestamps, query before the first timestamp, k larger than the size, back(steps) past the first page.

CHAPTER SUMMARY

Design problems are about choosing a pair of structures and keeping them consistent under every operation; write the target complexity per method first.

Min Stack: store the minimum with each entry. Frequency Stack: one stack per frequency level, maxFreq drops by at most one on a pop.

RandomizedSet: list + value → index map; delete by swapping with the last element; guard the case where the removed value is the last.

TimeMap / Snapshot Array: keep a time-ordered history per key and binary search for the first entry after the query.

Lazy tags (Stack with Increment) and cursors (Browser History) turn range operations into O(1).
