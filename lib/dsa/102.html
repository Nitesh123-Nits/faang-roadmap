DP on Graphs

A DP needs an acyclic order: topological order, sorted values, or Dijkstra's settling order.

A. Pattern Overview

Dynamic programming works on any structure whose states can be ordered so that dependencies come first. In a graph that order is a topological order of a DAG. Three situations cover most interview problems: DP on an explicit DAG (longest path, number of paths, course scheduling), DP on an implicit DAG (a grid where values strictly increase, so edges always point to larger values), and DP on a shortest-path graph (count shortest paths, restricted paths) where Dijkstra's settling order supplies the order.

KEY IDEA

If there is a cycle, no DP order exists. Detect it (Kahn leaves nodes unprocessed) or collapse strongly connected components before running the DP.

B. When to Recognize This Pattern

Pattern Recognition Signals

Prerequisites, dependencies, build order: a DAG.
"Longest / shortest / number of paths" in a directed acyclic graph.
Moves allowed only to strictly larger (or smaller) values on a grid or graph.
"Number of shortest paths": count along the shortest-path DAG.
"Minimum semesters / time with prerequisites": longest chain.
ONE-LINE TEST

Directed, acyclic (or made acyclic by a value ordering): process nodes in topological order and relax.

C. Core Intuition with Illustrations

Longest path and path counts in a DAG

The DAG has edges 0->1, 0->2, 1->3, 2->3, 3->4, 2->5, 5->4. Process nodes in topological order; for every edge u -> v set longest[v] = max(longest[v], longest[u] + 1) and paths[v] += paths[u].

Parallel Courses (1136) and minimum semesters

Courses with prerequisites: each semester you can take every course whose prerequisites are done, so the minimum number of semesters is the number of layers in Kahn's algorithm (the longest chain). If Kahn processes fewer than n courses there is a cycle: return -1.

Longest Increasing Path in a Matrix (329)

Moves go to adjacent cells with strictly larger values, so the move graph is acyclic by construction. Sort cells by value (or memoise a DFS) and set dp[cell] = 1 + max(dp[smaller neighbour]). For [[9,9,4],[6,6,8],[2,1,1]]:

Number of Ways to Arrive at Destination (1976)

Run Dijkstra and keep ways[v]. When a strictly shorter distance to v is found, reset ways[v] = ways[u]; when an equal distance is found, add ways[v] += ways[u]. Dijkstra settles nodes in non-decreasing distance order, so ways[u] is final when u is settled. WATCH FOR ZERO WEIGHTS

Zero-weight edges break the 'final when settled' argument for equal-distance nodes. LeetCode 1976 guarantees positive times; with zero-weight edges process ties in topological order of the shortest-path DAG.

Restricted Paths (1786)

Compute dist[v] to the target n with Dijkstra, then count paths from 1 to n that move only to nodes with strictly smaller dist. That condition makes the walk acyclic; process nodes in increasing dist and add ways[u] along each edge to a smaller-distance neighbour, modulo 10^9 + 7.

Longest path in a general graph is NP-hard; the DAG restriction is what makes the DP possible.

import java.util.*;

/** Ch 88: DP on graphs and DAGs; LeetCode 329, 1136, 1786, 1976. */
public class GraphDP {
    private static final int MOD = 1_000_000_007;

Java 17+

    /** Kahn order of a DAG on 0..n-1; the result is shorter if there is a cycle. */
    private static int[] topoOrder(int n, int[][] edges, List<List<Integer>> g) {
        int[] indeg = new int[n];
        for (int i = 0; i < n; i++) g.add(new ArrayList<>());
        for (int[] e : edges) {
            g.get(e[0]).add(e[1]);
            indeg[e[1]]++;
        }
        int[] order = new int[n];
        int head = 0, tail = 0;
        for (int i = 0; i < n; i++) if (indeg[i] == 0) order[tail++] = i;
        while (head < tail) {
            int u = order[head++];
            for (int v : g.get(u)) if (--indeg[v] == 0) order[tail++] = v;
        }
        return Arrays.copyOf(order, tail);
    }

    /** Longest path (in edges) in a DAG: dp over a topological order. */
    public static int longestPathDag(int n, int[][] edges) {
        List<List<Integer>> g = new ArrayList<>();
        int[] order = topoOrder(n, edges, g);
        int[] dp = new int[n];
        int best = 0;
        for (int u : order)
            for (int v : g.get(u)) {
                dp[v] = Math.max(dp[v], dp[u] + 1);
                best = Math.max(best, dp[v]);
            }
        return best;
    }

    /** Number of distinct paths from s to t in a DAG (long, no modulus). */
    public static long countPathsDag(int n, int[][] edges, int s, int t) {
        List<List<Integer>> g = new ArrayList<>();
        int[] order = topoOrder(n, edges, g);
        long[] ways = new long[n];
        ways[s] = 1;
        for (int u : order)
            for (int v : g.get(u)) ways[v] += ways[u];
        return ways[t];
    }

    /** LeetCode 1136: fewest semesters to finish all courses, or -1 on a cycle. */
    public static int minimumSemesters(int n, int[][] relations) {
        int[][] edges = new int[relations.length][];
        for (int i = 0; i < edges.length; i++)
            edges[i] = new int[]{relations[i][0] - 1, relations[i][1] - 1};
        List<List<Integer>> g = new ArrayList<>();
        int[] order = topoOrder(n, edges, g);
        if (order.length < n) return -1;
        int[] level = new int[n];
        int best = 1;
        Arrays.fill(level, 1);
        for (int u : order)
            for (int v : g.get(u)) {
                level[v] = Math.max(level[v], level[u] + 1);
                best = Math.max(best, level[v]);
            }
        return best;
    }

    /**
     * LeetCode 329: longest strictly increasing path in a matrix. The 'is
     * smaller than' relation is a DAG; process cells in increasing value.
     */
    public static int longestIncreasingPath(int[][] a) {
        int m = a.length, n = a[0].length;
        Integer[] cells = new Integer[m * n];
        for (int i = 0; i < cells.length; i++) cells[i] = i;
        Arrays.sort(cells, Comparator.comparingInt(id -> a[id / n][id % n]));
        int[][] dp = new int[m][n];
        int best = 0;
        int[] dr = {1, -1, 0, 0}, dc = {0, 0, 1, -1};
        for (int id : cells) {
            int r = id / n, c = id % n;
            dp[r][c] = 1;
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr >= 0 && nr < m && nc >= 0 && nc < n && a[nr][nc] < a[r][c])
                    dp[r][c] = Math.max(dp[r][c], dp[nr][nc] + 1);
            }
            best = Math.max(best, dp[r][c]);
        }
        return best;
    }

    private static long[] dijkstra(int n, List<List<int[]>> g, int src) {
        long[] dist = new long[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        dist[src] = 0;
        PriorityQueue<long[]> pq =
                new PriorityQueue<>(Comparator.comparingLong(x -> x[0]));
        pq.offer(new long[]{0, src});
        while (!pq.isEmpty()) {
            long[] top = pq.poll();
            int u = (int) top[1];
            if (top[0] > dist[u]) continue;
            for (int[] e : g.get(u))
                if (dist[u] + e[1] < dist[e[0]]) {
                    dist[e[0]] = dist[u] + e[1];
                    pq.offer(new long[]{dist[e[0]], e[0]});
                }
        }
        return dist;
    }

    private static List<List<int[]>> weighted(int n, int[][] edges, int shift) {
        List<List<int[]>> g = new ArrayList<>();
        for (int i = 0; i < n; i++) g.add(new ArrayList<>());
        for (int[] e : edges) {
            g.get(e[0] - shift).add(new int[]{e[1] - shift, e[2]});
            g.get(e[1] - shift).add(new int[]{e[0] - shift, e[2]});
        }
        return g;
    }

    /**
     * LeetCode 1976: number of shortest paths from 0 to n-1 (roads are
     * {u, v, time}, 0-indexed), modulo 1e9 + 7. Dijkstra order is a topological
     * order of the shortest-path DAG.
     */
    public static int countPaths(int n, int[][] roads) {
        List<List<int[]>> g = weighted(n, roads, 0);
        long[] dist = new long[n];
        long[] ways = new long[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        dist[0] = 0;
        ways[0] = 1;
        PriorityQueue<long[]> pq =
                new PriorityQueue<>(Comparator.comparingLong(x -> x[0]));
        pq.offer(new long[]{0, 0});
        while (!pq.isEmpty()) {
            long[] top = pq.poll();
            int u = (int) top[1];
            if (top[0] > dist[u]) continue;
            for (int[] e : g.get(u)) {
                long nd = dist[u] + e[1];
                if (nd < dist[e[0]]) {
                    dist[e[0]] = nd;
                    ways[e[0]] = ways[u];
                    pq.offer(new long[]{nd, e[0]});
                } else if (nd == dist[e[0]]) {
                    ways[e[0]] = (ways[e[0]] + ways[u]) % MOD;
                }
            }
        }
        return (int) ways[n - 1];
    }

    /**
     * LeetCode 1786: restricted paths from 1 to n (nodes 1-indexed): every step
     * must strictly decrease the distance to n. Count them modulo 1e9 + 7.
     */
    public static int countRestrictedPaths(int n, int[][] edges) {
        List<List<int[]>> g = weighted(n, edges, 1);
        long[] dist = dijkstra(n, g, n - 1);
        Integer[] byDist = new Integer[n];
        for (int i = 0; i < n; i++) byDist[i] = i;
        Arrays.sort(byDist, Comparator.comparingLong(i -> dist[i]));
        long[] ways = new long[n];
        ways[n - 1] = 1;
        for (int u : byDist) {
            if (u == n - 1) continue;
            for (int[] e : g.get(u))
                if (dist[e[0]] < dist[u]) ways[u] = (ways[u] + ways[e[0]]) % MOD;
        }
        return (int) ways[0];
    }
}
TIME O(V + E)
SPACE O(V + E)

DAG methods are linear in vertices plus edges. countPaths and countRestrictedPaths add Dijkstra's O((V + E) log V). longestIncreasingPath is O(mn) with memoised DFS (every cell is solved once).

F. Detailed Dry Run

DAG: Kahn order 0, 1, 2, 3, 5, 4. Process 0: longest[1] = longest[2] = 1, paths[1] = paths[2] = 1. Process 1: longest[3] = 2, paths[3] = 1. Process 2: longest[3] = max(2, 2) =

2, paths[3] = 2; longest[5] = 2, paths[5] = 1. Process 3: longest[4] = 3, paths[4] = 2. Process 5: longest[4] = max(3, 3) = 3, paths[4] = 3.

Matrix, cells by increasing value: both 1s have no smaller neighbour (dp = 1); the 2 at (2,0) sees a 1 (dp = 2); the 4 at (0,2) has only larger neighbours (dp = 1). Then (1,0) = 6 sees the 2 (dp = 3), (1,1) = 6 sees a 1 (dp = 2), (1,2) = 8 sees (1,1) (dp = 3), (0,1) = 9 sees (1,1) (dp = 3) and (0,0) = 9 sees (1,0) (dp = 4). The answer is 4: 1 -> 2 -> 6 -> 9.

G. Variations of the Pattern

Critical path / project scheduling

Earliest finish times in a task DAG are longest paths with node weights: finish[v] = dur[v] + max(finish[u]) over predecessors u.

Minimum cost path in a DAG

Replace max by min and add edge weights. Handles negative weights, unlike Dijkstra.

Counting with modulo

Path counts overflow quickly: reduce modulo 10^9 + 7 after each addition.

Cheapest flights and bounded stops

Add the number of edges used as a dimension (dp[k][v]), which is exactly Bellman-Ford with a layer limit (Chapter 55).

DP on SCC condensation

For graphs with cycles, collapse SCCs, then run the DAG DP on the condensation, with node values equal to SCC totals (Chapter 58).

J. Interview Tips

INTERVIEW

Say why an order exists: "the graph is a DAG" or "values strictly increase". That sentence justifies the DP.

Give Kahn or memoised DFS and the cycle check in one breath.

For counting shortest paths, state the reset-on-shorter, add-on-equal rule explicitly.

Follow-ups: print the longest path; handle zero-weight edges; k-th shortest path; very

large graphs (streaming topological order).

Edge cases: isolated nodes, multiple sources, cycles, equal values in the matrix, n = 1.

CHAPTER SUMMARY

Graph DP needs an order: topological order of a DAG, sorted values, or Dijkstra's settling order.

DAG longest path / path count run in O(V + E) and handle negative weights.

Counting shortest paths: reset the count on a shorter distance, add on an equal one.

Implicit DAGs (strictly increasing values, strictly decreasing distance) make memoised DFS valid.

Cycles: detect with Kahn or condense SCCs before applying the DP.
