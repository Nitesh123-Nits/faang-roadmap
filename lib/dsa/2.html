How to Use This Book

Most coding-interview problems are not new. They are a small number of patterns wearing different costumes. A candidate who has memorised 300 solutions still freezes on problem 301; a candidate who can recognise "this is a monotonic quantity, so two pointers" or "this is a feasibility check over a sorted answer space, so binary search on the answer" solves problems they have never seen.

This handbook teaches that recognition skill. Every chapter follows the same ten-part structure, so you always know where to look.

SectionWhat it gives you
A Pattern OverviewWhat the pattern is, why it exists, and how it differs from look-alikes
B When to Recognize ItKeywords, constraints and Pattern Recognition Signals you can spot before you see a solution
C Core IntuitionDiagrams of pointer movement, stacks, windows and search spaces, plus the correctness argument
D Brute Force → OptimalComplexity of the naive version, the bottleneck, and the derivation of the optimised one
E Java ImplementationComplete, compiled solutions with comments, edge-case handling, time and space complexity
F Detailed Dry RunStep-by-step state tables generated by executing the algorithm
G VariationsFive to eight related problems solved with the same idea
H Common MistakesOff-by-one, overflow, duplicates, wrong invariants, and how to avoid them
I Pattern ComparisonWhen to prefer this pattern over its neighbours
J Interview TipsHow to explain it, follow-ups to expect, edge cases to announce

Each chapter ends with a leveled problem list (Easy, Medium, Hard) with a recommended solving order, and a short summary.

Conventions

Java 17+. Solutions are written for clarity first. Every class shown compiles on its own. All listings in Parts I–XIII were compiled with JDK 21 and checked against brute-force implementations on thousands of random inputs before being typeset.
