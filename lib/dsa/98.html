Longest Increasing Subsequence

O(n^2) dp for clarity, O(n log n) tails array for speed, and its families.

A. Pattern Overview

The Longest Increasing Subsequence (LIS) is the longest subsequence whose values strictly increase. Two solutions matter: the O(n^2) DP (dp[i] is the LIS ending at i) and the O(n log

patience-sorting method, where tails[k] is the smallest possible last value of an increasing subsequence of length k + 1. The pattern extends to counting the LISes, rebuilding one, nesting envelopes, and divisibility chains.

KEY IDEA

tails is always sorted. That is what allows binary search: a new value either extends the longest sequence (append) or replaces the first tail that is >= it (a smaller tail keeps more future options).

B. When to Recognize This Pattern

Pattern Recognition Signals

"Longest increasing / non-decreasing subsequence" in an array.
Nesting or chains: envelopes, boxes, dolls, divisibility chains, pairs where one must fit inside the next.
"Minimum number of removals to make it sorted": n - LIS.
"Minimum number of increasing groups" (patience piles): equals the longest non-increasing subsequence (Dilworth).
n up to 10^5 forces the O(n log n) form.
ONE-LINE TEST

Order must be preserved, values must grow: LIS. Two dimensions: sort one, LIS the other.

COMMON TRAP

tails is not a valid subsequence. After processing [..., 3] it can contain [2, 3] even though 3 came after 5. Only its length is meaningful; rebuild the actual sequence from predecessor links.

Counting LIS (673)

Keep len[i] and count[i]. For each j < i with a[j] < a[i]: if len[j] + 1 > len[i] take len[j] + 1 and copy count[j]; if equal, add count[j]. For [1,3,5,4,7]:

inums[i]len[i]count[i]

Total = sum of count[i] for the maximal length (4): 1,3,5,7 and 1,3,4,7, so 2.

Russian Doll Envelopes (354)

Envelope (w, h) fits in (w', h') iff both are strictly smaller. Sort by w ascending and, for equal w, by h descending, so two envelopes of the same width can never be chained; then

run strict LIS on h. For [[5,4],[6,4],[6,7],[2,3]] the sorted heights are 3, 4, 7, 4; strict LIS length is 3 ([2,3] -> [5,4] -> [6,7]).

Largest Divisible Subset (368)

Sort ascending. If a[j] | a[i] and dp[j] + 1 > dp[i], extend. Divisibility is transitive, so checking consecutive chain members is enough. Keep a prev array to rebuild the set.

import java.util.*;

/** Ch 84: longest increasing subsequence; LeetCode 300, 673, 354, 368. */
public class LIS {

    /** O(n^2): dp[i] = longest strictly increasing subsequence ending at i. */
    public static int lengthDP(int[] nums) {
        int n = nums.length, best = 0;
        int[] dp = new int[n];
        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            for (int j = 0; j < i; j++)
                if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
            best = Math.max(best, dp[i]);
        }
        return best;
    }

    /**
     * O(n log n), patience sorting: tails[k] = smallest tail of an increasing
     * subsequence of length k + 1. Strict: replace the first tail >= x.
     */
    public static int lengthPatience(int[] nums) {

Java 17+

        int size = 0;

    /** Longest NON-decreasing subsequence: replace the first tail > x. */
    public static int lengthNonDecreasing(int[] nums) {
        int[] tails = new int[nums.length];
        int size = 0;
        for (int x : nums) {
            int lo = 0, hi = size;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (tails[mid] > x) hi = mid; else lo = mid + 1;
            }
            tails[lo] = x;
            if (lo == size) size++;
        }
        return size;
    }

    /** One actual LIS in O(n log n): remember each element's predecessor. */
    public static int[] sequence(int[] nums) {
        int n = nums.length;
        if (n == 0) return new int[0];
        int[] tailIdx = new int[n], prev = new int[n];
        int size = 0;
        for (int i = 0; i < n; i++) {
            int lo = 0, hi = size;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (nums[tailIdx[mid]] >= nums[i]) hi = mid; else lo = mid + 1;
            }
            prev[i] = lo > 0 ? tailIdx[lo - 1] : -1;
            tailIdx[lo] = i;
            if (lo == size) size++;
        }
        int[] out = new int[size];
        for (int k = size - 1, i = tailIdx[size - 1]; k >= 0; k--, i = prev[i])
            out[k] = nums[i];
        return out;
    }

    /** LeetCode 673: how many longest increasing subsequences are there? */
    public static int countLIS(int[] nums) {
        int n = nums.length, best = 0, ways = 0;
        int[] len = new int[n], cnt = new int[n];
        for (int i = 0; i < n; i++) {
            len[i] = 1;
            cnt[i] = 1;
            for (int j = 0; j < i; j++) {
                if (nums[j] >= nums[i]) continue;
                if (len[j] + 1 > len[i]) {
                    len[i] = len[j] + 1;
                    cnt[i] = cnt[j];
                } else if (len[j] + 1 == len[i]) {
                    cnt[i] += cnt[j];
                }
            }
            if (len[i] > best) {
                best = len[i];
                ways = cnt[i];
            } else if (len[i] == best) {
                ways += cnt[i];
            }
        }
        return ways;
    }

    /**
     * LeetCode 354: envelopes nest if both width and height are strictly
     * larger. Sort by width ascending, height DESCENDING, then LIS on heights.
     */
    public static int maxEnvelopes(int[][] env) {
        int[][] s = env.clone();
        Arrays.sort(s, (a, b) -> a[0] != b[0]
                ? Integer.compare(a[0], b[0]) : Integer.compare(b[1], a[1]));
        int[] h = new int[s.length];
        for (int i = 0; i < s.length; i++) h[i] = s[i][1];
        return lengthPatience(h);
    }

    /** LeetCode 368: largest subset in which every pair divides one another. */
    public static List<Integer> largestDivisibleSubset(int[] nums) {
        int n = nums.length;
        if (n == 0) return new ArrayList<>();
        int[] a = nums.clone();
        Arrays.sort(a);
        int[] dp = new int[n], prev = new int[n];
        int bestIdx = 0;
        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            prev[i] = -1;
            for (int j = 0; j < i; j++)
                if (a[i] % a[j] == 0 && dp[j] + 1 > dp[i]) {
                    dp[i] = dp[j] + 1;
                    prev[i] = j;
                }
            if (dp[i] > dp[bestIdx]) bestIdx = i;
        }
        List<Integer> out = new ArrayList<>();
        for (int i = bestIdx; i >= 0; i = prev[i]) out.add(a[i]);
        Collections.reverse(out);
        return out;
    }
}

TIME O(n log n)

SPACE O(n)

lengthPatience is O(n log n) with O(n) space. lengthDP, countLIS and largestDivisibleSubset are O(n^2). maxEnvelopes sorts first, then runs the fast LIS, giving O(n log n).

F. Detailed Dry Run

Tails for [10,9,2,5,3,7,101,18]: [10] -> [9] -> [2] -> [2,5] -> [2,3] -> [2,3,7] -> [2,3,7,101] -> [2,3,7,18]. Length 4. Note the last step replaced 101 by 18: if a future value is between 18 and 101, a length-5 sequence becomes possible.

Reconstruction: store, for every element, the index of the tail it replaced the predecessor of (prevIndex) and the index currently holding each length. Walk back from the index holding the last tail.

G. Variations of the Pattern

Strictly vs non-strictly increasing

Non-decreasing LIS searches the first tail > x (upper bound). Strict LIS searches the first tail >= x (lower bound). Mixing them is the top bug.

Maximum-sum increasing subsequence

Use the O(n^2) DP with sums, or a BIT keyed by value ranks storing the best sum for values below.

Longest bitonic subsequence

Compute LIS ending at i from the left and LDS starting at i from the right; answer max(l[i] + r[i] - 1).

Two-key nesting

Sort by one key (descending on ties of that key), LIS on the other: envelopes, boxes, towers, Maximum Height by Stacking Cuboids (1691, 3D).

Minimum deletions and patience piles

Minimum removals to sort: n - LIS. Minimum number of strictly increasing subsequences covering the array equals the longest non-increasing subsequence.

J. Interview Tips

INTERVIEW

Give the O(n^2) DP first, then offer patience sorting as the optimisation. That shows both understanding and range.

Explain tails in words: "the smallest possible end value for each length". It sells the binary search.

For envelopes, say why the heights are sorted descending on ties before you write the comparator.

Follow-ups: return the sequence; count the sequences; weighted version; online LIS as elements stream in; LIS in a circular array.
Edge cases: all equal, strictly decreasing, single element, duplicates, negative values.

CHAPTER SUMMARY

LIS length: O(n^2) DP on end index, or O(n log n) with the sorted tails array.

tails[k] is the smallest possible end of a length k+1 sequence; it is not itself a subsequence.

Strict vs non-decreasing = lower bound vs upper bound.

Counting carries (length, count); envelopes sort width ascending, height descending, then LIS on heights.

Weighted or windowed variants need the DP or a BIT/segment tree, not tails.
