BST Patterns

Left < node < right: search, validate and walk in sorted order.

A. Pattern Overview

A binary search tree (BST) keeps, for every node, all keys of the left subtree strictly smaller and all keys of the right subtree strictly larger (LeetCode's definition; duplicates are not allowed unless a problem says otherwise). Two consequences drive every BST problem:

Search by comparison: at each node you can discard one whole subtree, so lookup,

insert and delete cost O(h).

Inorder is sorted: an inorder walk yields keys in increasing order. Kth smallest, successor, range queries, validation and recovery all reduce to inorder with a twist.
KEY IDEA

The BST property is global, not local. Checking left.val < node.val < right.val at each node is wrong: a node deep in the left subtree can still exceed an ancestor. Correct validation carries an open interval (lo, hi) down the tree.

B. When to Recognize This Pattern

Pattern Recognition Signals

The statement says binary search tree (or "sorted" tree): use the order to prune.
"kth smallest / largest", "in sorted order", "next / previous greater", "closest value":

inorder or successor logic.

"Validate", "two nodes swapped": bounds, or look for inorder inversions.
"Within [low, high]": skip subtrees entirely outside the range.
"Iterator over a BST" with O(h) memory: controlled inorder.
ONE-LINE TEST

If the tree is a BST and your solution visits every node to answer a point query, you ignored the property. A point query is O(h).

C. Core Intuition with Illustrations

Validate with bounds, not with parent checks

Each node must fall in the open interval inherited from its ancestors. Going left sets hi = node.val; going right sets lo = node.val.

Figure 80. Every parent-child pair is ordered, yet the tree is not a BST.

Node 3 must lie in (5, 6), which excludes it, so the tree is invalid although every parent-child pair is ordered. Use long bounds (or null) so Integer.MIN_VALUE and MAX_VALUE as node values are handled.

Kth smallest: stop the inorder walk early

The iterative inorder stack pops nodes in sorted order; the k-th pop is the answer, and we stop right there: O(h + k).

VisitedRank so farState
11k left = 2
22k left = 1
33k left = 0 → answer

Answer for k = 3: 3. For many queries on a changing tree, augment each node with its subtree size and descend by rank (O(h) per query).

Inorder successor: the last node where we went left

The successor of p is the smallest key greater than p. Walk from the root: if p < node, this node is a candidate and the answer lies to the left (maybe a smaller candidate); otherwise go right. No parent pointers are needed.

NodeDecision
5p < node: candidate = 5, go left
3p ≥ node: go right
4p ≥ node: go right

Successor of 4 is 5. If p has a right child, the successor is that subtree's leftmost node; the descent above covers both cases.

Recover Binary Search Tree

Two nodes were swapped. In the inorder sequence this creates one or two descents (a[i] > a[i+1]). If the swapped nodes are adjacent there is one descent: swap that pair. Otherwise there are two: the first element of the first descent and the second element of the second descent are the culprits. Example: 1 3 2 4 (one descent: 3, 2) and 3 2 1 (descents 3 > 2 and 2 > 1: swap 3 and 1).

INTUITION

h is not log n. A BST built from sorted input is a linked list with h = n. Production code uses balanced trees (red-black in TreeMap, AVL, B-trees); interview problems state the BST is arbitrary and quote O(h).

E. Java Implementation

Search, insert, delete

BSTOps.java: LeetCode 700, 701, 450
/**
 * LeetCode 700 / 701 / 450 - search, insert and delete in a binary search tree;
 * delete returns the new subtree root.
 */
public class BSTOps {
    public static TreeNode search(TreeNode root, int key) {
        while (root != null && root.val != key)
            root = key < root.val ? root.left : root.right;
        return root;
    }

    /** Inserts key as a new leaf (duplicates are ignored). */
    public static TreeNode insert(TreeNode root, int key) {
        if (root == null) return new TreeNode(key);
        if (key < root.val) root.left = insert(root.left, key);
        else if (key > root.val) root.right = insert(root.right, key);
        return root;
    }

    /**
     * Deletes key if present. Two children: copy the inorder successor's value up,
     * then delete that successor.
     */
    public static TreeNode delete(TreeNode root, int key) {
        if (root == null) return null;
        if (key < root.val) root.left = delete(root.left, key);
        else if (key > root.val) root.right = delete(root.right, key);
        else {
            // 0 or 1 child: splice the node out

Java 17+

            if (root.left == null) return root.right;
            if (root.right == null) return root.left;
            // smallest node of the right subtree
            TreeNode succ = root.right;
            while (succ.left != null) succ = succ.left;
            root.val = succ.val;
            root.right = delete(root.right, succ.val);
        }
        return root;
    }
}

TIME O(h)

SPACE O(h)

Recursive versions use the call stack. Delete with two children copies the successor's value and removes it from the right subtree.

Validate BST

ValidateBST.java: LeetCode 98
/**
 * LeetCode 98 - Validate Binary Search Tree: every node must lie strictly inside
 * the open interval set by its ancestors.
 */
public class ValidateBST {
    public static boolean isValidBST(TreeNode root) {
        // long bounds: node values may equal Integer.MIN/MAX_VALUE
        return valid(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }

    private static boolean valid(TreeNode n, long lo, long hi) {
        if (n == null) return true;
        if (n.val <= lo || n.val >= hi) return false;
        return valid(n.left, lo, n.val) && valid(n.right, n.val, hi);
    }

    /** Alternative: a BST's inorder traversal is strictly increasing. */
    public static boolean isValidInorder(TreeNode root) {
        java.util.Deque<TreeNode> stack = new java.util.ArrayDeque<>();
        TreeNode cur = root;
        long prev = Long.MIN_VALUE;
        while (cur != null || !stack.isEmpty()) {
            while (cur != null) { stack.push(cur); cur = cur.left; }
            cur = stack.pop();
            if (cur.val <= prev) return false;
            prev = cur.val;
            cur = cur.right;
        }
        return true;
    }
}

Java 17+

TIME O(n)

SPACE O(h)

long bounds avoid the Integer.MIN_VALUE trap. The inorder variant keeps a prev and requires strictly increasing values.

Kth smallest and inorder successor

KthSmallest.java: LeetCode 230
import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 230 - Kth Smallest Element in a BST: stop the iterative inorder walk
 * after k visits.
 */
public class KthSmallest {
    public static int kthSmallest(TreeNode root, int k) {
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode cur = root;
        while (cur != null || !stack.isEmpty()) {
            while (cur != null) { stack.push(cur); cur = cur.left; }
            cur = stack.pop();
            if (--k == 0) return cur.val;
            cur = cur.right;
        }
        throw new IllegalArgumentException("k exceeds the number of nodes");
    }
}

Java 17+

InorderSuccessor.java: LeetCode 285
/**
 * LeetCode 285 / 510 flavour - smallest value greater than p.val in a BST, found in
 * O(h) without parent pointers.
 */
public class InorderSuccessor {
    public static TreeNode successor(TreeNode root, TreeNode p) {
        TreeNode candidate = null;
        while (root != null) {
            // root is a possible answer; look for a smaller one
            if (p.val < root.val) { candidate = root; root = root.left; }
            // root and its left subtree are too small
            else root = root.right;
        }
        return candidate;
    }
}

Java 17+

TIME O(h + k) / O(h)

SPACE O(h) / O(1)

The successor descent is iterative and needs no stack.

BST iterator

BSTIterator.java: LeetCode 173
import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 173 - BST Iterator: controlled inorder with a stack holding only the
 * left spine; next() is amortised O(1).
 */
public class BSTIterator {
    private final Deque<TreeNode> stack = new ArrayDeque<>();

    public BSTIterator(TreeNode root) { pushLeft(root); }

Java 17+

    public boolean hasNext() { return !stack.isEmpty(); }

    public int next() {
        TreeNode n = stack.pop();
        // the right subtree's left spine comes next in order
        pushLeft(n.right);
        return n.val;
    }

    private void pushLeft(TreeNode n) {
        for (; n != null; n = n.left) stack.push(n);
    }
}

TIME next: O(1) amortised

SPACE O(h)

Each node is pushed and popped exactly once over n calls, so the average cost per next() is constant.

Recover BST

RecoverBST.java: LeetCode 99
/**
 * LeetCode 99 - Recover Binary Search Tree: two values were swapped; find them as
 * the inversions of the inorder sequence.
 */
public class RecoverBST {
    private TreeNode first, second, prev;

    public static void recoverTree(TreeNode root) {
        RecoverBST r = new RecoverBST();
        r.inorder(root);
        int t = r.first.val;
        r.first.val = r.second.val;
        r.second.val = t;
    }

    private void inorder(TreeNode n) {
        if (n == null) return;
        inorder(n.left);
        if (prev != null && prev.val > n.val) {
            // first inversion: the larger element of the pair is misplaced
            if (first == null) first = prev;
            // last inversion: the smaller element is misplaced
            second = n;
        }
        prev = n;
        inorder(n.right);
    }
}

Java 17+

TIME O(n)

SPACE O(h)

Swap values, not nodes. With Morris traversal the space drops to O(1).

Range sum of a BST

RangeSumBST.java: LeetCode 938
/**
 * LeetCode 938 - Range Sum of BST: prune subtrees that lie entirely outside [lo,
 * hi].
 */
public class RangeSumBST {
    public static int rangeSum(TreeNode root, int lo, int hi) {
        if (root == null) return 0;
        // the left subtree is smaller still
        if (root.val < lo) return rangeSum(root.right, lo, hi);
        if (root.val > hi) return rangeSum(root.left, lo, hi);
        return root.val + rangeSum(root.left, lo, hi)
                + rangeSum(root.right, lo, hi);
    }
}

Java 17+

TIME O(n) worst

SPACE O(h)

Go left only when low < node, right only when node < high.

G. Variations of the Pattern

Build or transform

Trim a BST (669), Convert Sorted Array to BST (108, Chapter 43), Balance a BST (1382: inorder list, then rebuild), Convert BST to Greater Tree (538: reverse inorder with a running sum).

Two BSTs

Two Sum IV (653): two iterators, one forward and one backward, as in two pointers on a sorted array. All Elements in Two BSTs (1305): merge two inorder streams.

Ancestors in a BST

LCA of a BST (235): the first node whose value splits p and q (Chapter 45). Closest BST Value (270): descend, remembering the best.

Counting

Unique Binary Search Trees (96) is the Catalan number DP: G(n) = Σ G(i − 1) · G(n − i). Unique BSTs II (95) generates them recursively.

Augmented BSTs

Store subtree sizes for rank queries, or use TreeMap / TreeSet (floorKey, ceilingKey) when the problem is really an ordered-set problem (Contains Duplicate III, My Calendar).

J. Interview Tips

INTERVIEW

Open with the property: "left subtree strictly smaller, right strictly larger, and inorder is sorted." Then name which of the two you use.

On validation, volunteer the bounds trap (parent-only checking) and the Integer.MIN_VALUE trap.

Quote O(h), not O(log n), and mention the skewed case plus balanced trees as the fix.

Follow-ups: kth smallest with frequent inserts and deletes (augment with sizes); iterator with O(1) memory (threaded tree); two-pointer iterators for Two Sum IV; BST with duplicates.
Edge cases: empty tree, single node, skewed tree, Integer.MIN_VALUE / MAX_VALUE, deleting the root, k equal to n, no successor (largest node).

CHAPTER SUMMARY

BST = left < node < right globally; inorder is sorted; search, insert and delete are O(h).

Validate with an open interval (lo, hi) (use long), never with parent-only comparisons.

Kth smallest, iterator, successor are all controlled inorder; stop early instead of materialising the list.

Delete has three cases; for two children, copy the inorder successor and delete it from the right subtree.

Recover two swapped nodes by finding the inorder descents; h can be n, so state costs in h.
