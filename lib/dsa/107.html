Bit Manipulation

Treat integers as sets of bits: masks, shifts, XOR cancellation and Kernighan.

A. Pattern Overview

An int is a 32-element boolean array that the CPU can read, test and change in one instruction. Bit manipulation uses that fact to replace loops, hash sets and lookup tables by a handful of operators: &, |, ^, ~, <<, >> and >>>. Three ideas cover most problems: masks (test, set, clear, toggle one bit), XOR cancellation (a ^ a = 0, a ^ 0 = a) and lowest-set-bit tricks (n & (n - 1) and n & -n).

KEY IDEA

Know your shift. >> is arithmetic (sign-extending); >>> is logical. Use >>> whenever the value may be negative and you want to walk its 32 bits.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Without extra space" or "constant space" on a counting or uniqueness problem (XOR cancellation).
Powers of two appear in the statement, or the answer needs log loops over bit positions.
Set membership over at most 20-30 items (a bitmask is a set; Chapter 90).
Pairwise bit comparison (Hamming distance): handle each bit column independently.
Parity, flags, permissions, compact state in a single integer.
ONE-LINE TEST

Each bit position is independent, or equal values must cancel: think masks and XOR.

C. Core Intuition with Illustrations

Kernighan: clear the lowest set bit

Subtracting 1 flips the lowest set bit to 0 and every zero below it to 1. ANDing with the original therefore deletes exactly that one bit. Repeating it popcount(n) times counts the bits in O(popcount), not O(32). For n = 44:

The one-bit test for powers of two

A power of two has exactly one set bit, so n > 0 && (n & (n - 1)) == 0. A power of four additionally needs that bit in an even position: & 0x55555555 != 0.

Counting bits for all numbers in linear time

bits[i] = bits[i >> 1] + (i & 1): drop the last bit, reuse the earlier answer, add the bit you dropped.

XOR cancels pairs

XOR is commutative and associative, and every value XORed with itself vanishes. XOR-ing a whole array in which every element appears twice except one leaves that one element, in O(n) time and O(1) space.

Hamming distance, column by column

For totalHammingDistance, do not compare all pairs. For each bit column with c ones among

n numbers, exactly c (n - c) pairs differ in that column. Sum over 32 columns: O(32 n)

instead of O(n^2).

TRAP

Integer.MIN_VALUE has no positive counterpart: -MIN_VALUE == MIN_VALUE, and Math.abs(MIN_VALUE) is negative. Power-of-two tests must reject n <= 0 first.

E. Java Implementation

Power tests, popcount, reverse, Hamming distances and XOR tricks

BitBasics.java: masks, Kernighan, counting bits, single number, Hamming distance

import java.util.*;

/**
 * Ch 92: bit manipulation basics; LeetCode 136, 191, 231, 342, 338, 190, 461, 477.
 */
public class BitBasics {
    /** LeetCode 231: a power of two has exactly one set bit. */
    public static boolean isPowerOfTwo(int n) {
        return n > 0 && (n & (n - 1)) == 0;
    }

    /** LeetCode 342: one set bit, and it sits at an even position. */
    public static boolean isPowerOfFour(int n) {
        return n > 0 && (n & (n - 1)) == 0 && (n & 0x55555555) != 0;
    }

    /** LeetCode 191: Brian Kernighan, one iteration per set bit. */
    public static int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            n &= n - 1;                 // clears the lowest set bit
            count++;
        }
        return count;
    }

    /** LeetCode 338: bits[i] = bits[i >> 1] + (i & 1). */
    public static int[] countBits(int n) {
        int[] bits = new int[n + 1];
        for (int i = 1; i <= n; i++) bits[i] = bits[i >> 1] + (i & 1);
        return bits;
    }

    /** LeetCode 136: every value appears twice except one; XOR cancels pairs. */
    public static int singleNumber(int[] nums) {
        int x = 0;
        for (int v : nums) x ^= v;
        return x;

    }

    /** LeetCode 190: reverse the 32 bits of n. */
    public static int reverseBits(int n) {
        int r = 0;
        for (int i = 0; i < 32; i++) {
            r = (r << 1) | (n & 1);
            n >>>= 1;                   // unsigned shift
        }
        return r;
    }

    /** LeetCode 461: number of differing bit positions. */
    public static int hammingDistance(int x, int y) {
        return Integer.bitCount(x ^ y);
    }

    /** LeetCode 477: sum of Hamming distances over all pairs, O(32 n). */
    public static int totalHammingDistance(int[] nums) {
        int total = 0, n = nums.length;
        for (int b = 0; b < 32; b++) {
            int ones = 0;
            for (int v : nums) ones += (v >>> b) & 1;
            total += ones * (n - ones);  // pairs that differ at bit b
        }
        return total;
    }

    /** Lowest set bit as a mask (x & -x), 0 for 0. */
    public static int lowestSetBit(int x) {
        return x & -x;
    }

    /** Swaps two ints without a temporary using XOR. */
    public static int[] xorSwap(int a, int b) {
        a ^= b;
        b ^= a;
        a ^= b;
        return new int[]{a, b};
    }
}

TIME O(popcount) to O(32 n)

SPACE O(1) (O(n) for countBits)

Every routine is a fixed number of word operations per element. countBits stores its n + 1 results as the answer.

F. Detailed Dry Run

singleNumber([4, 1, 2, 1, 2]): the running XOR is 4, 5, 7, 6, 4. The pairs 1, 1 and 2, 2

cancel, leaving 4. isPowerOfTwo(44): 44 & 43 = 40 != 0, so false. isPowerOfTwo(64): 64 & 63 = 0, so true. hammingDistance(1, 4): 1 ^ 4 = 5 = 101, popcount 2.

totalHammingDistance([4, 14, 2]) with 4 bits: column 0 has ones {} (count 0 of 3, contributes 0); column 1 has {14, 2} (2 ones, contributes 2 x 1 = 2); column 2 has {4, 14} (2 ones, 2); column 3 has {14} (1 one, 1 x 2 = 2). Total 6, equal to the pairwise sum 2 + 2 + 2.

G. Variations of the Pattern

Missing number

XOR indices 0..n with all values; the unpaired index is the answer. The alternative is the arithmetic series, but XOR cannot overflow.

Sorting by popcount

Use Integer.bitCount as the primary key (LeetCode 1356), or a counting sort over popcount 0..14.

Swapping without a temp

a ^= b; b ^= a; a ^= b works for two distinct variables but fails when both names alias the same array cell (a[i] with i == j becomes 0). Never do this in production; it is a trivia question.

Reversing bits and bit-width problems

Reverse by swapping halves with masks (0xAAAAAAAA, 0xCCCCCCCC, ...) for a branch-free O(log

version, or simply loop 32 times; the loop is what interviewers expect.
Lowest bit as an iterator

for (int m = mask; m != 0; m &= m - 1) { int bit = m & -m; ... } visits every set bit; the same loop with sub = (sub - 1) & mask enumerates submasks (Chapter 90).

J. Interview Tips

INTERVIEW

State the invariant of each trick aloud: "n - 1 flips the lowest set bit and the zeros below it".

Ask about signedness and width before writing a bit loop.

Mention the library call (Integer.bitCount, Long.numberOfTrailingZeros) and that you implement it only because the interviewer asked.

Follow-ups: do it in O(1) with a lookup table or the SWAR popcount; extend to 64 bits;

extend to a stream.

Edge cases: 0, -1, Integer.MIN_VALUE, Integer.MAX_VALUE, all-equal arrays.

CHAPTER SUMMARY

Integers are bit arrays; masks test, set, clear and toggle single bits in O(1).

n & (n - 1) clears the lowest set bit, which gives popcount and the power-of-two test; n & -n isolates it.

XOR cancels equal pairs, so a single unpaired value falls out of one pass with no extra memory.

Bit columns are independent, turning pairwise Hamming distance into 32 column counts.

Mind signedness, width and operator precedence, the source of nearly every bug here.
