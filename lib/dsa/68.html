Bipartite Graph

Two-colour the graph; an odd cycle is the only obstruction.

A. Pattern Overview

A graph is bipartite if its vertices split into two sets A and B so that every edge joins A to B. Equivalently: it can be two-coloured, or it has no odd-length cycle. The test is a BFS or DFS that assigns each neighbour the opposite colour and fails on the first edge whose endpoints share a colour. O(V + E).

KEY IDEA

Bipartite ⇔ no odd cycle (König). BFS layers alternate colours, so the only way to fail is an edge inside one layer or between layers of equal parity: that edge closes an odd cycle.

Why BFS and DFS both work

Colour by parity of distance from the start (BFS layer) or parity of depth in the DFS tree. Tree edges are fine by construction; every non-tree edge must also join opposite parities. A violation produces a closed walk of odd length, which always contains an odd cycle.

Disconnected graphs

Run the colouring from every uncoloured vertex. Each component is coloured independently, and the graph is bipartite only if all components are. Forgetting this loop is the most common bug.

Parity Union-Find

Instead of traversing, union u with the opposite of v: keep 2n nodes, where x and x + n are the two colours of x. For each conflict (u, v): if find(u) == find(v) the constraint is violated; otherwise union(u, v + n) and union(v, u + n). This is the right tool when constraints arrive online.

Matching: the bipartite payoff

Once the graph is bipartite, the maximum number of disjoint pairs between the sides is a classic problem. Kuhn's algorithm tries each left vertex and searches an augmenting path (alternating unmatched / matched edges); O(V · E). Hopcroft–Karp batches augmentations into BFS phases for O(E √V). König's theorem: in bipartite graphs, max matching = min vertex cover.

INTUITION

There is no search: after choosing the colour of one vertex per component, every other colour is forced. That is why a linear pass decides a problem that looks like 2ⁿ choices.

E. Java Implementation

Is Graph Bipartite, Possible Bipartition, Kuhn's matching

Bipartite.java: LeetCode 785, 886 and maximum bipartite matching

import java.util.*;

/** Ch 57: bipartite check and matching; LeetCode 785, 886, plus Kuhn's matching. */
public class Bipartite {

    /** Two-colour every component by BFS; false on an odd cycle. */
    public static boolean isBipartite(List<List<Integer>> g) {
        int n = g.size();
        int[] color = new int[n];
        Arrays.fill(color, -1);
        Deque<Integer> queue = new ArrayDeque<>();
        for (int s = 0; s < n; s++) {
            if (color[s] >= 0) continue;
            color[s] = 0;
            queue.add(s);
            while (!queue.isEmpty()) {
                int u = queue.poll();
                for (int v : g.get(u)) {
                    if (color[v] < 0) {
                        color[v] = 1 - color[u];
                        queue.add(v);
                    } else if (color[v] == color[u]) {
                        return false;
                    }
                }
            }
        }
        return true;
    }

    /** LeetCode 785: graph given as adjacency arrays. */
    public static boolean isBipartite(int[][] graph) {
        List<List<Integer>> g = new ArrayList<>();
        for (int[] row : graph) {
            List<Integer> l = new ArrayList<>();
            for (int v : row) l.add(v);
            g.add(l);
        }
        return isBipartite(g);
    }

    /** LeetCode 886: people 1..n, dislikes {a, b}: split into two groups? */
    public static boolean possibleBipartition(int n, int[][] dislikes) {
        int[][] e = new int[dislikes.length][];
        for (int i = 0; i < e.length; i++)
            e[i] = new int[] {dislikes[i][0] - 1, dislikes[i][1] - 1};
        return isBipartite(GraphRepresentation.adjList(n, e, false));
    }

    /**
     * Maximum bipartite matching by augmenting paths (Kuhn). left nodes 0..nl-1,
     * adj[u] = right nodes. O(V * E).
     */
    public static int maxMatching(int nl, int nr, List<List<Integer>> adj) {
        int[] matchOfRight = new int[nr];
        Arrays.fill(matchOfRight, -1);
        int matching = 0;

        for (int u = 0; u < nl; u++)
            if (augment(u, adj, new boolean[nr], matchOfRight)) matching++;

    private static boolean augment(int u, List<List<Integer>> adj, boolean[] seen,
                                   int[] matchOfRight) {
        for (int v : adj.get(u)) {
            if (seen[v]) continue;
            seen[v] = true;
            if (matchOfRight[v] < 0
                    || augment(matchOfRight[v], adj, seen, matchOfRight)) {
                matchOfRight[v] = u;
                return true;
            }
        }
        return false;
    }
}

SPACE O(V)

Colouring is iterative (BFS). maxMatching uses recursive augmenting-path DFS: depth is at most the number of left vertices, which is fine for interview sizes; use Hopcroft–Karp for large inputs.

F. Detailed Dry Run

4-cycle 0-1-2-3-0: start at 0 (colour 0). Neighbours 1 and 3 receive colour 1. Process 1: neighbour 2 receives colour 0; neighbour 0 already has colour 0 ≠ 1, fine. Process 3: neighbour 2 has colour 0 ≠ 1, fine. Result: bipartite with sides {0, 2} and {1, 3}.

Triangle 0-1-2-0: 0 gets colour 0, its neighbours 1 and 2 both get colour 1. Processing 1 finds neighbour 2 with the same colour 1: odd cycle, not bipartite.

G. Variations of the Pattern

Conflict pairs (Possible Bipartition)

Build an undirected graph from dislikes and run the same check; vertices are 1-indexed in the problem, so size the array n + 1.

Weighted parity

Evaluate Division style constraints with parity only: DSU with a stored parity-to-root. Is Graph Bipartite can be solved this way too.

Counting colourings

A bipartite graph with c components has exactly 2^c proper 2-colourings. A non-bipartite graph has none.

Maximum matching and covers

Assign workers to jobs, domino tilings, minimum vertex cover and maximum independent set (via König). Maximum Students Taking Exam (1349) reduces to matching on a chessboard-coloured conflict graph.

Grids are bipartite

Colour cell (r, c) by (r + c) mod 2; every move changes colour. This explains parity arguments in knight tours, domino tiling and "can the robot return in an odd number of steps".

CHAPTER SUMMARY

Bipartite ⇔ two-colourable ⇔ no odd cycle. After fixing one colour per component all others are forced.

BFS / DFS colouring runs in O(V + E); loop over every component; fail only when an edge joins equal colours.

Parity Union-Find (x and x + n) handles online conflict edges.

Conflict-pair problems ("dislikes", "enemies") are edges of a graph you try to 2-colour.

Beyond the check: matching (Kuhn O(VE), Hopcroft–Karp O(E√V)) and König's theorem; grids are bipartite by (r + c) mod 2.
