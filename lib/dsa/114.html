Quickselect and Selection Algorithms

Find the k-th element in expected O(n) by partitioning and discarding the half you don't need.

A. Pattern Overview

Quickselect finds the k-th smallest element without sorting. Partition around a pivot; the pivot lands at its final sorted position p. If p == k you are done; otherwise recurse into only one side. The work shrinks geometrically (n + n/2 + n/4 + ...), so the expected time is O(n), against O(n log n) for sorting and O(n log k) for a heap.

KEY IDEA

Quickselect is quicksort that ignores one half. Everything you know about partitioning, duplicates and pivot choice carries over.

B. When to Recognize This Pattern

Pattern Recognition Signals

"k-th largest / smallest", "median", "top k in any order" on an array in memory.
Output order does not matter (K Closest Points), so full sorting is wasted effort.
You are asked to beat O(n log n) for selection.
Wiggle sort, partition around the median, minimum moves to equalise (the median minimises absolute deviations).
Data does not fit a heap-friendly stream model: the full array is available.
ONE-LINE TEST

Need only the k-th element or the best k unordered: partition, don't sort.

C. Core Intuition with Illustrations

Three-way partition (Dutch national flag)

Maintain three zones inside a[lo..hi]: < pivot, == pivot, > pivot. Pointers lt, i, gt: if a[i] < pivot swap it into the left zone, if a[i] > pivot swap it into the right zone, else step. After the pass the middle zone [lt, gt] is final. Handling equal keys as one zone is what keeps arrays of duplicates O(n) instead of O(n^2).

Selecting the 5th smallest of [3, 2, 1, 5, 6, 4]

kthSmallest(a, 4) (0-based). The Java code draws a random pivot; the trace below picks the middle element so the run is reproducible.

RangePivotEqual zone [lt, gt]Array after partitionDecision
[0..5]1[0, 0][1, 2, 5, 6, 4, 3]k > 0: go right
[1..5]6[5, 5][1, 2, 5, 4, 3, 6]k < 5: go left
[1..4]5[4, 4][1, 2, 4, 3, 5, 6]k in [4, 4]: found

The answer is 5 (the 2nd largest of six, LeetCode 215 with k = 2). Each round discards at least the pivot's zone.

Why it is expected linear

A random pivot lands in the middle half of the sorted order with probability 1/2, shrinking the range to at most 3n/4. The expected total work is a geometric series bounded by ~ 4n comparisons (more precisely <= 3.4 n for the median). The worst case O(n^2) requires consistently terrible pivots, and randomisation makes that vanishingly unlikely.

Median of medians: worst-case linear

Split into groups of 5, take each group's median, recursively select the median of those medians as the pivot. At least 3n/10 elements are guaranteed on each side, giving T(n) <= T(n/5) + T(7n/10) + O(n) = O(n). The constant is large, so it is rarely used in practice, but it is the answer to "can you do it in worst-case linear time?".

Selection on keys other than values

K Closest Points compares distances, but partitions the point objects. Use squared distances in long to avoid sqrt and overflow. The result is any set of k closest points, not sorted.

CHOOSING

Heap versus quickselect: if the interviewer says "data stream" or "cannot modify the array" choose a heap. If they say "optimal average time", quickselect.

E. Java Implementation

Quickselect, 3-way partition, K Closest Points, median of medians

Quickselect.java: expected-linear selection and the deterministic variant

import java.util.*;

/** Ch 99: selection in expected O(n); LeetCode 215, 973, 912 helpers. */
public class Quickselect {
    private static final Random RND = new Random(12345);

    /** k-th smallest (0-based k) in expected O(n); reorders a copy. */
    public static int kthSmallest(int[] nums, int k) {
        int[] a = nums.clone();
        int lo = 0, hi = a.length - 1;
        while (true) {
            if (lo == hi) return a[lo];
            int pivot = a[lo + RND.nextInt(hi - lo + 1)];
            int[] bounds = partition3(a, lo, hi, pivot);   // [lt, gt]
            if (k < bounds[0]) hi = bounds[0] - 1;
            else if (k > bounds[1]) lo = bounds[1] + 1;
            else return pivot;
        }
    }

    /** LeetCode 215: k-th largest, k is 1-based. */
    public static int findKthLargest(int[] nums, int k) {
        return kthSmallest(nums, nums.length - k);
    }

Java 17+

    /** Dutch national flag partition around pivot; returns the equal range. */
    static int[] partition3(int[] a, int lo, int hi, int pivot) {
        int lt = lo, i = lo, gt = hi;
        while (i <= gt) {
            if (a[i] < pivot) swap(a, lt++, i++);
            else if (a[i] > pivot) swap(a, i, gt--);
            else i++;
        }
        return new int[]{lt, gt};
    }

    private static void swap(int[] a, int i, int j) {
        int t = a[i];
        a[i] = a[j];
        a[j] = t;
    }

    /** LeetCode 973: k closest points to the origin, unordered. */
    public static int[][] kClosest(int[][] points, int k) {
        int[][] p = points.clone();
        int lo = 0, hi = p.length - 1;
        while (lo < hi) {
            long pv = dist(p[lo + RND.nextInt(hi - lo + 1)]);
            int lt = lo, i = lo, gt = hi;
            while (i <= gt) {
                long d = dist(p[i]);
                if (d < pv) { int[] t = p[lt]; p[lt++] = p[i]; p[i++] = t; }
                else if (d > pv) { int[] t = p[i]; p[i] = p[gt]; p[gt--] = t; }
                else i++;
            }
            if (k <= lt) hi = lt - 1;
            else if (k > gt + 1) lo = gt + 1;
            else break;
        }
        return Arrays.copyOf(p, k);
    }

    private static long dist(int[] p) {
        return (long) p[0] * p[0] + (long) p[1] * p[1];
    }

    /** Deterministic worst-case O(n) selection: median of medians (groups of 5). */
    public static int select(int[] nums, int k) {
        return select(nums.clone(), 0, nums.length - 1, k);
    }

    private static int select(int[] a, int lo, int hi, int k) {
        while (true) {
            if (hi - lo < 5) {
                Arrays.sort(a, lo, hi + 1);
                return a[k];
            }
            int groups = 0;
            for (int i = lo; i <= hi; i += 5) {
                int end = Math.min(i + 4, hi);
                Arrays.sort(a, i, end + 1);
                // gather medians in front
                swap(a, lo + groups++, i + (end - i) / 2);
            }
            int pivot = select(a, lo, lo + groups - 1, lo + (groups - 1) / 2);
            int[] b = partition3(a, lo, hi, pivot);
            if (k < b[0]) hi = b[0] - 1;
            else if (k > b[1]) lo = b[1] + 1;
            else return pivot;
        }
    }

    /** Median of an array (lower median for even length). */
    public static int median(int[] nums) {
        return kthSmallest(nums, (nums.length - 1) / 2);
    }
}

TIME O(n) expected

SPACE O(1) extra

Expected comparisons are about 3.4 n for the median and 2 n for extreme ranks. Median of medians is O(n) worst case. The Java code works on a copy (nums.clone()), so the caller's array is untouched.

F. Detailed Dry Run

findKthLargest([3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4): the 4th largest is the element at sorted index 9 - 4 = 5. Sorted: 1, 2, 2, 3, 3, 4, 5, 5, 6, so the answer is 4. Suppose the first pivot is 3: the 3-way partition gives zone < 3 of size 3 (1, 2, 2), zone == 3 of size 2 (indices 3-4), zone > 3 of size 4. Target index 5 lies in the right zone, so we continue on [5..8] only, 4 elements instead of 9. A pivot of 5 there puts 4 at index 5 and finishes.

medianOfMedians: for 25 elements, 5 groups of 5; sort each, collect the 5 medians, recursively select their median m; at least 9 elements are <= m and 9 are >= m (three groups have a median on that side, each contributing 3 of its 5 elements), so the next range has at most 16 elements.

G. Variations of the Pattern

Sort Colors (Dutch national flag)

The partition step on its own with three values 0, 1, 2 and pivot 1 (LeetCode 75).

Minimum moves to equal elements

The median minimises sum |a[i] - x|. Quickselect the median and add the distances (LeetCode 462).

Wiggle Sort II

Find the median with quickselect, then place values above the median in odd slots and values below in even slots using a virtual index mapping (three-way partition with permuted indices).

Top k frequent

Count with a map, then quickselect the entries on frequency: O(n) instead of O(n log k).

Median of two sorted arrays

A different selection problem: binary search on the partition of the smaller array, O(log min(m, n)).

J. Interview Tips

INTERVIEW

Mention all three solutions in order: sort, heap, quickselect, with their costs, then implement the one asked for.

Say "random pivot" and "three-way partition" unprompted; they prevent the two classic failures.

State expected versus worst case and offer median of medians for a guaranteed bound.

Follow-ups: streaming data (heap or sketches); external memory (selection by histogram); parallel selection; weighted median.
Edge cases: k = 1, k = n, all equal, already sorted, negative numbers.

CHAPTER SUMMARY

Quickselect partitions and recurses into one side, giving expected O(n) time and O(1) extra space.

Use a random pivot and a three-way partition to avoid worst cases on sorted or duplicate-heavy input.

Heaps win for streams and tiny k; quickselect wins for one query on an in-memory array.

Median of medians guarantees worst-case linear time at the cost of a big constant.

The median solves "minimum total distance" problems, so selection hides inside many of them.
