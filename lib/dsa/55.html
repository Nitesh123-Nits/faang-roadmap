LCA and Binary Lifting

Meet in the middle: lowest common ancestors and k-th ancestors.

A. Pattern Overview

The lowest common ancestor (LCA) of nodes p and q is the deepest node that has both as descendants (a node counts as its own descendant). It underlies tree distances (dist(p,q) = depth(p) + depth(q) − 2·depth(lca)), path queries and many "nearest shared ancestor" questions. Three tools cover almost every case:

KEY IDEA

Binary lifting stores the 2ʲ-th ancestor of every node. Because every integer is a

sum of distinct powers of two, any k-th ancestor is reached in at most log₂ k jumps,

and an LCA is found by lifting the deeper node, then jumping both nodes while their ancestors still differ.

B. When to Recognize This Pattern

Pattern Recognition Signals

"Lowest / nearest common ancestor", "closest shared parent", "merge point of two paths

up the tree".

"Distance between two nodes in a tree": LCA plus depths.
"The k-th ancestor", with many queries: binary lifting.
"Smallest subtree containing all the deepest leaves" (1123): LCA of a set, computed bottom-up.
Parent array input (parent[i]) with up to 5·10⁴ queries: the lifting table is the intended tool.
ONE-LINE TEST

Single query: recurse. Many queries on a fixed tree: precompute depths and up[][]. BST: use the values, no table needed.

C. Core Intuition with Illustrations

LCA in a binary tree: the node where the two reports meet

Return the node itself if it is p or q; otherwise ask both children. If both return non-null, p and q are in different subtrees and this node is the LCA. If only one is non-null, pass it up (it is either the LCA already found, or the single target).

TIP

This relies on both nodes existing in the tree. If one may be absent (LeetCode 1644), count how many targets were seen and verify both before trusting the result.

LCA in a BST: the first split point

Start at the root. If both values are smaller, go left; if both are larger, go right. The first node where they split (or equal one of them) is the LCA. This is O(h) and iterative with O(1) space.

Smallest subtree with all deepest nodes

Return (depth, node) from each subtree. If both sides have equal depth, the current node is the LCA of the deepest leaves below it; otherwise keep the deeper side's answer.

k-th ancestor and LCA queries

k-th ancestor: for each set bit j of k, replace v by up[j][v]. For k = 3 = 0b11 from node 6: up[0][6] = 3, then up[1][3] = 0. Answer 0.

LCA(u, v): (1) make u the deeper node; (2) lift it by depth[u] − depth[v]; (3) if now u == v, done; (4) for j from high to low, if up[j][u] != up[j][v], jump both; (5) the answer is the common parent up[0][u]. Step 4 works because the "ancestors still differ" predicate is monotone: all jumps that stay below the LCA are allowed, all that reach or pass it are not, exactly like binary search on the answer.

Example LCA(6, 4): depths 3 and 2; lift 6 by 1 to node 3; 3 ≠ 4; at every level the ancestors of 3 and 4 are equal (-1, -1, then 1 and 1), so no jump is taken; the answer is up[0][3] = 1.

E. Java Implementation

LCA of a binary tree, of a BST, and of the deepest leaves

LowestCommonAncestor.java: LeetCode 236, 235, 1123
/** LCA in a binary tree (236), in a BST (235), and of the deepest leaves (1123). */
public class LowestCommonAncestor {
    /**
     * 236: if p and q are in different subtrees the current node is the LCA;
     * otherwise the answer is in the one non-null result.
     */
    public static TreeNode binaryTree(TreeNode root, TreeNode p, TreeNode q) {
        if (root == null || root == p || root == q) return root;
        TreeNode left = binaryTree(root.left, p, q);
        TreeNode right = binaryTree(root.right, p, q);
        if (left != null && right != null) return root;
        return left != null ? left : right;
    }

    /**
     * 235: walk down while p and q are on the same side of the node; the first
     * split point is the LCA.
     */
    public static TreeNode bst(TreeNode root, TreeNode p, TreeNode q) {
        while (root != null) {
            if (p.val < root.val && q.val < root.val) root = root.left;
            else if (p.val > root.val && q.val > root.val) root = root.right;
            else return root;
        }
        return null;
    }

    /**
     * 1123: the deepest subtree whose two sides are equally deep; returns {depth,
     * node}.
     */
    public static TreeNode deepestLeaves(TreeNode root) {
        return deepest(root).node;
    }

    private record Result(int depth, TreeNode node) {}

    private static Result deepest(TreeNode n) {
        if (n == null) return new Result(0, null);
        Result l = deepest(n.left), r = deepest(n.right);
        if (l.depth == r.depth) return new Result(l.depth + 1, n);
        Result deeper = l.depth > r.depth ? l : r;
        return new Result(deeper.depth + 1, deeper.node);
    }
}

Binary lifting: k-th ancestor and LCA

BinaryLifting.java: LeetCode 1483 and the standard LCA
/**
  * Binary lifting on a rooted forest given as a parent array (parent[root] = -1):
  * up[j][v] is the 2^j-th ancestor of v.
  * LeetCode 1483 (k-th ancestor) and the standard O(log n) LCA. Preprocessing O(n
  * log n), each query O(log n).
 */
public class BinaryLifting {
    private final int[][] up;
    private final int[] depth;
    private final int levels;

    public BinaryLifting(int[] parent) {
        int n = parent.length;
        int lg = 1;
        while ((1 << lg) < n) lg++;
        levels = lg;
        up = new int[levels][n];
        for (int v = 0; v < n; v++) up[0][v] = parent[v];
        for (int j = 1; j < levels; j++)
            for (int v = 0; v < n; v++) {
                int mid = up[j - 1][v];
                // 2^j = 2^(j-1) + 2^(j-1)
                up[j][v] = mid == -1 ? -1 : up[j - 1][mid];
            }
        depth = new int[n];
        java.util.Arrays.fill(depth, -1);
        for (int v = 0; v < n; v++) computeDepth(v, parent);
    }

    /**
     * Climbs to the first node with a known depth, then fills the whole chain back
     * down (no recursion).
     */
    private void computeDepth(int v, int[] parent) {
        java.util.ArrayDeque<Integer> chain = new java.util.ArrayDeque<>();
        int cur = v;
        while (cur != -1 && depth[cur] == -1) {
            chain.push(cur);
            cur = parent[cur];
        }
        int d = cur == -1 ? -1 : depth[cur];
        while (!chain.isEmpty()) depth[chain.pop()] = ++d;
    }

    /**
     * k-th ancestor of v, or -1 if it does not exist: jump by the set bits of k.
     */
    public int kthAncestor(int v, int k) {
        for (int j = 0; j < levels && v != -1; j++)
            if ((k >> j & 1) == 1) v = up[j][v];
        return k >= (1 << levels) ? -1 : v;
    }

    /** Lowest common ancestor of u and v (they must be in the same tree), or -1. */
    public int lca(int u, int v) {
        if (depth[u] < depth[v]) { int t = u; u = v; v = t; }
        // lift the deeper node to the same depth
        u = kthAncestor(u, depth[u] - depth[v]);
        if (u == v) return u;
        for (int j = levels - 1; j >= 0; j--)

Java 17+

            // jump while the ancestors still differ
            if (up[j][u] != up[j][v]) { u = up[j][u]; v = up[j][v]; }
        return up[0][u];
    }

    public int depth(int v) { return depth[v]; }
}

SPACE O(n log n)

Depths are computed iteratively, so a 100 000-node chain does not overflow the stack. kthAncestor returns −1 when k exceeds the depth.

F. Detailed Dry Run

The LCA table above is the trace for the recursive algorithm; it shows the reports that arrive at each node in postorder. The lifting table is the full precomputation for 8 nodes (3 levels). To check a jump yourself: LCA(6, 7) have equal depth 3, neither is an ancestor of the other; at j = 2 and j = 1 the ancestors are equal (-1 and 1), at j = 0 the parents are 3 and 3, which are equal, so no jump happens and the answer is up[0][6] = 3.

G. Variations of the Pattern

Distance and paths

Distance between two nodes (1740), Find Distance in a Binary Tree, Step-by-Step Directions (2096): LCA plus depths or the two root paths.

Weighted and path aggregates

Store, next to each up[j][v], an aggregate (max edge, sum) of the 2ʲ edges covered. Then path queries (Minimum Edge on a Path, Kruskal reconstruction) cost O(log n).

LCA of many nodes

LCA of Deepest Leaves, LCA of a set of nodes (1676): the answer is the LCA of the two extremes in Euler order, or a recursion with counts.

With parent pointers

LCA III (1650): the two-pointer trick; climb each pointer to the other's start when it reaches the root. They meet at the LCA, exactly as in intersection of two linked lists (Chapter 21).

Offline and Euler tour

For up to ~10⁶ queries, an Euler tour with a sparse table gives O(1) per LCA. Tarjan's offline algorithm uses union-find. Both are beyond a typical interview but worth naming.

J. Interview Tips

INTERVIEW

Clarify first: binary tree or BST? Do p and q exist? Is a node its own descendant? Single or many queries?

Explain the recursion with the two reports: "if both sides found something, I am the LCA; otherwise I pass up what I found."

For many queries, sketch up[j][v] and say why jumping from the high bit down is correct (monotone predicate).

Follow-ups: nodes may be missing; parent pointers available; weighted edges; k-th ancestor; LCA of several nodes; online vs offline queries; dynamic tree changes (link-cut trees, out of scope).
Edge cases: p == q, one node is the ancestor of the other, root is the LCA, a skewed tree, k = 0, k beyond the root.

CHAPTER SUMMARY

LCA(p, q) = deepest node with both as descendants; a node is its own descendant.

Binary tree: postorder; if both children report non-null, the current node is the LCA. BST: descend to the first split. Both are single-query tools.

Binary lifting: up[j][v] = up[j−1][up[j−1][v]]; k-th ancestor jumps by the bits of k; LCA = equalise depths, then jump from high to low while ancestors differ.

dist(p, q) = depth(p) + depth(q) − 2 · depth(lca); a tree is a graph, so these ideas carry into Part VIII.

Watch for missing nodes, −1 propagation, and recursion depth on chains.
