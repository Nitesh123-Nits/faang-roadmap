Expression Parsing and Evaluation

Precedence, parentheses and postfix: calculators from stacks.

A. Pattern Overview

Evaluating 3 + 2 * 2 - (4 / 2) requires respecting precedence (* and / bind tighter than + and -), associativity (8 - 3 - 2 is (8 - 3) - 2) and parentheses. Three techniques cover every interview variant, in increasing generality:

TechniqueHandlesStateClassic problems
Sign + result stack+ - and parentheses (no * /)Saved (result, sign) per open bracketBasic Calculator (224)
Term stack+ - * /, no parenthesesA stack of terms to be summed; * / merge into the topBasic Calculator II (227)
Recursive descent+ - * /, parentheses, any nestingOne function per precedence levelBasic Calculator III (772)

KEY IDEA

Precedence is nesting in disguise. An expression is a sum of terms, a term is a product of factors, a factor is a number or a parenthesised expression. That

three-level grammar is the whole parser: expr → term (± term)*, term → factor (×

factor)*, factor → number | ( expr ).

B. When to Recognize This Pattern

Pattern Recognition Signals

"Evaluate the expression string" with + - * /, spaces, and possibly parentheses.
"Reverse Polish / postfix notation", "convert infix to postfix", "build an expression tree".
"Do not use eval": the constraint is the exercise.
"Add parentheses to maximise / count results": interval DP (Different Ways to Add

Parentheses, 241), not a stack.

Operators with different priority, or unary minus, or a custom operator table: precedence climbing.
CHOOSING THE TOOL

No parentheses → term stack (one pass, O(1) extra beyond the terms). Parentheses but only + - → sign + result. Everything → recursive descent or shunting-yard.

C. Core Intuition with Illustrations

Terms: * and / merge into the previous term

Treat the expression as a sum of terms. When you read + 3, push 3; for - 3, push −3; for * 3 or / 3, pop the last term, combine, push the result. At the end, sum the stack. Division is applied as soon as it is read, so 8 / 3 * 3 is (8 / 3) * 3 = 6, as left-to-right evaluation requires.

Parentheses: save and restore the context

For + - only, keep result (the sum so far in the current bracket) and sign (the sign of the next operand). At (, push result and sign, reset to 0 and +1. At ), finish the inner sum, then compute outer result + saved sign × inner. A leading − before ( is just the saved sign, so unary minus before a bracket needs no extra code.

Shunting-yard: operators wait on a stack until something weaker arrives

Read tokens left to right. Numbers go straight to the output. An operator first pops every stacked operator that binds at least as tightly (left-associativity), then is pushed. ( is pushed; ) pops to the output until (. At the end, pop everything. The output is postfix, which needs no precedence rules to evaluate.

Figure 52. The operator stack keeps lower-precedence operators waiting; the output is the postfix form.

Postfix evaluation: operators pop two values

Scan postfix tokens: push numbers; on an operator, pop the right operand first, then the left, apply, and push the result. After the last token, the single value left on the stack is the answer.

D. Brute Force to Optimal Solution

Brute force: find the innermost parentheses with a regex, evaluate the sub-expression, substitute, repeat: O(n²) and fragile.
Two-pass precedence: first evaluate all * /, then all + -: works, but needs a token list and does not nest.
Term stack (no parentheses): one pass, O(n), and the precedence rule is a single case per operator.
Recursive descent (with parentheses): one pass, O(n), O(depth) stack; the code mirrors the grammar and extends to ^, unary minus, functions.
Shunting-yard + RPN: separates parsing from evaluation, which is how real compilers and calculators work, and lets you reuse the postfix form for expression trees.

E. Java Implementation

Basic Calculator: + - ( )

BasicCalculator.java: LeetCode 224

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/** LeetCode 224 - Basic Calculator: digits, + - ( ) and spaces; unary minus allowed. */
public class BasicCalculator {

    public static int calculate(String s) {
        Deque<Integer> stack = new ArrayDeque<>();       // saved (result, sign) pairs
        int result = 0, sign = 1, num = 0;
        for (char c : s.toCharArray()) {
            if (Character.isDigit(c)) {
                num = num * 10 + (c - '0');
            } else if (c == '+' || c == '-') {
                result += sign * num;                    // finish the previous operand
                num = 0;
                sign = (c == '+') ? 1 : -1;
            } else if (c == '(') {
                stack.push(result);                      // save the outer context
                stack.push(sign);
                result = 0;
                sign = 1;
            } else if (c == ')') {
                result += sign * num;
                num = 0;
                result *= stack.pop();                   // apply the sign before '('
                result += stack.pop();                   // add the outer result
            }
        }
        return result + sign * num;
    }
}

TIME O(n)

SPACE O(depth)

Remember to add the last operand after the loop. Spaces are ignored by simply not matching any branch.

Basic Calculator II: + - * / with a term stack

BasicCalculatorII.java: LeetCode 227

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 227 - Basic Calculator II: + - * / without parentheses; division truncates toward
 * zero.
 */
public class BasicCalculatorII {

    public static int calculate(String s) {
        Deque<Integer> st = new ArrayDeque<>();          // terms still to be summed
        char op = '+';                                   // operator that precedes `num`
        int num = 0;
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (Character.isDigit(c)) num = num * 10 + (c - '0');
            if ((!Character.isDigit(c) && c != ' ') || i == s.length() - 1) {
                switch (op) {
                    case '+' -> st.push(num);
                    case '-' -> st.push(-num);
                    // bind tighter: merge into the last term
                    case '*' -> st.push(st.pop() * num);
                    // Java's int division truncates toward 0
                    case '/' -> st.push(st.pop() / num);
                    default -> { }
                }
                op = c;
                num = 0;
            }
        }
        int sum = 0;
        for (int v : st) sum += v;
        return sum;
    }
}

TIME O(n)

SPACE O(n)

Process an operand when the next operator (or the end of input) is seen, using the previous operator. Java's / truncates toward zero, as the problem requires.

Basic Calculator III: recursive descent

BasicCalculatorIII.java: LeetCode 772 (premium)

Java 17+

/** LeetCode 772 - Basic Calculator III: + - * / and parentheses, via recursive descent. */
public class BasicCalculatorIII {

    private String s;
    private int pos;

    public static int calculate(String s) {
        BasicCalculatorIII p = new BasicCalculatorIII();
        p.s = s.replace(" ", "");
        return p.expr();
    }

    /** expr := term (('+' | '-') term)* */
    private int expr() {
        int value = term();
        while (pos < s.length() && (s.charAt(pos) == '+' || s.charAt(pos) == '-')) {
            char op = s.charAt(pos++);
            int rhs = term();
            value = (op == '+') ? value + rhs : value - rhs;
        }
        return value;
    }

    /** term := factor (('*' | '/') factor)* */
    private int term() {
        int value = factor();
        while (pos < s.length() && (s.charAt(pos) == '*' || s.charAt(pos) == '/')) {
            char op = s.charAt(pos++);
            int rhs = factor();
            value = (op == '*') ? value * rhs : value / rhs;
        }
        return value;
    }

    /** factor := number | '(' expr ')' */
    private int factor() {
        if (s.charAt(pos) == '(') {
            pos++;                                       // skip '('
            int value = expr();
            pos++;                                       // skip ')'
            return value;
        }
        int num = 0;
        while (pos < s.length() && Character.isDigit(s.charAt(pos))) {
            num = num * 10 + (s.charAt(pos++) - '0');
        }
        return num;
    }
}

TIME O(n)

SPACE O(depth)

expr calls term, term calls factor, factor calls expr for a bracket: precedence is encoded by which function loops over which operator.

Evaluate Reverse Polish Notation

EvaluateRPN.java: LeetCode 150

Java 17+

import java.util.ArrayDeque;
import java.util.Deque;

/**
 * LeetCode 150 - Evaluate Reverse Polish Notation. Operands are pushed; an operator pops two.
 */
public class EvaluateRPN {

    public static int evalRPN(String[] tokens) {
        Deque<Integer> st = new ArrayDeque<>();
        for (String t : tokens) {
            switch (t) {
                case "+" -> st.push(st.pop() + st.pop());
                case "*" -> st.push(st.pop() * st.pop());
                case "-" -> {
                    // the FIRST popped is the right operand
                    int b = st.pop(), a = st.pop();
                    st.push(a - b);
                }
                case "/" -> {
                    int b = st.pop(), a = st.pop();
                    st.push(a / b);
                }
                default -> st.push(Integer.parseInt(t));
            }
        }
        return st.pop();
    }
}

TIME O(n)

SPACE O(n)

For - and / the first popped value is the right operand. Tokens like -11 are numbers, not operators: test the token string, not its first character.

Infix to postfix (shunting-yard)

InfixToPostfix.java: classic algorithm

Java 17+

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

/**
 * Shunting-yard: convert infix (+ - * / and parentheses, left-associative) to postfix tokens.
 */
public class InfixToPostfix {

    private static int prec(char op) {
        return (op == '*' || op == '/') ? 2 : 1;
    }

    public static List<String> toPostfix(String infix) {
        List<String> out = new ArrayList<>();
        Deque<Character> ops = new ArrayDeque<>();
        for (int i = 0; i < infix.length(); i++) {
            char c = infix.charAt(i);
            if (c == ' ') continue;
            if (Character.isDigit(c)) {
                int j = i;
                while (j < infix.length() && Character.isDigit(infix.charAt(j))) j++;
                out.add(infix.substring(i, j));          // operands go straight to the output
i=j-1;
            } else if (c == '(') {
                ops.push(c);
            } else if (c == ')') {
                while (ops.peek() != '(') out.add(String.valueOf(ops.pop()));
                ops.pop();                               // discard '('
            // operator: pop operators that bind at least as tightly
            } else {
                while (!ops.isEmpty() && ops.peek() != '(' && prec(ops.peek()) >= prec(c)) {
                    out.add(String.valueOf(ops.pop()));
                }
                ops.push(c);
            }
        }
        while (!ops.isEmpty()) out.add(String.valueOf(ops.pop()));
        return out;
    }
}

TIME O(n)

SPACE O(n)

>= in the pop condition makes operators left-associative. For right-associative ^ use > for that operator.

G. Variations of the Pattern

Unary minus and other prefix operators

Treat a − that follows ( or another operator (or starts the string) as unary: push a 0 before it (0 − x), or use a distinct token neg with the highest precedence in shunting-yard. The sign + result technique gets it for free.

Right-associative operators (^)

2 ^ 3 ^ 2 = 2 ^ 9. In shunting-yard pop while the stack top has strictly higher precedence (instead of at least as high) for right-associative operators. In recursive descent, have power call itself for its right operand.

Different Ways to Add Parentheses (241)

Not a stack problem: split at every operator, solve both sides recursively, combine with a double loop, and memoise by substring. It is the first interval-DP-flavoured expression problem (Part XI).

Expression trees

Postfix → tree: push a leaf for each number; on an operator pop two subtrees and push a new node. Build Binary Expression Tree From Infix (1597) combines shunting-yard with this step. The tree makes simplification, differentiation and code generation straightforward.

Calculator with variables or functions

Add a hash map for variable lookup in factor, and a function-call branch (name ( expr, expr )) that parses comma-separated arguments. The recursive-descent structure does not change: this is why interpreters use it.

Overflow and division

Use long accumulators when intermediate values can exceed int (2^31 − 1), and decide how to report division by zero (an exception is the honest answer). Division truncates toward zero in the usual problem statements; Math.floorDiv would be wrong for negatives.

J. Interview Tips

INTERVIEW

Name the grammar (expr, term, factor) before coding recursive descent: it shows you understand precedence structurally.

Start with the problem's constraints: no brackets means the term stack suffices; do not over-engineer.

Test the traps out loud: 2-1-1 (associativity), 3+5/2 (precedence), (1+(4+5+2)-3)+(6+8) (nesting), 1-(−2) (unary minus), 14-3/2 (truncation).

Follow-ups: add ^, unary minus, floating-point numbers, variables, error reporting with a position, an incremental / streaming calculator, converting postfix back to infix with minimal parentheses.
Edge cases: empty or whitespace-only string, a single number, leading minus, consecutive spaces, large numbers, division by zero, deeply nested brackets.

CHAPTER SUMMARY

Expressions are sums of terms, terms are products of factors; precedence and parentheses are nesting levels of that grammar.

No brackets: a term stack; * / merge into the top, + - push ±num, then sum. Apply the previous operator when the next one arrives, and flush at the end.

Brackets with + -: save (result, sign) at (; at ), result = saved + sign × inner. Unary minus is free.

Full grammar: recursive descent (expr → term → factor) or shunting-yard to postfix, then evaluate with a value stack (pop right operand first).

Left-associativity means pop while the stack top binds at least as tightly; division truncates toward zero; mind int overflow.
