Knapsack Patterns

Choose items under a budget: 0/1, unbounded, counting and subset sum.

A. Pattern Overview

The knapsack family answers: from these items, which can I pick to hit a budget? The state is (items considered, budget used). Four variants cover almost every interview problem, and they differ only in how often an item may be used and what is asked (feasible, best value, count).

KEY IDEA

The direction of the capacity loop in the 1D version encodes the item rule. Downwards, dp[w - wt] still holds the value before this item (use once). Upwards, dp[w - wt] may already include this item (use many times).

B. When to Recognize This Pattern

Pattern Recognition Signals

A list of numbers and a target sum, with the question "is it possible" or "how many

ways".

"Split into two groups with equal (or closest) sums": subset sum on half the total.
"Assign + or - to every number to reach a target": counting subsets.
Unlimited supply of each denomination or piece size.
Two resources at once (zeros and ones): two-dimensional capacity.
Sum bound is small (up to a few thousand to 10^5), while the number of items is moderate.
ONE-LINE TEST

Items + a bounded numeric budget: knapsack. Bounded budget is what makes it pseudo-polynomial O(n * W).

C. Core Intuition with Illustrations

0/1 knapsack: the two-dimensional table

dp[i][w] is the best value using the first i items with capacity w. Either skip item i

(dp[i-1][w]) or take it (value + dp[i-1][w - weight]). Items weights [1,3,4,5], values [1,4,5,7], capacity 7.

Figure 132. 0/1 knapsack table.

The optimum 9 comes from items 2 and 3 (weights 3 + 4 = 7, values 4 + 5 = 9).

Collapsing to one row

Row i depends only on row i-1, so one array suffices if each row is overwritten right to left (so reads still see the old row). After each item:

Afterdp[0..7]
item 1 (w=1, v=1)[0, 1, 1, 1, 1, 1, 1, 1]
item 2 (w=3, v=4)[0, 1, 1, 4, 5, 5, 5, 5]
item 3 (w=4, v=5)[0, 1, 1, 4, 5, 6, 6, 9]
item 4 (w=5, v=7)[0, 1, 1, 4, 5, 7, 8, 9]
Unbounded knapsack: loop upwards

With unlimited copies the same items give a higher answer. Running the capacity loop left to right lets dp[w - wt] already include the current item:

Afterdp[0..7]
item 1 (w=1, v=1)[0, 1, 2, 3, 4, 5, 6, 7]
item 2 (w=3, v=4)[0, 1, 2, 4, 5, 6, 8, 9]
item 3 (w=4, v=5)[0, 1, 2, 4, 5, 6, 8, 9]
item 4 (w=5, v=7)[0, 1, 2, 4, 5, 7, 8, 9]

The unbounded optimum is 9 as well: 3 + 4 (value 9) ties with 1 + 1 + 5 (value 9); no mix of weight 7 does better because every item has value density at most 1.4.

Subset sum and Partition Equal Subset Sum (416)

Can [1,5,11,5] be split into two equal halves? The total is 22, so we need a subset with sum

A boolean dp[s] says whether sum s is reachable; each number updates it right to left. The set of reachable sums grows: {0} -> {0,1} -> {0,1,5,6} -> {0,1,5,6,11,12,16,17} -> ...; 11 is reached, so the answer is true.
TRICK

Parity check first: if the total is odd, return false without any DP. A bitset (BitSet or long[] shifts) makes the update bits |= bits << x and the whole DP O(n W / 64).

Counting: Coin Change II (518) and Target Sum (494)

Counting combinations of coins (order does not matter): put the coin loop outside, the amount loop inside, ascending. change(5, [1,2,5]):

Target Sum: with P the sum of the numbers given +, P - (S - P) = target, so P = (S + target) / 2: count subsets with that sum. For [1,1,1,1,1] and target 3, P = 4:

ORDER MATTERS

Loop order changes the answer in counting problems. Coins outer, amount inner counts combinations (518). Amount outer, coins inner counts ordered sequences (Combination Sum IV, 377).

The O(n W) bound is pseudo-polynomial: polynomial in the value of W, exponential in its bit-length. Knapsack is NP-hard in general; the table works when W is small.

import java.util.*;

/** Ch 82: knapsack patterns; LeetCode 416, 518, 494, 1049, 474. */
public class Knapsack {

    /** 0/1 knapsack, full table: dp[i][w] = best value of items < i, capacity w. */
    public static int knapsack01Table(int[] wt, int[] val, int cap) {
        int n = wt.length;
        int[][] dp = new int[n + 1][cap + 1];
        for (int i = 1; i <= n; i++)
            for (int w = 0; w <= cap; w++) {
                dp[i][w] = dp[i - 1][w];                            // skip item i-1
                if (wt[i - 1] <= w)

Java 17+

                    dp[i][w] =
                            Math.max(dp[i][w],
                                    val[i - 1] + dp[i - 1][w - wt[i - 1]]);
            }
        return dp[n][cap];
    }

    /** 0/1 knapsack in one row: capacities descend so each item is used once. */
    public static int knapsack01(int[] wt, int[] val, int cap) {
        int[] dp = new int[cap + 1];
        for (int i = 0; i < wt.length; i++)
            for (int w = cap; w >= wt[i]; w--)
                dp[w] = Math.max(dp[w], val[i] + dp[w - wt[i]]);
        return dp[cap];
    }

    /** Unbounded knapsack: capacities ascend so an item may be reused. */
    public static int unboundedKnapsack(int[] wt, int[] val, int cap) {
        int[] dp = new int[cap + 1];
        for (int i = 0; i < wt.length; i++)
            for (int w = wt[i]; w <= cap; w++)
                dp[w] = Math.max(dp[w], val[i] + dp[w - wt[i]]);
        return dp[cap];
    }

    /** Subset sum over non-negative integers: is there a subset summing to t? */
    public static boolean subsetSum(int[] nums, int target) {
        if (target < 0) return false;
        boolean[] dp = new boolean[target + 1];
        dp[0] = true;
        for (int x : nums)
            for (int s = target; s >= x; s--) dp[s] |= dp[s - x];
        return dp[target];
    }

    /** LeetCode 416: can nums be split into two subsets of equal sum? */
    public static boolean canPartition(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;
        return total % 2 == 0 && subsetSum(nums, total / 2);
    }

    /** LeetCode 518: number of coin multisets (order ignored) making amount. */
    public static int change(int amount, int[] coins) {
        int[] dp = new int[amount + 1];
        dp[0] = 1;
        for (int c : coins)                         // coins outer: combinations
            for (int a = c; a <= amount; a++) dp[a] += dp[a - c];
        return dp[amount];
    }

    /**
     * LeetCode 494: assign + or - to every number so the total is target.
     * P - N = target and P + N = total, so count subsets with sum (total+target)/2.
     */
    public static int targetSumWays(int[] nums, int target) {
        int total = 0;
        for (int x : nums) total += x;
        if (Math.abs(target) > total || (total + target) % 2 != 0) return 0;
        int s = (total + target) / 2;
        int[] dp = new int[s + 1];
        dp[0] = 1;
        for (int x : nums)
            for (int j = s; j >= x; j--) dp[j] += dp[j - x];
        return dp[s];
    }

    /**
     * LeetCode 1049: smash stones; minimise the last stone = partition difference.
     */
    public static int lastStoneWeightII(int[] stones) {
        int total = 0;
        for (int x : stones) total += x;
        int half = total / 2;
        boolean[] dp = new boolean[half + 1];
        dp[0] = true;
        for (int x : stones)
            for (int s = half; s >= x; s--) dp[s] |= dp[s - x];
        for (int s = half; s >= 0; s--) if (dp[s]) return total - 2 * s;
        return total;
    }

    /**
     * LeetCode 474: largest subset of binary strings with <= m zeros, <= n ones.
     */
    public static int findMaxForm(String[] strs, int m, int n) {
        int[][] dp = new int[m + 1][n + 1];
        for (String s : strs) {
            int zeros = 0, ones = 0;
            for (char ch : s.toCharArray()) if (ch == '0') zeros++; else ones++;
            for (int a = m; a >= zeros; a--)
                for (int b = n; b >= ones; b--)
                    dp[a][b] = Math.max(dp[a][b], 1 + dp[a - zeros][b - ones]);
        }
        return dp[m][n];
    }
}

TIME O(n * W)

SPACE O(W)

Every variant is O(items x capacity) time with a single capacity array (two for Ones and Zeroes, giving O(L m n) time and O(m n) space). The explicit table version knapsack01Table keeps O(n W) space for reconstruction.

F. Detailed Dry Run

canPartition([1,5,11,5]): total 22, target 11. reach = {0}. After 1: {0,1}. After 5: {0,1,5,6}. After 11: {0,1,5,6,11,12,16,17} and 11 is present, so true (subset {11}; the rest sums to 11 as well).

lastStoneWeightII([2,7,4,1,8,1]): total 23. Smashing stones is equivalent to choosing a subset S and leaving |total - 2 sum(S)|. The largest reachable subset sum not exceeding 11 is 11, giving 23 - 22 = 1.

G. Variations of the Pattern

Minimise the difference

Last Stone Weight II (1049) and Partition into Two with Minimum Difference: find the achievable sum closest to total / 2.

Count with signs

Target Sum (494): count subsets summing to (S + target) / 2; return 0 if that value is negative or not an integer.

Unbounded minimisation and counting

Coin Change (min coins), Coin Change II (combinations), Perfect Squares, Rod Cutting: the capacity loop runs upwards.

Two-dimensional capacity

Ones and Zeroes (474): dp[z][o] is the largest subset size using at most z zeros and o ones; both loops run downwards for each string.

Bounded knapsack and grouping

Items with a count limit are split into powers of two (binary splitting) to become 0/1 items; items in groups (pick at most one per group) add an outer loop over groups.

J. Interview Tips

INTERVIEW

Recognise it quickly: a target sum and a list of numbers is knapsack; say "pseudo-polynomial, O(n * target)".

Explain the loop direction in one sentence ("downwards so each item is used once"). It is the most common follow-up.

Derive the reduction for Target Sum (P = (S + target) / 2) on the board; it is the insight interviewers want.

Follow-ups: recover the chosen items; reduce to a bitset; very large W with small n (meet in the middle); count distinct multisets.
Edge cases: empty list, target 0, zero-valued items, single item bigger than the capacity,

negative numbers (shift or split).

CHAPTER SUMMARY

Knapsack = items x budget. The 1D array has the budget as its index.

Downward capacity loop = each item once (0/1); upward = unlimited use.

Subset sum is boolean, counting adds, Target Sum reduces to counting subsets with sum (S + target) / 2.

Loop order changes counting answers: coins outer counts combinations, amount outer counts sequences.

O(n W) is pseudo-polynomial; use a bitset or meet in the middle when numbers are large.
