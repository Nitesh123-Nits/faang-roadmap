Media Processing Pipeline

Transcoding & packaging at scale

Functional Requirements
Accept uploads and register processing jobs
Probe and validate source media
Transcode to a bitrate ladder in parallel chunks
Thumbnails, sprites, captions, audio normalisation
Package for HLS / DASH with DRM
Priority lanes (live-to-VOD, premium, bulk)
Retry, resume and monitor jobs
Non-Functional Requirements
Throughput: 500K hours/day, elastic scale
Latency: 1 h video ready in < 15 min via parallel chunks
Reliability: at-least-once tasks, idempotent outputs
Cost: spot / preemptible instances, right-size encoding
Resilience: resume from last completed chunk
Observability: per-stage metrics and traces
Isolation: priority lanes and tenant quotas

Key design trade-offs

Chunk-parallel (fast) vs whole-file (simple, quality-consistent)

Workflow engine (state, retries) vs queue + cron

Spot (cheap, interruptions) vs on-demand

GPU (fast, costly) vs CPU (cheap, flexible)

Scaling & Failure Handling

R
Spot interruption: tasks leased with heartbeat; expired lease re-queues only that chunk
Orchestrator crash: durable workflow state resumes at last completed activity
Poison media: QC stage rejects corrupt files early; capped retries then deadletter with report
Backlogs: priority lanes and tenant quotas keep premium jobs flowing
