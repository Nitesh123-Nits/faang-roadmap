Hotel Booking System

Booking.com / Airbnb style

Functional Requirements
Search hotels by location, dates, guests, filters
View hotel details, photos, rooms and rates
Check live availability and price
Book a room (hold, pay, confirm)
Modify and cancel bookings with policy
Reviews and ratings
Sync inventory with hotels / channel managers
Non-Functional Requirements
Correctness: no overbooking beyond allowed overbook rate
Latency: search p99 < 500 ms
Availability: search 99.99%; booking 99.9%
Consistency: strong on inventory writes, eventual search
Scalability: read-heavy (100:1), seasonal peaks
Freshness: rate / availability changes in search within minutes
Durability: confirmed bookings never lost

Key design trade-offs

Search index (fast, slightly stale) vs live inventory query

Short hold during payment vs book-then-pay

Row lock per night (safe) vs counter with check (fast)

Allow small overbooking (revenue) vs strict

Scaling & Failure Handling

R
Search staleness: search shows approximate availability; the booking step always re-checks the Inventory DB
Double booking: transactional nightly decrement with CHECK constraint; idempotent confirm
Channel conflicts: external bookings consume the same inventory rows; overbook buffer per hotel
Seasonal peaks: cache availability, scale search nodes; throttle booking writes per hotel
