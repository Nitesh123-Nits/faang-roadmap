Functional Requirements
Create buckets and manage access policies
Upload, download and delete objects
Multipart upload for large files
Object versioning
Pre-signed URLs for temporary access
Lifecycle rules (expire, move to cold tier)
List objects by prefix with pagination
Non-Functional Requirements
Durability: 99.999999999% via erasure coding across AZs
Availability: 99.99% for reads and writes
Scalability: exabyte scale, add nodes online
Throughput: large sequential streams, parallel parts
Consistency: strong read-after-write per object
Security: encryption at rest and in transit, IAM
Cost: erasure coding (1.5x) instead of 3x copies

Key design trade-offs

Erasure coding (1.5x cost) vs 3x replication (faster repair)

Separate metadata plane vs co-located

Strong consistency (simple apps) vs eventual (cheaper)

Large chunks (throughput) vs small (flexibility)

Scaling &amp; Failure Handling
Durability: erasure coding across 3 AZs; checksums on write, read and periodic scrub
Node failure: Repair Worker rebuilds missing chunks from parity within minutes
Scale: metadata sharded by bucket + key hash; data nodes added without moving metadata
Hot objects: CDN absorbs popular reads; large uploads use parallel multipart
