Workflow Orchestration

Temporal / Cadence style

Functional Requirements
Define workflows as code (deterministic)
Durable timers, retries and timeouts
Activities with retry policies
Signals, queries and child workflows
Task queues and worker routing
Versioning of running workflows
Search, visibility and history inspection
Non-Functional Requirements
Durability: every state change persisted before ack
Exactly-once semantics: via event history replay, idempotent activities
Scalability: shard workflows by id, add History nodes
Latency: task dispatch < 50 ms
Availability: 99.99%, no lost workflows
Long-running: workflows sleep for months at no worker cost
Isolation: namespaces and quotas per team

Scaling &amp; Failure Handling
Worker crash: task times out and is re-dispatched; new worker replays history and continues
History node loss: shard ownership moves via membership ring; state reloaded from Cassandra
Non-determinism bugs: versioning APIs and replay tests before deploying workflow changes
Hot workflows: per-workflow rate limits and signal batching
