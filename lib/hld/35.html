Food Delivery System

Swiggy / DoorDash style

Functional Requirements
Browse nearby restaurants and menus
Place order with payment
Assign nearest suitable rider
Live order tracking with ETA
Restaurant accepts / rejects, marks ready
Ratings and reviews
Promotions and surge fees
Non-Functional Requirements
Latency: restaurant search < 300 ms; assignment < 3 s
Availability: 99.99% for ordering
Throughput: dinner peak 10x average
Real-time: rider location every 4 s
Consistency: strong for order state, eventual for tracking
Reliability: reassign if rider or restaurant fails
Cost: batch dispatch decisions

Scaling &amp; Failure Handling
Rider rejects / drops: offer timeout then next candidate; assigned orders are reassigned if heartbeats stop
Dinner peak: Kafka absorbs order bursts; dispatch batches decisions every few seconds
Redis loss: rebuild rider index from the next pings within seconds; orders unaffected
Restaurant outage: auto-pause and refund path; menu cache falls back to last known
