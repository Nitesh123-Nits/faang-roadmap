Configuration Management

Centralised dynamic config

Functional Requirements
Store configuration per app, environment, cluster
Versioned changes with history and rollback
Push updates to running instances (watch)
Gray / percentage releases and targeting rules
Typed validation with schemas
Secrets stored encrypted and scoped
Audit every change; RBAC and approvals
Non-Functional Requirements
Availability: reads survive config-server outage (local cache)
Consistency: linearizable writes (Raft), monotonic versions
Latency: propagation < 5 s to 200K instances
Scalability: 200K watchers via gateway fan-out
Safety: gray rollout and instant rollback
Security: encrypted secrets, RBAC, signed changes
Durability: Raft + snapshots

Key design trade-offs

Push (fast) + poll fallback vs poll only (simple)

CP store (consistent) vs AP (always writable)

Local cache on disk (survive outage) vs strict freshness

Config in Git (review) vs live DB (speed)

Scaling &amp; Failure Handling
Server outage: instances run on local disk cache; reads from replicas; writes pause only if Raft quorum lost
Bad config: schema validation, gray release by percentage, automatic rollback on error-rate guard
Thundering herd: jittered polls; Watch Gateway tier absorbs 200K streams
Security: secrets envelope-encrypted; access audited
