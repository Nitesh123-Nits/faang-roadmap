Functional Requirements
Create orders from checkout
Order state machine (placed, paid, packed, shipped, delivered)
Cancel, return and refund flows
Orchestrate inventory, payment and shipping steps
Order history and search for customers and support
Notifications on state changes
Idempotent order creation

Consistency: no lost or duplicate orders; sagas converge

Latency: create p99 < 500 ms (sync part)
Scalability: 10x seasonal peaks
Auditability: full state-transition history
Resilience: steps retried; compensations on failure
Observability: trace per order across services

Scaling & Failure Handling R

Orchestrator crash: workflow state durable; saga resumes at the failed step (idempotent steps)
Lost events: outbox written in the same transaction as the order; relay retries until published
Partial failure: compensations run in reverse; stuck orders surfaced on an ops dashboard
Duplicates: idempotency key on create; consumers dedupe by event_id
