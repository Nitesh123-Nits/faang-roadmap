URL Shortener

TinyURL / Bitly

Functional Requirements
Create a short URL from a long URL
Redirect a short URL to the original URL
Support custom aliases
Support link expiration (TTL)
Track click analytics (count, geo, referrer)
Disable / delete a link
Manage links per user via API key
Non-Functional Requirements
Availability: 99.99% for redirects, so AP over strict C
Latency: redirect p99 < 50 ms (cache hit < 10 ms)
Scalability: read-heavy (100:1), horizontally scalable
Durability: a mapping is never lost (RF=3 + backups)
Uniqueness: no short-code collisions
Consistency: strong on create, eventual for analytics
Security: rate-limit creates, URL blocklist, authN on manage APIs

Scaling &amp; Failure Handling
Scale reads: Redis in front of the store; 95%+ of redirects never reach the database
Scale writes: shard the URL Store by hash(short_code); KGS leases ranges, no hot counter
Replication: RF=3 across AZs; quorum writes, local-quorum reads
Failure: Redis loss only raises latency; KGS node loss wastes at most one range; Kafka buffers analytics
