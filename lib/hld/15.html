Pastebin

Text sharing service

Functional Requirements
Create a paste (text / code) and get a unique URL
View a paste by URL
Optional expiry (10 min to never)
Public, unlisted and private visibility
Syntax highlighting metadata (language)
Delete own paste
Per-user paste history (optional login)
Non-Functional Requirements
Availability: 99.9% for reads
Latency: read p99 < 100 ms
Durability: content never lost before expiry
Scalability: read-heavy, hot pastes cached
Uniqueness: unguessable, collision-free IDs
Limits: max paste size 10 MB, rate limited
Security: private pastes authenticated, abuse scanning

Key design trade-offs

Blob in S3 + metadata in DB vs all in DB

CDN for public pastes vs strict private access

Lazy expiry on read + background cleanup

Create

Client → Gateway → Paste Service → take key from KGS → content to S3 → metadata to DB

Read

Client → CDN / Redis hit, else Metadata DB + S3 → return content

Expiry

Expiry Worker scans by expires_at → deletes blob + metadata → returns key to pool

Content is stored in S3; the DB keeps only metadata (key, S3 path, expiry), so the DB stays small.

Scaling &amp; Failure Handling
Key service: each Paste node caches a batch of keys, so KGS downtime does not stop creates immediately
Durability: S3 11-nines storage; metadata RF=3 across AZs
Hot pastes: CDN and Redis absorb viral content; negative caching for missing keys
Abuse: rate limits, content scanning for malware and spam, size caps
