Flash Sale System

Limited-stock, high-burst sales

Functional Requirements
Show sale page and countdown (static, CDN)
Admit users fairly through a waiting room
Reserve limited stock atomically
One purchase per user (limit enforcement)
Create orders asynchronously
Pay within a time window or release stock
Bot and abuse protection
Non-Functional Requirements
Correctness: never oversell; per-user limit enforced
Throughput: 500K RPS burst for minutes
Latency: accept / reject decision < 100 ms
Availability: core system stays up, excess load rejected early
Fairness: FIFO admission, bot filtering
Isolation: sale traffic cannot hurt the main store
Consistency: strong on stock, eventual on orders

Scaling &amp; Failure Handling
Overload: CDN and waiting room absorb the surge; excess requests get a fast static "queue" or sold-out response
Redis failure: stock counters rebuilt from DB; sale paused until restored (fail closed, never oversell)
Stuck orders: unpaid reservations expire after 10 min and return stock
Isolation: dedicated cluster and quotas so the sale cannot affect the main store
