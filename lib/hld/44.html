Live Streaming Platform

Twitch / YouTube Live style

Functional Requirements
Streamers broadcast via RTMP / SRT
Viewers watch live with adaptive bitrate
Live chat with moderation
Stream discovery: live list, categories
Follow / subscribe / notifications
VOD recording and clips
Monetisation hooks (subs, bits, ads)
Non-Functional Requirements
Latency: glass-to-glass 2-5 s (low-latency HLS)
Availability: 99.99% for playback
Scalability: celebrity streams with 1M+ viewers
Resilience: ingest failover without dropping stream
Chat: 100K messages/s in a single room, moderated
Cost: transcode only top channels at full ladder
Consistency: eventual for stats, strict for entitlements

LL-HLS (CDN scalable, 2-5 s) vs WebRTC (sub-second, costly)

Transcode all channels vs only popular ones

Chat via Redis fan-out vs Kafka (durability)

Server-side ad insertion vs client-side

Scaling & Failure Handling R

Ingest failure: streamer reconnects to backup ingest (dual ingest); transcoder resumes from keyframe
Viral streams: CDN absorbs viewers; origin shield protects origin; chat rate limits and sampling for huge rooms
Transcoder capacity: full ladder only for top channels; others get passthrough + 1-2 renditions
Chat abuse: slow mode, shadow bans, automated filters before fan-out
