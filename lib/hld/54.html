Functional Requirements
Register and deregister service instances
Health checking with automatic removal
Lookup healthy endpoints by service name
Watch for endpoint changes (push)
Metadata: tags, zone, weight, version
DNS and API interfaces
Multi-datacenter service lookup
Non-Functional Requirements
Detection: failed instance removed in < 5 s
Availability: lookups survive registry outage (client cache)
Latency: endpoint lookup < 5 ms (local)
Scalability: 100K instances, 200K lookups/s
Consistency: AP preferred for reads, CP for registration
Safety: avoid mass deregistration on network partition
Operations: rolling upgrades, multi-DC

Scaling &amp; Failure Handling
Registry outage: consumers continue with cached endpoints and passive health ejection
Network partition: self-preservation stops mass eviction; CP writes pause on the minority side
Flapping instances: health check hysteresis (N failures to remove, M passes to add)
Stale endpoints: short DNS TTLs and push updates; clients retry on connect failure
