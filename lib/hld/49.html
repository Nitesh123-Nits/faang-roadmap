Log Aggregation System

ELK-style centralized logging

Functional Requirements
Collect logs from every service and host
Parse, enrich and normalise (JSON, trace ids)
Full-text and field search with time ranges
Dashboards, saved searches, live tail
Alerts on log patterns
Retention tiers: hot, warm, cold archive
Access control per team / tenant
Non-Functional Requirements
Ingest: 1M lines/s sustained, bursts 5x
Freshness: searchable in < 5 s
Availability: ingestion never blocks apps (buffering)
Loss: at-least-once, rare duplicates acceptable
Query: p95 < 3 s on recent data
Cost: tiering and sampling of debug logs
Security: PII scrubbing, RBAC, audit

Scaling &amp; Failure Handling
Search cluster slow / down: Kafka buffers (3 days); parsers back off and resume; no log loss
Agent restart: offset checkpoints on disk give at-least-once without gaps
Cost control: per-service quotas, sampling, aggressive tiering; drop DEBUG in production by default
Bad logs: parse failures go to a DLQ rather than blocking the pipeline
