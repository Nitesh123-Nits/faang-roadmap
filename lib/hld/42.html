Image Hosting Service

Imgur / Flickr style

Functional Requirements
Upload images (JPEG, PNG, WebP, GIF)
View images at multiple sizes via URL
Albums, tags, public / private visibility
Delete and replace images
Automatic thumbnails and format conversion
Basic content moderation
Per-user quotas and rate limits
Non-Functional Requirements
Latency: image load < 100 ms from CDN
Availability: 99.99% for reads
Durability: 11 nines for originals (S3)
Scalability: read-heavy 100:1, hot images cached
Cost: lifecycle old variants to cold, serve WebP / AVIF
Security: signed URLs for private images, size and type validation
Upload: resumable direct-to-S3

Key design trade-offs

Pre-generate sizes (fast, more storage) vs lazy resize

Direct S3 upload (offload) vs proxy through API

WebP / AVIF (small) vs JPEG compatibility

Content-hash dedupe (saving) vs per-user copies

Scaling &amp; Failure Handling
Processor lag: originals are safe in S3; the page shows a placeholder until variants are READY
Cache stampede: request coalescing at CDN and Delivery Service for lazy resizes
Abuse: size / type limits, rate limits, moderation, takedown purges CDN keys
Cost: lifecycle rules move cold variants to infrequent access tier
