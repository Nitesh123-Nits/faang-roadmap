Distributed ID Generator

Snowflake

Functional Requirements
Generate globally unique 64-bit IDs
IDs are roughly sortable by creation time
High throughput with no coordination per ID
Work across multiple data centres
Extract timestamp and node from an ID
Configurable custom epoch
Serve via library or lightweight service
Non-Functional Requirements
Uniqueness: never issue the same ID twice
Latency: sub-millisecond, local generation
Availability: no single point of failure
Throughput: 4,096 IDs per ms per worker
Ordering: monotonic per worker, k-sorted globally
Compactness: fits a 64-bit BIGINT
Clock safety: detect and survive clock skew

Generate Id

Clock Safety

NTP keeps clocks in sync; if clock goes backwards the worker waits and raises an alert

ID = 1 bit sign | 41 bits timestamp (ms) | 5 bits datacenter | 5 bits worker | 12 bits sequence

If the clock moves backwards the worker refuses to issue IDs until time catches up, and alerts.

No central bottleneck: IDs are generated locally; the registry is used only at startup
Failure: any generator can die, LB routes around it; its worker ID lease expires and is reused
Clock skew: persist last timestamp, refuse to go backwards, alert on drift above a few ms
Capacity: sequence overflow in a ms waits for the next ms; add workers to scale
