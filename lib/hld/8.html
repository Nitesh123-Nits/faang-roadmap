API Gateway

Single entry point

Functional Requirements
Route requests to backend services
Authenticate and authorize (JWT / OAuth2 / API keys)
Rate limiting and quotas per client
Request and response transformation
Protocol translation (REST to gRPC)
Response caching and aggregation
Canary, blue-green and versioned routing
Logging, metrics and distributed tracing
Non-Functional Requirements
Latency: adds < 10 ms p99 to each call
Availability: 99.99%, stateless nodes behind an LB
Scalability: scale gateways horizontally
Resilience: timeouts, retries, circuit breakers
Security: TLS / mTLS, WAF, token validation
Agility: routes and policies hot-reload
Observability: every request traced and logged

Key design trade-offs

Central gateway (control) vs sidecar mesh (no hop)

Aggregation at gateway (fewer calls) vs BFF (flexibility)

Cache at edge (speed) vs freshness

Plugin chain (flexible) vs latency per plugin

Scaling &amp; Failure Handling
Scale: stateless nodes behind an LB; autoscale on RPS and p99 latency
Failure: per-upstream circuit breaker, timeouts, bulkheads, retry budget
Config safety: versioned routes, canary rollout, instant rollback
Zone loss: nodes spread across 3 AZs with N+2 headroom
