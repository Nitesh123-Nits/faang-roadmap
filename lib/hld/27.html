Functional Requirements
Ingest activity events (likes, comments, follows)
Show a per-user activity feed
Real-time push to online users
Aggregate similar events
Mark read / unread, unread badge counts
Pagination for history
Per-user mute and preference filters
Non-Functional Requirements
Latency: event visible to online users < 1 s
Throughput: 58K events/s, bursts 5x
Availability: 99.99%, feed readable when realtime is down
Consistency: eventual, ordered per user
Durability: events persisted before ack
Scalability: partition by user_id
Efficiency: aggregation reduces noise and storage

Scaling &amp; Failure Handling
Realtime outage: feed still readable from Redis / Cassandra; clients poll as fallback
Bursts: Kafka absorbs spikes; fan-out consumers autoscale on lag
Duplicates: event IDs make writes idempotent; clients dedupe by activity_id
Reconnect: SSE resumes using Last-Event-ID against the recent window
