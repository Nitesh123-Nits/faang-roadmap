Git tags and Semantic Versioning

MAJOR X.0.0 Breaking change: removed endpoint, incompatible event schema (feat! / BREAKING CHANGE)

2.0.0

MINOR 1.X.0 Backward-compatible new feature (feat)

1.5.0

PATCH 1.4.X Backward-compatible bug fix (fix, perf, security)

1.4.1

A bump resets the lower numbers to 0.

Pre-release precedence, lowest to highest:

1.5.0-alpha.1 →

1.5.0-beta.1 →

1.5.0-rc.1 →

1.5.0

Release tag

FORMAT
vMAJOR.MINOR.PATCH
v1.5.0
EXAMPLE
N OT E

The v is a tag convention, not part of SemVer

Pre-release

FORMAT

-alpha.N, -beta.N, -rc.N

EXAMPLE
v1.5.0-rc.1
N OT E

Sorts before the stable release

Build metadata

FORMAT
+build
1.5.0+20261109
EXAMPLE
N OT E

Ignored when comparing versions

Maven development

FORMAT
-SNAPSHOT
1.5.0-SNAPSHOT
EXAMPLE
N OT E

Maven convention; dropped at release

Per-service (monorepo)

FORMAT
service-vX.Y.Z
order-service-v1.5.0
TEAM
EXAMPLE
N OT E

One tag per deployable

Docker / Helm

FORMAT

X.Y.Z (no v)

EXAMPLE
acme/order-service:1.5.0
N OT E

Helm appVersion: "1.5.0"
