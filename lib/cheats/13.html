Git Production Incident Playbook

What to run when a bad commit is live, history is lost, someone force-pushed, or a secret is in the repo. Stop the damage first, find the cause second, clean up last.

Bad commit is live

Prod is broken; the culprit is one pushed commit.

git revert <sha>
git push origin main
# redeploy; investigate afterwards
git bisect start
git bisect bad
git bisect good v1.4.1
git bisect run ./test.sh
git bisect reset

Needs a deterministic test. Skip untestable commits with git bisect skip.

Revert, don't reset. History stays intact and CI/CD can redeploy.

Bad merge is live

Who changed this line, when did this string appear?

Trace a change.

A merged PR broke prod.

git log -S"text" --oneline
git log -G"regex" -p -- path
git log --follow -p -- path
                                                                        git blame -L 40,60 path
git revert -m 1 <merge-sha>

-m 1 keeps the mainline parent. To re-merge the branch later, revert the revert first, or Git skips those changes.

-S finds changes in occurrence count; -G matches diff lines by regex.

Secret was committed

Conflicts keep recurring

Key, token or password is in history.

Same conflict on every rebase.

# 1. revoke and rotate first
git filter-repo \
  --replace-text rules.txt
git push --force --all
git config rerere.enabled true

rerere records and replays your resolutions.

Rotation is the fix. Rewriting history is cleanup; forks and caches may keep the data.

MERGE & REBASE
BIG FILES

Huge file committed

Rebase or merge?

Integrating long-lived work.

Repo bloated, pushes rejected.

git merge --no-ff feature
# linear, local only
git rebase main
                                                                        # keep branch shape
git filter-repo \
  --strip-blobs-bigger-than 10M
# going forward
git lfs track "*.bin"

Rebase only your private branches. Never rebase shared history.

Large binaries belong in LFS or artifact storage.

THE RULE

Revert before you reset, copy before you rewrite, and rotate a leaked secret before you clean the history.
