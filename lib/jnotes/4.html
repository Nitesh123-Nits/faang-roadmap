public final class Employee {
    private final String name;
    private final List<String> skills;

    public Employee(String name, List<String> skills) {
        this.name = name;
        this.skills = List.copyOf(skills);          // defensive copy in
    }

    public String getName() { return name; }
    public List<String> getSkills() { return skills; } // already unmodifiable
}

WHY THE DEFENSIVE COPY MATTERS

Without it, a caller keeps a reference to the original list and can mutate the "immut‐ able" object from outside. The same applies to getters: return a copy or an unmodi‐ fiable view, never the internal collection.

For collections, use List.copyOf() , Set.of() and Map.of() (Java 9+). They return unmodifiable collections and throw UnsupportedOperationException on modifica‐ tion. Collections.unmodifiableList() is only a view: if the original changes, the view changes.

Watch out for mutable fields such as java.util.Date ; prefer LocalDate and

LocalDateTime .

I N T E RV I E W L I N E . Immutable objects are thread-safe by design, easy to cache,

safe as map keys, and predictable to debug. Real examples: String , wrapper classes, BigDecimal , LocalDate , UUID .
