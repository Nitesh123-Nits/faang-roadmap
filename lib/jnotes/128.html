End-to-End Web Request Flow

From a browser to a server and back.

Browser → DNS resolver → Service socket → NIC → Server
#STAGEWHAT HAPPENSGOAL
1BrowserThe user enters a URL; the browser checks its cache; if not found, asks DNSGet the IP and request the page
2DNS resolverReceives the DNS query, looks up the domain, returns the IP (e.g. 93.184.216.34)Resolve domain to IP
3Service socketThe OS creates a socket and connects to IP:port (443); handles the protocol: TCP handshake, TLS handshake for HTTPSEstablish a reliable connection
4NIC (network interface)Converts data into packets, sends them over the network, receives packets back, passes them up to the OSTransmit and receive packets
5Server and componentsPackets arrive at the server NIC; load balancer routes; web server (Nginx/Apache) handles HTTP; application server (Node.js/Java) processes the logic; DB is queried if needed; response generatedProcess the request and return the response

THE RETURN PATH

Server → NIC → service socket → (DNS is not used for the response) → browser. The response data flows back as packets and is assembled into the original page in the browser.
