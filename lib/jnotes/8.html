CHAPTER 05

Interface vs Abstract Class

Both provide abstraction, but they model different things. An interface is a contract: what a class can do. An abstract class is a base: what a class is, with shared state and code.

WHEN TO USE WHICH

Use an interface when you define a capability that unrelated classes can have, ex‐ pect multiple inheritance of type, or want loose coupling. Think CAN DO: Runnable ,

Comparable , Serializable , Payment .

Use an abstract class when related classes share state, constructors or protected members, or when you want default implementations and leave some methods to subclasses. Think IS A: Animal , Employee , AbstractList , InputStream .
