CHAPTER 36

Virtual Threads

Project Loom, Java 21+. Virtual threads make concurrency cheap while keeping the code simple and synchronous.

THE PROBLEM

Modern apps handle thousands of concurrent I/O‐bound requests. Platform threads are expensive, so one thread per request does not scale:

High memory per thread (about 1–2 MB).
Expensive creation and context switching.
Many threads spend most of their time waiting for I/O.

PLATFORM VS VIRTUAL THREADS

ASPECTPLATFORM THREADVIRTUAL THREAD
Managed byOS / JVMJVM
OS thread relationshipUsually 1:1Many virtual : few carrier (M:N)
Creation costHighVery low
Memory footprintLarge (1–2 MB)Small (a few KB)
Millions of threadsNot practicalPossible
Blocking I/OExpensive (blocks an OS thread)Cheap (parks the virtual thread)
Thread pool requiredYes (usually)No (one VT per task)
Best forCPU-bound workHigh-concurrency I/O-bound work

HOW THEY WORK DURING BLOCKING I/O

The virtual thread is running on a carrier thread (a platform thread).
It hits blocking I/O (DB, HTTP). The virtual thread parks.
The carrier thread is released to run another virtual thread.
When the I/O completes, the virtual thread resumes on a carrier.

Blocking a virtual thread does N OT block the underlying carrier thread.
