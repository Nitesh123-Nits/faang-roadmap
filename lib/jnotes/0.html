Java Backend Interview Notes

Rebuilt from the sticky-note cheat sheet collection “Java Backend Interview Sticky Notes”. Content has been reorganised into chapters, tightened, and extended with short explanations where a bullet alone would not carry the idea.

Set in Cormorant Garamond, Source Serif 4, Inter and JetBrains Mono. Three colours throughout: ink, paper and a single terracotta accent.

Verify version-specific behaviour against the current official documentation before relying on it in production.

Read this first

This book is built for the last mile of interview preparation, and for the days after you land the job, when you still need the one-page answer fast.

Every chapter follows the same shape: a short statement of what the thing is, the comparison or flow that matters, a code sample where one helps, and a closing line you can say out loud. Tables are for comparing; code is for recognising; the closing note is for remembering.

HOW THE BOOK IS ORGANISED

Java Foundations. The language and the machine underneath it: strings, copying, ex‐ ceptions, the JVM, class loading, garbage collection and the build.

Functional Java and Collections. Lambdas, streams and collectors, then the collection types you reach for every day and how to choose between them.

Concurrency. From the first thread to virtual threads: locks, CAS, executors, futures, deadlocks and how to keep shared state correct.

Spring and Spring Boot. The container, dependency injection, bean lifecycle, startup, AOP, the MVC request path, and the production features around them.

Security. How a request becomes an authenticated principal, and how JWT makes that stateless.

Data and Transactions. The persistence stack, the N+1 trap, propagation, isolation, locking and connection pools.

Reactive and Networking. Event loops, non‐blocking I/O, and what actually happens between a browser and your server.

Rapid Revision. The original one‐page cheat sheet, kept as the final‐hour read.

HOW TO USE IT

Read a part end to end once. Afterwards, treat it as a reference: open the chapter, scan the table, read the closing note. If you cannot explain a chapter without look‐ ing, read it again, then draw it.
