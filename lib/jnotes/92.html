(OPTIONAL) CONFIGURE THE EXECUTOR
@Configuration
public class AsyncConfig implements AsyncConfigurer {

    @Bean(name = "taskExecutor")
    public ThreadPoolTaskExecutor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(5);
        executor.setMaxPoolSize(20);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("async-exec-");
        executor.initialize();
        return executor;
    }
}

The bean named taskExecutor is picked up by @Async automatically. Use

@Async("otherExecutor") to choose a specific executor.

IMPORTANT

@Async works through a Spring AOP proxy. Calls within the same class (self‐invoc‐ ation) bypass the proxy, so @Async will not be applied.

BEST PRACTICES

Use for I/O‐bound or time‐consuming tasks: emails, file processing, third‐party

calls.

Handle exceptions inside @Async methods. They will not propagate to the caller

(use AsyncUncaughtExceptionHandler for void methods).

Avoid returning void if you need to know the result; return CompletableFuture .
Tune the pool size to the workload; too many async tasks exhaust system re‐

sources.

Use MDC if you need to pass logging context to async threads.
For complex workflows, consider Spring Events, message queues or Project Re‐

actor.
