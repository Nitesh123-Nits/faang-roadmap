if (lock.tryLock(2, TimeUnit.SECONDS)) {

} else {

CONDITIONS

Unlike synchronized , which has one wait set per object, a ReentrantLock can have many conditions, for example notFull and notEmpty on a bounded buffer.

WHEN TO USE IT

Use it when you need timed or interruptible acquisition, fairness, multiple conditions, or non‐blocking attempts. Otherwise synchronized is simpler and safer.

PITFALLS

Forgetting to unlock() in finally leads to deadlock.
Calling unlock() more times than lock() throws IllegalMonitorStateException .
Fair locks have overhead.
Holding a lock for long work reduces concurrency.
Do not mix synchronized and ReentrantLock on the same resource.
