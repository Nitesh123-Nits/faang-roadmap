THE CAS RETRY LOOP

while (true) {
    int oldValue = read();                 // 1. read current value
    int newValue = calculate(oldValue);    // 2. compute the new value
    if (CAS(oldValue, newValue)) break;    // 3. try to swap
    // 4. failed: another thread changed it, so retry
}

This is optimistic concurrency: assume no conflict, detect it, retry.

JAVA EXAMPLE

class LockFreeCounter {
    private final AtomicInteger counter = new AtomicInteger(0);

    public void increment() {
        int current;
        do {
            current = counter.get();
        } while (!counter.compareAndSet(current, current + 1));
    }
}

In practice counter.incrementAndGet() does this for you.

THE ABA PROBLEM

Thread A reads value A. Thread B changes it to B and back to A. Thread A's CAS suc‐ ceeds even though the state changed in between.

Solution: AtomicStampedReference attaches a version stamp: (A,1) → (B,2) → (A,3) ,

so the CAS detects the change.

WHERE CAS IS USED

AtomicInteger , AtomicStampedReference , LongAdder , DoubleAdder , and lock‐free stacks, queues and

AtomicLong ,

AtomicBoolean ,

AtomicReference ,

non‐blocking algorithms.

ONE-LINE ANSWER. CAS is a lock-free optimistic mechanism where a thread

atomically compares the current value with an expected value and updates it only if they match; otherwise the operation fails and the thread retries. Best when contention is low; beware ABA and CPU spinning.
