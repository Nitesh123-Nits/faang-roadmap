WHY STRING IS IMMUTABLE

CHAPTER 02

Why String Is Immutable

Immutability means that once a String exists, its content never changes. Every operation that appears to modify it returns a new object. This is a deliberate design choice with seven payoffs.

#REASONWHY IT MATTERS
1String poolEqual literals share one instance. Mutation would corrupt every reference to it
2SecurityClass names, file paths, URLs and credentials cannot be altered after validation
3Thread safetyNo synchronization needed to share a string across threads
4CachingSafe as HashMap keys and in internal caches
5hashCode consistencyContent never changes, so the hash can be computed once and cached
6Class loading and interningClass names are strings; intern() only works if strings are stable
7SimplicityFewer side effects and fewer bugs

HOW IT IS ACHIEVED

The value is stored in a private final byte[] (since Java 9).
There are no setters or methods that modify content.
Every "modification" such as concat or replace returns a new String .

WRITING YOUR OWN IMMUTABLE CLASS

Declare the class final .
Make all fields private final .
Initialise fields only in the constructor.
Provide no setters.
Return defensive copies of mutable fields.
