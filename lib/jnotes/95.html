@RETRYABLE

EXTERNALISE CONFIGURATION

retry.max-attempts=5
retry.delay=1000
retry.multiplier=2
retry.max-delay=30000
retry.jitter=true
@Retryable(
    maxAttemptsExpression = "${retry.max-attempts}",
    backoff = @Backoff(
        delayExpression = "${retry.delay}",
        multiplierExpression = "${retry.multiplier}",
        maxDelayExpression = "${retry.max-delay}",
        random = true))

SELF-INVOCATION LIMITATION

An internal call bypasses the Spring proxy, so retry will not trigger. Call the @Retryable method through another bean.

WHEN TO USE

USE @RETRYABLE FOR (TRANSIENT FAILURES)DO NOT USE FOR (PERMANENT FAILURES)
External API callsValidation errors
Database deadlocksBusiness rule failures
Transient network issuesBad requests (4xx)
Kafka publish failuresEntity not found
Redis connection timeoutsPermanent failures

KEY TAKEAWAYS

Retry improves reliability but should be used only for transient failures.
Exponential backoff reduces pressure on downstream systems.
Jitter prevents retry storms and distributes load.
Combine with timeouts, circuit breakers and monitoring for full resilience.
