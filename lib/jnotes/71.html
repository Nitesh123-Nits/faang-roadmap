EXAMPLE

@Component
public class DemoBean implements InitializingBean, DisposableBean, BeanNameAware {

    public DemoBean() { System.out.println("1. Constructor"); }

    @Autowired
    public void setDep(Dependency d) { System.out.println("2. DI: setter"); }

    @Override public void setBeanName(String name) { System.out.println("3. Aware: " +
name); }

    @PostConstruct
    public void init() { System.out.println("4. @PostConstruct"); }

    @Override public void afterPropertiesSet() { System.out.println("5.
afterPropertiesSet"); }

    @PreDestroy
    public void preDestroy() { System.out.println("6. @PreDestroy"); }

    @Override public void destroy() { System.out.println("7.
DisposableBean.destroy"); }
}

IMPORTANT NOTES

@PostConstruct runs after dependency injection but before the bean is fully avail‐

able.

A BeanPostProcessor can return a proxy instead of the original bean.
If several initialisation callbacks exist, the order is @PostConstruct →

afterPropertiesSet() → custom init-method .

Only the callbacks that are implemented or configured are called.
Destruction callbacks are called only when the container shuts down properly.
Default scope is singleton: one instance per container.

R E M E M B E R . Spring doesn't just create beans; it manages their lifecycle from

birth (creation) to death (destruction).
