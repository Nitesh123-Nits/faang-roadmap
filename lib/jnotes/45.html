Deadlocks

A deadlock is a situation where two or more threads are permanently blocked, each waiting for a resource held by another.

// Thread T1                         // Thread T2
synchronized (lockA) {               synchronized (lockB) {
    synchronized (lockB) { //. }         synchronized (lockA) { //. }
}                                    }

T1 holds A and waits for B. T2 holds B and waits for A. Neither can proceed.

THE FOUR NECESSARY CONDITIONS (COFFMAN)

All four must hold at once. Break any one and deadlock cannot occur.

#CONDITIONMEANING
1Mutual exclusionAt least one resource is non-shareable
2Hold and waitA thread holds a resource while waiting for another
3No preemptionResources cannot be forcibly taken
4Circular waitA circular chain of threads exists, each waiting on the next

COMMON CAUSES

Inconsistent lock ordering, nested locks, long lock duration (holding locks during I/ O, DB or network calls), too many locks, and waiting on external systems while holding a lock.

HOW TO PREVENT DEADLOCKS

Consistent lock ordering. Always acquire locks in the same global order (A → B
C), never B → A.
Minimise lock scope. Keep critical sections small.
Avoid nested locks. Refactor to reduce dependencies.
Use tryLock() with a timeout. Do not wait forever; back off, retry or fail fast.
