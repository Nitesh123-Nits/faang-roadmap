INTERFACE VS ABSTRACT CLASS
interface Payment {
    void pay(double amount);                       // abstract
    default void info() { System.out.println("Payment Info"); }
    static String getType() { return "Online Payment"; }
}

abstract class Employee {
    protected String name;
    protected double salary;
    Employee(String name, double salary) { this.name = name; this.salary =
salary; }
    void display() { System.out.println(name); }   // concrete
    abstract double calculateSalary();             // abstract
}

CAN INTERFACES REPLACE ABSTRACT CLASSES?

Not fully. Interfaces can provide abstract, default, static and private methods. They cannot provide constructors, instance variables, mutable state, protected members or initialisation logic.

DECISION TREE

Do you need shared state (fields) or constructors? Yes → abstract class.
No. Do you only need a contract or capability? Yes → interface.
Neither fits cleanly? Reconsider the design.

B E S T P R AC T I C E . Prefer interfaces for flexibility and loose coupling. Use ab-

stract classes only when classes genuinely share code and state. Combining both is common: an interface defines the contract, an abstract class supplies

the skeleton ( List and AbstractList ).
