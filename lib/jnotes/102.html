SECURITY CONFIGURATION SNIPPET

@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf /> csrf.disable())
            .sessionManagement(s />
s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth /> auth
                .requestMatchers("/api/auth/**").permitAll()
                .anyRequest().authenticated())
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }
}

TOKEN STORAGE ON THE CLIENT

OPTIONNOTES
Local storageEasy, but exposed to XSS
Session storageCleared with the tab; same XSS exposure
HttpOnly cookieRecommended for web: not readable by JavaScript
MobileSecure storage (Keychain / Keystore)

ADVANTAGES

Stateless (no server‐side session), scalable, cross‐domain and cross‐service, self‐con‐ tained (claims inside the token), secure (digitally signed).

BEST PRACTICES

Use HTTPS always.
Keep tokens short‐lived (use refresh tokens for longevity).
Use a strong secret or key and rotate it.
Store tokens securely on the client.
Validate the token on every request.
Handle expiration gracefully.
