@Primary vs @Qualifier

Both resolve bean ambiguity when multiple beans of the same type exist. Without either, Spring throws NoUniqueBeanDefinitionException .

@Qualifier has higher priority. If both are present, @Qualifier wins.

@PRIMARY

@Service
public class EmailServiceImpl1 implements EmailService {}

@Service
@Primary                         // chosen by default
public class EmailServiceImpl2 implements EmailService {}

@Autowired
private EmailService emailService;     // gets EmailServiceImpl2

@QUALIFIER

@Service("emailService1")
public class EmailServiceImpl1 implements EmailService {}

@Service("emailService2")
public class EmailServiceImpl2 implements EmailService {}

@Autowired
public NotificationService(@Qualifier("emailService1") EmailService emailService) {
    this.emailService = emailService;
}

BEST PRACTICES

Use @Primary for a global default implementation of an interface.
Use @Qualifier for fine‐grained, explicit control.
Use meaningful qualifier names ( "smsService" , "emailService" ).
Do not overuse @Primary ; keep configuration explicit and clear.

IN ONE LINE.

@Primary says "this is my default choice." @Qualifier says "this is

the one I want."
