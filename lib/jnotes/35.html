Evolution of Concurrency

From doing one thing at a time to managing millions of tasks with ease. Each step solved a limit of the one before.

#MODELIDEABEST FOR
1Single threadOne task at a time. Simple and predictable, but a blocking call blocks everythingSimple apps, scripts
2Multi-threadingThreads run in parallel and share memory. Better CPU use, but needs locks and invites race conditionsCPU-bound tasks
3Thread poolsReuse a fixed number of threads; tasks are queued. Limits creation cost and protects the systemServer apps, APIs
4Event loopOne thread handles many operations using non- blocking I/O and callbacksHigh I/O apps (Node.js)
5Async / awaitSyntactic sugar over promises and callbacks; async code that reads synchronouslyModern async code
6Reactive programmingData flows over time as streams; composable, resilient, handles async plus eventsReal-time, streams, UIs
7Virtual threadsLightweight threads managed by the runtime. Millions of threads, blocking-style code, simple mental modelHighly concurrent apps
