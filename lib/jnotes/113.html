TRANSACTION PROPAGATION

NESTED relies on JDBC savepoints and does not work with every JPA provider or

database/driver combination.

@Service
public class OrderService {

    @Transactional                                   // REQUIRED
    public void placeOrder(Order o) {
        orderRepo.save(o);
        auditService.log(o);                         // runs independently, see
below
    }
}

@Service
public class AuditService {

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void log(Order o) {
        auditRepo.save(new Audit(o));                // commits even if
placeOrder() rolls back
    }
}

IMPORTANT NOTES

Propagation does not start or commit transactions by itself. It only defines how

a method participates.

Rollback rules ( @Transactional(rollbackFor = //.) ) still apply. By default, un-

checked exceptions trigger rollback; checked exceptions do not.

REQUIRES_NEW and NOT_SUPPORTED suspend the outer transaction, so ensure the

connection pool is big enough (a suspended transaction still holds its connec‐ tion while a new one is acquired).

Like all Spring proxy features, @Transactional is not applied on self-invocation:

calling another method on this bypasses the proxy.

BEST PRACTICES

Use REQUIRED for business operations.
Use REQUIRES_NEW for audit logs, notifications and outbox events.
Avoid REQUIRES_NEW inside loops (it can exhaust connections).
Keep transactions short and focused.
Handle exceptions properly: unchecked exceptions trigger rollback by default.

R E M E M B E R . Choose the right propagation to ensure data consistency, perform-

ance and proper resource usage. Default = REQUIRED.
