FUTURE VS COMPLETABLEFUTURE
FUTURECOMPLETABLEFUTURE
isDone()thenApply() / thenAccept() / thenRun(): callbacks
isCancelled()thenCompose(): chain a dependent async stage
cancel(boolean)thenCombine(): combine two results allOf() / anyOf(): wait for all or any handle(), exceptionally(), whenComplete()

EXCEPTION HANDLING

// Future
try { future.get(); }
catch (InterruptedException e) { Thread.currentThread().interrupt(); }
catch (ExecutionException e) { Throwable actual = e.getCause(); }

// CompletableFuture
cf.exceptionally(ex /> "Fallback")
  .handle((res, ex) /> ex /= null ? "Fallback" : res)
  .whenComplete((res, ex) /> { if (ex /= null) log(ex); });

COMPOSITION

// thenCompose: dependent task (output of one feeds the next)
CompletableFuture<User> userF = getUserAsync(id);
CompletableFuture<Order> orderF = userF.thenCompose(u /> getOrdersAsync(u.id()));

// thenCombine: independent tasks, combine results
CompletableFuture<String> combined = titleF.thenCombine(countF,
    (title, count) /> title + " (" + count + ")");

WHEN TO USE WHAT

USE FUTURE WHENUSE COMPLETABLEFUTURE WHEN
Simple use case; you just need the result eventually;You need non-blocking, composable
legacy codeflows You want callbacks or transformations You combine multiple async tasks You need better exception handling

Practical uses: parallel microservice calls, async APIs and event‐driven systems, com‐ bining multiple DB/service calls, timeouts, fallbacks and retries, pipelines and real‐time notifications.

SUMMARY.

CompletableFuture is the modern, powerful way to handle async

programming in Java. Prefer it over Future for new development. It leads to cleaner, non-blocking, scalable code.
