CHAPTER 24

20 Must-Know Concurrency Concepts

A one-line glossary you should be able to explain with a drawing.

#CONCEPTMEANING
1ConcurrencyMultiple tasks make progress by taking turns on one CPU
2Concurrency vs parallelismConcurrent = interleaved. Parallel = simultaneous on multiple cores
3Processes vs threadsThreads share memory within a process; processes are isolated
4Thread lifecycleNEW → RUNNABLE → RUNNING → BLOCKED → TERMINATED
5Race conditionUnsynchronised access to shared data leads to incorrect results
6MutexOnly one thread holds the lock at a time; others wait
7SemaphoreAllows N threads to access a resource concurrently
8Condition variableA thread waits on a condition; another thread signals when ready
9Coarse vs fine lockFine-grained locking allows more parallelism but adds complexity
10Reentrant lockThe same thread can acquire its own lock multiple times without blocking itself
11Try-lockAttempt to acquire without blocking; returns immediately
12CASAtomically update a value only if it matches the expected value
13DeadlockTwo threads each hold a lock the other needs; stuck forever
14LivelockThreads keep responding to each other but make no actual progress
15Signaling patternOne thread signals another to wake it when a condition is met
16Thread poolReuse a fixed set of threads to execute many tasks efficiently
17Producer-consumerProducers add to a shared buffer; consumers remove; blocking when full or empty
18Reader-writer lockMany readers concurrently; a writer needs exclusive access
19Thread-safe cacheUse read-write locks so concurrent reads are safe and writes are protected
20Blocking queueProducer blocks when full, consumer blocks when empty; thread- safe
