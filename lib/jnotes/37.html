CHAPTER 25

How synchronized Works Internally

synchronized gives two guarantees: mutual exclusion and memory visibility.

THE MONITOR

Every Java object has an associated monitor, like a lock. It tracks:

Owner: the thread currently holding it.
Entry queue: threads waiting to enter.
Wait set: threads that called wait() .

BYTECODE

synchronized (lock) {
    // critical section
}

compiles to monitorenter , then the critical section, then monitorexit . The JVM en‐ sures monitorexit runs even if an exception occurs.

LOCK ACQUISITION FLOW

A thread wants to enter. Is the monitor available?
Yes: acquire it and run the critical section.
No: wait or block in the entry queue.
On release, one waiting thread acquires the lock.

REENTRANCY

A thread can acquire the same monitor multiple times. The monitor keeps a hold count:

Enter 1st (count 1)

Enter 2nd (count 2)

Exit (count 1)

Exit (count 0, released)
