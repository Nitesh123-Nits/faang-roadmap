CHAPTER 62

The N+1 Query Problem

A performance problem where N additional queries are executed to fetch related data for N records.

Example. Fetch all orders and their items:

List<Order> orders = orderRepository.findAll();   // 1 query

for (Order order : orders) {
    order.getItems();                              // N queries (lazy load per
order)
}

Total = N + 1 queries. Good: one query with a join. Bad: one query for the parents plus one for each child set.

SOLUTIONS

#SOLUTIONHOWWATCH OUT FOR
1JOIN FETCHFetch related data in the same query: select distinct o from Order o left join fetch o.itemsMultiple @OneToMany fetches cause a Cartesian product
2@EntityGraphDeclaratively define what to fetch: @EntityGraph(attributePaths = {"items"})Cleaner alternative; control the fetch plan without JPQL
3Batch fetchingLoad related entities with IN clauses in batches: hibernate.default_batch_fetch_size=50 or @BatchSize(size = 50)Reduces N queries to about N/batch_size; good for large collections
4FetchMode.SUBSE LECTHibernate loads all collections for the parents using a single subselectGreat when you need all collections for a set of parent entities
5DTO projectionFetch only required data: select new com.example.OrderSummary(o.id, c.name) from Order o join o.customer cBest for read-only APIs; less memory
6Use JOIN for filteringLet the database do the filtering, not Java loopsAvoids loading unneeded data
