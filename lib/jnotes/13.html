Class Loader Subsystem

The class loader subsystem prepares Java classes and loads them into memory. It works in three phases: loading, linking, initialisation.

LOADING: THE THREE CLASS LOADERS

BootstrapNone (top of the hierarchy)Core Java library from rt.jar / base modulesjava.lang.String, java.util.*

Loading is delegated upward: a loader asks its parent first, and only loads the class itself if the parent cannot. That is why you cannot replace java.lang.String with your own.

LINKING

Verification. Checks that the bytecode is valid and follows the JVM specification (no illegal memory access, no invalid instructions).
Preparation. Allocates memory for static variables and sets default values.
Resolution. Replaces symbolic references (method calls, field accesses) with direct references.

INITIALISATION

Static variables receive their assigned values, and static blocks ( static { //. } ) run, once, when the class is first used.
