SYNCHRONIZED

Provides mutual exclusion: one lock per object.

Instance method: locks this .
Static method: locks the Class object.
Block: locks the object you name.
synchronized (this) {
    // critical section
}

VOLATILE

Guarantees visibility: no thread‐local caching, always read from main memory.
Does not provide atomicity ( count/+ is still unsafe).
Use for flags, status and configuration: private volatile boolean running = true;

WAIT, NOTIFY, NOTIFYALL

Used inside synchronized blocks to coordinate threads.

METHODEFFECT
wait()Releases the lock and waits
notify()Wakes one waiting thread
notifyAll()Wakes all waiting threads

Rules: call them from a synchronized context; wait() releases the lock; always call wait() in a while loop, not an if , to guard against spurious wakeups.

synchronized (lock) {
    while (!condition) lock.wait();
    // proceed
}

THREAD SAFETY VS RACE CONDITION

Thread-safe: behaves correctly in the presence of multiple threads.
Race condition: the outcome depends on the timing of threads.

count/+ is not atomic; it is three steps: read, increment, write.
