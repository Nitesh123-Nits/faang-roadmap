@Component vs @Bean

Both create Spring-managed beans; they are used in different situations.

@COMPONENT@BEAN
RegistrationAuto-detected during component scanManually registered in a @Configuration class
Applied toA classA method
Best forClasses you ownThird-party or external library classes
ControlLess configurationFull control over object creation: constructor, properties, dependencies
@Component
class EmailService {}

@Configuration
class AppConfig {
    @Bean
    EmailClient emailClient() {
        return new EmailClient();
    }
}

WHICH ONE SHOULD YOU USE?

Do you own the source code? Yes → @Component .
No, or you need custom initialisation → @Bean .

CHEAT SHEET

@Component = automatic registration (via component scanning).
@Bean = manual registration (via a @Configuration class).
@Bean methods in a @Configuration class execute once by default (singleton).
Both become Spring beans managed by the IoC container.
@Service , @Repository and @Controller are specialised forms of @Component .
