THE PAPER IN ONE LINE

Stop trusting wall clocks. Define order by cause and effect, and a simple counter is enough to build a consistent ordering.

IN EVERYDAY TERMS

Three friends in three cities are texting about dinner. Each phone’s clock is a little off, so timestamps can lie. But one fact never lies: a reply always comes after the message it answers. Lamport builds a complete theory of order from that single fact.

THE PROBLEM

On one machine, “which came first?” is easy: look at the order of instructions. Across machines it is not. Every server has its own clock, the clocks drift, and a message can take 2 ms or 2 seconds.

If server A stamps an event 10:00:00.050 and server B stamps another 10:00:00.040 , you still cannot say B was first. B’s clock may simply run fast.

The question

Can we define “happened before” without trusting any clock at all?

travelled from a to b. Three rules define it:

Same machine If a comes before b on one machine, then a → b.
Message Sending a message happens before receiving it.
Chain If a → b and b → c, then a → c.

If neither a → b nor b → a holds, the events are concurrent. That does not mean “at the same moment”. It means no chain of messages connects them, so neither could have influenced the other.

HOW IT WORKS

The logical clock: a counter that respects cause and effect

Keep a counter Every process has one number, starting at 0.
Count every event Before each event, add 1 to your counter.
Attach it to messages When you send a message, include your current counter.
Jump ahead on receive When you receive one, set your counter to max(yours, message) + 1 .

Numbers in circles are clock values. A message forces “send before receive”; events with no message path between them are concurrent.

This guarantees one direction: if a → b then clock(a) < clock(b). To get a single order everyone agrees on, break ties with the process ID: compare (clock, processId) .

What it is good for

Mutual exclusion

Everyone broadcasts timestamped requests. The lowest (timestamp, id) goes first. No central lock server.

Replicated state machines

If every replica applies the same commands in the same order, they stay identical. Paxos and Raft (next chapters) make this fault tolerant.

SAY IT IN AN INTERVIEW

“Lamport clocks give an ordering that respects causality without synchronized clocks. They cannot detect concurrency; vector clocks can, at the cost of O(number of nodes) metadata.”
