per plan (config svc)

Rate limiter. Atomic counters in Redis keyed by client + route, enforced at the gateway.

AspectDesign notes
Key APIsinternal: allow(key, cost) →{allowed, remaining, retryAfter} ; HTTP: 429 + Retry-After , RateLimit-* headers
Data modelRedis hash per key {tokens, ts} with TTL; rules config (plan, route) →(rate, burst)
Algorithmtoken bucket (bursts OK) or sliding‐window counter (smooth); fixed window only for coarse limits
BottlenecksRedis round‐trip per request; hot keys (one big tenant)
Failure modesRedis down →fail‐open (availability) or fail‐closed (protection); local fallback limiter
ScalingRedis Cluster with hash tags; local token pre‐allocation (batch 10 tokens) to cut round‐trips
Trade‐offsprecision vs latency/cost; global vs per‐region limits (per‐region is simpler, slightly over‐admits)
