Images vs Containers; Layers and Caching

ImageContainer
Whatimmutable, layered filesystem + metadata (entrypoint, env, user)a running (or stopped) instance: image + writable layer + namespaces/cgroups
Identitycontent digest sha256:… (tags are movable pointers)container ID
Lifecyclebuild →push →pullcreate →start →stop →rm
EachRUN,COPY,ADDcreates a layer. The build cache is reused until the first changed instruction; everything after is

rebuilt.

Order instructions from least to most frequently changing: base →OS packages →dependency manifest →dependencies

→source code.

Deleting files in a later layer does not shrink the image (they still exist in the earlier layer). Clean up in the same

RUN.

9.2Multi‐stage Build for Spring Boot (Production‐oriented)

Multi-stage build + layered Spring Boot JAR →small,

cache-friendly

image

Layers are cached top-down: put rarely-changing content first so a code change re-uploads only a few hundred KB.

Two stages. Build with a full JDK and Maven cache; ship only a JRE plus the extracted application layers.

DOCKERFILE (SPRING BOOT 3.3+ LAYERED EXTRACTION, BUILDKIT)
# syntax=docker/dockerfile:1
############ build stage ############
FROM eclipse-temurin:21-jdk AS build
WORKDIR /workspace
COPY .mvn/ .mvn/
COPY mvnw pom.xml ./
RUN --mount=type=cache,target=/root/.m2 ./mvnw -B -q dependency:go-offline
COPY src/ src/
RUN --mount=type=cache,target=/root/.m2 ./mvnw -B -q package -DskipTests
# split the fat jar into dependency / loader / snapshot / application layers
RUN java -Djarmode=tools -jar target/*.jar extract --layers --launcher --destination extracted

############ runtime stage ############
FROM eclipse-temurin:21-jre AS runtime
# pin by digest in CI for reproducibility: eclipse-temurin:21-jre@sha256:...
RUN groupadd --system --gid 10001 app && useradd --system --uid 10001 --gid app --no-create-home app
WORKDIR /app
COPY --from=build --chown=app:app /workspace/extracted/dependencies/
COPY --from=build --chown=app:app /workspace/extracted/spring-boot-loader/
COPY --from=build --chown=app:app /workspace/extracted/snapshot-dependencies/ ./
COPY --from=build --chown=app:app /workspace/extracted/application/
USER 10001:10001
EXPOSE 8080
ENV JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError -XX:+HeapDumpOnOutOfMemoryError -
XX:HeapDumpPath=/tmp"
# exec form →java  is PID 1 and receives SIGTERM directly
ENTRYPOINT ["java", "org.springframework.boot.loader.launch.JarLauncher"]
