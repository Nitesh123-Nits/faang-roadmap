R.9 One‐Page Checklist: System Design Interview

Before drawing boxes

Deep dives

☐Clarify users, core use‐cases, ☐Non‐functional: scale, latency, availability, consistency, durability ☐Estimates: QPS (avg/peak), storage/year, bandwidth, cache size ☐APIs for core flows (request/response, idempotency, pagination) ☐Data model: entities, keys, indexes, access patterns, shard key

out‐of‐scope

☐Bottleneck identified and addressed (DB writes, hot keys, fan‐out) ☐Consistency mechanism for the key invariant ☐Failure modes: dependency down, node loss, region loss, duplicates ☐Scaling: partitioning, replication, autoscaling, queues ☐Security: authN/authZ, encryption, abuse/rate limits ☐Observability: metrics, traces, alerts that matter

Wrap‐up

High‐level design

☐Clients →edge (CDN, LB, gateway) →services →stores ☐Read path and write path drawn separately ☐Sync vs async decisions explained ☐Cache placement and invalidation strategy

☐State trade‐offs you made and alternatives rejected ☐Cost and operational complexity ☐How the design evolves at 10× scale
