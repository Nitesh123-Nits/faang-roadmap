10.7Rolling Updates and Rollbacks

CommandPurpose
kubectl set image deploy/orders app=registry.example.com/orders:1.14.3trigger a rollout (prefer GitOps/Helm in practice)
kubectl rollout status deploy/orders --timeout=5mwait for success (CI gate)
kubectl rollout history deploy/ordersrevisions
kubectl rollout undo deploy/orders --to-revision=7roll back to a previous ReplicaSet
kubectl rollout restart deploy/ordersrestart pods gradually (e.g. pick up a new Secret)
kubectl rollout pause/resume deploy/ordersbatch several changes into one rollout

Progressive delivery (canary, blue‐green, automated analysis) →Argo Rollouts or Flagger. Database migrations must be backward compatible — during a rollout old and new pods run together.
