CHAPTER VI

Retrieval, Agents & Tools

How language models are wired into larger applications — the part of the field that looks most like the systems an engineer already builds.

No. 39

RAG (Retrieval-Augmented Generation)

A pattern where relevant documents are fetched from an external store at query time and inserted into the prompt, grounding the model's answer in facts it wasn't trained on.

ENGINEER’S NOTE

architecturally, this is very like a cache-aside or read-through pattern, but the "cache" is a semantic index and the "reader" is the LLM.

No. 40

Vector Database

A database purpose-built to store embeddings and perform fast similarity search over them (e.g. Pinecone, Milvus, pgvector) — the retrieval half of RAG.

No. 41

Semantic Search

Search by meaning rather than exact keyword match, achieved by comparing the embedding of a query against embeddings of candidate documents.

No. 42

Function Calling / Tool Use

A capability letting a model emit a structured request to invoke an external function or API, with the result returned to it for further reasoning — the bridge between an LLM and your codebase.

No. 43

Agent

A system that uses an LLM in a loop — planning, calling tools, observing results, and iterating — to pursue a goal across multiple steps rather than answering in one shot.

No. 44

MCP (Model Context Protocol)

An open protocol standardizing how applications expose data sources and tools to LLMs, so a model can connect to many services through one consistent interface.
