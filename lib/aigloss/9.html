CHAPTER VIII

Engineering & Deployment

The operational vocabulary of putting a trained model into production — the terrain most familiar to a backend engineer.

No. 49

Model Serving / Inference Endpoint

The runtime infrastructure that loads a trained model and exposes it behind an API for real-time or batch predictions — conceptually your familiar service layer, but GPU-bound.

No. 50

Latency & Throughput

Latency is time-to-first-token or time-to-full-response for one request; throughput is how many requests or tokens the system serves per second — the same trade-offs you already tune for any API.

No. 51

Quantization

Reducing the numeric precision of a model's weights (e.g. 32-bit to 4-bit) to shrink memory footprint and speed up inference, usually at a small cost in accuracy.

No. 52

LoRA / PEFT

Parameter-Efficient Fine-Tuning methods (Low-Rank Adaptation being the most common) that adapt a large model by training only a small set of additional weights, dramatically cutting cost.

No. 53

Model Distillation

Training a smaller "student" model to mimic a larger "teacher" model's outputs, yielding a lighter model that retains much of the teacher's capability.

No. 54

GPU / TPU & VRAM

Specialized processors (Graphics/Tensor Processing Units) built for the parallel matrix math of neural networks; VRAM is their onboard memory, which typically caps how large a model you can load.

No. 55

Streaming Response

Returning generated tokens to the client incrementally as they're produced, rather than waiting for the full output — much like chunked HTTP responses, and essential for perceived responsiveness.
