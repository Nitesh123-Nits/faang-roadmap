Crowd-sourced, end-to-end encrypted location tracking over Bluetooth.

DEEP DIVE

An AirTag has no GPS and no internet connection. It is a tiny Bluetooth Low Energy beacon that relies on other people's devices to carry its location to the cloud. The design goal is that Apple can relay the data but cannot read it.

The protocol in outline

When the owner pairs the tag, a key pair is generated and the private key stays with the

owner's devices.

The tag broadcasts a public key over BLE, a few times per second. The advertised key

rotates on a schedule, so a passive observer cannot follow one tag forever.

Any nearby participating device hears the broadcast, gets its own location, and encrypts

that location with the broadcast public key.

It uploads the encrypted blob, indexed by a value derived from the public key, over

HTTPS.

The owner's device derives the same lookup values, fetches the blobs, and decrypts

them with the private key.

Design lessons

Public-key encryption makes the relay blind. The finder's phone can encrypt but never decrypt.
Rotating identifiers trade lookup convenience for privacy.
Low-power budgets shape everything: no GPS, tiny payloads, infrequent advertising.
Abuse is part of the design. Anti-stalking alerts exist because a tracker that follows you is a threat model, not an edge case.
TA K E AWAY

When a system must be reachable but not trusted with data, encrypt at the edge to a key the server never holds, and make identifiers unlinkable over time.
