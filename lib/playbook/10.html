Sharding strategies

Range — ordered, good for scans, prone to hot ranges.
Hash — even spread, no range scans.
Consistent hashing — adding or removing a node moves only about 1/N of keys; virtual nodes smooth load.
Directory — flexible, but a new dependency.

Consistency spectrum Linearizable (behaves like one copy) → sequential → causal → read-your-writes / monotonic reads → eventual. Stronger guarantees cost latency and availability. CAP says that during a network partition you must choose consistency or availability; PACELC adds that even without a partition you trade latency for consistency.

Indexes: B-tree vs LSM

B-TREE (POSTGRES, MYSQL INNODB)LSM-TREE (CASSANDRA, ROCKSDB)
WritesIn-place page updatesSequential appends, later compaction
ReadsPredictable, one lookup pathMay check several levels (Bloom filters help)
Best forRead-heavy, range queriesWrite-heavy, ingest

Rule of thumb: replicate first, shard last; every shard multiplies operational work.
