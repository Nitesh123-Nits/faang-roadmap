How DNS Works

THE IDEA

A hierarchy of caches and delegations that turns names into addresses.

REMEMBER

DEEP DIVE

The Domain Name System is a distributed, hierarchical database. No single server knows everything; each knows whom to ask next, and almost every answer is cached.

A lookup for api.example.com

The browser and operating system check their caches.
On a miss, the stub resolver asks a recursive resolver (your ISP, or 1.1.1.1 / 8.8.8.8),

which checks its own cache.

The resolver asks a root server, which answers with the servers for the .com TLD.
The TLD server answers with the authoritative name servers for example.com .
The authoritative server returns the record. The resolver caches it for the record's TTL

and returns it to the client.

Why architects care

TTL is your failover speed. A 24-hour TTL means a bad record lingers; use 30–300 s for records you may change.
DNS as a load balancer. Round-robin, weighted, latency-based and geo routing (Route
steer traffic across regions, but clients cache, so it is coarse.
Anycast lets many servers share one IP, so resolvers and CDNs reach the nearest one.
JVM caching. The JVM can cache DNS results ( networkaddress.cache.ttl ); in cloud environments set a short value or endpoint changes will be ignored.

Failure story: many big outages start with DNS, so review record changes like code.
