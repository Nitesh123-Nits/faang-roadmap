DEEP DIVE

Scanning every driver for each request is impossible. A geospatial index turns “who is near here?” into a few key lookups.

H3: hexagonal hierarchical index

Uber's open-source H3 divides the globe into hexagonal cells at 16 resolutions. Each cell has a 64-bit id.
Hexagons have equidistant neighbours, so “within k rings” approximates a circle well, avoiding the corner-versus-edge distortions of squares.
Each cell has a parent and children, so you can coarsen or refine resolution cheaply (bit operations on the id).
Search = compute the rider's cell, take its gridDisk(k) neighbours, and read the drivers in those cells.

Operating it

Drivers update location every few seconds. Keep live positions in memory (Redis or a stateful service) with a short TTL, not in the primary DB.
Shard by cell id, with a consistent hash ring so cells can move between nodes.
Pick resolution per use case: finer for dense cities, coarser for rural.

Takeaway: turn a 2D proximity problem into a 1D key lookup.
