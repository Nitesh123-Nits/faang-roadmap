Scaling stateful connections

A WebSocket pins a client to one server, so you need a way to find it. Keep a connection registry (user id → node) in Redis, or broadcast through a pub/sub backbone (Redis, Kafka, NATS) that every node subscribes to.
Sticky sessions help the handshake, but never rely on them for correctness.
Expect clients to drop. Use heartbeats, reconnect with exponential backoff and jitter, and sequence numbers so a client can resume from the last event it saw.
Keep per-connection memory small; one node can hold hundreds of thousands of idle connections if tuned (file descriptors, buffers).
IN SPRING

Spring MVC supports SseEmitter ; Spring WebFlux returns Flux<ServerSentEvent> and scales idle connections better on few threads. For WebSocket use STOMP over a broker relay (RabbitMQ) or a plain handler for custom protocols. Default to SSE when you only push server to client.
