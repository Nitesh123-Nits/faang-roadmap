Where do service boundaries actually go?

MONOLITH
MICROSERVICES

Monolith complexity lives inside the app.

Microservices move it to the network, data, operations and organization.

KEY CHALLENGES
Identifying correct service boundaries
Avoiding circular dependencies
Avoiding overly large services
Sync vs async communication decisions
Avoiding overly small services / nanoservices
Defining ownership of functionality
Managing cross-cutting concerns
Defining bounded contexts
Versioning service contracts
Managing service dependencies
Preventing a distributed monolith

Classic failure: Order → Payment → Inventory → User → Shipping, all called synchronously per request. That's not microservices. It's a distributed monolith with extra network hops.
