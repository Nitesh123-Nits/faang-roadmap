Strong Consistency vs Eventual Consistency

Choose between always reading the latest committed value and accepting temporary staleness for speed and availability.

THE 30-SECOND ANSWER

With strong consistency (for example linearizability), every read reflects the latest completed write, as if there were one copy of the data; this requires coordination between replicas. With eventual consistency, replicas that stop receiving updates converge to the same value but may return older values in the meantime. Use strong consistency for invariants like balances and uniqueness; use eventual consistency where brief staleness is harmless and availability or latency matters more.
