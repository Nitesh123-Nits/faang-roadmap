API Gateway vs Service Mesh

Separate edge traffic from clients (north–south) from service-to-service traffic (east–west) and decide who enforces what.

THE 30-SECOND ANSWER

An API gateway is the entry point for external clients, enforcing authentication, quotas, and routing for north–south traffic. A service mesh is infrastructure for east–west traffic between services, typically with a proxy per workload providing mTLS, retries, timeouts, traffic shifting, and uniform telemetry. They complement each other. Add a mesh only when many services need consistent network policy that you do not want in every codebase.

Quick revision

API Gateway vs Service Mesh

QUICK REVISION CARD
CORE DIFFERENCE

Edge API policy for external clients versus uniform network policy for service-to-service calls.

CHOOSE A WHEN

External clients need auth, quotas, and routing; few services; simple internal policy.

CHOOSE B WHEN

Many polyglot services needing mTLS, consistent resilience, traffic shifting, and telemetry.

BIGGEST TRADE-OFF

Simple edge control versus powerful but costly east–west control.

KEY FAILURE MODE

Retry amplification across layers; control-plane or policy errors.

ONE-LINE ANSWER

“Gateway for north–south API policy, mesh for east–west mTLS and traffic control; pick one owner for retries.”
