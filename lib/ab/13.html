Server-Side vs Client-Side Load Balancing

Decide whether a dedicated balancer picks the backend instance or the calling service does.

THE 30-SECOND ANSWER

With server-side load balancing, clients send traffic to a balancer that picks an instance and tracks health, so clients stay simple but the balancer is an extra hop and a shared dependency. With client-side load balancing, the caller fetches the instance list from a registry and chooses directly, removing the hop but putting policy and stale-data risk into every client.

Quick revision

Server-Side vs Client-Side Load Balancing

QUICK REVISION CARD
CORE DIFFERENCE

A balancer in the request path versus a caller-embedded balancer using registry data.

CHOOSE A WHEN

External or polyglot clients; central policy; simple clients.

CHOOSE B WHEN

Controlled internal stack; avoid extra hop; locality or custom policy; gRPC.

BIGGEST TRADE-OFF

Central simplicity and control versus lower latency and flexibility with client complexity.

KEY FAILURE MODE

Balancer saturation or outage (server-side); stale instance lists (client-side).

ONE-LINE ANSWER

“Server-side at the edge for simplicity; client-side or mesh internally for latency and control, with retries on a different instance.”
