Stateless vs Stateful Services

Decide whether a service instance keeps client or workload state between requests or pushes that state to external stores.

THE 30-SECOND ANSWER

A stateless service keeps no client-specific state between requests, so any instance can handle any request and you can scale, replace, and autoscale freely, with state living in databases or caches. A stateful service keeps state locally for speed or ordering, which requires affinity, replication, and recovery. Make application tiers stateless by default; use stateful designs where locality, ordering, or the nature of the system demands them.
