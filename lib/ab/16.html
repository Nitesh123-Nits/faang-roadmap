API Gateway vs BFF (Backend for Frontend)

Decide whether all clients share one edge API or each client experience gets its own tailored backend.

THE 30-SECOND ANSWER

An API gateway is one shared entry point that applies common policy and routes to services. A Backend for Frontend (BFF) is a dedicated backend per client experience, such as web, mobile, or TV, that aggregates and shapes data for that UI and is owned by the same team. Use a gateway for shared edge concerns; add BFFs when client needs diverge enough that one API forces compromises.

API Gateway vs BFF (Backend for Frontend)

QUICK REVISION CARD
CORE DIFFERENCE

One shared edge API versus a tailored backend per client experience.

CHOOSE A WHEN

Similar clients; shared policy and routing; one API team.

CHOOSE B WHEN

Divergent clients; aggregation per UI; frontend team autonomy; token handling for browsers.

BIGGEST TRADE-OFF

Simplicity and central policy versus tailored APIs at the cost of more services.

KEY FAILURE MODE

Business logic leaking into BFFs; lowest-common-denominator gateway API.

ONE-LINE ANSWER

“Gateway for shared edge policy; BFF per client experience for aggregation and shaping; rules stay in domain services.”
