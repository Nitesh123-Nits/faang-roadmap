Database per Service vs Shared Database

Decide whether each service owns its data or all services read and write the same database.

THE 30-SECOND ANSWER

With database per service, each service owns its data and exposes it only through an API or events, enabling independent schema changes and scaling but forcing eventual consistency and no cross-service joins. With a shared database, services read and write common tables, giving easy joins and ACID transactions but coupling their schemas and releases. Database per service is the default for true microservices; a shared database is a pragmatic choice inside a monolith or modular monolith.
