04 Sync vs Async CommunicationSync when the caller needs the answer now.Async for decoupling, spikes, fan-out, or long-running work.
05 REST vs GraphQLREST for simple, cacheable resource APIs.GraphQL for many client types with varied data needs.

08 Reverse Proxy vs API GatewayReverse proxy for TLS, routing, and caching.Gateway when you need auth, rate limits, and API products.
09 API Gateway vs Service MeshGateway for north-south traffic.Mesh for east-west mTLS, retries, and traffic policy across many services.
10 Server-Side vs Client-Side LBServer-side LB for simplicity and polyglot clients.Client-side LB to remove a hop and use rich discovery data.
11 Layered vs HexagonalLayered for simple CRUD services.Hexagonal for rich domains with several adapters and strong test needs.
12 Orchestration vs ChoreographyOrchestration for complex, auditable workflows.Choreography for simple, loosely coupled reactions.

INTERVIEW TIP — CROSS-CUTTING PATTERN

Part I decisions are rarely independent. State the constraint first (team size, consistency need, client diversity, failure tolerance), then derive the architecture. Candidates who name the constraint before the technology consistently sound more senior.

COMMON MISTAKE

Resume-driven architecture: adopting microservices, a mesh, GraphQL, and event choreography together multiplies operational cost. Introduce each only when a measured problem justifies it.
