Partitioning vs Sharding

Both split data into pieces; the difference is whether the pieces stay in one database or spread across servers.

THE 30-SECOND ANSWER

Partitioning divides a table into smaller parts inside a single database instance, improving pruning, maintenance, and data lifecycle. Sharding distributes data across independent database servers by a shard key to scale writes and storage beyond one machine. Partition first for manageability; shard when one primary can no longer handle the write or storage load.
