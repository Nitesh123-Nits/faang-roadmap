Application Architecture

Part I covers the decisions you make before you choose a database or a cache: how to carve the system into deployable units, how those units talk to each other, how requests enter the system, and how multi-step workflows are coordinated. These choices are the most expensive to reverse, which is why interviewers use them to separate engineers who can name technologies from engineers who can reason about constraints.

The fourteen comparisons are grouped into four questions. Decomposition (chapters 1–3, 11, 14) asks how to split the system and how to structure code inside each piece. Communication (4–7) asks whether calls are synchronous or asynchronous and which protocol carries them. The traffic edge (8–10, 13) asks what stands between clients and services. Coordination (12) asks who owns the flow of a business process that spans services.

Throughout, the running example is an e-commerce platform with Spring Boot services behind an API gateway, backed by relational and NoSQL stores, Redis, and Kafka, with a standard observability stack.
