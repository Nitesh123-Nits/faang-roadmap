REST vs GraphQL

Choose between resource-oriented HTTP endpoints and a single typed query interface where the client shapes the response.

THE 30-SECOND ANSWER

REST exposes resources at URLs with fixed representations and uses HTTP semantics, which makes it simple, cacheable, and universally supported. GraphQL exposes one typed schema where clients request exactly the fields they need, reducing round trips and over-fetching but shifting complexity, caching, and cost control to the server. Choose REST for simple, cacheable APIs and GraphQL for diverse clients with varied data needs.

Quick revision

REST vs GraphQL

QUICK REVISION CARD
CORE DIFFERENCE

Fixed resource representations over HTTP versus client-shaped queries against a typed schema.

CHOOSE A WHEN

Public or partner API, cacheable content, few client types, simplicity.

CHOOSE B WHEN

Many client types, composite screens, need to reduce round trips and over-fetching.

BIGGEST TRADE-OFF

Simplicity and HTTP caching versus client flexibility and server-side cost control.

KEY FAILURE MODE

Expensive queries and N+1 resolvers (GraphQL); chatty clients and over-fetching (REST).

ONE-LINE ANSWER

“REST for simple, cacheable resources; GraphQL as an aggregation layer for varied clients, with cost limits and batching.”
