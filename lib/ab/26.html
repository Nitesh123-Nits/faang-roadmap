Normalization vs Denormalization

Trade update simplicity and consistency for read performance by deciding where facts live.

THE 30-SECOND ANSWER

Normalization stores each fact once and relates tables by keys, which simplifies updates and prevents anomalies. Denormalization duplicates data to avoid joins or to precompute results, speeding specific reads at the cost of write complexity and possible inconsistency. Normalize first; denormalize deliberately for a measured read bottleneck, and decide how copies stay correct.

When should you choose normalization vs denormalization?

NORMALIZE

Correctness and update simplicity matter; the data changes often; join cost is acceptable.

DENORMALIZE

A measured read path is too slow, the duplicated data changes rarely, and you can keep it in sync.

HYBRID

Normalized write model; denormalized read models or materialized views.
