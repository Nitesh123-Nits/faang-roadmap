Hierarchical Caching Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Multiple cache levels — browser, CDN, application, distributed and database caches — each closer to different layers of the request path.

Serve each request from the nearest cache that can answer it, falling through levels only on a miss.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Latency and load across a global request path where no single cache is sufficient.

Different data has different scope and volatility; layered caches optimize cost, latency and hit ratio.

How it works

The browser checks its local cache first.
A miss goes to the CDN edge for static and cacheable responses.
Next, the gateway or reverse proxy may return a cached response.
The application checks an in-process cache, then a distributed cache.
Only on a full miss does the database serve the request.
Responses populate caches on the way back with appropriate TTLs.
HIERARCHICAL CACHING ARCHITECTURE

Advantages

Disadvantages

Lowest latency for the most common requests.
Multiple invalidation points and staleness risk.

+ Dramatically reduced origin and database load.

Hard to reason about which layer served the data.

When to use

When not to use

High-traffic read-heavy systems with global users and mixed static and dynamic content.

Highly personalized, rapidly changing data requiring strong freshness.
