II.10

Microkernel Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A minimal core system providing essential services, with additional functionality implemented as separate plug-in components or servers.

Keep the kernel tiny and stable; everything else is replaceable and communicates through the kernel.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Large cores that are fragile to change and cannot support product variants.

Born in operating systems (Mach, QNX) and later applied to product-line software.

How it works

Applications call the kernel API.
The kernel provides minimal services: process management, messaging, registry.
Feature modules register with the kernel.
The kernel routes requests to the proper module.
Modules run isolated from the core and each other.
Product variants are built by choosing modules.

Disadvantages

+ Isolation: a failing module does not crash the kernel.

Flexible customization and portability.
More moving parts than a monolith.
Product-line friendly.
Performance penalties on hot paths.

When not to use

Operating systems, product-line applications, ruledriven systems with swappable features.

Performance-critical single-purpose systems or apps without variability.
