VII.11

Fault-Tolerant Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A design that continues operating correctly in the presence of component failures, using redundancy, isolation and graceful degradation.

Assume failures will occur; contain them and keep serving, possibly with reduced functionality.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Cascading failures and total outages when a dependency or component misbehaves.

Distributed systems have constant partial failure; resilience must be designed in (Release It!, chaos engineering).

How it works

Requests pass a rate limiter that protects capacity.
Calls use bulkheads so one dependency cannot exhaust shared resources.
Timeouts bound waiting time.
Retries with exponential backoff and jitter handle transient errors.
The circuit breaker opens after repeated failures and fails fast.
A fallback provides degraded but useful results.
