MAJOR SERVICES & COMPONENTS
COMMUNICATION MECHANISMS

Order, Restaurant/Menu, Dispatch, ETA and pricing, Tracking, Payment, Notification, Rating.

REST for ordering; Kafka for order state events; WebSocket/SSE push for live tracking; high-frequency GPS via a streaming ingestion path.

DATA STORAGE ARCHITECTURE
EXTERNAL DEPENDENCIES

PostgreSQL for orders; Redis GEO or specialized geospatial store for courier locations; Elasticsearch for restaurant search; object storage for images.

Maps/routing, payment provider, SMS/push providers, restaurant POS integrations.

CHOSEN ARCHITECTURAL STYLE
WHY THIS ARCHITECTURE WAS SELECTED

Event-driven microservices with a real-time streaming edge and geospatial indexing.

Dispatch quality depends on fresh location data and fast matching, so location state lives in memoryoptimized geo stores and state changes flow as events. Order data stays transactional.

KEY TRADE-OFFS

Eventual consistency in tracking and ETA; location firehose cost; dispatch algorithm complexity; surge handling at meal peaks needs autoscaling and queues.
