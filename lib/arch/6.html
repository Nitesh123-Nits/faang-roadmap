Client-Server Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Clients initiate requests; servers own resources and logic and respond. The relationship is asymmetric.

Centralize data and rules on servers, keep clients thin or specialized, and communicate through a request– response protocol.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Duplicated logic and inconsistent data across standalone programs; enables shared state and central control.

Networking and shared databases made centralized service providers practical; it underlies almost every modern network application.

How it works

A client opens a connection and sends a request.
The server authenticates and authorizes the caller.
The server executes logic against its data store.
The server returns a response (data, status, errors).
The client renders or acts on the response.
State lives on the server; clients can be replaced freely.
CLIENT-SERVER ARCHITECTURE

Advantages

Central data, security and rules; one place to update.
Heterogeneous clients share one backend.
Simple mental model and tooling.

+ Server capacity can be scaled independently of

clients.

When to use

Almost any networked application with shared state: web, mobile backends, databases and email.

Real-world applications

A REST API serving web and mobile apps
Database servers and JDBC clients
SSH and SMTP.

Quick summary

PRIMARY PURPOSECentralize state and logic behind a request protocol
SCALABILITYMedium — replicate servers
COUPLINGMedium — protocol contract
MAIN DRAWBACKCentral server bottleneck / SPOF

Disadvantages

The server is a single point of failure and a bottleneck unless replicated.
Clients depend on network availability.
Chatty protocols create latency problems.
Server evolution must stay compatible with old

clients.

When not to use

Offline-first or fully decentralized scenarios (consider local-first or peer-to-peer).

Key engineering considerations

Version the API for old clients. Make servers stateless where possible. Budget for retries, timeouts and backpressure at the client.
