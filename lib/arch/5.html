Three-Tier Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A physical/runtime split into presentation tier, application tier and data tier, each deployed on separate infrastructure.

Place UI, business logic and data on separately deployable and scalable tiers connected over the network.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Two-tier designs where clients held business logic and talked directly to the database, hurting security and scalability.

Web applications needed thin clients, a protected data tier and the ability to scale the middle tier on its own.

How it works

The browser loads static assets from the web/CDN tier.
API calls go to a load balancer in front of the application tier.
Any stateless app server handles the request.
App servers are the only components allowed to reach the data tier.
The database tier is replicated and backed up independently.
Each tier is scaled and secured (firewalls, subnets) on its own.
