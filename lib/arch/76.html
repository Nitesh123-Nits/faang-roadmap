VI.01

Database-Centric Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A design where the shared relational database is the system’s center: business logic, integrity and often integration live in or around the database.

Centralize data and enforce rules close to it with constraints, stored procedures and views so every application sees one consistent truth.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Inconsistent data across applications and duplicated validation logic.

Relational databases offered strong integrity and tooling; many enterprises integrated applications through one schema.

Multiple applications integrated through one central database

How it works

Applications connect to the central database.
Business rules run as constraints, triggers or stored procedures.
Applications access data through views and procedures.
The database enforces integrity and transactions.
Reports and integrations read directly from the same schema.
Schema changes are coordinated across all consumers.
