CQRS with Event Sourcing

WHAT IS IT?
FUNDAMENTAL IDEA

The write side stores events as the source of truth (Event Sourcing) and the read side builds query models from those events (CQRS).

Combine an immutable event log for writes with projections for reads to get audit, replay and tailored query models.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Needs for full history plus fast, flexible queries in complex domains.

The two patterns complement each other: events are the natural synchronization mechanism between write and read models.

Event store feeds multiple projections; commands and queries are separate

How it works

A command loads an aggregate by replaying its events.
Business rules run and new events are appended with optimistic concurrency.
Events are published to the bus.
Projectors build one or more read models.
Queries are served from the read stores.
Rebuilding a read model means replaying the event stream.
