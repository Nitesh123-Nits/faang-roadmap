II.01

Clean Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Concentric layers — entities, use cases, interface adapters, frameworks — where source-code dependencies point only inward.

Business rules must not depend on UI, database or frameworks; outer details plug into inner policy through interfaces.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Business logic entangled with frameworks and persistence, making change and testing expensive.

Robert C. Martin consolidated Hexagonal, Onion and DCI ideas into one rule: the dependency rule.

How it works

A controller converts an HTTP request into a use-case input model.
The use case orchestrates entities to apply business rules.
It talks to persistence only through an output port (interface).
An adapter in the outer layer implements that port against the database.
The use case returns an output model; a presenter formats it for the view.
Dependencies never point outward, so inner layers run without framework or DB.
