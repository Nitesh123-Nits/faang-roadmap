Component-Based Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A system composed of self-contained, replaceable components with well-defined provided and required interfaces.

Build software by assembling reusable components that encapsulate behavior and communicate only through interfaces.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Monolithic code that cannot be reused, replaced or tested in parts.

Component models (COM, EJB, OSGi) emerged to support reuse and assembly of larger systems.

Components connected by provided and required interfaces
Module

Sync call

How it works

Decompose functionality into cohesive components.
Each component declares provided and required interfaces.
A container or composition root wires components together.
Components interact only through interfaces.
Components can be replaced or upgraded independently.
Contracts are verified through interface tests.
COMPONENT-BASED ARCHITECTURE

Advantages

Disadvantages

Reuse and replaceability.
Interface and versioning overhead.

+ Parallel development against interfaces.

Over-componentization adds indirection.
Easier testing by mocking required interfaces.
Runtime wiring can be complex.
Lower coupling than monolithic code.
Cross-component transactions are harder.

When to use

When not to use

Large applications built from reusable pieces, UI frameworks and product lines with swappable parts.

Small applications where a few classes suffice.
