VII.01

Cloud-Native Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Applications designed to exploit cloud elasticity: containerized, loosely coupled services managed by orchestration, automation and declarative infrastructure.

Build for failure and change — immutable infrastructure, automation, observability and managed services as defaults.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Lift-and-shift apps that run in the cloud but do not use its elasticity, resilience or automation.

The CNCF defined cloud-native around containers, microservices, dynamic orchestration and continuous delivery.

How it works

Code is built into immutable container images by CI.
Images are deployed declaratively (GitOps) to an orchestrator.
Ingress routes traffic to stateless services.
Autoscalers adjust capacity to load.
Services use managed databases, queues and storage.
Observability and automated rollback keep the system healthy.
