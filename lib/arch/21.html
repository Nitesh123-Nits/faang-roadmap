Vertical Slice Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Code organized by feature (request → handler → data access), where each slice contains everything it needs end-to-end.

Optimize for cohesion within a use case instead of abstraction across layers, so slices change independently.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Feature changes that touch every layer and shared abstractions that become over-general.

Popularized by Jimmy Bogard as a reaction to heavy layering and generic service/repository abstractions.

Each slice owns its full stack through a shared pipeline

How it works

A request maps to one use-case slice.
A dispatcher runs shared behaviors (validation, auth, logging).
The slice’s handler contains the logic for that feature only.
The slice queries or updates the data store directly.
Different slices may use different data access approaches.
Adding a feature means adding a slice, not editing many layers.
