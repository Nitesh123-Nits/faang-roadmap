Layered vs Clean vs Hexagonal vs Onion

All four organize code inside a single deployable. Layered organizes by technical responsibility with downward dependencies; Clean, Hexagonal and Onion invert dependencies so the domain depends on nothing outside it.

Complexity trade-offs

Suitable use cases

Layered is cheapest. The other three buy independence from frameworks and databases at the cost of interfaces, mapping and discipline. Their structural differences are small: they enforce the same inward dependency rule with different vocabulary.

Layered: CRUD-heavy apps with simple rules.
Clean: long-lived apps with explicit use cases and several delivery channels.
Hexagonal: integration-heavy services with many adapters.
Onion: DDD-driven domains with rich models.

Practical recommendation. Use layered for simple CRUD. For non-trivial domains pick the hexagonal vocabulary (ports/adapters) with DDD tactical patterns inside; treat Clean and Onion as equivalent variations rather than competing choices. Enforce the dependency rule with ArchUnit.
