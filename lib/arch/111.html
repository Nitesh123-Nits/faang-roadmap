Complexity trade-offs

Suitable use cases

Complexity moves from code (monolith) to boundaries (modular) to infrastructure and data (microservices). Each step adds operational cost that must be paid for by a real need: team count, scaling profile or release cadence.

Monolith: one small team, early product, uncertain domain.
Modular monolith: growing team, domain being discovered, moderate scale.
Microservices: many teams, divergent scaling, high release frequency, strong DevOps.

Practical recommendation. Start with a modular monolith. Extract a module into a service only when a concrete driver exists — independent scaling, team ownership or a different availability need — and the boundary has proven stable.
