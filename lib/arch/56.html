Unidirectional Data Flow Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A general principle where data flows in one direction

state to view, events to state changes — rather than in loops of two-way bindings.

State flows down to views; user intent flows up as events; only one place mutates state.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Hard-to-trace updates and inconsistent state from bidirectional updates.

It is the common root of Flux, Redux, MVI, Elm and React’s props/state model.

State flows down; events flow up; one update path
Database / store
Service / component
Client
Module
Domain core

How it works

State is held in one place.
The view is a pure function of state.
The user interacts, producing an event.
The event goes to an update function, never directly to the view or state.
The update function produces the next state.
The view re-renders from the new state.
