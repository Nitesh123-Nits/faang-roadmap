Orchestration-Based Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A central orchestrator controls a business process by calling participating services in a defined order and handling failures.

Centralize workflow logic in one component that commands services and tracks state.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Opaque, scattered process logic in choreographed systems.

Complex workflows need visibility, timeouts and compensation in one place; engines like Camunda and Temporal address this.

How it works

The orchestrator starts a workflow instance.
It sends a command to the first service and waits for the result.
It persists state after each step to survive crashes.
It chooses the next step or compensation based on results.
Timeouts and retries are managed centrally.
The full process is visible and inspectable in one place.
