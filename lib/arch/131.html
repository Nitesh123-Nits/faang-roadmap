DATA STORAGE ARCHITECTURE
EXTERNAL DEPENDENCIES

In-memory geo index sharded by cell; relational store for trips; time-series store for location history; data lake for analytics and ML.

Maps/routing, payment processors, SMS/push, identity verification.

CHOSEN ARCHITECTURAL STYLE
WHY THIS ARCHITECTURE WAS SELECTED

Event-driven microservices with geo-sharded inmemory state and a streaming location pipeline.

Matching needs sub-second access to current driver positions, so hot location state is partitioned geographically in memory. Trip lifecycle is a state machine published as events so pricing, payments and notifications react independently.

KEY TRADE-OFFS

Geographic sharding complicates cross-region trips; dispatch-quality tuning; surge pricing fairness; heavy location traffic cost.
