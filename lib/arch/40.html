Shared-Nothing Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Each node is self-sufficient — owns its own CPU, memory and disk — and nodes share no state; they coordinate only over the network.

Partition data and work so no node contends for shared resources, giving near-linear scale-out.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Contention and single points of failure caused by shared disks, memory or locks.

Stonebraker (1986) proposed it for parallel databases; it underpins modern scale-out data systems.

How it works

Data is partitioned by a key across nodes.
A router sends each request to the node owning the data.
Each node reads and writes only its local storage.
Nodes replicate partitions to peers for fault tolerance.
Adding nodes adds capacity; data is rebalanced.
Cross-partition queries are coordinated at the router or client.
SHARED-NOTHING ARCHITECTURE

Advantages

Disadvantages

Near-linear horizontal scalability.
Cross-partition joins and transactions are hard.

+ No shared bottlenecks or single point of contention.

Partitioning keys must be chosen well (hot spots).
Failure of a node affects only its partition (with replicas).
Rebalancing is operationally complex.
Application must be partition-aware.

+ Commodity hardware.

When to use

When not to use

Massive-scale databases and services with partitionable workloads and key-based access.

Workloads dominated by cross-entity transactions or ad-hoc joins.
