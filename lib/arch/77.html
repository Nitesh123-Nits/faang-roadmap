VI.02

Polyglot Persistence

WHAT IS IT?
FUNDAMENTAL IDEA

Using multiple data store technologies, each chosen for the data model and access pattern of the workload it serves.

No single database is best for everything; match store to need — relational, document, key-value, graph, search.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Forcing every workload into one database that fits none perfectly.

NoSQL and specialized stores matured, and microservices allowed independent data choices.

Different stores for different workloads

How it works

Identify workloads and their access patterns.
Select a store per workload (ACID, document, cache, search, graph).
Services access the stores they own.
Changes flow between stores via events or CDC.
Search and analytic stores are derived from the source of truth.
Operations standardize backup, monitoring and security across stores.
POLYGLOT PERSISTENCE

Advantages

Disadvantages

Best performance and fit per workload.
Operational burden of many technologies.

+ Independent scaling of each store.

Data consistency across stores is hard.
Features unavailable in a single database.
Skills and tooling fragmentation.
Avoids over-stretching one technology.
Cross-store queries are difficult.

When to use

When not to use

Systems with distinct workloads, such as transactions, search, caching and recommendations, and teams able to operate them.

Small teams or workloads that fit comfortably in PostgreSQL.

Real-world applications

Key engineering considerations

E-commerce (SQL orders, document catalog, search index)

Designate one source of truth per dataset. Use CDC to feed derived stores. Limit the number of technologies and standardize operations.
