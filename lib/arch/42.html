Broker Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A broker component mediates between clients and servers, handling discovery, routing and communication so they remain decoupled.

Clients address services logically; the broker locates and invokes them, hiding location and protocol.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Direct dependencies and hard-coded endpoints between distributed components.

CORBA-era distributed objects and modern message brokers need a mediator to manage heterogeneity and location.

How it works

Servers register their services with the broker.
A client sends a request addressed logically to the broker.
The broker locates a suitable server.
It marshals the request and forwards it.
The server processes it and returns a result via the broker.
The broker returns the result to the client.
