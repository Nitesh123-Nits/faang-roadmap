III.11

Space-Based Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Processing units with in-memory data grids replicated across a virtualized middleware, removing the central database as a bottleneck.

Keep hot data in a distributed in-memory grid next to the processing and write back to the database asynchronously.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Database bottlenecks and scalability limits under extreme and unpredictable load.

Derived from tuple-space ideas (JavaSpaces, GigaSpaces) for high-volume transactional systems.

Processing units with replicated in-memory grid; asynchronous persistence

How it works

A request hits any processing unit via the load balancer.
The PU reads and writes data in its in-memory grid replica.
The data grid replicates changes to other PUs.
A data writer persists changes to the database asynchronously.
The deployment manager spins up more PUs under load.
On failure, another PU holds the replicated data.
