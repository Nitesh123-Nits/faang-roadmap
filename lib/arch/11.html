Serverless Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Applications built from managed services and shortlived functions where the provider handles servers, scaling and patching.

Pay per invocation and compose managed building blocks (functions, queues, storage, auth) instead of running servers.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Idle capacity cost and the operational burden of capacity planning and patching.

Cloud providers abstracted servers away (AWS Lambda, 2014) so teams could ship event-driven logic without infrastructure.

How it works

A client calls an API gateway or an event occurs (upload, message).
The platform starts a function instance on demand.
The function runs briefly and writes to managed storage.
It emits an event or message to continue the workflow.
The platform scales instances automatically, including to zero.
Billing is per invocation and duration.

When to use

When not to use

Spiky or low-traffic APIs, event processing, glue logic, data pipelines, and prototypes where operations staff is limited.

Steady high-throughput workloads, long-running jobs, ultra-low-latency needs, or strict portability requirements.
