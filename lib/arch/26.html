II.11

Micro-Frontends Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Splitting a web UI into independently developed and deployed frontend applications composed into one experience.

Apply microservice thinking to the frontend: vertical teams own a feature from UI to API.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Monolithic frontends where many teams block each other on one codebase and release.

Large web apps outgrew single SPA teams; module federation and edge composition made runtime composition practical.

A shell composes independently deployed frontends, each with its backend

How it works

The browser loads a shell from a CDN.
The shell resolves which micro-frontends to mount for the route.
Each micro-frontend bundle is fetched from its own deployment.
Composition happens via module federation, web components, iframes or edge includes.
Each team calls its own backend.
Cross-MFE communication uses events or shared contracts, not shared state.
