Redux Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A single global store holding all application state, updated only by dispatching actions processed by pure reducer functions.

Predictable state container: state is read-only, changes are described by actions, and reducers compute new state.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Scattered mutable state and unpredictability in large client applications.

Dan Abramov and Andrew Clark simplified Flux (2015) into a single store with pure reducers and time-travel debugging.

How it works

A component dispatches an action describing what happened.
Middleware may intercept it to run async side effects.
The reducer computes new state from the previous state and action.
The store saves the new immutable state.
Subscribed components select the slices they need.
DevTools can log and replay actions (time-travel).
