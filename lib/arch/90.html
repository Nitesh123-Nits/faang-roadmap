Kubernetes-Based Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Applications run as Pods managed by Kubernetes, which schedules, scales, heals and networks containers across a cluster of nodes.

Declare the desired state; controllers continuously reconcile reality to match it.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Manual placement, scaling and recovery of containers across many machines.

Kubernetes became the standard container orchestrator for portable, self-healing deployments.

Cluster with control plane, worker nodes, ingress and storage

How it works

Manifests (Deployments, Services, Ingress) are applied to the API server.
State is stored in etcd; controllers reconcile desired vs actual.
The scheduler places Pods onto nodes by resources and constraints.
Services and ingress route traffic to healthy Pods.
Probes restart failed Pods; autoscalers add replicas and nodes.
Rolling updates replace Pods gradually and roll back on failure.
