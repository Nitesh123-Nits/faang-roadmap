MVVM (Model-View-ViewModel)

WHAT IS IT?
FUNDAMENTAL IDEA

The ViewModel exposes observable state and commands; the View binds to them declaratively and the ViewModel knows nothing about the view.

Use data binding so the view updates automatically when ViewModel state changes.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Glue code in MVP and tight coupling between views and presentation logic.

Introduced by Microsoft for WPF/Silverlight and adopted by Android Jetpack, Vue and Angular.

How it works

The user interacts with a bound control.
Binding invokes a command or updates a property in the ViewModel.
The ViewModel calls the model or repositories.
The model returns data asynchronously.
The ViewModel updates observable state.
The binding engine re-renders the view automatically.
MVVM (MODEL-VIEW-VIEWMODEL)

Advantages

Disadvantages

Minimal glue code through binding.
Binding can be hard to debug.

+ ViewModel is testable without UI.

ViewModels can bloat; overhead for simple screens.
Views stay declarative and swappable.
Memory leaks with improper subscriptions.
Works well with reactive streams.
Two-way binding hides data flow.

When to use

When not to use

Rich client UIs with a binding framework: Android Jetpack, WPF, Angular, Vue.

Very simple screens or platforms without binding support.
