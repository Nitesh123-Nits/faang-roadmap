MAJOR SERVICES & COMPONENTS
COMMUNICATION MECHANISMS

Catalog, Playback/DRM, Search, Recommendation, User/Subscription, Upload, Transcoding, Analytics.

REST/GraphQL for control plane; HTTP adaptive streaming (HLS/DASH) via CDN for video; queues for transcoding jobs; Kafka for viewing events.

DATA STORAGE ARCHITECTURE
EXTERNAL DEPENDENCIES

Object storage for master files and renditions; relational/NoSQL for metadata; feature store for recommendations; data lake for analytics.

CDN/ISP caches, DRM license servers, payment providers, device vendors.

CHOSEN ARCHITECTURAL STYLE
WHY THIS ARCHITECTURE WAS SELECTED

Microservices control plane with a CDN-based data plane, a fan-out/fan-in transcoding pipeline and stream processing for telemetry.

Video bytes dominate cost and latency, so they bypass application services and are delivered from edge caches. Transcoding is embarrassingly parallel, so it uses queues and elastic workers.

KEY TRADE-OFFS

CDN cost and cache-fill complexity; transcoding compute cost; recommendation freshness vs cost; DRM adds device-specific complexity.
