Distributed Cache Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A cluster of cache nodes that holds frequently accessed data in memory across machines to cut latency and database load.

Serve hot reads from fast, shared, partitioned memory instead of hitting the primary store.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Database bottlenecks and high latency for read-heavy workloads.

Web scale made database round trips the dominant latency and cost.

Cache-aside with a partitioned, replicated cache cluster

How it works

The application computes the key and finds its shard by consistent hashing.
On a hit, the value returns from memory.
On a miss, the app reads from the database.
It writes the value to the cache with a TTL.
Writes update the database and invalidate or update the cache.
Replicas provide failover; nodes can be added with minimal key movement.
