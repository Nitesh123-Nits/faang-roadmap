Screaming Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A structure where the top-level organization reveals the system’s purpose (billing, orders) rather than the framework (controllers, models).

Package by business capability so the architecture “screams” what the system does.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Codebases whose folders say “Spring MVC” instead of what the product is for.

Robert C. Martin argued that architecture should communicate intent, with frameworks as details.

Package by capability, not by framework layer
Module

Sync call

How it works

Top-level folders are named after business capabilities.
Each capability holds its own controllers, services and persistence.
A new developer sees the domain at a glance.
Frameworks live inside capabilities rather than defining structure.
Cross-capability calls go through explicit public APIs.
Capabilities can later become modules or services.
SCREAMING ARCHITECTURE

Advantages

Disadvantages

Discoverability of purpose and features.
Shared concerns need careful placement.

+ High cohesion within capabilities.

+ Frameworks stay replaceable details.

Teams used to layer-based packaging need adjustment.
Does not by itself define dependency rules.

When not to use
