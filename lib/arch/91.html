Container-Based Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Applications packaged with their dependencies into containers that run consistently on any host with a container runtime.

Package once, run anywhere — isolated, lightweight and immutable runtime units.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

“Works on my machine” differences and heavy VMbased deployments.

Docker made Linux containers easy to build, ship and run.

How it works

A Dockerfile defines the image with app and dependencies.
CI builds and pushes the image to a registry.
The runtime pulls the image on the host.
It starts an isolated container using namespaces and cgroups.
Networks and volumes connect containers to the world.
Containers are replaced, not patched, for updates.
