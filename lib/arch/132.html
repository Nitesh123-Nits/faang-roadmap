MAJOR SERVICES & COMPONENTS
COMMUNICATION MECHANISMS

Post, Feed/Timeline, Social graph, Media, Search, Notification, Moderation, Ads.

REST/GraphQL APIs; Kafka for post events; async fanout workers; push notifications; CDN for media.

DATA STORAGE ARCHITECTURE
EXTERNAL DEPENDENCIES

Sharded relational or wide-column store for posts; graph or adjacency store for relationships; Redis for timeline caches; object storage for media; search index.

Push providers (APNs/FCM), CDN, ML moderation services, ad platforms.

CHOSEN ARCHITECTURAL STYLE
WHY THIS ARCHITECTURE WAS SELECTED

Event-driven microservices with CQRS-style read models (timelines), hierarchical caching and CDNbased media delivery.

Reads vastly outnumber writes, so timelines are precomputed (fan-out on write) for normal users and merged at read time for celebrities. Events decouple posting from feed building, search indexing and notifications.

KEY TRADE-OFFS

Fan-out storage cost and delay; hot-key celebrity accounts; eventual consistency of feeds; moderation and ranking complexity.
