Interpreter Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A system interprets a program or script in a domain language at runtime by parsing it and executing its structure with an engine.

Embed a language (DSL) so behavior is expressed as data that the interpreter evaluates.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Needing flexible, user-defined or frequently changing behavior without rebuilding the application.

Scripting, query languages and workflow engines require runtime evaluation of external definitions.

How it works

The user or system supplies a script or expression.
The lexer and parser build an abstract syntax tree.
The evaluator walks the tree node by node.
Variables and functions are resolved in the runtime context.
Results and side effects are produced.
Errors are reported with source positions.

Disadvantages

When not to use
