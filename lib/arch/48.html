MVC (Model-View-Controller)

WHAT IS IT?
FUNDAMENTAL IDEA

Separates an application into Model (data and rules), View (presentation) and Controller (input handling that updates the model and selects the view).

Keep presentation, input handling and business data apart so each can change independently.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

UI code that mixes rendering, input handling and business logic into unmaintainable screens.

Introduced in Smalltalk-80 and became the standard for server-rendered web frameworks (Spring MVC, Rails, ASP.NET MVC).

Controller mediates; the view observes or reads the model

How it works

The user triggers an action (HTTP request or UI event).
The controller interprets the input and validates it.
The controller calls the model to perform the operation.
The model updates state or reads data from storage.
The controller selects a view and passes it model data.
The view renders the response to the user.

When to use

When not to use

Server-rendered web applications and APIs with request-driven interaction.

Highly interactive, stateful client UIs where two-way binding or unidirectional state fits better.
