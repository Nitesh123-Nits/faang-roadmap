Flux Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A unidirectional data flow pattern where Actions are dispatched to Stores through a central Dispatcher, and Views re-render from Store state.

Data flows in a single direction — Action → Dispatcher

Store → View — preventing cascading, hard-totrace updates.
PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Complex two-way data binding that made large client apps unpredictable.

Facebook introduced Flux (2014) to fix cascading update bugs, such as the notification-count problem, in large React apps.

How it works

A user interaction in a view calls an action creator.
The action creator creates an action and sends it to the dispatcher.
The dispatcher forwards the action to all registered stores.
Stores update their state and emit a change event.
Views listening to stores read new state and re-render.
Data never flows backward from views to stores directly.
