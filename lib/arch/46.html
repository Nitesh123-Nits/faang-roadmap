Kappa Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

A single stream-processing pipeline over a replayable log handles both real-time and reprocessing.

Use one codebase and treat batch as replaying the log through the same stream job.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Lambda’s duplicated logic and operational complexity.

Jay Kreps proposed it as stream engines matured and logs such as Kafka became durable and replayable.

How it works

All data is written to a durable, replayable log.
A stream job processes events and writes to a serving store.
Logic changes are deployed as a new job version.
The new job replays the log from the start into a new output table.
When caught up, traffic switches to the new output.
The old job and table are retired.
