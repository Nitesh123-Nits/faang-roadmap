Stream Processing Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Continuous processing of unbounded event streams in near real time, with stateful operators and windowing.

Treat data as an infinite stream and compute incrementally as events arrive.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

The latency of batch for use cases needing immediate insight or reaction.

Real-time analytics, fraud detection and monitoring required sub-second processing at scale.

How it works

Producers publish events to a log such as Kafka.
A stream processor consumes events continuously.
It applies filters, joins and windowed aggregations.
Operator state is kept in local stores with checkpoints.
Results are emitted to topics, stores or alerts.
On failure the job restarts from the last checkpoint with exactly-once or at-least-once semantics.
