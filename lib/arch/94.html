VII.06

Multi-Cloud Architecture

WHAT IS IT?
FUNDAMENTAL IDEA

Using services from two or more cloud providers for the same system or portfolio.

Avoid single-vendor dependence and exploit each provider’s strengths, at the cost of added complexity.

PROBLEM IT SOLVES
WHY IT WAS INTRODUCED

Vendor lock-in, regional gaps, compliance demands and provider-level outage risk.

Enterprises acquire workloads across clouds or need negotiating leverage and resilience.

How it works

A global traffic manager routes requests among clouds.
Workloads are packaged in containers for portability.
Infrastructure is defined with provider-neutral IaC.
Identity, observability and CI/CD are cloud-agnostic.
Data replication or partitioning handles state across clouds.
Failover shifts traffic if a provider or region fails.
