CHANGE DATA CAPTURE (CDC)
Supports analytics, reporting and microservices integration.
COMMON USE CASES

Real‐time analytics and reporting, data warehousing and ETL/ELT, data replication and synchronisation, event‐driven microservices, audit, monitoring and compli‐ ance, search synchronisation, cache updates.

CHALLENGES

Log growth and management, handling schema changes, ensuring data consist‐ ency and ordering, de‐duplication and idempotency, increased complexity in setup and monitoring.

POPULAR TOOLS

Debezium, AWS DMS (Database Migration Service), Oracle GoldenGate, StreamSets, Flink CDC, Kafka Connect (with CDC connectors).

A change is made in the source database ( INSERT orders , UPDATE products ).
The change is recorded in the transaction log (the WAL).
The CDC connector reads changes from the log, continuously.
Changes are converted into events and published to topics ( orders_topic ,customers_topic , products_topic ).
Consumers process the events in real time: Elasticsearch (search), Redis (cache), a data warehouse (analytics), microservices (events).
CONSUMER-SIDE RULES

Delivery is typically at least once, so consumers must be idempotent. Ordering is guaranteed per partition (usually per key), not globally. Plan for schema evolution and for initial snapshots when onboarding a new table.

R E M E M B E R . CDC enables systems to react to data changes as they happen,

powering real‐time integrations, analytics and modern data architectures.
