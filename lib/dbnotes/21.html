Maintenance overhead: more indexes, more overhead. Too many hurt perform‐

ance.

BEST PRACTICES
Index columns used in WHERE , JOIN , ORDER BY , GROUP BY .
Use composite indexes wisely: put the most selective column first, but also

match your query patterns.

Avoid indexing low‐cardinality columns. Do not over‐index.
Regularly review and remove unused indexes.
Use EXPLAIN / EXPLAIN ANALYZE to verify usage.
READING EXPLAIN (MYSQL)
EXPLAIN SELECT * FROM users WHERE city = 'Delhi';
-- type: ref        -> an index lookup was used
-- key:  idx_city   -> which index
-- rows: 5          -> estimated rows scanned (lower is better)
HOW TO ANSWER IN AN INTERVIEW

Explain what an index is and why it is needed. Explain the underlying structure (B+ tree). Walk through query execution with and without an index. Name the index types with examples. Discuss when it is used and not used. Mention trade‐offs. Al‐ ways mention the query optimizer's role. Use a diagram if you can.

R E M E M B E R . Good indexing means faster queries and happy users.
