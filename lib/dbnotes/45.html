RESP PROTOCOL

A lightweight, simple text protocol with minimal parsing overhead. It supports pipelining: sending several commands in one network round trip. Less data on the wire, fewer round trips, more throughput.

ZERO-COPY AND EFFICIENT MEMORY MANAGEMENT

Zero‐copy techniques such as sendfile and writev reduce copying between kernel and user space. Memory is managed by jemalloc , a memory allocator that favours performance and limits fragmentation.

PERSISTENCE DONE ASYNCHRONOUSLY

RDB snapshots and the AOF (append‐only file) are handled in the background (RDB via a forked child process; AOF fsync policy is configurable), so persistence does not block the main thread under normal operation.

SMALL, OPTIMISED CODEBASE

Written in ANSI C, portable and highly optimised. A small codebase is easy to audit, maintain and tune.

SUMMARY

In‐memory speed, single‐threaded event loop, efficient data structures, optimised I/ O, lightweight protocol, zero‐copy and efficient memory, async persistence, and an optimised codebase together make Redis extremely fast, predictable and efficient.
