Cardinality: how many instances take part in a relationship.
CARDINALIT YMEANINGEXAMPLE
1:1One to oneUser and profile
1:NOne to manyCustomer and orders
N:1Many to oneOrders and customer
M:NMany to manyStudents and courses (needs a join table)

KEYMEANING
Primary keyUniquely identifies a record
Candidate keyA minimal set of attributes that could be the primary key
Foreign keyReferences the primary key in another table
Composite keyA primary key made of several attributes
EXAMPLE: E-COMMERCE MODEL
CUSTOMER 1---N ORDER
ORDER    1---N ORDER_ITEM
PRODUCT  1---N ORDER_ITEM
ORDER    1---1 PAYMENT
CUSTOMER 1---N ADDRESS
CATEGORY 1---N PRODUCT   (self-reference via parent_category_id)
LOGICAL SCHEMA
CREATE TABLE customers (
  customer_id BIGINT PRIMARY KEY,
  name        VARCHAR(100) NOT NULL,
  email       VARCHAR(255) UNIQUE NOT NULL,
  phone       VARCHAR(20),
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE orders (
  order_id     BIGINT PRIMARY KEY,
  customer_id  BIGINT NOT NULL,
  order_date   DATETIME NOT NULL,
  status       VARCHAR(20) NOT NULL,
  total_amount DECIMAL(12,2) NOT NULL,
  CONSTRAINT fk_orders_customer FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)
);
