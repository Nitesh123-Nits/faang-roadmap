SQL vs NoSQL: when to use which? SQL for structured data, joins and strong con‐ sistency. NoSQL for flexible schema, horizontal scale or specialised access patterns (cache, graph, time series). Often both.

Explain joins with examples. Inner returns matching rows; left keeps all left rows with NULLs on no match; right the mirror; full keeps all; cross is every combina‐ tion.

FIVE ANSWERS WORTH MEMORISING
Clustered versus non-clustered: data is physically in index order versus a sep‐ arate structure with pointers. One clustered per table.
Optimistic versus pessimistic: version check at commit versus lock up front. Trust first, verify later versus lock first, then work.
Isolation anomalies: dirty read (uncommitted), non‐repeatable read (row changed), phantom read (new row appears).
Why a query ignores an index: function on the column, type mismatch, lead‐ ing wildcard, low selectivity, OR across columns, stale statistics, composite‐in‐ dex order.
