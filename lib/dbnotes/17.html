THE STAGES
SQL query. The user writes a query, for example SELECT id, name, salary FROM
employees WHERE department_id = 10 AND salary > 50000 ORDER BY salary DESC; .
Parser. Checks syntax, validates table and column names, checks permissions, and produces an internal representation. Query tree. The parser builds a tree of the logical structure. Nodes are operations: SELECT (projection), FILTER (conditions), SORT (ordering), TABLE (data source).

3.

Optimizer / planner. Evaluates alternative execution strategies using statistics and metadata (table size, indexes, data distribution). It is cost-based: it compares plans, estimates cost (I/O, CPU, memory) and picks the cheapest. Execution plan. The chosen sequence of operations, with access methods, estimated cost and expected rows. Example: index scan on department_id , filter salary > 50000 , sort by salary DESC , return result. Index scan? The engine checks whether a usable index exists. If yes, perform an index scan (faster): skip non-matching rows, jump directly to matches, reduce I/O. If no, do a full table scan (slower). Find matching data. Using the index or table scan, the engine locates row pointers (RID or primary key) and applies all conditions, keeping only qualifying rows. Read required pages. Data pages come from disk or, preferably, the buffer cache. Reading fewer pages means better performance. Return rows. The final result set goes back to the client in the requested format.R E M E M B E R . You describe what you want; the optimizer decides how to get it.Your job is to give it good schema, good indexes and fresh statistics.
