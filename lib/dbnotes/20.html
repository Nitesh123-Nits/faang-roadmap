TYPES OF INDEXES
T YPENOTES
PrimaryCreated automatically on the primary key; unique and not null
SecondaryOn non-primary-key columns to speed up searches there
UniqueEnsures all values are unique (some DBs allow one NULL)
Composite (multi-column)Order of columns matters: an index on (a, b) serves a, or a and b
Full-textText search (MATCH --. AGAINST in MySQL)
SpatialGeographic data (GIS)

Other physical kinds you will meet: hash (fast equality lookup) and covering in‐ dexes.

WHEN AN INDEX IS USED, AND WHEN NOT
USEDNOT USED
WHERE (equality or range)Functions on the indexed column, WHERE UPPER(name) = 'ALICE'
JOIN conditionsLeading wildcard, LIKE '%abc'
ORDER BY, GROUP BY, DISTINCTOR across different columns Low-selectivity columns (gender, flags)

The query optimizer decides whether to use an index. It is a cost decision, not a rule.

TRADE-OFFS
Extra storage: indexes take disk space.
Slower writes: INSERT , UPDATE and DELETE must also update the index.
