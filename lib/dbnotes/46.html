PostgreSQL Connection Pooling

Opening a database connection is expensive. A pool opens connections once and reuses them.

WHY A CONNECTION IS EXPENSIVE
STEPAPPROXIMATE COST
TCP handshake~1 ms
TLS negotiation~5 ms
DB authentication~3 ms
Session setup~1 to 2 ms
Total overhead~10 ms+

Every request that opens its own connection pays this. At 1000 requests per second, that is 10 seconds of wasted time per second. In PostgreSQL, each connection also consumes a backend process on the database server.

RECOMMENDED POOL SIZE

A commonly cited formula (PostgreSQL):

pool_size = (CPU cores x 2) + effective_spindle_count

Example: a 4‐core machine with SSD gives a pool size of about 9 to 10, which is suffi‐ cient in most cases. More connections means more contention and less through- put. A small pool with a queue beats a huge pool.
