SQL IN AN RDBMS
DML: DATA
INSERT INTO employee (id, name, salary) VALUES (1, 'Nitesh', 100000);
UPDATE employee SET salary = 120000 WHERE id = 1;
DELETE FROM employee WHERE id = 1;
DQL: QUERY
SELECT id, name, salary, department
FROM employee
WHERE salary > 100000
ORDER BY salary DESC;
DCL: ACCESS
GRANT SELECT, INSERT ON employee TO user1;
REVOKE INSERT ON employee FROM user1;
TCL: TRANSACTIONS
START TRANSACTION;
UPDATE employee SET salary = 150000 WHERE id = 1;
SAVEPOINT salary_update;
UPDATE employee SET salary = 200000 WHERE id = 1;
ROLLBACK TO salary_update;
COMMIT;

Flow: start, update, savepoint, update, rollback to savepoint, commit. Only the first update survives.

EASY MNEMONIC

DDL defines the structure. DML manipulates the data. DQL queries the data. DCL controls access. TCL controls transactions.

R E M E M B E R . DDL changes auto‐commit in most DBMS. DML changes are con‐

trolled by TCL. Always commit important transactions, and use DCL for secur‐ ity.
