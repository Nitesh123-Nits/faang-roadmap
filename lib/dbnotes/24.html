WHEN INDEXING FAILS
CHAPTER 12

When Indexing Fails

Indexes are powerful, but not magic. They do not help when the query or the data prevents their use. Nine classic reasons.

FUNCTIONS ON THE INDEXED COLUMN

Wrapping the column in UPPER() , DATE() , SUBSTR() forces the database to compute the function for every row, so the index cannot be used.

-- Bad
WHERE UPPER(name) = 'JOHN'
-- Better
WHERE name = 'John'

Where you genuinely need the function, create a functional (expression) index on it.

TYPE MISMATCH

Comparing different data types forces implicit conversions and can force a full scan.

WHERE id = '123'   -- id is INT: implicit conversion may kill index usage
LEADING WILDCARD IN LIKE

LIKE '%abc' cannot use the index because the start of the string is unknown.

WHERE name LIKE '%abc'   -- full scan
WHERE name LIKE 'abc%'   -- can use the index
OR CONDITIONS ON DIFFERENT COLUMNS

WHERE a = 1 OR b = 2 often prevents index usage and the optimizer may choose a

full table scan. Rewrite as a UNION of two indexed queries, or index both columns so the engine can combine them.
