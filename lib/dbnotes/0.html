Database Interview Notes

Rebuilt from the sticky-note cheat sheet collection “Database Interview Sticky Notes for Backend Developers”. Content has been reorganised into chapters, tightened, and extended with short explanations where a bullet alone would not carry the idea.

Set in Cormorant Garamond, Source Serif 4, Inter and JetBrains Mono. Three colours throughout: ink, paper and a single terracotta accent.

Verify engine-specific behaviour (defaults, syntax, limits) against the current official documentation before relying on it in production.

Read this first

This book is built for the last mile of interview preparation, and for the days after you land the job, when you still need the one-page answer fast.

Every chapter follows the same shape: a short statement of what the thing is, the comparison or flow that matters, a code sample where one helps, and a closing line you can say out loud. Tables are for comparing; code is for recognising; the closing note is for remembering.

HOW THE BOOK IS ORGANISED

Foundations. What a database is, how to model data, how to normalise it, and where the bytes actually live.

SQL. The five command families, the everyday cheat sheet, joins, the logical execution order, and how a query runs inside the engine.

Indexing and Storage Internals. B+ trees, clustered and non-clustered indexes, why an index is sometimes ignored, and what pages and fragmentation do to speed.

Transactions and Concurrency. ACID, isolation levels and their anomalies, optimistic and pessimistic locking, and what @Transactional really does.

Choosing and Scaling. Which database for which workload, CAP, why Redis is fast, connection pooling, optimisation and change data capture.

Rapid Revision. The original one-page cheat sheet, kept as the final-hour read.

HOW TO USE IT

Read a part end to end once. Afterwards, treat it as a reference: open the chapter, scan the table, read the closing note. If you cannot explain a chapter without look‐ ing, read it again, then draw it.
