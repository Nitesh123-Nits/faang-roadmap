CHAPTER 11

Clustered vs Non-Clustered Index

Both improve retrieval speed. They differ in where the data physically lives.

CLUSTEREDNON-CLUSTERED
Data layoutRows are physically stored in index orderIndex structure is separate from the table data
Leaf nodesContain the actual data rowsContain pointers (row ID or primary key)
How manyOnly one per tableMany per table

CLUSTERED INDEX EXAMPLE

An Employee table clustered on id is stored on disk in id order. A B+ tree sits over it: the root routes to internal nodes, and the leaves are the rows ( 1 Alice, 2 Bob ; 4

David, 5 Emma ), linked in order.

SELECT * FROM Employee WHERE id = 3;
-- Root -> Leaf -> Data row (very fast)
NON-CLUSTERED INDEX EXAMPLE

The table (heap) holds rows in no particular order, each with a row ID. A separate B+ tree on name stores Alice -> 101 , Bob -> 102 , and so on.

SELECT * FROM Employee WHERE name = 'Charlie';
-- Index search -> find pointer -> table access -> data row (more steps)
