Isolation Levels

Isolation is a property of database transactions that determines how and when changes made by one transaction become visible to other concurrent transactions.

WHY IT MATTERS

Multiple transactions may run concurrently. The isolation level controls the bal‐ ance between data consistency and concurrency. Higher isolation means more consistency but lower concurrency.

THE FOUR LEVELS, LOWEST TO HIGHEST
Read Uncommitted. Transactions can read data modified by others even if not committed. Allows dirty reads. Highest concurrency, lowest consistency.
Read Committed. A transaction reads only committed data. Prevents dirty reads, allows non‐repeatable reads. Common default in Oracle, SQL Server and Postgr‐ eSQL.
Repeatable Read. Rows read once cannot change during the transaction. Pre‐ vents dirty and non‐repeatable reads. May allow phantom reads, depending on the implementation. Default in MySQL InnoDB.
Serializable. Transactions behave as if run one after another. Prevents all three anomalies. Maximum consistency, lowest concurrency, highest overhead.
