Why Redis Is So Fast

Redis is an in-memory data-structure server, optimised for speed at every layer. Eight reasons stack together.

IN-MEMORY DATA STORE

All data lives in RAM, which is orders of magnitude faster than disk.

MEDIUMAPPROXIMATE ACCESS TIME
RAM~100 nanoseconds
SSD~100 microseconds
HDD~10 milliseconds

That is roughly 1000x between RAM and SSD, and far more against a spinning disk.

SINGLE-THREADED EVENT LOOP

Commands are executed by a single thread driven by an event loop on I/O multi‐

plexing ( epoll / kqueue ). No context switching, no lock contention, predictable

performance, and it still handles thousands of connections.

Since Redis 6, optional I/O threads can read and write sockets in parallel, but com‐ mand execution stays single‐threaded.

EFFICIENT DATA STRUCTURES

String, Hash, List, Set, Sorted Set, Bitmap, HyperLogLog, Geospatial: simple, highly optimised structures implemented in C, with O(1) time for most operations.

OPTIMISED I/O MODEL

OS‐level I/O multiplexing ( epoll on Linux, kqueue on macOS, IOCP on Windows)

lets one thread serve many connections with high throughput and low latency. Non‐blocking I/O keeps the server busy with useful work, not waiting.
