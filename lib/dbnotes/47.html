BEST PRACTICES
Always use connection pooling.
Size the pool from the formula (CPU x 2 + disks), not from the request rate.
Never open and close a connection per request.
Use transaction pooling (pgBouncer) for high concurrency.
Set connection timeouts so failures are fast.
Monitor pool metrics: active, idle, waiting.
Do not exceed max_connections on the PostgreSQL server, summed across all ap‐

plication instances.
