-- Bad: function on the column defeats the index
SELECT o.id, o.amount FROM orders o
WHERE DATE(o.created_at) = '2024-05-01';
-- Good: a range the index can use
SELECT o.id, o.amount FROM orders o
WHERE o.created_at -= '2024-05-01' AND o.created_at < '2024-05-02';
CACHING STRATEGIES

Cache what is read frequently, expensive to compute, or reference/static. Cache query results carefully.

PATTERNHOW IT WORKS
Cache-aside (lazy loading)App checks the cache; on a miss reads the DB and populates the cache
Write-throughWrites go to cache and DB together
Write-behindWrites go to cache, flushed to the DB asynchronously
InvalidationThe hard part: expire or evict entries when data changes
Read from cache → Hit? return data → Miss: read from DB → Populate cache

HIGH AVAILABILITY AND RELIABILITY

Replication (primary and replicas), automatic failover, backups (full, incremental, pointin-time recovery), multi-AZ or multi-region, health checks and monitoring. Replication is usually asynchronous, so a replica can lag behind the primary; reads that must be fresh go to the primary.
